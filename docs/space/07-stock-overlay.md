## 第1章 功能概述与定位

**目的**：在 P1 的 3D 渲染（05）与定位（06）之上，叠加 WMS 实时库存数据，让用户在 3D 中看到每个库位的**真实状态与占用**，并支持"按物料/批次/容器找货"。

**本章范围（07）：**
- `IWmsStockQuery` 完整契约（批量按编码查库存状态/量/容量；按物料反查库位）。
- 刷新机制：按需快照 + 可选轮询（间隔下限、可见区裁剪、无推送）。
- 状态着色：库存状态 → 实例颜色（复用 05 `setInstanceColor`）。
- 库容利用率：库位/货架/库区聚合 + 热力着色。
- 按物料/批次/容器定位（D8 P2 半，复用 06 飞行）。
- 选中信息卡叠库存数据（接 06 第4.2）。

**不含（划清边界）：**
| 能力 | 去哪章 |
|---|---|
| 3D 渲染 / 实例化 / 着色 API 本身 | [05 章](./05-viewer-core.md)（07 调 `setInstanceColor`，不实现它） |
| 相机 / 拾取 / 飞行定位基础设施 | [06 章](./06-camera-pick.md)（07 复用，不重造） |
| 库存数量/批次/容器的**业务真相与写入** | WMS 模块（07 只读，绝不写） |
| 拣货路径动画 / 作业热图 | [08 章](./08-advanced-viz.md) |

> **为什么是只读同步、与 04 的事件刚好相反**：库位目录发布（04）是低频主数据写 → 用持久化事件（可靠投递）；库存叠加（07）是高频读、要即时 → 用同步只读查询。两者都**单向 Space→WMS、契约在 Space 侧**（沿用采购模块低耦合手法），但一写一读、一异步一同步，性质相反。**04 已经是本契约的第一个消费者**（停用前置 0 库存校验，04 §6），07 把它扩成完整批量 + 反查契约。

## 第2章 IWmsStockQuery 契约（Space 侧定义，WMS 实现）

### 2.1 接口（编译期 Space 不依赖 WMS 实现）
```csharp
// CP6.Core/Services/Space/IWmsStockQuery.cs —— 契约定义在消费者(Space)侧
public interface IWmsStockQuery
{
    // ① 批量按库位编码查库存（叠加主力；04 的单条停用校验 = codes 单元素特例）
    Task<IReadOnlyList<WmsStockDto>> GetStockByLocationsAsync(
        Guid tenantId, IReadOnlyCollection<string> locationCodes, CancellationToken ct = default);

    // ② 按物料/批次/容器反查"哪些库位有它"（D8 P2 半，第6章）
    Task<IReadOnlyList<WmsLocationHit>> FindLocationsAsync(
        Guid tenantId, StockLocateQuery query, CancellationToken ct = default);
}

public sealed class WmsStockDto
{
    public string LocationCode { get; set; } = "";  // join key
    public int    BinStatus    { get; set; }        // ★0空 1有货 2满 3锁定 4在拣（与 README §六一致）
    public decimal Qty         { get; set; }        // 当前库存量（基本单位）
    public decimal? Capacity   { get; set; }        // 库容（可空，WMS 有则给，算利用率用，第5章）
    public string?  TopMaterial{ get; set; }        // 占位主物料（可空，信息卡/着色预留）
    // —— 字段预留：未来扩温区/锁定原因/批次数等，v1 不消费（YAGNI）——
}
```
- `BinStatus` 取值与 README §六、04 章一致：**空/有货/满/锁定/在拣**。WMS 把其内部库存模型映射成这 5 态返回。
- **WMS 实现该接口**（如 `CP6.Core/Services/Wms/WmsStockQuery.cs`），DI 注入；Space 只依赖 `IWmsStockQuery` 抽象——无反向编译依赖。
- 契约**纯读**：无任何写方法。join 一律按 `LocationCode`（00 §7 的 join key）。

### 2.2 批量是硬要求
- 万级库位绝不能逐个查（N 次 RPC 必崩）。`GetStockByLocationsAsync` 一次传一批编码（当前可见区，第3/8章），WMS 一次返回——网络往返压到批次级。
- 批大小有上限（如每批 ≤ 1000 编码），超出由 Space 侧分批并发（受控并发数）。

## 第3章 刷新机制（D5）

> D5 定稿：**按需快照(A) + 可选轮询 + 无推送**，轮询有**间隔下限**、查询做**可见区裁剪**。

### 3.1 无推送（v1）
- WMS **不主动推**库存变化（不做 SignalR/WebSocket 实时推送）。Space **按需拉**。
- 理由：库存推送要 WMS 改造 + 长连接成本，P2 性价比低；按需快照已满足"看当前库存"需求。实时推送留 P3+（YAGNI）。

### 3.2 按需快照（A，主力）
```
触发快照拉取：
  · 进入 3D 浏览页 / 切楼层后建图完成
  · 用户点"刷新库存"按钮
  · 相机停稳后（可选，见轮询）
→ 收集当前可见区库位编码（第8章裁剪）→ GetStockByLocationsAsync(batch)
→ 着色（第4章）+ 缓存本次快照（带时间戳，信息卡显"数据时间"）
```
- 快照是**某一刻的照片**，UI 显刷新时间，用户知道"非毫秒级实时"。

### 3.3 可选轮询（默认关）
```
开启轮询（用户切开关）：
  每 interval 拉一次可见区快照，interval ≥ 下限（如 minInterval=5s，防打爆 WMS）
  相机移动中暂停轮询（取景未定，查了也白查）；停稳后恢复
  离开页面/切后台 → 停轮询
```
- **间隔下限**强制（即使用户配更小也夹到下限）；可见区裁剪让每轮只查当前视锥库位。
- 轮询是**可选增强**，默认关（按需快照够用）；开了也只是定时重拉快照，机制同 §3.2。

### 3.4 可见区裁剪（贯穿）
- 每次快照只查**当前层 ∩ 视锥内（或当前 LOD 可见）** 的库位编码——不查看不见的、不查别层的。
- 与 05 的分桶/剔除天然契合：取"可见桶"内的库位编码即可（05 已算好可见桶）。

## 第4章 状态着色

### 4.1 状态 → 颜色（v1 固定默认色板）
| BinStatus | 含义 | 默认色（v1 固定） |
|---|---|---|
| 0 空 | 无货 | 绿 |
| 1 有货 | 部分占用 | 蓝 |
| 2 满 | 占满 | 红 |
| 3 锁定 | 冻结/盘点锁 | 灰 |
| 4 在拣 | 拣货作业中 | 黄 |
- **v1 固定默认色 + 字段预留**（YAGNI 决策）：色板写死在前端常量，但留 `colorScheme` 配置位，未来可做租户自定义配色，v1 不实现配置 UI。
- 着色 = 调 05 `setInstanceColor(locationId, color)`——**改实例色，不重建几何**（05 §10 句柄）；批量着色一次刷一批，`requestRender` 触发一次重绘。

### 4.2 着色模式切换
| 模式 | 着色依据 |
|---|---|
| 状态模式（默认） | BinStatus → 上表色 |
| 利用率热力模式 | OccupiedRatio → 热力渐变（第5章） |
| 结构模式（关叠加） | 回 05 默认灰（无库存色，纯看结构） |
- 图例（legend）随模式显示色含义；切模式即重着色（用缓存快照，不必重拉）。

### 4.3 未放置/无数据处理
- `Placed=false`（采纳态无几何）库位不在 3D 中（05 不渲染），自然不着色。
- WMS 未返回某编码（如刚发布未建 bin）→ 该库位标"无数据"中性色 + 信息卡注明。

## 第5章 库容利用率（热力）

### 5.1 计算
```
库位利用率 = Qty / Capacity （Capacity 有值时；无则按 BinStatus 粗估：空=0/有货=0.5/满=1）
货架利用率 = Σ库位Qty / Σ库位Capacity（聚合该货架已放置库位）
库区利用率 = 同理聚合到 Zone
```
- 利用率热力模式（§4.2）把 `[0,1]` 映射到冷→暖渐变（如蓝→黄→红），一眼看出哪片满了。
- 聚合在**前端用快照数据算**（库位级数据已在手），不额外请求 WMS。

### 5.2 聚合视图
- 库位级：每盒按自身利用率着色。
- 货架/库区级（远 LOD，05 库位桶隐藏时）：货架/库区色块按聚合利用率着色——远看库区热力分布，近看单格。与 05 的 LOD 联动（远聚合、近明细）。

## 第6章 按物料/批次/容器定位（D8 的 P2 半）

> D8：按库位编码定位是 P1（06 已做）；**按物料/批次/容器定位是 P2**——因为"哪个库位有这个料"是 **WMS 的库存真相**，要查了才知道。

### 6.1 流程（反查 + 复用 06 定位）
```
搜索框输入 物料号/批次/容器号 → locateByStock(query):
  1. IWmsStockQuery.FindLocationsAsync(tenantId, {materialNo|lot|container, …})
       → WMS 返回命中库位列表 [{locationCode, floorId, qty, …}]（WmsLocationHit）
  2. 未命中 → I-SPACE-701「无库位存放该物料」
  3. 命中 N 个：
     · 高亮全部命中库位（05 setInstanceColor 高亮色）+ 列候选清单（编码+量+楼层）
     · 跨层命中按楼层分组；点某条 → 复用 06 locate(该 code)（切层+飞行+高亮，06 §6）
     · "下一个/上一个"在命中集间巡航（复用 06 飞行）
```
- **关键复用**：07 不重造定位——只把 06 的入口从"输入编码"换成"输入物料 → WMS 反查出一批编码 → 喂给 06 的 `locate`"。06 的切层/飞行/高亮/信息卡全程复用。
- `FindLocationsAsync` 的查询条件（StockLocateQuery）：物料号、批次、容器号、（可选）库区范围；WMS 实现按其库存索引返回。

### 6.2 命中可视化
- 命中库位**整批高亮**（与周边区分），非命中可选**变暗/半透明**（聚焦命中）。
- 命中数多（如一个常用料铺满半个仓）→ 限高亮 + 列表分页 + 按量/楼层排序，避免满屏高亮失去意义。

## 第7章 选中信息卡叠库存（接 06）

06 §4.2 的选中信息卡，在 07 接入后**叠库存行**：
```
库位编码：A-03-02-05
层级路径：WH1 / 1层 / 库区A / 货架R03 / 第2列 第2层 第1深
状态：已发布   来源：引擎生成
```

- 选中单库位时按需查该编码（或用快照缓存）；信息卡库存行带**数据时间戳**（提示非实时）。
- hover tooltip 可选叠"状态 + 量"（轻量），详情在 click 信息卡。

## 第8章 性能与降级

| 机制 | 做法 |
|---|---|
| 可见区裁剪 | 只查当前层 ∩ 可见桶的库位编码（第3.4），不全量 |
| 批量查询 | 一批编码一次 RPC（第2.2），超上限分批并发（受控） |
| 快照缓存 | 一次快照缓存复用：切着色模式/算利用率/开信息卡都用缓存，不重拉 |
| 轮询节流 | 间隔下限 + 相机移动暂停（第3.3） |
| WMS 慢/不可用 | 查询超时 → 降级：保留上次快照 + 标"库存数据获取失败/陈旧" W-SPACE-701，不阻断 3D 浏览（结构照看） |
| 大命中集 | 物料定位命中过多 → 限高亮 + 分页（第6.2） |

> **降级原则**：库存是**叠加增强**，WMS 不可用时 3D 结构浏览（P1 能力）必须照常——07 失败不拖垮 05/06。

## 第9章 API 与契约接口

| 端点/接口 | 类型 | 说明 |
|---|---|---|
| `IWmsStockQuery.GetStockByLocationsAsync` | C# 契约（WMS 实现） | 批量按编码查库存（第2.1） |
| `IWmsStockQuery.FindLocationsAsync` | C# 契约 | 按物料/批次/容器反查库位（第6.1，D8 P2） |
| `GET /api/space/floor/{id}/stock?bbox=` | HTTP（前端用） | 取可见区库存快照（服务端调 IWmsStockQuery 批量，可见区裁剪） |
| `GET /api/space/stock/locate?material=&lot=&container=` | HTTP | 按物料反查库位（服务端调 FindLocationsAsync）→ 命中列表 |
- 前端不直接调 WMS：经 Space 后端的 `/stock` 端点中转（统一鉴权/多租户/可见区裁剪），后端再调 `IWmsStockQuery`。
- 04 的停用校验也走 `IWmsStockQuery.GetStockByLocationsAsync`（单编码），与本章同一契约。

## 第10章 消息一览

| ID | 种别 | 内容 | 触发 |
|---|---|---|---|
| W-SPACE-701 | Warn | 库存数据获取失败，显示上次快照（可能陈旧） | IWmsStockQuery 超时/异常，降级（第8） |
| I-SPACE-701 | Info | 无库位存放该物料/批次/容器 | FindLocationsAsync 空命中（第6.1） |
| I-SPACE-702 | Info | 找到 N 个库位（M 层），点击定位 | 物料定位多命中（第6.1） |
| I-SPACE-703 | Info | 库存已刷新（数据时间 hh:mm:ss） | 快照拉取完成（第3.2） |
| W-SPACE-702 | Warn | 命中库位过多，仅高亮前 K 个 | 大命中集限流（第6.2） |

## 第11章 集成与依赖

| 关系 | 说明 |
|---|---|
| → WMS（同步只读） | `IWmsStockQuery`（Space 定义、WMS 实现）：批量查库存 + 按物料反查；单向、无反向编译依赖；纯读 |
| ← 05 渲染内核 | 用 `setInstanceColor`（着色不重建）+ `requestRender`（重绘）+ 可见桶（裁剪/聚合） |
| ← 06 定位 | 物料定位（D8 P2）复用 06 的 `locate`（切层+飞行+高亮）；信息卡叠库存行 |
| ← 04 发布契约 | 04 停用校验是本契约的第一个消费者（单编码查 0 库存）；本章扩为完整批量 + 反查 |
| ← 00 数据模型 | join key=LocationCode；只叠 Placed=true 库位；BinStatus 5 态对齐 README §六 |
| → 08 高级可视化 | 08 作业热图复用本章库存/利用率数据源 |
| → PUB 权限 | 库存查看接功能权限；可见库位接数据权限（无权库位不查/不显） |
| 多租户 | 所有查询带 TenantId，WMS 按租户隔离；前端经 Space 后端中转鉴权 |
