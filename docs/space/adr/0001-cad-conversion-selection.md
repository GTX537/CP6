# ADR-0001：DWG/DXF 转换与 CAD IR 技术选择

- 状态：**Accepted, implementation selection gated by experiment**
- 日期：2026-07-25
- 关联：E01-S02、E02-S01、D05、D12、D13、D15

## 1. 问题

Space MVP 必须接受 DWG/DXF，但当前主工作树没有正式 CAD 解析链。产品不能把“请用户另存为 DXF”作为唯一 DWG 方案，也不能在没有 SaaS 授权、隔离和几何保真证据时绑定某个 SDK。

## 2. 决策

采用以下固定优先级：

1. 首选通过全部硬门槛的**自托管嵌入式 SDK**。
2. 嵌入式方案不通过时，使用运行在批准区域内的**受控转换服务**。
3. 两者均不通过时，阻断 DWG Beta；DXF、底图和地图编辑器继续交付。

所有方案只能输出冻结的 CAD IR，不能直接写 Draft。规则引擎和 AI 都消费同一 IR。

## 3. 硬门槛

任一不满足即淘汰：

| 类别 | 门槛 |
|---|---|
| 格式 | 读取 MVP 兼容矩阵内的 DWG/DXF；不得要求终端用户安装 AutoCAD，受控 Worker 可安装已批准的运行时 |
| 授权 | 使用范围必须有实名 Owner 批准并受许可证约束；生产、多租户 SaaS、再分发或跨组织托管必须另有覆盖相应范围的明确授权 |
| 隔离 | 在无业务凭据、无公共网络写权限的隔离 Worker/转换服务运行 |
| 保真 | 单位、坐标、Layer、Handle、Block/Insert、属性和变换可追踪 |
| 容量 | 平台硬上限 200MB、单图 100 万图元有可预测的拒绝和资源保护 |
| 安全 | 文件头、扩展名、MIME、恶意文件扫描；解析崩溃不影响 API 进程 |
| 输出 | 只生成版本化 CAD IR/Artifact，不直接操作版本修订表 |
| 运维 | 支持超时、取消、幂等、可恢复重试、指标和许可证健康检查 |

## 4. 必测兼容矩阵

### 4.1 文件版本

- DXF：R12/AC1009、2000、2007、2013、2018。
- DWG：2000、2007、2013、2018 及供应商明确支持的较新稳定版本。

### 4.2 MVP 必须识别

- `LINE`
- `LWPOLYLINE` / `POLYLINE`
- `ARC`
- `CIRCLE`
- `INSERT` / `BLOCK`
- `ATTRIB` / `ATTDEF`
- `TEXT` / `MTEXT`
- `HATCH`（允许降级为边界/装饰）
- Layer、颜色、线型、单位和坐标变换

`SPLINE`、`ELLIPSE`、`DIMENSION`、嵌套 Block 和 XRef 必须进入矩阵并给出 `Supported / Flattened / Issue / Rejected` 结论。未知图元不得静默丢弃。

## 5. 评分规则

通过硬门槛后按 100 分评分：

| 维度 | 权重 |
|---|---:|
| 图元、块和属性覆盖 | 25 |
| 几何/单位/坐标保真 | 20 |
| 性能、内存和稳定性 | 15 |
| 安全隔离与可运维性 | 15 |
| SaaS 授权和总成本 | 15 |
| 供应商支持、版本策略和退出能力 | 10 |

总分低于 80 不得进入 Site Provider 候选名单。每个声明 CAD GA 的 Site 至少需要一个通过全部硬门槛且总分不低于 80 的唯一最高分候选，并将其配置为 Primary。存在唯一第二名时可以配置为可选 Backup；Backup 缺失或第二名并列不阻断 V1 Core GA。最高分并列时无法唯一确定 Primary，保持 No-Go，必须由同一冻结环境复测或经批准的评分仲裁形成不同最终分数。原文件不离开 CP6 受控区域、部署依赖更少仍是仲裁输入，但不得让较低最终分数覆盖较高分数成为 Primary。

机器执行规则固定为 `cad-provider-adr-0001-v2`。正式评分使用 `tools/CP6.Space.CadExperiment qualify-providers`：每个候选必须绑定同一黄金集 SHA-256、同一冻结环境 SHA-256、Provider 版本、试验 Preflight 哈希和四项硬门槛证据；六维分数超出各自权重即拒绝输入。唯一最高分候选通过全部硬门槛且不低于 80 时生成 Primary 认证输入；存在唯一第二名时额外生成可选 Backup。最高分并列、没有合格候选或冻结基线混用时输出 No-Go，且不得生成认证写入输入。生成的认证输入由选择报告 SHA-256 绑定，仍须经受控 Site Provider 管理接口、权限与 Revision fence 写入；评分工具本身不修改 Site 配置。

## 6. 试验方法

1. 使用 `docs/space/acceptance/v1.0.0` 五类种子样本完成最小试验。
2. E02-S01 使用完整 20 份黄金数据和 50MB/100万图元压力样本复测。
3. 每次运行记录：
   - 方案和版本。
   - OS、CPU、内存、Worker 限额。
   - 文件 SHA-256。
   - 解析耗时和峰值内存。
   - 输入图元、输出图元、Issue 数。
   - 单位、坐标和几何误差。
   - 崩溃、超时、取消和重试结果。
4. 输出兼容矩阵、评分表、许可证意见和部署图。

## 7. 几何误差判定

- 直线端点和块插入点：绝对误差 ≤1mm。
- 角度：绝对误差 ≤0.1°。
- 闭合多边形面积：相对误差 ≤0.1%。
- 单位或坐标系无法确定：必须产生 Blocking Issue，禁止猜测后写 Draft。

## 8. 回退

- 主 SDK 故障时，同一 SourceHash 可以切换到受控转换服务重新生成 Artifact。
- 转换服务不可用时，任务进入可重试失败，不产生部分 Draft。
- 用户仍可使用 DXF、PDF/图片底图和地图编辑器。
- 已有 Published 不受任何转换任务影响。

## 9. 验收证据

E02-S01 完成必须附：

- Primary 的名称/版本；配置了可选 Backup 时一并记录。
- 完整评分表和淘汰理由。
- 法务/采购的 SaaS 授权结论。
- CAD 版本/实体矩阵。
- 五类布局、50MB 和 100万图元报告。
- Worker 隔离、取消、超时和崩溃恢复证据。
