# CP6 3D Space 产品需求说明书

版本：v1.2 AI 生成需求对齐基线  
基线日期：2026-07-25  
适用范围：CP6 Space、WMS、PUB、Integration  
产品状态：已完成产品评审，可进入技术试验和实施拆分  

## 1. 文档定位

本文是 CP6 3D Space 的当前产品需求基线。它把菜鸟数字空间案例、CP6 已有代码和本轮确认的产品决策放到同一套需求体系中。

优先级发生冲突时，按以下顺序解释：

1. 本文及同目录的新版需求文档。
2. CP6 当前代码和数据库约束。
3. `docs/space/` 既有 00～09 设计丛书。
4. 2026 年 6 月形成的历史总纲和实施笔记。

本基线明确替代两项旧决定：

- “CAD 导入推迟到 P3+”改为“低成本 3D 建模是第一版最高优先级”。
- “人员与设备永不纳入”改为“第一版不实现，但完整蓝图保留，后续分期建设”。

## 2. 已确认的产品决策

| 编号 | 决策 |
|---|---|
| D01 | 第一优先级是理清 CP6 当前 Space 业务和开发逻辑，再支持展示、真实仓库和 SaaS 商品化。 |
| D02 | Space 是 CP6 主业务模块，同时保持独立边界，可单独部署并连接其他 ERP/WMS。 |
| D03 | 产品采用多租户模式，支持租户内部用户以及客户、供应商、第三方物流商登录查看。 |
| D04 | 第一版 MVP 包含低成本建模、人工校正、仓库版本发布、库位同步 WMS、3D 库存和拣货任务。 |
| D05 | 低成本建模必须同时支持 CAD+Excel 和地图编辑器，两条路径产出同一种空间模型。 |
| D06 | 第一套验收场景是通用货架仓，预留货主、批次、容器和制造属性。 |
| D07 | 当前没有真实验收仓数据，第一版必须建设标准样本和 WMS 模拟器。 |
| D08 | 保留现有 Site/Floor/Zone/Aisle/Rack/Location 作为 Published 运行态物化，新增独立版本化设计工作区和通用空间元素。 |
| D09 | 正式模型版本以整个仓库为发布单位，楼层可以分别编辑。 |
| D10 | 同时支持 Space 新建库位并发布 WMS，以及从既有 WMS 采纳库位后反向放置。 |
| D11 | 模板分平台公共模板和租户私有模板，第一版不建设跨租户模板市场。 |
| D12 | CAD/Excel 解析只写草稿；校验通过后才能发布；回退通过重新发布历史版本完成。 |
| D13 | AI 自动生成完整仓库属于 MVP；首版输入是结构化 DWG/DXF 的 CAD IR，PDF/图片识别和自然语言生成后置。 |
| D14 | AI 采用混合、Provider 中立架构，只生成可审查提案；人工确认后原子写入 Draft，永不自动发布。 |
| D15 | 单位、坐标、几何、拓扑、碰撞、货架层和库位编码由确定性引擎负责，AI 只做语义识别和属性建议。 |
| D16 | 外部 AI 默认不接收原始文件；既有租户 AI 策略默认关闭，试点租户显式启用结构化特征外发。 |
| D17 | 客户、供应商和 3PL 只读 Published，不可访问 Draft、源文件、AI 提案、Prompt、费用和运行日志。 |

## 3. 产品愿景

普通仓库业务人员不需要掌握 CAD 深度操作、Blender、3ds Max 或 Three.js，也能在较短时间内把仓库图纸和业务数据转成可编辑、可发布、可连接 WMS 的 3D 空间。

Space 不是 3D 展示插件。它是连接以下事实的空间业务模块：

- ERP 的订单、产品、物料、客户、供应商和成本事实。
- WMS 的仓库、库位、库存、任务和作业事实。
- Space 的物理拓扑、几何布局、空间属性和空间版本事实。
- 后续 PDA、WCS、IoT 的人员、设备和现场事件事实。

## 4. 当前问题

### 4.1 产品问题

1. 现有 Space 已经实现不少功能，但文档仍把部分能力描述为“待编码”，现状与蓝图不一致。
2. 现有建模方式以模板和 CP6 JSON 为主，不能从客户常见的 CAD、Excel 快速建立仓库。
3. `Space_Floor` 已保存底图字段，但编辑器没有形成上传、显示、标定和描图流程。
4. 货架模型使用统一层高和格口数，不能表达每层不同规格。
5. 墙、柱、门、月台、托盘和设备缺少统一空间元素与资产库。
6. 路径、库存和热图已经存在，但产品界面没有统一说明真实数据、模拟数据和未接入数据。

### 4.2 用户问题

1. 新客户建仓需要开发人员手工准备数据，复制成本高。
2. 仓库业务人员无法独立完成建模和校正。
3. CAD、Excel、WMS 库位和 3D 场景之间没有一条可审计的数据链。
4. 模型发布失败时，用户难以判断失败在哪个阶段以及如何回退。
5. 外部客户、供应商和 3PL 缺少限定范围的空间查看入口。
6. 固定图层规则无法覆盖大量非标准命名和缺失属性，人工仍需逐层理解图纸语义。

## 5. 用户与权限范围

### 5.1 平台侧角色

| 角色 | 主要职责 | 默认数据范围 |
|---|---|---|
| 平台管理员 | 租户开通、公共模板、平台配置 | 全平台，敏感操作强审计 |
| 平台支持人员 | 经授权协助租户排查建模和集成问题 | 临时授权租户与仓库 |
| 平台审计员 | 查看跨租户操作和安全记录 | 只读审计数据 |

### 5.2 租户侧角色

| 角色 | 主要职责 |
|---|---|
| 租户管理员 | 用户、角色、外部协作方、数据范围 |
| 空间建模人员 | CAD/Excel 导入、AI 提案审查、地图编辑、人工校正 |
| 仓库主数据管理员 | 仓库、库区、编码规则、WMS 映射 |
| 发布管理员 | 模型校验、审批、发布、回退 |
| 仓库主管 | 查看库存、任务、空间状态和异常 |
| 现场作业人员 | 定位库位、查看被授权任务 |
| 运营分析人员 | 查看利用率、路径和后续诊断 |
| 集成管理员 | WMS 适配、模拟器、事件和失败重试 |
| 只读查看者 | 查看被授权的 2D/3D 场景 |

### 5.3 外部协作角色

| 角色 | 第一版默认可见内容 |
|---|---|
| 客户 | 自己的订单、库存、SKU、库位和作业进度 |
| 供应商 | 自己的送货、预约、收货状态和相关区域 |
| 第三方物流商 | 被授权仓库、货主或业务范围内的数据 |

外部账户默认只读。授权必须同时包含租户、外部组织、仓库/区域、业务对象、字段范围和有效期。跨租户或授权判断失败时默认拒绝。

## 6. 产品范围

### 6.1 第一版 MVP

1. 模型来源与仓库版本管理。
2. DWG、DXF 上传；DWG 可在内部转换后进入统一解析流程。
3. PDF、PNG、JPG 底图上传、显示和两点标定。
4. CAD 图层映射、语义解析、置信度、异常清单和人工校正。
5. 结构化 CAD IR 的 AI 语义补全、完整仓库提案、人工审查和原子写入 Draft。
6. Excel 标准模板、字段映射方案、预检、导入和错误报告。
7. 地图编辑器、参数化组件库、模板、阵列、对齐和批量编码。
8. 墙、柱、门、月台、库区、巷道、货架、托盘和常见设备静态元素。
9. 货架逐层高度、格口数、深度、尺寸和承重。
10. 仓库级草稿、校验、预览、发布、历史版本和回退。
11. Space 新建库位发布到 CP6 WMS。
12. 从既有 WMS 导入库位并反向放置、绑定。
13. WMS 模拟器以及标准 WMS 适配接口。
14. Three.js 单层、多层和全站查看。
15. 真实或模拟库存状态、物料/批次/容器定位。
16. 真实或模拟拣货任务路径查看。
17. 多租户权限、外部协作查看、审计和数据来源标识。

### 6.2 第二阶段

1. PDA 人员位置、闲忙状态、作业轨迹和停留。
2. WCS、AGV、IoT 设备实时状态和告警。
3. 货主、SKU 属性、ABC 周转的空间叠加。
4. 仓库总览 KPI 和指标快照。

### 6.3 第三阶段

1. 路径、拥堵、停留、容量和布局诊断。
2. 上架推荐、库位优化和人员调度建议。
3. 建议审批后转换为 WMS/WCS/PDA 任务。
4. 执行事件回流和效果评价。
5. 布局方案、历史实单仿真和 CAD 导出/回写。

### 6.4 第一版明确不做

1. 园区道路、停车区、外场车辆和完整园区交通仿真。
2. 任意非标准 CAD 的无人工全自动识别承诺。
3. 真实人员定位、设备控制和 WCS 调度。
4. 高精度物理仿真。
5. 跨租户模板交易市场。
6. Space 直接修改 WMS 库存数量或作业单据。
7. PDF/图片计算机视觉自动建仓和自然语言从空白生成完整仓库；仅预留接口。

## 8. 系统职责边界

| 系统 | 权威事实 | Space 的处理方式 |
|---|---|---|
| ERP | 订单、产品、物料、客户、供应商、成本 | 只引用业务键和必要展示字段 |
| WMS | 仓库执行、库存、批次、容器、任务 | 发布库位目录；只读查询库存和任务 |
| Space | 几何、拓扑、空间元素、编码规则、模型版本 | 自己保存和审计 |
| 文件服务 | CAD、Excel、底图和解析产物 | 保存 SHA-256、来源、Artifact 和版本引用 |
| AI Provider | CAD IR 的语义分类和属性建议 | 只接收策略允许的最小化结构化特征，不拥有几何、编码和发布决定 |
| PDA/WCS/IoT | 人员、设备和现场实时事件 | 后续阶段通过标准事件接入 |

内部库位身份使用稳定 `LocationLogicalId`，在 CP6 中保持 `Space_Location.Id = WmsBin.Id`；库位编码是可读业务契约，外部 WMS 通过 `TenantId + AdapterId + SiteId + LocationLogicalId` 保存绑定。发布后的编码按受控规则冻结，几何可以调整而不更换身份。

## 9. 低成本建模定义

### 9.1 用户结果

- 普通仓库业务人员经过简单指导即可完成，不要求专业 3D 建模经验。
- CAD 和地图编辑器两条路径得到同构数据，可互相切换和继续编辑。
- 用户只处理异常项，不需要逐个重画已正确识别的对象。
- 2D 修改自动反映到 3D，不做第二次建模。
- AI 结果先进入提案审查，不把概率结果伪装成已发布事实。

### 9.2 第一版量化目标

| 指标 | 目标 |
|---|---|
| 标准仓首个可编辑 3D 场景 | CAD+Excel 上传后 60 分钟内完成 |
| 标准图层自动识别覆盖率 | 可识别目标元素中不低于 80% |
| AI 完整仓库提案 | 50MB 标准 CAD 到可审查提案 P95 不超过 15 分钟 |
| AI 整体语义准确率 | 黄金数据集不低于 90% |
| AI 高置信度精确率 | 黄金数据集实测不低于 95% |
| 人工操作量下降 | 相对纯人工地图建模不低于 70% |
| 标准地图规模 | 500 个货架、10,000 个库位 |
| 地图编辑批量生成 | 500 个货架和 10,000 个库位无需逐个创建 |
| 2D/3D 一致性 | 保存后同一版本内对象数量、编码和尺寸一致 |
| 发布一致性 | Space 与 WMS 模拟器库位数量和编码 100% 一致 |

自动识别覆盖率只适用于符合平台图层规范或已配置映射模板的 CAD。非标准图纸进入异常清单，不得把错误识别隐藏为成功。

## 10. 标准验收仓

第一版内置一套不含真实客户信息的通用货架仓：

| 数据 | 基线 |
|---|---|
| 租户 | 2 个，验证隔离 |
| 仓库 | 每租户 1 个 |
| 楼层 | 2 层 |
| 功能区 | 收货、存储、拣选、包装、发货 |
| 巷道 | 不少于 10 条 |
| 货架 | 500 个 |
| 库位 | 10,000 个 |
| SKU | 不少于 100 个 |
| 库存记录 | 不少于 5,000 条 |
| 拣货任务 | 不少于 20 个，含跨区和跨层 |
| 异常样本 | 图层未知、编码重复、坐标越界、Excel 缺列、WMS 超时 |

样本同时提供：

- 规范 DXF。
- 可转换 DWG。
- PDF/PNG 底图。
- 标准 Excel。
- 带异常的 CAD/Excel。
- 至少 20 份、覆盖 5 类布局的脱敏 AI 黄金 CAD 和机器可读标准答案。
- WMS 模拟库存和拣货任务。

## 11. 数据来源与状态标识

任何运行态数据都必须显示以下信息：

- 数据类型：真实、模拟、暂未接入。
- 来源系统和连接名称。
- 数据时间和系统接收时间。
- 当前延迟或快照时间。
- 最后成功时间和最近失败状态。

模拟数据与真实数据使用不同的数据源标识和清理范围，禁止在同一生产仓库中静默混用。

## 12. 非功能需求

### 12.1 多租户与安全

1. 所有新业务表必须带 `TenantId` 并使用 CP6 全局租户过滤和写入盖章。
2. 文件对象、缓存键、后台任务和事件同样必须带租户。
3. 外部用户不能通过猜测 ID 读取其他组织、仓库或货主数据。
4. CAD/Excel 上传执行扩展名、MIME、大小、恶意文件和压缩炸弹检查。
5. 平台人员进入租户数据前必须取得临时授权并记录真实操作者。
6. 原始 CAD/Excel/底图默认不得发送外部 AI；Provider 响应按不可信输入校验。
7. 外部用户不得访问 Draft、来源文件、AI 提案、Prompt、费用或运行日志。

### 12.2 性能

1. 10,000 库位场景在目标浏览器中可交互浏览。
2. 大对象列表必须批量查询，禁止逐库位访问 WMS。
3. CAD/Excel 解析使用后台任务，页面可关闭后重新查看进度。
4. 3D 标签按视野和缩放级别虚拟化。
5. 场景与解析结果按租户、仓库、版本缓存并支持失效。
6. 平台单文件硬上限 200MB，租户默认 100MB；单图不超过 100 万 CAD 图元。
7. 单租户最多同时运行 3 个 AI 生成任务；50MB 标准 CAD 到提案 P95 不超过 15 分钟。

具体帧率、首屏时间和解析耗时在 CAD 技术选型试验后锁定，不在未测量前虚构。

### 12.3 一致性与恢复

1. 解析只产生草稿版本。
2. 未解决阻断问题前禁止发布。
3. 发布 API 必须可重复调用，不产生重复库位。
4. WMS 成功并回读验证前不切换当前 Published 运行态；部分或不确定状态必须进入可恢复对账，不得误报成功。
5. 回退通过重新发布历史版本完成，不直接覆盖审计历史。
6. WMS 暂时不可用时保留待重试状态，并提供人工重试。
7. AI Apply 必须校验基础 ContentRevision 并在单事务中写入 Draft；冲突或失败时零写入。

### 12.4 可观测性

每个解析、AI 生成与发布任务记录 `CorrelationId`、租户、仓库、模型版本、源文件哈希、操作者、开始/结束时间、处理数量、失败数量和错误摘要。AI 任务还记录策略、Provider、模型、规则版本、用量、费用和人工修改率，但日志不保存原始文件、密钥或未脱敏 Prompt。

## 13. 高层验收标准

1. 同一标准仓分别通过 CAD+Excel 和地图编辑器建模，最终对象数量、库位编码和 3D 结果一致。
2. DWG、DXF、PDF/PNG 底图和 Excel 均能进入规定的建模流程。
3. 解析结果提供成功、警告、阻断三类清单，支持按图层和元素定位修正。
4. 未解决阻断问题时发布按钮不可用，后端直接调用同样拒绝。
5. 发布后 CP6 WMS 或 WMS 模拟器得到相同的库位目录。
6. 重复发布同一版本不生成重复库位。
7. 可从 WMS 采纳现有库位，在地图中绑定后保持原编码不变。
8. 3D 场景可显示库存状态并按物料、批次、容器定位。
9. 可加载拣货任务并显示库位顺序和路径。
10. 两个租户使用相同仓库码、库位码和模板名时互不干扰。
11. 客户、供应商和 3PL 只能看到授权的数据范围和字段。
12. 任一失败场景都不会破坏当前已发布版本，并可追踪到日志和操作人。
13. AI 高置信度提案也必须经过用户确认；不存在自动批准或自动发布接口。
14. AI Provider 超时、非法输出、限流和 Draft Revision 冲突均不产生部分草稿。
15. AI 被禁用时，规则解析、Excel、底图和地图编辑器仍可完成建模。
