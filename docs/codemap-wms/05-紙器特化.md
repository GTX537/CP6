# 05 · 紙器業特化扩展（原紙/インキ/パレット/残材/Kit/Slotting/CrossDock/サンプル/版型）

> 先读 [`README.md` §0/§1](README.md)。全部 `文件:行号` 与代码片段 2026-06-22 实测、逐字引用。
> 9 个紙器业特化功能，每个抓核心动作 + 一句【特化点】。

## 0. 关键事实

- 状态非 enum，是 `WmsTxnType.cs` 内 `static class` 常量；实体状态字段是 `int Status`/`string OpenStatus`。
- ⚠️ **只有 Kit/Cross-Dock 走 `IStockMovementService`**（满足铁律）；其余（PaperRoll/Ink/Pallet/Remnant/Sample/PlateMold/Slotting）用**独立专用表**(`T_PaperRoll` 等)自管理在库，**与主 `Stock` 表解耦**。
- 采番前缀：`ROLL/INK/ICM/PLT(パレット)/REM/KIT/SLP/XD/SMP/PLT2(版型,因PLT被占)`。

## 1. 原紙ロール — 消費(残米減算+自动迁移) + 巾割(1→N)

**消費** `POST /paper-roll/{no}/consume`（`PaperRollView.vue:188-197`→`paperRollApi.consume`）。Service `ConsumeAsync`（`PaperRollService.cs:60-81`）：
```csharp
if (lengthM <= 0) throw new InvalidOperationException("WM-MSG-202: 消費長は0より大きい値を指定");
... if (roll.Status == Disposed) throw ... "WM-MSG-043: 廃棄済ロールは消費不可";
if (roll.RemainingLengthM < lengthM) throw ... $"WM-MSG-202: 消費長({lengthM}) > 残米({roll.RemainingLengthM})";
roll.RemainingLengthM -= lengthM;
if (roll.RemainingLengthM == 0) roll.Status = Disposed;                                      // 完全消費
else if (DisposeThresholdM.HasValue && RemainingLengthM <= DisposeThresholdM) roll.Status = Remnant;  // 残米
else if (roll.Status == InStock) roll.Status = InUse;                                        // 在庫→使用中
```
**巾割** `POST /paper-roll/slit`（子巾逗号串解析）。Service `SlitAsync`（`:99-165`）：子巾合计 `>parent.WidthMm`→`WM-MSG-203`；逐子巾 `NextAsync("ROLL")` 采番继承亲卷属性+`ParentRollNo`；`KeepRemnant && 残端>0` 多建 1 残端卷(`Status=Remnant`)；**亲卷 `Status=Disposed; RemainingLengthM=0`**。
实体 `PaperRoll`(`RemainingLengthM`/`DisposeThresholdM`/`int Status`，`PaperRollStatus` InStock0/InUse1/Remnant2/Disposed3)。错误码 `WM-MSG-202/070/043/203`。
**【特化点】** 原紙非整数件，按"残长"连续量管理；用即减米，到 `DisposeThresholdM` 自动标 `Remnant` 触发残材回用；巾割是 1 母卷物理切成 N 窄卷，须 1→N 拆账并保留父子血缘，残端留存最大化回用。

## 2. インキ — ロット混合(2→1，期限取早，双血缘)

**混合** `POST /ink/lots/mix`（`InkLotView.vue:299-311`→`inkApi.mix`，返 `{newLotNo}`）。Service `MixLotsAsync`（`InkService.cs:72-115`）：
```csharp
if (req.ParentLotNoA == req.ParentLotNoB) throw ... "同一ロット同士の混合は不可";
... if (lotA.Quantity < req.ParentQtyA) throw ... "親A 残量不足"; (lotB 同理)
lotA.Quantity -= req.ParentQtyA; lotB.Quantity -= req.ParentQtyB;
var minExpiry = lotA.ExpiryDate < lotB.ExpiryDate ? lotA.ExpiryDate : lotB.ExpiryDate;   // 期限取早
_db.InkLots.Add(new InkLot { InkLotNo=NextAsync("INK"), OpenStatus=Opened, ExpiryDate=minExpiry,
    Quantity=req.ParentQtyA+req.ParentQtyB, ParentLotNoA=lotA.InkLotNo, ParentLotNoB=lotB.InkLotNo, ... });
```
实体 `InkLot`(`OpenStatus`/`ExpiryDate`/`Quantity`/`ParentLotNoA/B`)。配套 `RecordMatchAsync`(`:125-144`)记顾客×色番调色配方 `FormulaJson`。Mix 校验用本地中日文 message(非 WM-MSG)。
**【特化点】** 印刷专色调合：两桶不同批油墨按比例混成一桶专色，新桶独立 lot 且 **期限取两亲最早**(保守安全)，保留双血缘 `ParentLotNoA/B` 便于回溯。

## 3. パレット — 状态机(组成→保管→出荷待機→出荷済，禁混载)

**端点** `POST /pallet/{no}/complete-building`(`PalletService.cs:75-83` 仅 Building 可)、`/move-to-shipping`(`:85-96` 仅 InStock 可)、`/mark-shipped`(`:98-109` WaitingShip/InStock 可)。`CreateAsync`(`:33-54`)**强制混载禁止** `ProductCd/LotNo` 必填(否则抛"混載禁止原則")。实体 `Pallet`(`ProductCd`/`LotNo`/`MaxStackLayers`/`int Status`/`ShippedOutboundNo`，`PalletStatus` Building0/InStock1/WaitingShip2/Shipped3)。错误码 `WM-MSG-070`+`WM-MSG-043`(5处)。
**【特化点】** 完成品整托"1製品1ロット·禁混载·FIFO·段积崩溃防止"：一托=一品一批，`MaxStackLayers/HeightMm` 防压塌，出荷待機区独立状态可在确定出荷前先物理移到待机库位。

## 5. Kit/組立 — 実行(BOM 部品 OUT + Kit 品 IN，经铁律)

**実行** `POST /kit/orders/{no}/execute`（`KitView.vue:386-396`→`kittingApi.execute`）。Service `KittingService.cs:169-288`（ASSEMBLE）：
```csharp
if (order.Status != KitOrderStatus.Draft) throw ... "WM-MSG-043: 下書きでないため実行不可";
var components = ... KitMasterComponents.Where(KitSku == order.KitSku).OrderBy(LineNo); if (count==0) throw "WM-MSG-020";
foreach (var c in components) {   // 1. 部品 OUT × N
    var needed = c.RequiredQty * order.Qty;
    var stock = ... Stocks.Where(ProductCd==c.ComponentProductCd && !RecallFlag && AvailableQty>=needed && OwnerType==Self)
        .OrderBy(ExpiryDate).ThenBy(ReceiveDate).FirstOrDefault() ?? throw new InsufficientStockException(...);
    var txn = await _stock.ApplyAsync(new { TxnType=WmsTxnType.OUT, ...ProductCd=c.ComponentProductCd, LotNo=stock.LotNo, Qty=needed, RelatedType="KIT_ASSEMBLE" });
    txnNos.Add(txn);
}
var inTxn = await _stock.ApplyAsync(new { TxnType=WmsTxnType.IN, ProductCd=order.KitSku, LotNo=kitLotNo, Qty=order.Qty, RelatedType="KIT_ASSEMBLE" });   // 2. Kit 品 IN × 1

```
DISASSEMBLE 反向(Kit OUT + 部品 IN，部品新 lot `DKIT{date}-{尾4}-{line}`)。实体 `KitMasterComponent`(UK `KitSku+LineNo`)/`KitOrder`(`Direction`/`KitLotNo`/`ExecutedTxnNos`)。错误码 `WM-MSG-070/043/020/021/001`+`InsufficientStockException`。
**【特化点】** 套装组立扣料：按 BOM 一次扣 N 部品产出 1 套装 SKU，**所有扣料/产出严格经 `IStockMovementService`**(满足 §13.3 铁律)，可反向 DISASSEMBLE 拆套退料(新采 lot 防混)。

## 6. Slotting — ABC 分析(OUT 频次)+ 移库推荐

**分析** `POST /slotting/analyze`（`SlottingView.vue:167-176`→`slottingApi.analyze`，返 `{slottingPlanNo}`）。Service `SlottingService.cs:37-110`：
```csharp
var stats = ... StockTransactions.Where(WarehouseCd && TxnType==OUT && TxnDateTime>=since).GroupBy(ProductCd).Select(g => new {Count, Qty});
var sorted = stats.OrderByDescending(Count).ThenByDescending(Qty);
foreach (var s in sorted) {   // 累计构成比帕累托 80/95
    cumulative += s.Count; var ratio = cumulative / totalCount;
    string rank = ratio <= 0.80m ? "A" : (ratio <= 0.95m ? "B" : "C");
    string pattern = rank switch { "A" => "PIK-A-*", "B" => "PIK-B-*", _ => "RES-C-*" };
    var currentLoc = ... Stocks 在库最大的 LocationCd;
    bool needs = currentLoc != null && !currentLoc.StartsWith(prefix);
    recs.Add(new SlottingRecommendation { AbcRank=rank, CurrentLocationCd=currentLoc, RecommendedLocationPattern=pattern, NeedsRelocation=needs });
}
```
`Status=Recommended`，后续 `ApproveAsync`/`CancelAsync`。**纯推荐，不动实库存**。错误码 `WM-MSG-070/043`。
**【特化点】** 品类多、出库频次悬殊：用历史 OUT 频次 ABC 把高频 A 推拣货前棚(`PIK-A-*`)、低频 C 推后排上段(`RES-C-*`)缩短拣货行走，输出可审批的移库建议清单。

## 7. Cross-Dock — 越库直发(仮置きロケ IN 即 OUT)

**実行** `POST /cross-dock/{no}/execute`（`CrossDockView.vue:124-131`→`crossDockApi.execute`）。Service `CrossDockService.cs:60-102`：
```csharp
if (order.Status != Planned) throw ... "WM-MSG-043: 計画状态でないため実行不可";
var inTxn = await _stock.ApplyAsync(new { TxnType=WmsTxnType.IN, LocationCd=order.TempLocationCd, ...Qty=order.Qty, RelatedType="XDOCK_IN" });   // 1. 仮置きロケへ着荷
var outTxn = await _stock.ApplyAsync(new { TxnType=WmsTxnType.OUT, LocationCd=order.TempLocationCd, ...Qty=order.Qty, RelatedType="XDOCK_OUT" });  // 2. 即出荷
order.InTxnNo=inTxn; order.OutTxnNo=outTxn; order.Status=Executed;
```
同库位连发 IN+OUT，净变化 0 但留两条 Txn 关联入荷/出荷。错误码 `WM-MSG-070/043/021`。
**【特化点】** 来料直发：急单标准箱到货无需上架，月台仮置き区一进一出转去发货月台，用 IN+OUT 双 Txn 保全程可追溯(关联 InboundNo↔OutboundNo)，省上架·拣货两步。

## 8. サンプル在庫 — 貸出/返却 + 超期检出

**貸出** `POST /sample-stock/{no}/lend`（body `{lentTo, expectedReturnDate}`），`/return`，`/overdue`(`SampleStockController.cs:68-70`)。Service `LendAsync`：仅 `InStock/Returned` 可(否则 `WM-MSG-043`)→`Status=LentOut`+`LentTo/LentAt/ExpectedReturnDate`。`OverdueAsync`(`:116-124`)`Status==LentOut && ExpectedReturnDate<Today` 升序。实体 `SampleStock`(`SampleType` PROTO/COLOR/DUMMY，`SampleStatus` InStock0/LentOut1/Returned2/Expired3)。错误码 `WM-MSG-043`(5处)/`WM-MSG-070`。
**【特化点】** 试作/色样品借还：打样箱/色见本/Dummy 常借给客户，须记借出人·应还日并一键查超期未还，状态机区分"在库可借/借出中/已还可再借/失效"，避免有去无回。

## 9. 版型在庫(印版·木型) — 使用記録(shots 累计+寿命预警)

**使用記録** `POST /plate-mold/{no}/use`（body `{shots}`），`/warnings`(默认 threshold 0.9)。Service `RecordUsageAsync`（`PlateMoldService.cs:78-91`）：
```csharp
if (p.Status != Usable) throw ... "WM-MSG-043: 使用可状态のみ記録可";
p.UsedShots += shots; p.LastUsedAt = Now;
if (p.MaxShots.HasValue && p.UsedShots >= p.MaxShots.Value) p.Status = LifeReached;   // 寿命到达自动锁
```
`WarningListAsync`(`:126-137`)筛 `UsedShots/MaxShots >= threshold` 降序。`CompleteMaintenanceAsync`(`:104-114`)**研磨保养后 `UsedShots=0` 重置**。实体 `PlateMoldStock`(`MaxShots`/`UsedShots`/`PlateMoldStatus` Usable0/Maintenance1/LifeReached2/Discarded3)。
> ⚠️ Controller 顶部 `using` 显式别名(`PlateMoldController.cs:4-6`)，因 ERP 侧有同名 `PlateMold` 实体；采番 `PLT2`(PLT 被パレット占)。
**【特化点】** 印版有最大耐印数(ショット寿命)，到寿命掉色/爆线：每单印量计入 `UsedShots`，到 `MaxShots` 自动锁 `LifeReached` 防误用，`warnings` 90% 预警备版，研磨后寿命计数复位再用。

## 关键发现
1. **状态非 enum**，是 `WmsTxnType.cs` 内 `static class` 常量(`PaperRollStatus`/`InkOpenStatus`/`PalletStatus`/…)。
2. **只有 Kit/Cross-Dock 走 IStockMovementService**(`KittingService` BOM OUT+Kit IN、`CrossDockService` IN+OUT)；其余用独立专用表与主 Stock **解耦**(`T_PaperRoll`/`T_InkLot`/`T_Pallet`/…自管理在库)。
3. `WM-MSG-203`(巾割子巾超亲巾)需求文档无文案，仅代码内用。
4. Mix/Slotting 部分校验用本地中日文 message 而非 WM-MSG 码。
5. 采番 `PLT2`(版型，因 `PLT` 被パレット占用)。
