## ⭐ 引当 Allocate（接缝①）— POST /api/wms/outbound-order/{no}/allocate

**前端**：`OutboundOrderView` `canAllocate=status===1`(Confirmed)，`onAllocate`（`:247-254`）确认→ `outboundOrderApi.allocate`。api `:29-31`。
**后端**：Controller `Allocate`（`OutboundOrderController.cs:91-101`）catch `InsufficientStockException`/`InvalidOperationException`→400。

**Phase7 候选过滤** `FindCandidateStockAsync`（`OutboundService.cs:325-340`）：
```csharp
return _db.Stocks.Where(s => s.ProductCd == productCd && s.WarehouseCd == warehouseCd
    && !s.IsDeleted && !s.RecallFlag && s.AvailableQty >= needed
    && s.OwnerType == StockOwnerType.Self
    && s.QcStatus != StockQcStatus.Failed && s.QcStatus != StockQcStatus.Hold)   // ← Phase7 QC 过滤
    .OrderBy(s => s.ExpiryDate ?? DateTime.MaxValue)      // FEFO
    .ThenBy(s => s.ReceiveDate ?? DateTime.MaxValue)
    .ThenBy(s => s.LotNo)
    .FirstOrDefaultAsync();
```
排除 `FAILED/HOLD`(QC)、`RecallFlag`(召回)、`OwnerType!=Self`(VMI)、`AvailableQty<needed`(单行须足，第一版「1明细=1lot」限制)。

**主流程 + 材料不足分流** `AllocateAsync`（`:342-443`）：
```csharp
if (header.Status != OutboundOrderStatus.Confirmed)
    throw new InvalidOperationException("WM-MSG-043: 確定済でないため引当できません");
var anyShortage = false;
foreach (var d in details) {   // d.AllocatedQty < d.RequiredQty 的行
    var needed = d.RequiredQty - d.AllocatedQty;
    // 多仓路由解析候选仓优先序，逐仓 FEFO 找单一 Stock
    var candidateWarehouses = _routing != null ? await _routing.ResolveCandidateWarehousesAsync(...) : new List<string>{ header.WarehouseCd };
    Stock? candidate = null; string chosenWarehouse = header.WarehouseCd;
    foreach (var wh in candidateWarehouses) { candidate = await FindCandidateStockAsync(wh, d.ProductCd, needed); if (candidate != null) { chosenWarehouse = wh; break; } }
    if (candidate == null) {
        if (header.OutboundType == OutboundType.Material && _shortage != null) {
            await _shortage.CreateAsync(new MaterialShortage { ... RelatedOutboundNo=outboundNo, ProductCd=d.ProductCd, RequiredQty=needed, AvailableQty=0m, Status=Open, ... });
            if (_shortageNotifier != null) await _shortageNotifier.NotifyAsync(header.WorkOrderNo ?? "", d.ProductCd, needed);
            anyShortage = true; continue;                  // ★ 材料：不抛，继续下一行
        }
        throw new InsufficientStockException(d.ProductCd, d.LotNo ?? "", needed, 0m);   // ★ 非材料(出荷)：抛异常
    }
    var txnNo = await _stock.ApplyAsync(new StockMovementRequest { TxnType=WmsTxnType.RSV, WarehouseCd=chosenWarehouse, LocationCd=candidate.LocationCd, ProductCd=candidate.ProductCd, LotNo=candidate.LotNo, Qty=needed, RelatedType="OUTBOUND", ... });
    d.AllocatedQty += needed; d.WarehouseCd = chosenWarehouse; d.LotNo = candidate.LotNo; d.LocationCd = candidate.LocationCd; d.AllocateTxnNo = txnNo;
}
header.Status = anyShortage ? OutboundOrderStatus.PartialAllocated : OutboundOrderStatus.Allocated;
```
**分流二分支**：`Material(1)`+注入 `_shortage` → 写 `T_MaterialShortage`(OPEN)+SignalR+`continue`(不抛)，header 置 `PartialAllocated(5)`；否则(Shipping/Transfer)→`throw InsufficientStockException`(整批回滚)。`MaterialShortage.AvailableQty` 硬编码 0（命中即不缺，未命中只知无满足单行）。`_shortage/_shortageNotifier/_routing` 可选注入(默认 null)。
**校验与错误码**：header 不存在→`WM-MSG-070`；非 Confirmed→`WM-MSG-043`；非材料不足→`WM-MSG-040`(`InsufficientStockException`)。
> `RSV` 只动 `AllocatedQty`(`StockMovementService.cs:243-244`)，PhysicalQty 不变，AvailableQty 随减。

## ⭐ 梱包/出荷確定 Ship（接缝②）— POST /api/wms/outbound-order/{no}/ship

**前端**：两入口共用端点——`OutboundOrderView`(`canShip=status 2||3`，`onConfirmShip` `:258-270`)、专用 `/wms/packaging`（`router/index.ts:129`）`PackingShipView.vue`（左队列 `status=3,outboundType=2`，右填重量/carrier/tracking，`onShip` `:216-236`）。api `outboundOrder.ts:37-40`，返回 `{packageNo}`。
**后端** `ShipAsync`（`OutboundService.cs:449-532`）：
```csharp
if (header.Status != Allocated && header.Status != Picking)
    throw new InvalidOperationException("WM-MSG-043: 引当済 or ピッキング中のみ出庫確定可");
var details = ... d.ShippedQty < d.AllocatedQty ...;
if (details.Count == 0) throw new InvalidOperationException("WM-MSG-041: 出庫対象明細がありません");
foreach (var d in details) {
    var shipQty = d.AllocatedQty - d.ShippedQty;
    var txnNo = await _stock.ApplyAsync(new { TxnType=WmsTxnType.OUT, WarehouseCd=d.WarehouseCd ?? header.WarehouseCd, ...Qty=shipQty, RelatedType="OUTBOUND" });
    d.ShippedQty += shipQty; d.ShipTxnNo = txnNo;
}
header.Status = OutboundOrderStatus.Completed;
string? packageNo = null;
if (header.OutboundType == OutboundType.Shipping) {
    packageNo = await _seq.NextAsync("PKG");
    _db.ShippingPackages.Add(new ShippingPackage { PackageNo=packageNo, OutboundNo=outboundNo, CarrierCd=req.CarrierCd ?? header.CarrierCd, TrackingNo=req.TrackingNo, ... });
}
await _db.SaveChangesAsync();
try { await _notifier.NotifyOutboundShippedAsync(outboundNo, packageNo); } catch { }   // best-effort SignalR
// ★ 接缝②：WMS→ERP 出荷回写
if (header.OutboundType == OutboundType.Shipping && !string.IsNullOrWhiteSpace(header.WebOrderNo)) {
    try { await _erpBridge.OnShipmentConfirmedAsync(outboundNo, userName); }
    catch { /* best-effort */ }
}
return packageNo;
```
> `OUT` 同时减 `PhysicalQty` 和 `AllocatedQty`(`StockMovementService.cs:229-231`)，故注释「UNRSV 不要」。
**校验与错误码**：header 不存在→`WM-MSG-070`；状态非 Allocated/Picking→`WM-MSG-043`；无可出明细→`WM-MSG-041`。

**接缝②实现** `ErpBridgeHook.OnShipmentConfirmedAsync`（`ErpBridgeHook.cs:26-134`）：取 OutboundOrder/Order/出荷数明细(任一空→Skipped)→**按製品CD分组顺次充当**(`:83-109`)：`od.ShippedQty += apply`、`od.ShipStatus = ShippedQty>=ordered ? 9 : 5`、`od.LastOutboundNo`→ヘッダ rollup `order.ShipStatus`→`SaveChanges`+`PersistEvent(Success/Skipped/Failed)`。幂等靠累计 `ShippedQty`。详见 [codemap-erp 受注篇出荷回写专讲](../codemap-erp/05-受注-order.md)。

**接缝③④逐字（自动展开）**（`OutboundService.cs:538-626`）：去重键=`WorkOrderNo`/`WebOrderNo` 上有未取消 OutboundOrder(命中→`WM-MSG-043`)；③ `OutboundType=Material,仓W01`、源 `WorkOrderMaterials`；④ `OutboundType=Shipping,仓W01`、源 `OrderDetails`。两者生成后仍是 Draft，需后续 Confirm→Allocate。MES/ERP 触发点经 `WmsBridgeHook.OnWorkOrderIssuedAsync`(`:30-56`)/`OnOrderCreatedAsync`(`:58-84`)，best-effort+`PersistEvent`。

**接缝⑤逐字**（`CancelOrderAsync` `:254-296`）：
```csharp
if (header.Status == Completed) throw new InvalidOperationException("WM-MSG-043: 完了済の指示は取消不可");
if (header.Status == Allocated || header.Status == Picking) {
    foreach (var d in details.Where(x => x.AllocatedQty > x.ShippedQty)) {
        var releaseQty = d.AllocatedQty - d.ShippedQty;
        await _stock.ApplyAsync(new { TxnType=WmsTxnType.UNRSV, WarehouseCd=d.WarehouseCd ?? header.WarehouseCd, ...Qty=releaseQty, RelatedType="OUTBOUND", Remark=$"取消による引当解除 {outboundNo}" });
        d.AllocatedQty -= releaseQty;
    }
}
header.Status = OutboundOrderStatus.Cancelled;
```
反向级联由 `OrderCancelBridgeHook`（`Integration/OrderCancelBridgeHook.cs`）**先取消 Outbound(解RSV)后取消 WO**（顺序防 AllocatedQty 二重解除）；`AutoCancellable = o.Status < Picking`(Picking 及以后需二段人工确认)。

### 错误码（grep 实证）
`WM-MSG-020`(明细0件)、`WM-MSG-021`(数量>0)、`WM-MSG-040`(库存不足,Allocate/Ship 抛)、`WM-MSG-041`(出庫対象明細なし,Ship)、`WM-MSG-043`(状态守卫,多句尾:訂正/確定/引当/ピッキング/取消/完了/重複生成)、`WM-MSG-070`(不存在/404)、`WM-MSG-071`(成功)、`WM-MSG-SHORTAGE-409`(缺料非OPEN→409)；无前缀(出庫倉庫CD必須/PackageNo·CarrierCd required)。

## 关键发现
1. **拣货行级无后端持久化**：`confirmPick/confirmShort/onComplete` 仅改前端 `lineState`，不落库。
2. **前端 statusMap 缺 PartialAllocated=5**，后端置 5 时裸显数字（真实 UI 盲点）。
3. **MaterialShortage 唯一创建路径是 Allocate 分支**；拣货屏「短缺報告」不写 MaterialShortage(纯 UI)。
4. **接缝③④生成后仍是 Draft**，需后续 Confirm→Allocate 才触发接缝①材料不足分流。
5. **接缝⑤只释放 `AllocatedQty-ShippedQty`**（已出货部分不退引当）；Bridge 自动级联仅 `Status<Picking`，Picking 需二段人工确认。
6. `ShippingController` 仅只读(packages 照会)，梱包记录由 `ShipAsync` 内部创建。
