## 倉庫 CRUD — GET/POST/PUT/DELETE /api/wms/warehouse

**前端**：`/wms/warehouse`（`router/index.ts:105`）→ `WarehouseListView.vue`，`reload()`（`:100-106`）→ `warehouseApi.search`。`onSave()`（`:118-131`）按 `editing.id` 区分 create/update；`onDelete`（`:134-141`）确认删。编辑时 `warehouseCd` 禁改。api `warehouse.ts`。type `Warehouse`（`types/wms/wms.ts:51-64`，含 `allowNegative`——直接影响库存铁律负库存判定）。
**后端**（`WarehouseController.cs`，`[Route("api/wms/warehouse")][Authorize]`，直注 `_db`）：
- `Search`（`:24-33`）：`Where(!IsDeleted)` + `WarehouseCd.Contains`/`WarehouseType==`/`BaseCd==`。
- `Create`（`:44-60`）：`WarehouseCd` 空→`400 裸文本`；重复→`WM-MSG-001`；`Id=Guid.Empty` 强制再采番 + 盖审计 → INSERT → `WM-MSG-071`。
- `Update`（`:62-86`）：未找到→`404 WM-MSG-070`；白名单逐字段赋值（**不含 WarehouseCd**）；`DbUpdateConcurrencyException`→`409 WM-MSG-072`（乐观锁，`BaseBizEntity.RowVersion [Timestamp]`）。
- `Delete`（`:88-103`）：**有物理库存残**(`PhysicalQty != 0`)→`400 WM-MSG-004`；否则软删 `IsDeleted=true`。
- 实体 `Warehouse`（`T_Warehouse`，`AllowNegative` 决定后续负库存放行）。

# 🔒 重点专章：库存写入铁律 IStockMovementService

## 接口签名（`IStockMovementService.cs:12-28`）
```csharp
public interface IStockMovementService
{
    // 在庫変動 1 件を適用（自動採番 + 在庫更新 + Txn 発行を 1 トランザクションで）
    Task<string> ApplyAsync(StockMovementRequest req, CancellationToken ct = default);
    // 棚移動（MOVE）— 源 OUT と 先 IN を 1 ペアで発行。返り値=[0]源OUT, [1]先IN
    Task<(string OutTxnNo, string InTxnNo)> MoveAsync(StockMoveRequest req, CancellationToken ct = default);
}
```
`StockMovementRequest`（`:33-52`）：`TxnType/WarehouseCd/LocationCd/ProductCd/LotNo(空=无批)/Qty/ExpiryDate(仅IN)/ReceiveDate/OwnerType(默认SELF)/OwnerCd/PaperRollNo/RelatedNo/RelatedType`。

## ① ApplyAsync 核心（`StockMovementService.cs:34-157`）
1. `Validate(req)`（`:36`，见下）。
2. 非 InMemory 时 `BeginTransactionAsync`（`:38-43`，InMemory 测试库跳过事务）。
3. **按业务 UK 取行 or 新建**（`:48-77`）：`FirstOrDefault(WarehouseCd && LocationCd && ProductCd && LotNo && !IsDeleted)`，无则 `new Stock{三数量=0}` + `Add`。
4. `ApplyDelta(stock, req)` 增减分流（`:222-253`，六 TxnType 见 README §0.1，末尾 `AvailableQty = PhysicalQty - AllocatedQty` 强制重算）。
5. **负库存守卫**（`:82-94`）：读 `Warehouse.AllowNegative`，false 时 `PhysicalQty<0 || AvailableQty<0` → `throw InsufficientStockException`。
6. **追加不变 Txn**（`:99-122`）：`_seq.NextAsync("TXN")` 采番 → `new StockTransaction{...}` + `Add`。
7. `SaveChangesAsync` → `CommitAsync`（`:124-125`，Stock 更新与 Txn INSERT 同一事务，任一失败 `RollbackAsync`）。
8. best-effort SignalR `NotifyStockChangedAsync`（`:127-144`，try/catch 吞，「notifier failure must not break stock movement」）。

`Validate`（`:200-219`）：`TxnType/WarehouseCd/LocationCd/ProductCd` 必填、`LotNo != null`（空文字代无批）；`Qty==0 && TxnType!=ADJ`→`WM-MSG-031`；IN/OUT/RSV/UNRSV 且 `Qty<=0`→`WM-MSG-021`。

## ② MoveAsync（`:159-196`）
```csharp
if (req.Qty <= 0) throw new ArgumentException("WM-MSG-011: 移動数量は0より大きい値を指定してください。");
if (string.Equals(req.FromLocationCd, req.ToLocationCd, ...)) throw new ArgumentException("WM-MSG-010: ...異なるロケーションを指定...");
var outNo = await ApplyAsync(new {...TxnType=MOVE, LocationCd=From, Qty=-req.Qty, RelatedType="MOVE"});  // 源 OUT
var inNo  = await ApplyAsync(new {...TxnType=MOVE, LocationCd=To,   Qty=+req.Qty, RelatedType="MOVE", RelatedNo=outNo});  // 先 IN，RelatedNo 串联
return (outNo, inNo);
```
两笔各走 `ApplyAsync`（各自一事务一 Txn），先笔 `RelatedNo=outNo` 成对。

## T_Stock / T_StockTransaction
- `Stock.cs`：业务 UK 4 列（`:18-32`）、三数量 `decimal(21,8)`（`:34-44`，注释 `PhysicalQty - AllocatedQty = AvailableQty`）、特殊标志 `ExpiryDate/RecallFlag/OwnerType/OwnerCd/PaperRollNo/QcStatus(默认PENDING)`。
- `StockTransaction.cs`：`[Table("T_StockTransaction")]`，PK `TxnNo`(`TXN{yyyyMM}{NNNN}`)，核心列 + V1.1 扩展连携列(`ReceiptInspectionNo/KitOrderNo/RmaNo/CrossDockFlag/PaperRollNo/ConsumedLengthM`)；设计宣言「INSERT only，唯一真实源」。

## 关键发现
1. **倉庫/Location CRUD 无 Service 层**，直操 DbContext；铁律只约束库存数量变动。
2. **Location 管理前端 UI 未实现**（后端齐全，前端无调用）。
3. **QC 状态变更是铁律合法例外**（不动数量、不发 Txn）。
4. **AvailableQty 永不手填**，每次 ApplyDelta 末尾强制重算。
5. **WM-MSG 码无前端 i18n 映射**，裸码抛给用户（潜在 UX 缺口）。
6. **事务在 InMemory 测试库下跳过**（需 SQL Server 集成测试覆盖事务/RowVersion）。
