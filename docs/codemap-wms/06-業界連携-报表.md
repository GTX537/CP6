# 06 · 業界連携(WM300~330) + 报表（WCS/RF手持/IoT/VMI/RMA + Dashboard + ReportCenter）

> 先读 [`README.md` §0/§1](README.md)。全部 `文件:行号` 与代码片段 2026-06-22 实测、逐字引用。

## 0. 关键纠偏（实读结果，与常见假设不符）

1. **IoT 告警不是 SignalR，是 30 秒轮询**（`IotMonitorView.vue:233` `setInterval`）。SignalR `wmsHub` 推的是**库存变动**(StockChanged/InboundReceived/OutboundShipped)，唯一消费者是 `WmsDashboardView`。缺料告警走另一条 `MaterialShortageNotifier`→`MaterialShortageDetected`(反射推送)。
2. **RMA→ERP CreditNote 接缝触发点是 `CloseAsync`（クローズ）**，方法名 `OnReturnConfirmedAsync`，真实落 `CreditNote`。
3. **WmsDashboard 用 EF Core，不是 Dapper**(`WmsDashboardService.cs:12` 注释「将来移行予定」)。
4. **WM-MSG 码全是 service 内联字面量**，直接当 message 回前端，未入 i18n Seed(裸码显示)。

## 1. WCS·任务下发（払出） — POST /api/wms/wcs-task/{no}/dispatch

> WCS 状态机 `Created(0)→Dispatched(1)→Executing(2)→Completed(3)`，旁路 `Failed(9)`。
**前端**：`/wms/wcs-task`→`WcsTaskView.vue`，status0 显示「払出」，`onDispatch`（`:198-204`）→`wcsApi.dispatch(taskNo, deviceCd)`。api `connectivity.ts:21-23`。
**后端**：Controller `Dispatch`（`WcsTaskController.cs:40-45`，内嵌 `DispatchReq`）。Service `DispatchAsync`（`WcsService.cs:56-67`）：deviceCd 非空→`GetTracked`(不存在`WM-MSG-070`)→仅 `Created` 可払出(否则 `WM-MSG-043`)→`Status=Dispatched`+`DeviceCd`+`DispatchedAt`。
> **无外部 WCS 设备回调端点**：执行后的 start/complete/fail 由人工/上位系统同步调状态机迁移，无 webhook/消息队列入站。`FailAsync` 记 `ErrorMessage`。
**错误码**：`deviceCd required`、`WM-MSG-043`(各状态尾巴)、`WM-MSG-070`、`TaskType required`。

## 2. RF手持·作业完了（MOVE 落实库存） — POST /api/wms/mobile/task/{no}/done

**前端**：`/wms/mobile`→`MobileTaskView.vue`，`doneTask`（`:196-208`）用 `ElMessageBox.prompt` 让作业者输实绩数量→`mobileApi.done(no, {scannedQty})`。**不接 SignalR**，纯 REST+`onMounted(reload)`。
**后端**：Controller `Done`（`MobileController.cs:57-67`）catch `InsufficientStockException`+`InvalidOperationException`→400。Service `CompleteAsync`（`MobileService.cs:137-176`）**MOVE 分支真移库存**：
```csharp
// MOVE 種別のみ実在庫を動かす（他は伝票側の確定フローが在庫を動かす）
if (task.TaskType == MobileTaskType.Move) {
    if (...字段不足) throw new InvalidOperationException("WM-MSG-303");
    if (doneQty <= 0) throw new InvalidOperationException("WM-MSG-031");
    var (outTxn, inTxn) = await _stock.MoveAsync(new StockMoveRequest { WarehouseCd=task.WarehouseCd!, FromLocationCd=task.FromLocationCd!, ToLocationCd=task.ToLocationCd!, ProductCd=task.ProductCd!, LotNo=task.LotNo ?? "", Qty=doneQty, ... });
    task.OutTxnNo = outTxn; task.InTxnNo = inTxn;
}
```
其余类型只改任务状态(由对应单据流去动库存)。`MoveAsync` 内部对 IN/OUT 各调 `ApplyAsync`，提交后 best-effort 推 SignalR → 手持 MOVE 完了会在 Dashboard 时间线弹两条(OUT+IN)。
**错误码**：`WM-MSG-303`(MOVE 字段不足)、`WM-MSG-031`(数量≤0)、`WM-MSG-043`、`WM-MSG-070`；扫码侧 `WM-MSG-300/301/302`(空扫/解析不能/与指示不一致)。

## 3. ⭐ RMA·返品クローズ → ERP CreditNote 接缝 — POST /api/wms/rma/{no}/close

> RMA 状态机 `Authorized(1)→Received(2)→Inspecting(3)→Judged(4)→Closed(5)`。**接缝在 Close 触发**。
**前端**：`/wms/rma`→`RmaView.vue`，status4(Judged) 显示「クローズ」，`onClose`（`:275-280`）→`rmaApi.close`。
**后端** `CloseAsync`（`RmaService.cs:237-260`）：
```csharp
if (h.Status != RmaStatus.Judged) throw new InvalidOperationException("WM-MSG-043: 判定済のみクローズ可");
h.Status = RmaStatus.Closed; await _db.SaveChangesAsync();   // ← 先落 Closed
try {
    var result = await _erpBridge.OnReturnConfirmedAsync(rmaNo, userName);   // ★ 接缝
    if (!result.Success) _logger.LogWarning(...);
} catch (Exception ex) { _logger.LogWarning(ex, ...); }   // best-effort：桥接异常只 LogWarning 不回滚
```
**接缝实现** `ErpBridgeHook.OnReturnConfirmedAsync`（`ErpBridgeHook.cs:136-232`，CreditNote 生成 `:182-205`）：
```csharp
orderDetail.ReturnedQty = (orderDetail.ReturnedQty ?? 0m) + detail.Qty;   // 回填受注明细
...
Db.CreditNotes.Add(new CreditNote { CreditNoteNo=NewCreditNoteNo(), WebOrderNo=webOrderNo, RmaNo=rmaNo,
    Type=CreditNoteType.Refund, CustomerCd=rma.CustomerCd, ProductCd=detail.ProductCd, Qty=detail.Qty, Reason=rma.ReturnReason, IssueDate=DateTime.Today, ... });
```
步骤：查 RMA(空→Skipped `WM-MSG-RMA-404`)→明细空→`WM-MSG-020`(转 Skipped)→`ResolveWebOrderNoAsync`(按 `OriginalShippingNo` 找出库单的 WebOrderNo)→逐明细累加 `ReturnedQty`+每行生成一张 `CreditNote(Refund，单号 CN{yyyyMMdd}-{GUID前4})`→`SaveChanges`→`PersistEventAsync`(Success/Skipped/Failed)。`ErpBridge:Enabled=false` 时 `NoOpErpBridgeHook` 返 SKIPPED。
> **判定処分(Judge)才真正动库存**(`:160-235`)：Resell/Repair 走 MOVE，Scrap/SupplierReturn 走 ADJ -Qty；返品入庫(Receive)把货 IN 到 `{倉庫}-RMA-HOLD` 保留位。Close 不动库存只动 ERP。

## 4. ⭐ Dashboard·KPI 聚合 — GET /api/wms/dashboard/kpi（EF Core）

**前端**：`/wms/dashboard`→`WmsDashboardView.vue`，`onMounted` 并行拉 4 端点 + 建 SignalR。`loadKpi`（`:210`）。SignalR 高频事件用 `scheduleKpiReload` 300ms 防抖。
**后端** `WmsDashboardService.GetKpiAsync`（`:20-84`，**纯 EF Core**）：
```csharp
var stockSummary = await _db.Stocks.AsNoTracking().Where(!IsDeleted && PhysicalQty != 0m).GroupBy(_ => 1)
    .Select(g => new { Value = g.Sum(s => s.PhysicalQty * (s.UnitPrice ?? 0m)), Skus = ..., Physical = ..., Allocated = ... }).FirstOrDefaultAsync();
```
KPI 8 项：总库存金额/活跃SKU/实物/引当(一把 GroupBy) + 滞留SKU(近90天动过的差集) + 今日入庫予定/出荷予定/未结棚卸。其余三端点 `GetTransactionTrend`(按日 GroupBy TxnType)/`GetWarehouseValue`(按仓金额)/`GetAlerts`(临期+入庫遅延+待批棚卸,用 `EF.Functions.DateDiffDay`)。纯只读无错误码。

## 5. SignalR 实时通道（wmsHub）

**前端** `utils/wmsHub.ts`：连 `/hubs/wms`，`withAutomaticReconnect([0,2000,5000,10000,30000])`，分组订阅 `SubscribeWarehouse/Product`。Dashboard 消费(`WmsDashboardView.vue:267-286`)：`StockChanged`(unshift 时间线超50截断)/`InboundReceived`/`OutboundShipped`(toast)→`scheduleKpiReload`。

## 关键发现
1. **IoT 是 30 秒轮询非 SignalR**；SignalR wmsHub 唯一消费者是 Dashboard。
2. **RMA→ERP CreditNote 接缝真实存在**，触发点 `CloseAsync`，best-effort 不阻断；每返品明细生成一张 `CreditNote(Refund)`+回填 `OrderDetail.ReturnedQty`+落 `IntegrationEvent`。
3. **WmsDashboard 全 EF Core**(注释明示 Dapper 仅将来移行)，与 MES Dashboard 的 Dapper/SP 版不同。
4. **WCS 无外部设备回调端点**，纯同步状态机。
5. **VMI 无 ERP 接缝**(保管料只落本表)。
6. WM-MSG 码内联字面量，未入 i18n Seed(裸码显示)。
