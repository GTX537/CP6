# 02 · 入庫指示(WM030) + 入庫実績(WM040)

> 先读 [`README.md` §0/§1](README.md)。全部 `文件:行号` 与代码片段 2026-06-22 实测、逐字引用。

## 0. 架构定位

- **入庫指示**（`T_InboundOrder`）= 计划，不触达库存；**入庫実績**（`T_InboundReceipt`）= 真增库存（经 `ConfirmReceiptAsync → IStockMovementService.ApplyAsync(IN)`）。
- **所有入庫汇聚一条路**：实绩収貨 / 完成品入庫(MES接缝) / 采购GR委托 最终都走 `ConfirmReceiptAsync`，无旁路直接写 `Stock`。
- 采番 `IN`(指示)/`RC`(实绩)。

## ⭐ 入庫実績 確定収貨 — POST /api/wms/inbound-receipt（真增库存核心）

**前端**：`/wms/inbound-receipt`（`router/index.ts:110`）→ `InboundReceiptView.vue`。带 `?inboundNo=`=参照模式（取予定、状态须 1||2、逐行只取未收满行算差额 `:139-162`），否则直入模式。`onConfirm`（`:164-179`）前端校验每行 `productCd && locationCd && receivedQty>0`→ `inboundReceiptApi.confirm(form)`。api `inboundReceipt.ts:14-16`，返回 `{receiptNo}`。type `InboundReceipt`/`InboundReceiptDetail`（`wms.ts:214-242`，含 `stockTxnNo`）。
**后端**：
- Controller `Confirm`（`InboundReceiptController.cs:36-47`）catch `InsufficientStockException`/`InvalidOperationException`/`ArgumentException`→400，成功 `WM-MSG-071 + {receiptNo}`。
- Service `ConfirmReceiptAsync`（`InboundService.cs:297-416`）核心步骤：
  1. `ValidateReceipt(dto)`（`:299`）。
  2. 参照模式（`:305-317`）：取予定状态须 `Confirmed||PartialReceived`（否则 `WM-MSG-043`），予定明细装 `orderDetailMap`。
  3. `NextAsync("RC")` 采番 + 写实绩 header(`Status=Confirmed`)。
  4. **逐明细经 `IStockMovementService` 真增库存**（`:337-357`）：
```csharp
foreach (var d in dto.Details) {
    var txnNo = await _stock.ApplyAsync(new StockMovementRequest {
        TxnType = WmsTxnType.IN, WarehouseCd = dto.WarehouseCd, LocationCd = d.LocationCd,
        ProductCd = d.ProductCd, LotNo = d.LotNo ?? "", Qty = d.ReceivedQty,
        UnitCd = d.UnitCd, UnitPrice = d.UnitPrice, RelatedNo = receiptNo, RelatedType = "INBOUND",
        OperatorCd = dto.OperatorCd ?? userName, ReceiveDate = header.ReceiveDateTime,
        ExpiryDate = d.ExpiryDate, PaperRollNo = d.PaperRollNo,
    });
```
  5. 实绩明细 `StockTxnNo = txnNo` 回填追溯。
  6. 予定明细累计回写 `od.ReceivedQty += d.ReceivedQty`（仅 `RefOrderLineNo` 命中 map）。
  7. `SaveChangesAsync`。
  8. 予定状态自动迁移（`:391-410`）：全收→`Completed`/部分→`PartialReceived`。
  9. best-effort 通知 `NotifyInboundReceivedAsync`→返回 receiptNo。
**校验与错误码**：`ValidateReceipt`（`:483-501`）`WarehouseCd` 必填/`Details` 0 件→`WM-MSG-031`/行 `ProductCd`/`LocationCd` 空→`WM-MSG-031`/`ReceivedQty<=0`→`WM-MSG-031`；参照状态错→`WM-MSG-043`；予定不存在→`WM-MSG-070`；`ApplyAsync` IN 要求正数(`WM-MSG-021`)、库存不足`InsufficientStockException`。
**数据流**：`confirm(form)` → `ConfirmReceiptAsync` → 写 `T_InboundReceipt` → 每行 `_stock.ApplyAsync(IN)` → `Stock.PhysicalQty += Qty` + `StockTransaction(IN)` → 回填 `StockTxnNo` + 累计回写 `T_InboundOrderDetail.ReceivedQty` + 予定状态迁移。**库存在此真正增加。**

## ⭐ 完成品入庫（MES 接缝③）— CreateFinishedGoodsFromWorkOrderAsync（无独立 HTTP，经 Bridge）

> MES 全工程完了时经 `IWmsBridgeHook` 调入（见 [codemap-mes 製造実績篇](../codemap-mes/02-製造実績-productionresult.md)）。另有手工屏 `ProductionInboundView.vue`（`/wms/product-inbound`）直走 `POST /wms/inbound-receipt`(`sourceType=PRODUCTION`)，二者并存。

**触发链**：MES `ProductionResultService.cs:256-258` `if(justCompleted) await _wmsBridge.OnProductionCompletedAsync(WorkOrderNo, wo.CompletedQty, userName)` → `WmsBridgeHook.OnProductionCompletedAsync`（`:86-112`，try/catch + IntegrationEvent 三态）。
**实现** `CreateFinishedGoodsFromWorkOrderAsync`（`InboundService.cs:418-463`）：
```csharp

private const string FinishedGoodsLocation = "W01-FG";
```

**幂等护栏**：键 `(WorkOrderNo, SourceType=PRODUCTION, !IsDeleted)`，命中即抛 `WM-MSG-043`，被 Hook `catch(InvalidOperationException)` 接住→Skipped（不重复增库存，不阻塞工序完了）。仅防整张实绩重复，不按数量去重。
**测试佐证**（`WmsErpClosedLoopTests.cs:133-139`）：第2次调用 `Assert.ThrowsAsync<InvalidOperationException>`，`InboundReceipts.Count==1`。
> ⚠️ **差异**：自动完成品入庫落 `W01/W01-FG`（常量），手工屏 `ProductionInboundView.vue` 前端默认 `W03/W04`，且手工屏**不经**幂等护栏（护栏只在 `CreateFinishedGoodsFromWorkOrderAsync` 内）。

## ⭐ 采购 GR 委托入庫（PoNo 钩子）— WmsReceiveServiceAdapter.ReceiveAsync（采购内部委托）

> 采购收货 `GoodsReceiptService.cs:107-114` `await _wmsReceive.ReceiveAsync(...)`，适配器真实注册 `Program.cs:165`。
**适配器**（`WmsReceiveServiceAdapter.cs:23-66`）三步贯穿 WM030→WM040：
```csharp
private const string ReceivingLocation = "RECV";   // 收货暂存库位
// 1. 建入库预定（PoNo 钩子）
var inboundNo = await _inbound.CreateOrderAsync(new InboundOrderDto {
    PoNo = request.PoNo,                            // ← PoNo 钩子（PA060 連携将来用）
    InboundType = 1,                                // 购买入库

// 2. 确定预定（Draft→Confirmed）

// 3. 确认入库实绩（StockMovementService IN，库存真增加，落 RECV 暂存位）
var receiptNo = await _inbound.ConfirmReceiptAsync(new InboundReceiptDto {
    InboundNo = inboundNo, SourceType = InboundSourceType.Purchase, WarehouseCd = warehouse,
    Details = request.Lines.Select(l => new InboundReceiptDetailDto { ..., LotNo="", ReceivedQty=l.Qty, LocationCd=ReceivingLocation }).ToList(),

return new WmsReceiveResult { WmsInboundNo = inboundNo, ... };   // 返 InboundNo（检收按 InboundNo 查 QcInspection）
```

## 关键发现
1. **接缝③ 两条并存**：自动链(W01/W01-FG,过幂等护栏) vs 手工屏(W03/W04,不过护栏)——仓库默认值不一致。
2. **幂等粒度**：键 `(WorkOrderNo, PRODUCTION)` 仅防整张实绩重复，不按数量累计；`goodQty=wo.CompletedQty`。
3. `WM-MSG-043` 被复用于「状态非法 + 完成品重复入庫」两类语义。
4. **真增库存唯一路径**：实绩/完成品/采购GR 都汇聚 `ConfirmReceiptAsync → ApplyAsync(IN)`，无旁路。
