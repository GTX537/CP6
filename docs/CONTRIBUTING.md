# 文档维护规则

目标是让下一次找文档、写文档和交接任务都有固定入口。[返回文档中心](README.md)。

## 新文档放置

1. 先在 [文档中心](README.md) 找所属业务域或用途；能放进已有目录的文档，沿用已有目录。
2. 长期规范使用稳定、有含义的文件名；任务计划、研究记录和阶段复盘使用 `YYYY-MM-DD-topic.md`，模块已有命名规范时优先沿用。
3. 新建一个目录时同时提供 `README.md`，说明用途、阅读顺序、当前规范入口和资料状态，并在上一级入口增加链接。
4. `docs/` 根目录放全局导航和维护规则。新产品、架构、需求或面试文档分别进入对应分类。现存 `build_user_manual_docx.py` 是历史导出工具，源文件缺失，不能视为当前可用导出入口；本次保持脚本位置和行为。

新文档建议在标题后写明：用途、适用模块或版本、状态（草案 / 当前规范 / 历史资料）、更新日期，以及相关规范或替代文档。日期是内容核验日期，不能因移动文件就刷新旧方案的事实时点。

## 一份信息有一个维护位置

| 信息 | 维护位置 |
| --- | --- |
| 最新项目进展 | [PROJECT_STATE](project-memory/PROJECT_STATE.md) |
| 已完成能力与里程碑 | [05-Completed](project-memory/05-Completed.md) |
| 后续工作与优先级 | [06-Todo](project-memory/06-Todo.md) |
| 影响交接的变更 | [CHANGELOG-AI](project-memory/CHANGELOG-AI.md) |
| 模块规则、批准记录、验收条件 | 模块自己的规范和证据目录；总索引只链接，不复制一套状态 |
| 用户操作步骤 | [manuals](manuals/README.md)；开发计划与 QA 原始记录留在 [superpowers](superpowers/README.md) |

`approval/` 是审批工程设计，`oa/` 是配套实现教材；`learning-basics/` 与 `learning/` 面向不同基础；两套面试目录采用不同编排。它们并非仅凭主题相似就可以删除的重复文件。

## 附件、图源与原始资料

- Markdown 与配套附件保持在同一主题内。Mermaid 的 `.mmd` 是图源，`.svg` / `.png` 是展示版本，更新时核对配套关系。
- 同名 `.docx` 通常是历史导出；修改 Markdown 不会自动更新 Word。重新导出时标明源文档和核验日期，避免维护两套正文。Excel 可能是独立设计源，不能统一当作导出文件。
- `docs/file/` 同时有已跟踪资产和本地忽略资料；`.gitignore` 不会取消已有文件的跟踪。只整理已确认的文件，不批量删除、取消跟踪或上传原始附件。
- 渲染临时文件放入已忽略的 `docs/_manual_render/` 或仓库临时目录，不在正式导航里把它们当成发布结果。

## 移动与归档

1. 从最新 `main` 建立任务分支；原工作区有其他改动时使用独立 worktree，遵守 [仓库规则](../AGENTS.md)。
2. 搜索完整路径、相对链接、图片引用以及脚本 / 工作流中的消费者；路径参与审批、摘要或验收时，先遵守对应规范，不直接移动。
3. 移动时保留正文与附件，记录旧路径 → 新路径，同步修复入站链接和文档自己的相对链接。
   历史 Word 等不宜改写的附件若依赖相对路径，可以保留明确标注的兼容跳转页，链接到唯一正文并说明保留原因，不复制正文。
4. 只有具备历史日期或替代依据时才归档。在入口注明资料时点和当前入口；归档不代表其中任务已经完成。
5. 检查完整 diff、链接和附件完整性，更新上述四份项目记忆文件，再按仓库交付流程提交、合并、验证远端 `main`。

## 验证与日常查找

在仓库根目录执行：

```powershell
# 列出 Git 实际管理的文档，包括已被后来的忽略规则覆盖的旧资产
git -c core.quotepath=false ls-files docs

# 搜索主题；增加 -g 可限制文件类型
rg -n '关键词' docs -g '*.md'

# 检查文档中心的本地文件链接（不请求外网、不校验标题锚点）
python -X utf8 scripts/check-docs-links.py docs/README.md docs/CONTRIBUTING.md

# 校验补充导航与迁移引用的命令及结果
# 见 docs/_inventory/2026-09-07-docs-organization.md
git diff --check
```

链接检查失败后先修复目标或链接；不能通过虚构文件、空白占位页或忽略新增错误来通过检查。没有重新审计的旧正文应保留历史状态，不因整理导航而宣称全部内容已经更新。
