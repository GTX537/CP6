# PUB 模块接入清单（章09 §5/§7）

> 业务模块接入 PUB 四粒度权限 + 公共能力的标准步骤与检查清单。
> **范本**：代码生成器（`/pub/codegen`）产出的模块**开箱即带**本清单全部能力——新模块首选"配元数据 → 生成 → 微调"。
> **既有模块改造**（采购/财务/MES/WMS/销售全量）属 B3 阶段，逐模块按本清单核对。

---

## 一、登录聚合管线（已就位）

```
登录(AuthController.Login)
  → ICurrentPermissionContext.PrewarmAsync(userId)        // 多角色聚合 BuildAsync + IMemoryCache 缓存
  → 返回菜单(按全部角色 RoleIds 取并集)
后续请求(带 JWT)
  → [Authorize] 验登录
  → [RequirePermission] 读 ICurrentPermissionContext.GetAsync()(命中缓存) → 403/放行
  → service 用 IDataScopeFilter.Apply 注入数据范围
  → [FieldMask] 序列化前掩码隐藏字段
角色/权限变更 → InvalidateByRole / Invalidate 失效缓存 → 下次重建
```

三处后端强校验读**同一** `UserPermissionContext`（操作并集 / 数据最宽 MAX / 字段最宽 MIN）。
端到端证明见 `CP6.Tests/FourGranularityIntegrationTests`。

## 二、单模块接入五步

以 `Order`（资源键 `order`）为例：

**步骤 1 — 实体实现 `IDataScoped`（补 `DeptId`）**
```csharp
public class Order : BaseBizEntity, IDataScoped
{
    public Guid? DeptId { get; set; }   // 数据权限"本部门/及下级/自定义"比对
    // Creator 来自基类，作"本人"比对
}
```
> 需一支迁移加 `DeptId` 列（可空，存量数据不受影响）。

**步骤 2 — 注册资源（启动时）**
```csharp
// 数据权限资源（章03）
DataScopeRegistry.Register("order", "受注", new[]{1,2,3,4,5}, 2);
// 字段权限资源 + 可控字段（章04）
FieldRegistry.Register("order",
    new FieldRegistry.Field("UnitPrice","単価"),
    new FieldRegistry.Field("Amount","金額"));
```
> 菜单 `Sys_Menu.MenuKey` 设为资源键（如 `order`）；操作点经"功能权限"页维护（`/pub/role-perm`）。

**步骤 3 — Controller 贴特性**
```csharp
[Authorize]
[Route("api/erp/order")]
public class OrderController : ControllerBase
{
    [HttpPost][RequirePermission("order","add")]    public ... Add(...)
    [HttpPut] [RequirePermission("order","edit")]   public ... Edit(...)
    [HttpDelete][RequirePermission("order","delete")] public ... Delete(...)
    [HttpGet] [FieldMask("order")]                   public ... Query(...)
}
```
> 特性参数须编译期常量；继承 `BaseCrudController<T,TSvc>` 时在 override 上贴常量特性（生成器自动写入）。

**步骤 4 — service 注入数据范围**
```csharp
var ctx = await _current.GetAsync();
var q = _dataScopeFilter.Apply(_db.Orders, "order", ctx);   // 自动按用户范围过滤
// 或直接继承 BaseCrudService<Order>（QueryAsync 已自动 Apply）
```
更新时拒写只读/隐藏字段：`_fieldPerm.StripReadOnly(incoming, original, "order", ctx);`

**步骤 5 — 前端按操作权限显隐**
```vue
<el-button v-permission="'order:export'">导出</el-button>
```
> 登录后 `permission store` 拉 `/pub/role-perm/my-actions`；`v-permission` 无权移除元素（仅 UX，后端才是强校验）。

## 三、接入检查清单（八项，逐项核对）

- [ ] **1. 实体** 实现 `IDataScoped` 且有 `DeptId`（迁移已加列）
- [ ] **2. 数据资源** `DataScopeRegistry.Register(资源键,…)` 已注册，支持的范围类型正确
- [ ] **3. 字段资源** `FieldRegistry.Register(资源键, 可控字段…)` 已注册（如需字段权限）
- [ ] **4. 菜单键** `Sys_Menu.MenuKey` = 资源键；操作点已在"功能权限"页定义
- [ ] **5. 操作权** 增/改/删/导出等动作贴 `[RequirePermission(资源键, 动作)]`
- [ ] **6. 数据权** 列表/查询走 `IDataScopeFilter.Apply` 或继承 `BaseCrudService`
- [ ] **7. 字段权** 返回 DTO 的查询贴 `[FieldMask(资源键)]`；更新走 `StripReadOnly`
- [ ] **8. 前端** 操作按钮 `v-permission`；只读字段按 `/my-readonly` 置灰；附件用 `<PubUpload>`；导入导出用 `PubImportDialog`/`usePubExcel`
