## 同一笔业务的 Playwright 骨架

文件：[order-to-cost.spec.ts](../../../cp6.web/e2e-mainline/order-to-cost.spec.ts)；独立配置：[playwright.mainline.config.ts](../../../cp6.web/playwright.mainline.config.ts)。与现有默认 `e2e` 目录隔离，不改旧测试发现规则，不启动应用、迁移或远程 Actions。

模拟数据：单租户、单仓库、一个成品、一个材料、一道工序、人民币、零税率。100 件订单 × 30 元 = 3000 元；每件耗料 2 kg；原料期初 20 kg、采购 180 kg、材料单价均为 10 元/kg。标准人工 2 小时 × 30 元、机时 1 小时 × 20 元；实际人工 2.5 小时、机时 1.25 小时。标准总成本 2080 元，实际总成本 2100 元，实际单位成本 21 元，差异 20 元。金额断言保留十进制字符串，不用浮点数掩盖精度。

17 步顺序：隔离 PostgreSQL 与模拟基础资料 → 浏览器登录并检查客户/产品/仓库 → 询盘交接生成订单 → 订单审批 → MRP → 真实 PR/工单 → PR 审批转 PO → PO 审批收货 → 收货检验放行 → 工单下达及标准成本 → 领料 → 报工 → 完工入库 → 实际成本归集 → 发货 → 开票 → 查看成本单并核对整链单号和金额。

基础资料可由测试准备；询盘、审批等外部输入允许模拟服务，但必须走原业务契约。订单、PR、PO、收货、检验、库存、工单、发票和成本必须通过应用真实入口落到 PostgreSQL；不能预填这些业务结果、拦截主线 API 返回成功或把占位单号当作已转单。已有 `golden-path-flow.spec.ts` 只有订单/MES/库存的旧 API 流程；`manufacturing-cost.spec.ts` 是拦截 API 的组件场景，均不冒充新主线通过。

骨架明确保留未接线的浏览器驱动；第 1 步立即报告 `MAINLINE_NOT_CONNECTED`，不使用 `test.skip`、`test.fixme` 或预期失败来掩盖结果。附带 `mainline-progress.json` 记录最后连续通过步骤、断点和实际结果。本轮本地 Chrome 实际执行为 **0/17，未接通环境准备**，1 个失败、0 个跳过；只打开空白浏览器，没有运行产品 PostgreSQL 验收。两个新增 TypeScript 文件的定向类型检查及用例发现通过，详见[本轮交付](../../development/evidence/MAINLINE-PLAN-20261117/DELIVERY.md)。
