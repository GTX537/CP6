# C04A 多组织目标恢复接线

基线 Core `4210f3d7508338d66d8bf7594c1eff4893da0644`、CRM `e930eb02c13472b177301f5103d3bb9d526e2ba4` 已核对远端 main；各仓创建同任务独立分支。上一轮容器绑定已交付，不重开未受影响测试。

实际共享预览有两个组织业务目标，旧来源包括原生 CP6DB、C02 私有 Core 库和 Docker CP6DB。现有恢复仅证明单个目标终止，不能据此证明整个目标集合都允许恢复旧来源。此缺口必须先于实际启用协调关闭。

新增规范的 2–16 目标集合 Anchor/Receipt，共享协议逐字节镜像；集合按组织 ID 排序，拒绝重复、缺项和错误绑定。每份来源冻结请求绑定完整集合 Anchor 摘要。原单目标摘要和行为保持兼容。

Core 新增多目标恢复入口，先获得全部原生目标证明及保护锁，再获得来源锁；所有目标必须永久关闭，且许可均包含当前来源。核验集合与原冻结绑定并完成来源事务后才释放任一目标锁。精确重放保留原有元数据和业务恢复写入语义；旧单目标入口不能恢复集合绑定来源。

CRM 新增只读集合 Anchor 与集合终止状态入口，原配置及选择请求按原始文件摘要固定。既有逐目标永久终止操作继续使用；部分终止不会允许源恢复。Core 目标连接从严格命名的私有环境变量解析，不进入公共文件和输出。

主任务实现 CRM 操作入口与跨仓真实发布 CLI 验证；一个限定子代理实现 Core 接线和输入/协议测试。SQL、构建及测试由主任务统一串行执行，仅覆盖新集合行为和直接受影响原单目标路径。完成一次集中差异审查、状态及证据归档、正常 PR 合并和远端包含性验证，不触发 Actions。

没有实际冻结、终止、切换或生产操作。启动入口/特权身份控制、前向启用及最终执行批准包继续推进；0.2 字节签收、CRM11/C04B 正式验收和观察周期保留。总体仍 60%（3/5）。
