# C04A 独立本机恢复宿主

从已确认 main（Core 648b6915、CRM a22116a）创建同任务独立 worktree。来源证明/整组启用草稿 Core #114 / CRM #75 的 SQL 门禁继续开放，保留 62 项通过结果，不在这一分支混入其代码或重复相关检查。

当前恢复宿主通过 LiveEnvironment 引用旧 CRM API、基础设施、SQL 和验收初始化/清理逻辑。新增 CRM `tools/Crm.LocalPreviewHost`，仅依赖 .NET / ASP.NET 共享框架，复用原私有 manifest、fixture、配置、证书、账户及数据库。只启动原固定 Core/CRM/Web/dispatcher 角色及 HTTP 回调 relay；没有 SQL 客户端、初始化入口、测试场景或数据库清理代码。现有发布目录和运行预览均不修改。

提供只读 `inspect-local`（绑定 manifest/fixture 原文件摘要，输出待审阅请求和必要入口/配置文件摘要）及 `run-local`（绑定审阅后的请求原字节）。请求准确绑定原路径与摘要、固定启动参数所需输入；持有只读文件句柄直至宿主结束。该范围不冒充完整发布包/管理员隔离或正式切换批准，实际执行包须另外绑定当前 0.2 版本。

运行前检查停止标记、已有角色进程记录和私有根目录互斥租约；停止标记存在时不启动任何子进程，也不清除标记。启动与就绪等待各阶段重复检查停止/取消。只结束自己创建并持有的进程，按 Web→dispatcher→CRM→Core→relay 清理，失败也等待退出。进程记录须匹配本次所有者才可删除；固定输出不泄露私有配置或异常。已存在的旧宿主没有该互斥协议，实际执行仍必须先退休旧入口。

回调 relay 沿用三个明确路径和实际本机回调端口，转发原请求与响应，不再携带故障注入、验收计数或 SQL 逻辑。保留 Windows 本机运行范围和现有 Dapr 外部生命周期边界。

验证仅使用自有临时 HTTP 子进程、Node 入口和文件：正常启动/停止、预存停止标记、双宿主/已有进程拒绝、启动中取消/失败清理、输入字节变化拒绝、回调路径/状态/正文转发及依赖中无 CRM API/SQL。以真实发布宿主执行新场景；不连接 SQL、不替换现有进程，不把假 HTTP 子进程称为真实迁移验收。必要状态、边界、审查、正常 PR、main 合并和远端包含性完整闭环；每次远端写入前新鲜 Actions 检查。

总体 60%（3/5）。完成本组件后，源/目标 SQL 门禁、实际生命周期/特权控制与批准执行恢复包、CRM11/C04B 及观察期仍需继续。
