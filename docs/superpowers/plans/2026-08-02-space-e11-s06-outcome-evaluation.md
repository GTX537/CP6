# Space E11-S06 优化效果评估与收益看板实现计划

状态：合同冻结，进入实现
起始基线：`f7a6576b2a8bc38a8819a534548a841ed9b24ba3`
功能分支：`codex/space-e11-s06-outcome-evaluation`

## 1. 目标与事实边界

E11-S03～S05 已形成不可变调度建议、OA 审批选择、真实 `MobileTask` 分派、执行状态和动作回执。E11-S06 在这些证据之上增加只读、按审批批次即时计算的效果评估，回答“建议被采用多少、执行闭环到哪里、计划配对在可比几何口径下是否优于稳定顺序配对”。

推荐、审批与回执继续是不可变计划证据；`MobileTask` 和任务事件继续是执行事实。Space 不复制任务状态，不写入评估快照，不自动审批、分派、重试、补偿或改变 WMS/WCS/PDA 事实。

## 2. HTTP、权限与审计

在 E11-S04 审批资源下新增：

- `GET .../approval-requests/{approvalRequestId}/evaluation`

端点沿用 `space:operations:dispatch:read`，审计动作固定为 `space.operations.dispatch-evaluation.read`，资源类型固定为 `DispatchOutcomeEvaluation`。外部 Portal 主体、空租户/操作者、越站点或越 WMS 作用域访问继续由现有推荐、审批与执行读取链路失败关闭。

响应不返回内部用户 ID、`AssignedTo`、姓名、邮箱、人员明细或轨迹；只返回批次级来源时点、漏斗、时长、可比几何结果、收益边界和限制。

## 3. 执行闭环漏斗

漏斗固定返回推荐、选择、有效分派回执、已开始、已完成、需关注和已补偿数量，并使用明确分母计算：

- 选择率 = 已选择 / 推荐返回；
- 分派成功率 = 有效 Applied 回执 / 已选择；
- 开始率 = 有 StartedAt 证据 / 已选择；
- 完成率 = 当前 Completed / 已选择。

所有百分比固定为 0～100、保留一位小数。持久化证据数量、rank、TaskId 或人员身份不能对账时返回 `SPACE_DISPATCH_EVALUATION_EVIDENCE_INVALID`，不得以较小分母伪造更高转化率。

## 4. 时长口径

只在时点存在且单调时计算：审批耗时、请求到整批分派耗时、平均分派到开始、平均执行时长和平均分派到完成。每个平均值同时返回样本数；缺失或逆序时点从该项排除并加入稳定限制码，不以零补齐。

执行状态直接沿用 E11-S05 的批次状态与统一 `ObservedAtUtc`，因此页面上的评估与逐任务执行事实使用同一观察时点。

## 5. 可比计划几何

“优化前”不是历史实际路线，而是同一审批选中任务和人员队列的稳定顺序反事实：任务按 TaskId、人员按 SourceId + ExternalId 排序后逐一配对。推荐方案使用 E11-S03 已冻结的 `GeometricDistanceMeters`；反事实方案只使用同一不可变 Published 版本中的库位锚点重新计算。

比较仅在以下条件全部满足时可用：至少两个选择、每个推荐配对都有同层几何距离、每个人员位置和任务目标都有同版本库位锚点、稳定顺序配对全部同层，且不违反原请求的最大距离约束。否则返回 `Unavailable` 和单一稳定原因码，不输出部分队列或选择性样本收益。

可用时返回队列数量、稳定顺序基线米数、推荐米数、差值、差值百分比和 `Improved/Neutral/Regressed`。该值只代表 Published 平面几何配对差异，不代表实际路线、行走时间、SLA 或财务收益。

## 6. 收益声明边界

本卡明确将以下三类收益标为不可用：

- 实际行走距离节省：没有任务—人员关联的路线轨迹；
- 吞吐提升：没有同口径历史控制组或前后窗口；
- 货币收益：没有人工成本、设备成本和归因基线。

Viewer 必须显示这些原因，不能把完成率、计划几何差或单批次时长换算为金额、吞吐提升或实际距离节省。

## 7. Viewer 与本地化

DSP 面板在存在审批后显示“效果评估”区，支持显式刷新，并展示证据时点、四级漏斗、时长样本、计划几何比较、不可用收益及限制。关闭面板、刷新建议、切换审批/站点或组件卸载会使旧评估响应失效；评估失败不得清空现有执行事实。

新增简中、繁中、英语、日语、韩语完整词条并同步生成快照；既有 i18n 静态欠账不得净增加。

## 8. 自动化门禁与交付

- 纯计算引擎覆盖漏斗分母、百分比、完整/缺失/逆序时点、稳定顺序比较、单任务、缺锚点、跨层、最大距离阻断、改善/中性/回退和证据不一致。
- 服务覆盖内部主体、站点/租户/WMS 作用域、旧 Published 版本锚点、执行观察时点复用和隐私；API 覆盖权限与审计。
- 前端覆盖 API、看板渲染、不可用收益、刷新与旧响应失效。
- 运行 Space Unit、默认 Integration、CP6.Tests、前端全量、TypeScript strict、生产构建、solution Release、EF pending、SDK drift、i18n 与 `git diff --check`。
- 功能分支先推远端备份；通过后 no-ff 合入 `integration/space-v1-20260730`，合并态复验并推送，再验证祖先关系后删除临时分支/工作树。`main` 在 Space 整体发布边界批准前不改动。

## 9. 明确不做

- 实际路线重建、任务级人员轨迹关联、历史控制组、A/B 实验、趋势仓、预测、SLA、吞吐或金额归因。
- 新评估表、定时聚合 Worker、自动决策、审批、分派、重试、补偿或任何 WMS/WCS/PDA 写入。
- E12 规划方案与历史仿真，或扩展冻结的 Design v1 HTTP/SDK。
