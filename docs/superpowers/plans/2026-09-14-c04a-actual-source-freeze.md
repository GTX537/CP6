# C04A 实际源端冻结组件

本任务实现实际来源冻结与绑定状态读取；C04A 的跨源排空、目标首写协调、自动恢复和实际执行仍在同一目标的后续范围内。沿用用户已确认的空来源、本机环境、负责人和营业日历，不重复设计审批。

- 从 `origin/main` 的 `3cda543bb19333e5b956dff33eb81137f41b6a92` 建立独立分支；保留其他工作区改动和分叉的本地 main。
- 复用原 20 表冻结事务，将实际身份、锁内检查摘要和审核材料引用绑定到同一事务的数据库标记。普通 rehearsal 命令仍拒绝实际库，且不能操作带实际绑定的恢复副本。
- 新入口只支持首次冻结、原请求重放和状态验证。实际库重新开放必须等待目标 Closed/首写与路由恢复协调，当前入口明确拒绝 reopen/seal，避免将人工引用解释为目标状态证据。
- 实际身份同时包含实例、机器、库名、broker/database/family/recovery-fork GUID 及操作身份；不得仅依赖库名或 broker GUID。原生与 Docker 的两个 CP6DB 分别登记。
- 新行为使用独立 SQL 测试库验证；复用旧结果，只复验被共享事务抽取直接影响的代表场景。集中审查一次，修复仅定向复验。
- 独立发布 CLI 并保留文件哈希、原始执行与失败记录；同步四份项目状态。每次远端写入前重新检查工作流，正常 PR 合并后核验远端 main。

审核材料的 SHA-256 是引用和防漂移绑定，不是签名验证或写入身份隔离证明。当前任务不运行实际库冻结；须先完成可审阅的跨源切换及恢复包，再请求该最终执行批准。整体进度保持 60%（3/5）。
