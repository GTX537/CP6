# 空间编辑器工具反馈增强设计

## 背景

本地验收中，用户可以使用“拖拽”工具平移画布，但认为“选择、旋转、打点、新建库区、保存、导入、导出、反向建模”均没有响应。

逐项浏览器复现确认：工具切换事件、选择、打点、撤销/重做、新建库区、导入文件选择器、导出下载和旋转命令均可执行，控制台无错误。问题来自交互反馈不足：

- 选择、旋转、打点和新建库区在切换后还需要一次画布操作，但页面没有说明下一步。
- 旋转必须先选中单个货架，再拖动 Konva Transformer 的旋转手柄；当前手柄尺寸小、对比度低，缩放后难以发现。
- “反向建模”在未选中货架时直接禁用，用户无法通过点击获知禁用原因。
- 导出成功只触发浏览器下载，没有页面内成功反馈。
- 工具激活态只有按钮底色变化，不足以表达画布已进入不同交互模式。

因此本任务不是重写工具引擎，而是在不改变既有手势和场景数据的前提下，让每次操作都具有可见、可理解的反馈。

## 已批准方案

采用方案 A“反馈增强”：保留现有工具切换模型，增加持续的上下文提示、专用鼠标形态、高对比度旋转手柄和动作结果反馈。

未采用的方案：

- “选择后直接移动与旋转”会合并工具模式，但会引入选择、框选、移动之间的手势冲突，回归范围过大。
- “首次分步教学遮罩”偏重，需要额外持久化首次使用状态，且不能持续解决旋转手柄难发现的问题。

## 目标

1. 用户点击任一工具后，可以立即确认工具已经激活并知道下一步操作。
2. 用户无需猜测即可完成单货架旋转。
3. 依赖选择状态的动作必须解释其前置条件。
4. 保存、导入和导出保持现有数据语义，并提供与动作相称的反馈。
5. 不修改数据库、API、场景 DTO、命令栈语义和发布数据。

## 非目标

- 不把选择、拖拽和旋转合并为单一直接操作模式。
- 不改变 15° 旋转吸附、按 Ctrl 关闭吸附等现有规则。
- 不增加首次使用向导、用户偏好持久化或遥测。
- 不重构 Space Editor 的整体布局、模板库、连接体面板或属性面板。
- 不在本任务中调整画布缩放和平移规则。

## 交互设计

### 工具激活反馈

工具按钮继续使用当前主色高亮。切换工具时，在画布左上角显示一个持续存在的上下文提示条；提示条不自动消失，直到用户切换工具或离开编辑器。

提示内容由当前工具及必要的选择状态决定：

| 工具 | 提示标题 | 操作说明 |
| --- | --- | --- |
| 选择 | 选择模式 | 单击选择货架；拖动空白区域可框选 |
| 拖拽 | 拖拽模式 | 拖动画布可平移视角；拖动货架可移动货架 |
| 旋转，未选货架 | 旋转模式 | 先单击一个货架，再拖动高亮圆形手柄 |
| 旋转，已选货架 | 旋转模式 | 拖动高亮圆形手柄旋转；按住 Ctrl 可关闭 15° 吸附 |
| 打点 | 打点模式 | 单击画布添加标注点，可使用撤销取消 |
| 新建库区 | 新建库区 | 在画布上拖出矩形范围，然后填写库区信息 |

提示条是说明性 UI，不拦截画布指针事件，不覆盖命令结果，也不进入保存数据。

### 鼠标形态

画布容器根据当前工具设置明确的鼠标形态：

- 选择：`default`；进入空白框选拖动时使用选择态反馈。
- 拖拽：空闲为 `grab`，拖动过程中为 `grabbing`。
- 旋转：`crosshair`；悬停旋转手柄时保持 Konva 的旋转指针。
- 打点：`crosshair`。
- 新建库区：`crosshair`。

光标仅表达当前交互，不改变 InteractionManager 的事件分发规则。

### 旋转手柄

RotateTool 继续使用单选货架的 Konva Transformer。激活旋转模式并选中货架后：

- 旋转手柄使用不小于 18 px 的屏幕尺寸。
- 手柄采用 CP6 主色填充、白色内边或外边，并增加深色轮廓，确保在青色、紫色、橙色库区上均可见。
- 手柄与货架之间的连接线使用主色并增加线宽。
- 手柄尺寸保持屏幕像素级可见性，不随世界坐标缩放到不可操作。
- 旋转开始、实时角度文本、角度吸附和命令提交逻辑保持不变。

### 选择依赖动作

“反向建模”不再因未选择货架而完全不可点击。未选择单个货架时点击该按钮，显示“请先在画布上选中一个货架”；选中单货架后按现有流程打开绑定对话框。

按钮的 `title` 或等价辅助说明仍随状态更新，以支持鼠标悬停和辅助技术。

### 保存、导入和导出

- 保存：保留当前 loading、防重复提交、成功、冲突和失败提示。
- 导入：点击后继续打开系统文件选择器；取消选择不提示错误，不改变数据。
- 导出：下载成功创建后显示“导出成功”；请求或文件生成失败继续显示“导出失败”。

## 组件边界与数据流

### 工具反馈模型

新增一个纯函数或等价的只读映射，根据 `activeTool` 和 `hasSelectedRack` 生成提示标题、说明和画布光标类。该模型不依赖 Konva、API 或 Pinia，便于单元测试和国际化键管理。

`FloorEditor.vue` 负责：

1. 从 `activeTool` 与 `selectedRack` 计算当前反馈。
2. 将提示条渲染在画布容器内。
3. 给画布容器绑定工具类和可访问说明。
4. 在工具切换、选择变化后自然更新反馈。

`InteractionManager` 和各工具继续负责实际鼠标事件及命令执行，不承载页面文案。

### 旋转样式

旋转手柄样式由 `RotateTool` 在激活时配置 Transformer，在退出时恢复或清理。不得把手柄样式写入 RackVO 或场景保存负载。

### 结果反馈

导出成功提示由 `FloorEditor.vue` 在下载链接触发后发出。反向建模的前置条件继续复用 `openBindDialog` 中现有的业务提示逻辑，模板按钮不得在调用前阻断该逻辑。

## 国际化与可访问性

- 新增提示文案使用现有 `t(...)` 入口，不在模板中绕过国际化。
- 活跃工具按钮继续具有可识别的视觉状态，并补充 `aria-pressed`。
- 提示条使用 `role="status"` 或等价语义，但避免每次选择变化造成高频打断；工具切换是主要播报时机。
- 禁止仅依赖颜色表达旋转手柄；轮廓、尺寸和连接线共同提供识别。
- 不在本任务中修复仓库中既有的中日文混合词条，但新增文案不得扩大混用范围。

## 异常与边界处理

- 场景尚未加载时切换工具只更新 UI 状态，不抛出异常；提示条仍可显示。
- 旋转模式下点击空白区域会清除选择，并将提示恢复为“先单击一个货架”。
- 多选货架时不显示单货架旋转手柄，提示要求选择一个货架。
- 导入文件选择器被取消时保持静默。
- 导出 API 失败或浏览器无法创建下载时显示现有失败提示，不产生成功提示。
- 提示条使用 `pointer-events: none`，不得遮挡画布选择、拖拽、打点或框选。

## 测试策略

### 单元测试

- 每个 `ToolType` 生成正确的提示与光标类型。
- 旋转模式根据是否选中单货架生成不同说明。
- 未知或缺失状态使用安全的选择模式反馈。
- RotateTool 激活时配置预期的手柄尺寸和可见样式，退出时不遗留事件。

### 组件测试

- 点击工具按钮更新活跃态、`aria-pressed`、提示条和画布类。
- 未选货架点击“反向建模”显示前置条件提示。
- 选中货架后“反向建模”仍打开原有对话框。
- 导出成功显示成功提示；导出失败显示失败提示。
- 撤销/重做禁用规则不因反馈层改变。

### 浏览器验收

在本地 API、CP6DB 和 18080 前端环境中验证：

1. 五个工具按钮均可切换并显示对应持续提示。
2. 拖拽仍能平移画布和移动货架。
3. 旋转模式可选中货架、发现手柄、提交旋转并撤销。
4. 打点后撤销/重做状态正确。
5. 新建库区拖框后显示命名对话框，取消不落数据。
6. 导入打开系统文件选择器，导出产生 JSON 下载并显示成功提示。
7. 浏览器控制台无新增错误。

## 交付与回退

本任务只涉及前端代码、测试和必要项目状态文档，不需要数据库迁移或 API 发布。功能可通过回退单个前端提交恢复原行为；回退不会影响已经保存的场景数据。

实施完成后先在独立任务分支运行相关单元测试、前端全量测试、类型检查和构建，再合入本地验收分支供 18080 热更新验证。未经完整门禁和用户验收，不合并至 `main`。
