## 架构骨架（三层承载行业差异）

```
核心层（全租户共享，窄而稳）：Item / SalesOrder / Quotation / PriceList /
  BusinessPartner / BOM / Routing + 状态机、信用、ATP、编号规则
行业包层（Industry Pack，按租户启用）：强类型扩展表挂核心实体
  （纸器包=版型/抜型/巻方向/紙質…；电源包=安规/绕组…）+ 包内专属页面/流程节点
租户微调层（复用 SFS 低代码表单）：客户自加字段/校验/布局
```

**设计原则**：MRP/财务/WMS 永远只依赖核心层字段；行业包是强类型扩展表（可进计算）；SFS 兜客户级长尾。纸器现有租户 = 第一个行业包的验收用例；63 项目逐个分拣「进核心/进纸器包/进 SFS」，分拣表即迁移映射表。

## 既有资产复用清单

- **SFS 低代码表单**（内核好，布局/报表缺——正好被微调层需求拉动，与 SFS 深化 spec 呼应）
- **WFS 工作流**（已做真，含信箱/稟議書打印）= 审批适配器默认实现
- **多租户基建**（P0 后角色亦租户级）= 行业包启用开关的宿主
- **FxRate/多币种、i18n 五语、IntegrationEvent 桥/横切规范(docs/00-横切接线规范.md)** 照用
- **MRP(A1)/工艺(A2)** 的 BOM 展开与工时地基 = ATP 与成本的输入

## 待正式 spec 时展开的推荐值（用户未逐项确认，写 spec 时先过一遍）

1. **v1 流程链范围**：Quotation→SalesOrder→出货(接 WMS)→开票(接 F1 油路) 四环闭合；询价(Inquiry)/框架协议(Blanket)不进 v1；订单变更管理(版本+变更单)进 v1（商业 ERP 及格线）。
2. **定价引擎**：价格表(客户×Item×数量阶梯×币种×有效期) + 折扣规则表驱动；报价/订单自动带价可人工覆盖留痕。SheetUnitPrice/ProductLotPrice 归入纸器包或映射进价格表。
3. **信用管控**：额度入 BusinessPartner 主数据，占用=AR 余额+未出货订单实时算；超限走审批适配器放行（硬闸）。
4. **ATP**：v1 做库存 ATP（现库存−已承诺），MRP/MPS ATP 留接口。
5. **编号规则**：租户级可配置采番（前缀/日期段/流水位数/重置周期），Sales 先用，后续各模块迁入。
6. **术语词典**：行业包携带 i18n 术语覆盖层（租户启用包后「Item」显示为「製品」or「品目」等），不另造机制、扩展现有 i18n。
7. **审批适配器**：~~`IApprovalGateway`~~ **勘误（2026-07-09 评审）：不新造接口，"可插拔审批"即既有 `IApprovalService.SubmitAsync(bizType,…)` + `Wf_ApprovalBinding` + `IApprovalCallback`（审批解耦 spec 2026-07-07 契约）**；PowerEgg stub 迁到 IApprovalService 的备选实现位。单据侧只存"迁移点→BizType"映射（见 2026-07-09 配置基建设计 §1④）。
8. **存量迁移**：spec 内含 PA070 63 项目分拣表（核心/纸器包/SFS 三桶）+ Quotation/Order/Product 存量映射；迁移脚本按 Space 波4 THROW 校验先例写。

## 与既有路线的关系

- **不动**：M-ERP 修复波（权限/测试/硬编码）照旧先行——老模块冻结前仍需及格。
- **F1 财务油路**：出货→开票接线以新 Sales 模块为一等公民设计，老模块桥只维持。
- **SFS 深化 / Space P2.5**（main=51298f6 两 spec）与本设计无冲突；SFS 深化优先级因本设计的微调层依赖而上升。
