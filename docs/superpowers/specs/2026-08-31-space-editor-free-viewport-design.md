# 空间编辑器自由视口设计

## 1. 背景与问题证据

空间编辑器当前能够显示楼层布局，但视口不能按用户预期自由缩放和平移：

- 鼠标滚轮事件会进入 `SceneStage` 并修改内部视图状态，但现有 Konva 节点仍保留旧的屏幕坐标和尺寸，只执行 `batchDraw()` 不会产生可见缩放。
- “拖拽”工具点击空白画布时直接返回，没有进入视口平移流程，因此空白区域拖动不会改变画面。
- 在公开 Docker 验收环境中，对画布发送滚轮事件后，操作前后的画布截图 SHA-256 完全一致；在“拖拽”模式下对空白画布拖动 120 × 80 像素，操作前后的画布截图 SHA-256 也完全一致。这证明事件存在，但可视结果没有变化。
- 仓库中存在一份基于旧版 `main` 的未合并原型，可作为交互实现参考；本任务不直接合并该原型，而是在最新 `origin/main` 上重新实现并补齐当前几何解析、工具反馈和验收要求。

## 2. 目标

本任务为二维俯视空间编辑器提供完整、可预测的自由视口能力：

1. 用户可以围绕鼠标所在位置连续缩放，而不是只能缩放固定中心。
2. 用户可以在任何工具模式下临时平移画布，并在“拖拽”模式下直接拖动空白区域平移。
3. 用户可以通过工具栏精确缩放、适配全部内容和复位视图。
4. 用户能够检视楼层布局的任意角落，同时不改变仓区、巷道、货架、标注等业务对象的数据。
5. 视口操作保持流畅，并在手势结束后恢复准确、统一的坐标和选择框状态。

## 3. 非目标

- 不实现三维透视、相机环绕或自由飞行；这些能力属于 3D Viewer，不属于二维空间编辑器。
- 不修改数据库、API、DTO、楼层场景保存格式或发布格式。
- 不把视口位置写入场景数据、命令历史或保存请求；刷新页面后仍按初始适配视图进入。
- 不在本任务中重构现有七层 Konva 图层结构；是否合并图层需要单独的性能数据和任务评估。
- 本轮以桌面鼠标和触控板产生的滚轮事件为范围；触屏双指缩放不在本次验收范围内。

## 4. 方案选择

采用方案 A：两阶段视口变换。

### 4.1 手势预览阶段

滚轮缩放或拖动平移进行中时，对全部可视 Konva 图层应用临时 `scale` 和 `position` 变换。这个阶段不重新解析场景、不重建节点，优先保证连续反馈和帧率。

### 4.2 提交重绘阶段

手势结束、取消或滚轮停止后，将预览结果提交为唯一的规范视口状态，再按新的视口状态重绘场景一次。提交后清除图层上的临时变换，并刷新 Transformer、命中区域和辅助图形，避免后续编辑发生坐标漂移。

### 4.3 未采用方案

- 每个滚轮或拖动事件都完整重绘：实现直接，但会频繁重新解析和重建楼层节点，大场景下容易产生卡顿。
- 将全部场景改为世界坐标并把缩放永久放到根容器：长期模型更统一，但会扩大到工具、Transformer、命中测试、导入导出和现有七层结构的系统性重构，不适合本次缺陷修复的范围。

## 5. 交互设计

### 5.1 鼠标和键盘

- 在任意工具模式下，鼠标滚轮或触控板滚动围绕当前指针位置缩放。
- 在任意工具模式下，按住 `Space` 后用鼠标左键拖动可平移画布。
- 在任意工具模式下，按住鼠标中键拖动可平移画布。
- 在“拖拽”工具模式下：
  - 在空白区域按住左键拖动，平移画布。
  - 在货架上按住左键拖动，仍然移动货架，不触发视口平移。
- 视口导航开始后，当前编辑工具暂时停止处理同一次指针序列；导航结束后恢复原工具，不改变用户选中的工具。
- 平移期间光标显示抓取状态；结束、取消、失焦或指针丢失后必须恢复正常状态。

### 5.2 工具栏

空间编辑器工具栏新增以下控件：

- 缩小
- 当前缩放百分比
- 放大
- 适配全部
- 复位视图

所有控件提供中文可见提示和可访问名称，键盘可聚焦并可触发。工具栏与鼠标/触控板操作共享同一个视口控制器，百分比始终反映规范视口状态。

### 5.3 缩放定义

- 页面首次进入时自动适配全部内容，并把该初始适配结果定义为 `100%`。
- 用户缩放范围为相对初始适配的 `10%` 至 `800%`。
- 工具栏放大、缩小使用固定倍率步进，并以画布中心为锚点。
- 滚轮缩放以指针下的世界坐标为锚点：缩放前后，该世界点应保持在同一屏幕位置。
- 超出范围的输入被钳制到边界，不允许产生 `NaN`、`Infinity` 或负比例。

### 5.4 适配与复位

- “适配全部”计算所有有效可视对象的联合包围盒，并使用 48 像素安全边距放入当前画布。
- 联合包围盒包括仓区、巷道、旋转后的货架和标注点。
- “复位视图”回到页面首次进入时计算出的初始适配状态，即 `100%` 和初始平移位置。
- 空场景或全部几何无效时，适配与复位回到稳定的默认中心视图，不抛异常。

## 6. 架构设计

### 6.1 纯视口数学模块

新增独立的视口数学模块，例如 `cp6.web/src/space-editor/viewport.ts`。该模块不依赖 Vue、Pinia 或 Konva，负责：

- 缩放范围钳制。
- 围绕锚点缩放的平移计算。
- 世界坐标与屏幕坐标互转。
- 场景联合包围盒和适配视图计算。
- 画布尺寸变化时保持世界中心点。
- 有限数校验和安全回退。

纯函数设计使核心坐标逻辑可以被稳定、快速地单元测试。

### 6.2 `SceneStage` 作为视口所有者

`SceneStage` 持有唯一规范视口状态：

```ts
interface ViewportState {
  panX: number
  panY: number
  zoom: number
  canvasWidth: number
  canvasHeight: number
}
```

同时缓存当前已解析场景，负责：

- 应用临时图层变换。
- 提交视口并完整重绘。
- 维护初始适配视图。
- 在场景编辑重绘时保留当前视口。
- 在提交后刷新 Transformer、命中区域和辅助图形。
- 发出统一的 `viewportchange` 通知，供工具栏同步百分比和禁用状态。

所有可视图层必须参与相同的临时变换，避免标注、选择框或辅助层相对业务对象漂移。提交后，各图层恢复无临时缩放/位移的基线状态。

### 6.3 统一视口控制器

滚轮、`Space` + 左键、中键、“拖拽”工具空白左键和工具栏按钮统一调用同一控制器。控制器负责导航手势生命周期、指针捕获、工具抑制、预览和提交，避免不同入口各自实现坐标公式。

`InteractionManager` 在视口导航期间不向当前编辑工具分发会修改场景的指针事件。视口提交后通知当前工具刷新依赖屏幕坐标的状态，但不生成编辑命令，也不标记场景为已修改。

### 6.4 画布尺寸变化

使用 `ResizeObserver` 监听编辑器画布容器。尺寸变化时：

1. 记录变化前画布中心对应的世界坐标。
2. 更新 Konva Stage 和规范视口尺寸。
3. 调整平移，使同一世界坐标仍位于新画布中心。
4. 提交一次重绘并刷新 Transformer。

如果尺寸为零或不可用，则暂缓重绘并保留上一个有效视口，不产生异常状态。

## 7. 内容边界计算

- 仓区和巷道统一使用编辑器现有的多边形解析逻辑，避免与当前数据兼容规则分叉。
- 货架按中心、宽高和旋转角计算四个角点，再取轴对齐包围盒；不能只用未旋转宽高。
- 标注使用有效点坐标参与边界计算。
- 缺失、格式错误或非有限坐标的单个对象被忽略，并允许其余有效对象继续适配。
- 如果没有任何有效对象，返回稳定默认边界；禁止把无效值传给 Konva。

## 8. 状态与事件流程

### 8.1 滚轮缩放

1. 读取指针位置和当前规范视口。
2. 计算钳制后的目标缩放和目标平移。
3. 立即对图层应用临时变换。
4. 连续滚轮事件复用预览状态，并重置 120 毫秒提交计时器。
5. 停止滚动后提交规范视口、清除临时变换、重绘并刷新工具状态。

### 8.2 指针平移

1. 在满足平移手势条件时捕获指针并记录起点。
2. 指针移动时只更新临时平移预览。
3. `pointerup`、`pointercancel`、窗口失焦或组件销毁时结束手势。
4. 正常结束提交新视口；取消或异常中断时也必须清理监听器、光标和临时状态，视已有预览安全提交到最后有效位置。

### 8.3 工具栏操作

工具栏操作是离散动作，不需要等待防抖：计算目标状态后立即提交重绘。到达最小或最大缩放时禁用对应按钮。

### 8.4 场景编辑与保存

- 场景内容变化时使用当前规范视口重绘，不自动复位。
- 视口变化不进入 Pinia 场景数据、撤销/重做命令栈、导出内容或保存请求。
- 仅业务对象发生变化时，编辑器才进入未保存状态。

## 9. 异常与冲突处理

- 锚点缺失时使用画布中心；画布中心也无效时拒绝本次操作并保持旧状态。
- 所有进入视口状态的数值先做有限数校验；无效输入回退到上一个有效状态。
- `Space` 键在输入框、文本域或可编辑元素获得焦点时不接管，避免阻止用户输入空格。
- 浏览器窗口失焦、页面切换、指针捕获丢失和组件卸载都必须清理全局监听器与防抖计时器。
- 导航手势一旦开始，同一指针序列不得同时创建标注、绘制仓区、选择对象、旋转货架或写入命令历史。
- 导航结束后，选择状态与当前工具保持不变；Transformer 必须重新对齐被选对象。

## 10. 测试设计

### 10.1 纯函数单元测试

- 锚点缩放前后世界点的屏幕位置不变。
- 缩放严格钳制在相对初始适配的 10% 至 800%。
- 联合边界覆盖仓区、巷道、旋转货架和标注，并正确应用 48 像素边距。
- 空场景、部分错误几何、零尺寸画布和非有限输入返回稳定结果。
- 画布尺寸变化后世界中心点保持不变。

### 10.2 `SceneStage` 与交互测试

- 滚轮预览会改变全部可视图层的临时变换，提交后清除临时变换并按新视口重绘。
- `Space` + 左键和中键在五种工具模式下都能平移。
- “拖拽”模式在空白区域平移，在货架上移动货架，两者互不串行为。
- 导航期间不会意外选择、创建标注、绘制仓区、旋转对象或标记场景为已修改。
- 提交后 Transformer、命中测试和屏幕/世界坐标转换保持一致。
- `pointercancel`、失焦、组件卸载和连续滚轮防抖没有监听器或计时器泄漏。

### 10.3 Vue 组件测试

- 工具栏五个入口可见、可聚焦、可通过键盘触发，并有可访问名称。
- 百分比随滚轮、拖动、适配、复位和按钮缩放同步。
- 最小/最大缩放时相应按钮禁用。
- 视口操作不触发保存按钮的脏状态。

### 10.4 工程门禁

- 运行空间编辑器相关单元测试和组件测试。
- 运行前端类型检查、完整测试与生产构建。
- 审查相对 `main` 的完整 diff，确认无调试代码、机器专属配置、敏感信息和范围外改动。

### 10.5 Docker 浏览器验收

使用合并后 `main` 的精确 Git SHA 构建验收镜像，并在 `cp6.uk` 执行：

- 对画布滚轮缩放后，前后画布截图哈希不同，且指针所指对象仍位于同一屏幕位置附近。
- 对空白画布平移后，前后画布截图哈希不同。
- 能通过缩放和平移依次检视布局四个角落，并能使用“适配全部”一次恢复完整布局。
- 在五种编辑工具中验证 `Space` + 左键和中键平移，在“拖拽”模式验证空白与货架的分流。
- 验证工具栏缩小、百分比、放大、适配全部和复位视图。
- 验证浏览器控制台没有 Vue、Konva、运行时和坐标错误。
- 验证导航过程不发出场景保存请求，不改变 CP6DB 数据。

## 11. 交付与回退

- 代码、测试、必要文档和项目状态记录在同一任务分支闭环。
- 通过本地门禁后提交 Pull Request；CI 全部通过并审查完整 diff 后再合并到 `main`。
- Docker 验收镜像必须来自合并后 `main` 的精确 Git SHA。即使本任务只修改 Web，API 与 Web 的验收身份仍按同一发布提交记录，CP6DB 不做迁移或数据写入。
- 如验收发现回归，回退到上一个已验证 Web 镜像；若验收发布同时重建 API，则两者一并按上一组已验证镜像身份恢复。数据库无需回退。

## 12. 完成标准

- 用户可以在任意工具下围绕指针缩放，并平移到任意布局角落。
- 初始适配为 100%，缩放范围为 10% 至 800%，工具栏状态与手势同步。
- “拖拽”模式空白拖动画布、货架拖动对象，行为明确且无冲突。
- 适配全部覆盖所有有效可视对象，复位视图回到初始适配。
- 缩放和平移不修改场景数据、不进入撤销栈、不触发保存或数据库写入。
- 选择框、命中测试和所有编辑工具在视口变化后仍准确可用。
- 自动化门禁和 Docker 浏览器验收全部通过，并留下可复现证据。
