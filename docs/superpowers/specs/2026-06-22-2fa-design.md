# 双因素认证（2FA）设计 spec — S 类安全合规 #2

> 源：brainstorming 共识（2026-06-22）。底座 = #1 认证加固（BCrypt + 策略/锁定/审计 + 刷新令牌轮换 + 登出 jti 黑名单 + httpOnly 三 Cookie + CSRF 双提交 + 强制改密 + Sys 授权加固）。本子项目在其上叠加 2FA。命名空间 **Sys**，错误码 **E-SEC-01x**，多租户 `BaseTenantEntity`。

## §0 范围

**做（MVP）**：TOTP 认证器（RFC 6238）为主第二因子 + 邮件 OTP 作回退/恢复通道；按租户 2FA 策略（关闭/可选/强制）；两步式登录 + 短命 pending 令牌承载"半登录"态；强制租户下登录时强制入会；2FA 失败接入既有登录锁定；安全事件审计；admin 重置用户 2FA；全栈前端（挑战屏/入会屏/个人设置/租户策略）+ 五语 i18n。

**不做（YAGNI）**：短信 OTP（无网关、SIM 攻击面）、WebAuthn/passkey（独立大子项目）、备份恢复码（已用邮件作恢复，不重复）、"记住此设备 N 天"（留后续增量）、per-角色 2FA 策略（先按租户）。

### §2.3 pending 半登录状态 + 邮件 OTP — `IDistributedCache`（不建表）
**pending 会话状态（评审#2，pending 令牌一次性化）：**
- key `sec:2fa:pending:{pendingJti}`，value = `{userId, tenantId, purpose}`（JSON），TTL = `Security:TwoFactor:PendingTokenMinutes`（默认 5）。
- pending 令牌（§3.5）携带 `pendingJti`（=该 key 的 jti）。每次 /auth/2fa/* 先校验该 key 存在（不存在=已用/过期 → `E-SEC-013`）。
- **2FA 成功（或入会完成）即删该 key** → pending 令牌一次性失效，重放同令牌 → key 不存在 → E-SEC-013。

**邮件 OTP（评审#3，绑 pending 会话，避免多窗口互相覆盖）：**
- key `sec:2fa:otp:{pendingJti}`，value = **OTP 的 SHA-256 哈希**（不存明文）+ 尝试计数，TTL = `Security:TwoFactor:EmailOtpMinutes`（默认 5）。
- 单次有效：验证成功即删。重发限流 key `sec:2fa:otp:cooldown:{pendingJti}`（默认 60s TTL）。
- 决策：短命瞬态数据用缓存（仿 jti 黑名单），不污染库；按 pendingJti 隔离每个登录会话。

### §2.4 EF 迁移
`dotnet ef migrations add TwoFactor --project CP6.Core --startup-project CP6.WebApi`（`Sys_User` 3 列 + `Sys_Tenant` 1 列；无新表）。

## §3 组件 / 服务（`CP6.Core/Services/Sys/`）

### §3.1 `SecurityOptions` 加 `TwoFactorOptions`
```csharp
public class TwoFactorOptions {
    public string Issuer { get; set; } = "CP6";        // otpauth:// issuer（认证器显示名）
    public int CodeWindow { get; set; } = 1;            // TOTP 容时窗口（±N 个 30s 步长）
    public int EmailOtpMinutes { get; set; } = 5;       // 邮件 OTP 有效分钟
    public int EmailOtpLength { get; set; } = 6;        // 邮件 OTP 位数
    public int EmailResendCooldownSeconds { get; set; } = 60;
    public int PendingTokenMinutes { get; set; } = 5;   // pending 令牌寿命
}
```
（接入 `SecurityOptions` 根：`public TwoFactorOptions TwoFactor { get; set; } = new();`）

### §3.2 `ITotpService` / `TotpService`（引包 `Otp.NET`）
```csharp
public interface ITotpService {
    string GenerateSecret();                                   // base32, 20 字节随机
    string BuildOtpAuthUri(string secret, string userName);    // otpauth://totp/{Issuer}:{user}?secret=..&issuer=..
    bool Verify(string secret, string code);                   // RFC6238, 30s 步长, ±CodeWindow
}
```
- `Verify` 用 `Otp.NET.Totp(Base32Encoding.ToBytes(secret)).VerifyTotp(code, out _, new VerificationWindow(CodeWindow,CodeWindow))`。
- `BuildOtpAuthUri`：`otpauth://totp/{Uri.EscapeDataString(Issuer)}:{Uri.EscapeDataString(userName)}?secret={secret}&issuer={Uri.EscapeDataString(Issuer)}&period=30&digits=6`。前端用它渲染 QR（前端 qrcode 库，后端只给 URI）。

### §3.3 `IEmailSender` / `SmtpEmailSender` + `LogEmailSender`
```csharp
public interface IEmailSender { Task SendAsync(string to, string subject, string body); }
```
- `SmtpEmailSender`：读 `Email:Smtp`（Host/Port/User/Pass/From/EnableSsl），`System.Net.Mail.SmtpClient` 发送。
- `LogEmailSender`：**仅 Development** 兜底——`ILogger` 输出 `[EMAIL→{to}] {subject}: {body}`（含 OTP），保 dev/gstack QA 无外部依赖可跑。
- **DI 选择 + 生产防护（评审#6）**：`Program.cs` 工厂注册——
  - `Email:Smtp:Host` 非空 → `SmtpEmailSender`（任何环境）。
  - Host 空 + **Development** → `LogEmailSender`。
  - Host 空 + **非 Development**（生产）→ **启动失败**（`throw` 明确异常，提示"启用邮件 OTP 但未配置 SMTP"），杜绝 OTP 落生产日志的安全风险。（若运维确不需邮件回退，可显式 `Security:TwoFactor:EmailFallbackEnabled=false` 关闭邮件 OTP 而非兜底日志。）

### §3.4 `ITwoFactorService` / `TwoFactorService`
```csharp
public interface ITwoFactorService {
    int ResolveTenantMode(Guid tenantId);                      // 读 Sys_Tenant.TwoFactorMode（IgnoreQueryFilters，登录期无上下文）
    bool IsChallengeRequired(Sys_User user, int tenantMode);   // user.TwoFactorEnabled || tenantMode==2
    bool MustEnroll(Sys_User user, int tenantMode);            // tenantMode==2 && !user.TwoFactorEnabled
    string BeginEnrollment(Sys_User user);                     // 生成密钥写 user.TwoFactorSecret(未启用)，返 otpauth URI（评审#7：若 user.TwoFactorEnabled 则抛 E-SEC-017 拒绝，不静默覆盖；须先 ResetAsync）
    Task<bool> ConfirmEnrollmentAsync(Sys_User user, string code);  // 验码 → 置 TwoFactorEnabled+EnrolledAt，审计 Enrolled
    bool VerifyTotp(Sys_User user, string code);
    Task SendEmailOtpAsync(Sys_User user, string pendingJti);  // 评审#3:按pendingJti存;限流→生成OTP存缓存哈希→IEmailSender发,审计EmailOtpSent;user.Email空抛E-SEC-015
    Task<bool> VerifyEmailOtpAsync(Sys_User user, string pendingJti, string code);// 比对 sec:2fa:otp:{pendingJti} 哈希，成功删 key
    Task ResetAsync(Sys_User user);                            // admin 重置：清 Enabled/Secret/EnrolledAt，审计 Reset
}
```
- Core 层抛 `InvalidOperationException("E-SEC-01x")`（限流/过期/无效/无邮箱/已启用），控制器转 BizException。

**密钥安全边界（评审#7，必须落码）：**
1. `BeginEnrollment` 若 `user.TwoFactorEnabled==true` → 拒绝（`E-SEC-017`，提示先 reset），**不静默覆盖** `TwoFactorSecret`。
2. `setup`/`setup-self` 端点返回 `otpauthUri`/`secret` **仅在未启用（入会中）时**；已启用用户再调 → 拒绝（须先 reset）。
3. **`TwoFactorSecret` / `otpauthUri` 绝不写入** `Sys_SecurityLog` / `OperLog` / 前端日志 / 审计 reason（审计只记事件类型，不带密钥）。

**邮件 OTP 不绕过强制入会（评审#4）：**
- 仅 `user.TwoFactorEnabled==true` 的用户在登录挑战时可用邮件 OTP 回退；或 admin reset 后的恢复流程。
- 租户 `Required` 且用户**未** `TwoFactorEnabled`（mustEnroll 态，pending purpose=2fa_enroll）→ **禁用邮件 OTP**（`/auth/2fa/email-otp` 在 enroll 态返 `E-SEC-014`，必须先完成 TOTP enrollment）。否则强制 TOTP 被邮箱验证码绕过。

### §3.5 pending 令牌（半登录态，评审#1/#2 强化）
- 复用 `JwtHelper`：新增静态 `GeneratePendingToken(userId,tenantId,purpose,pendingJti,secret,issuer,audience,minutes)`，claims = `NameIdentifier`/`tenant_id`/`token_use`（`2fa_verify`|`2fa_enroll`）/**`jti`=pendingJti**，短寿命（PendingTokenMinutes）。
- **服务端一次性状态（评审#2）**：签发时同步写 `sec:2fa:pending:{pendingJti}`（§2.3，存 userId/tenantId/purpose，同 TTL）。**JWT 短命只是第一道；权威是缓存 key**：每次 /auth/2fa/* 校验 JWT 后再查该 key 存在性（不存在=已用/过期 → `E-SEC-013`），2FA 成功/入会完成即删 key → 令牌一次性、不可重放、避免多窗口覆盖。
- **Cookie（评审#1）**：pending 分支同时写两 cookie——
  - **`cp6_2fa`**（新增常量，httpOnly，Path=`/api/auth`，Secure/SameSite 同三 Cookie）= pending 令牌。
  - **`cp6_csrf`**（非 httpOnly，复用现有 CSRF cookie）= 让前端能在 2FA POST 带 `X-CSRF-Token`。
  - `AuthCookieWriter` 加 `WritePendingCookies(resp,pendingToken,csrf)` / `ClearPendingCookies(resp)`；`ClearAuthCookies` 一并清 cp6_2fa（cp6_csrf 已在清单）。
- **CSRF 校验（评审#1，不豁免）**：`/auth/2fa/setup`/`enroll`/`verify`/`email-otp` 是 POST，**不在 CsrfMiddleware 的 login 豁免内**，故启用 CSRF 时自动要求 `X-CSRF-Token==cp6_csrf`（沿用 #1 加固既有 CsrfMiddleware，无需特例）。spec 明确：2FA pending 阶段**走 CSRF 校验**（非豁免）。
- /auth/2fa/* 端点 `[AllowAnonymous]` + 手动读 cp6_2fa + 校验（签名/issuer/audience/未过期/token_use 匹配 + 缓存 key 存在）→ 取 userId/tenantId/pendingJti。**pending 令牌不是 cp6_at**，普通 [Authorize] 接口不接受 → 半登录态进不了受保护资源。

## §4 流程

### §4.1 登录（AuthController.Login 改造）
密码校验/锁定/禁用/租户停用判定**不变**。`_tenant.CurrentTenantId=user.TenantId` 后、签发三 Cookie 前插入 2FA 分支：
```
mode = _2fa.ResolveTenantMode(user.TenantId)
if _2fa.IsChallengeRequired(user, mode):
    purpose = _2fa.MustEnroll(user, mode) ? "2fa_enroll" : "2fa_verify"
    pendingJti = NewGuid()
    缓存写 sec:2fa:pending:{pendingJti} = {userId,tenantId,purpose} TTL=PendingTokenMinutes   # 评审#2
    pendingToken = JwtHelper.GeneratePendingToken(userId,tenantId,purpose,pendingJti,...)
    csrf = AuthCookieWriter.NewCsrfToken()
    _cookies.WritePendingCookies(Response, pendingToken, csrf)   # 评审#1：cp6_2fa + cp6_csrf 同写
    audit TwoFactorChallenged(reason = purpose=="2fa_enroll" ? "enroll" : null)
    返回 { twoFactorRequired:true, mustEnroll:(purpose=="2fa_enroll") }   # 不发三 Cookie/不记 LoginSuccess
    return
# 否则照旧：RecordSuccess + 审计 LoginSuccess + IssueAsync + WriteAuthCookies + 返档案
```
> 锁定/审计已在密码阶段完成；2FA 挑战不重复记 LoginSuccess（成功在 2FA 通过后记）。

### §4.2 入会（强制租户 or 可选用户自助）
- `POST /auth/2fa/setup` `[AllowAnonymous]`（登录期读 cp6_2fa；或已登录态读 cp6_at——两种入口）：`BeginEnrollment` 返 `{ otpauthUri, secret }`（secret 供手动输入备选）。**不置 Enabled**。
- `POST /auth/2fa/enroll` body `{code}`：`ConfirmEnrollmentAsync` 验码 → 置 Enabled。**登录期入口**：成功后等同登录完成 → `RecordSuccessAsync`+审计 LoginSuccess+`IssueAsync`+`WriteAuthCookies`+清 cp6_2fa，返 `{userName,nickName,roleId,menus,mustChangePassword}`。**已登录态自助入口**：仅置 Enabled 返 `{code:0}`。

### §4.3 挑战验证（登录期）
- `POST /auth/2fa/verify` body `{code, method}`（`method:"totp"|"email"`）`[AllowAnonymous]`（读 cp6_2fa+校验缓存 key，purpose=2fa_verify）：先 `EnsureNotLocked`；按 `method` 调 `VerifyTotp` 或 `VerifyEmailOtpAsync(user,pendingJti,code)`。失败 → `RecordFailureAsync`+审计 TwoFactorFailed+`E-SEC-011`。成功 → **删 sec:2fa:pending:{pendingJti}**（一次性）+ 同 §4.2 登录完成路径（发三 Cookie）+审计 TwoFactorVerified+LoginSuccess。
- `POST /auth/2fa/email-otp` `[AllowAnonymous]`（读 cp6_2fa+校验缓存 key）：**评审#4——purpose=2fa_enroll（强制入会态）→ 拒 `E-SEC-014`（必须先 TOTP 入会，邮件不绕过）**；purpose=2fa_verify → `SendEmailOtpAsync(user,pendingJti)`（user.Email 空→`E-SEC-015`；限流命中→`E-SEC-016`；发送失败→`E-SEC-018`）。返 `{code:0}`（不泄露邮箱）。

### §4.4 admin 重置 + 租户策略
- **admin 重置**：`UserController` 加 `POST reset-2fa` body `{userId}`，`[RequirePermission("user","edit")]`（重置 2FA = 用户编辑权，与授权加固一致）→ `_2fa.ResetAsync` 清 Enabled/Secret + 审计 TwoFactorReset。
- **租户策略**：`GET/PUT /api/sys/two-factor-policy` body `{mode}`（新建 `TwoFactorPolicyController`，作用于**当前请求租户** `ITenantContext.CurrentTenantId`，租户管理员设本租户策略），`[RequirePermission("user","edit")]`（MVP：复用用户管理编辑权=租户管理员级；无独立"租户设置"菜单，列 §9 后续可拆专属权限点）→ 写 `Sys_Tenant.TwoFactorMode`。

### §4.5 半登录态守卫
- pending 令牌（cp6_2fa）非 cp6_at → 普通 [Authorize] 接口返 401（不接受）。无需新中间件。
- 前端：登录返 `twoFactorRequired` → **不置 cp6_authed**，跳 2FA 挑战/入会屏；2FA 完成（发三 Cookie）后才置 cp6_authed。

### §4.6 已登录态自助启停 2FA（评审#5，全 `[Authorize]`，走 cp6_at + CSRF）
当前用户 = `(await _perm.GetAsync()).UserId`。这些端点是**完整登录态**（非 pending），不读 cp6_2fa。
- `GET /api/auth/2fa/status` → `{ enabled, tenantMode, canDisable }`（canDisable = enabled && tenantMode!=Required）。
- `POST /api/auth/2fa/setup-self` → 已启用则拒（评审#7：`E-SEC-017`，须先 disable/reset）；否则 `BeginEnrollment` 返 `{otpauthUri, secret}`。
- `POST /api/auth/2fa/enroll-self` body `{code}` → `ConfirmEnrollmentAsync` 置 Enabled+审计 Enrolled，返 `{code:0}`。
- `POST /api/auth/2fa/disable-self` body `{currentPassword, code, method}` → **强校验**：①`_hasher.Verify(currentPassword)` 失败→`E-SEC-006`；②`VerifyTotp` 或 `VerifyEmailOtpAsync`（注：自助 disable 的邮件 OTP 走已登录态另一缓存 key `sec:2fa:otp:self:{userId}`，不依赖 pending）失败→`E-SEC-011`；③**租户 `Required` 时禁止自助关闭**→`E-SEC-019`（"贵租户已强制 2FA，不可自行关闭"）。全过 → `ResetAsync` 清 Enabled/Secret + 审计 TwoFactorReset(reason="self-disable")。

## §5 错误码（E-SEC-01x，五语 seed）

| 码 | 中文（i18n key=码本身，仿既有 E-SEC-0xx） | 用处 |
|---|---|---|
| E-SEC-011 | 验证码错误 | TOTP/邮件 OTP 验证失败 |
| E-SEC-013 | 验证码会话已过期或失效，请重新登录 | pending 缓存 key 不存在/过期（评审#2 一次性失效后重放） |
| E-SEC-014 | 请先完成双因素认证设置 | mustEnroll 态访问需启用的操作 / 强制入会态请求邮件 OTP（评审#4） |
| E-SEC-015 | 当前账户未配置邮箱，无法使用邮件验证码 | user.Email 空（评审#8） |
| E-SEC-016 | 验证码发送过于频繁，请稍后再试 | 邮件 OTP 重发限流 |
| E-SEC-017 | 双因素认证已启用，请先重置后再重新设置 | setup/BeginEnrollment 时已 Enabled（评审#7，防静默覆盖密钥） |
| E-SEC-018 | 邮件验证码发送失败，请稍后重试 | IEmailSender 抛异常（评审#8） |
| E-SEC-019 | 贵租户已强制启用双因素认证，不可自行关闭 | disable-self 且租户 Required（评审#5） |

> 复用既有 E-SEC-002（账户已锁定）于 2FA 锁定、E-SEC-006（原密码错误）于 disable-self 密码校验。`SecurityEventType` 加 9~14：`TwoFactorChallenged=9/TwoFactorVerified=10/TwoFactorFailed=11/TwoFactorEnrolled=12/TwoFactorReset=13/TwoFactorEmailOtpSent=14`，i18n `sec.event.9~14` 五语标签。

## §6 配置（appsettings）
- `Security:TwoFactor`（Issuer/CodeWindow/EmailOtpMinutes/EmailOtpLength/EmailResendCooldownSeconds/PendingTokenMinutes）。
- `Email:Smtp`（Host/Port/User/Pass/From/EnableSsl）——生产配置；**dev/appsettings.Development.json 留 Host 空 → 走 LogEmailSender**。

## §7 i18n / 菜单 / 前端
- `I18nSec2faScreenSeed`（或并入 `I18nSecScreenSeed`）：E-SEC-011~019 + sec.event.9~14 + 2FA 挑战屏/入会屏/个人设置/租户策略词条，五语。

  - `LoginView`：`authApi.login` 返 `twoFactorRequired` → 路由到 2FA 屏（`mustEnroll` → 入会屏 QR+确认；否则挑战屏 TOTP 输入+"改用邮件"）。

## §10 自审
范围聚焦单一子项目（2FA），与 #1 认证加固解耦叠加；数据模型最小（3+1 字段，无新表，OTP 走缓存）；流程两步式 pending 令牌天然隔离半登录；防爆破复用既有锁定；邮件 dev 兜底保 QA 可跑；授权/审计/i18n/多租户全对齐既有约定。无遗漏跨子系统依赖。
