# 双因素认证（2FA）设计 spec — S 类安全合规 #2

> 源：brainstorming 共识（2026-06-22）。底座 = #1 认证加固（BCrypt + 策略/锁定/审计 + 刷新令牌轮换 + 登出 jti 黑名单 + httpOnly 三 Cookie + CSRF 双提交 + 强制改密 + Sys 授权加固）。本子项目在其上叠加 2FA。命名空间 **Sys**，错误码 **E-SEC-01x**，多租户 `BaseTenantEntity`。

## §0 范围

**做（MVP）**：TOTP 认证器（RFC 6238）为主第二因子 + 邮件 OTP 作回退/恢复通道；按租户 2FA 策略（关闭/可选/强制）；两步式登录 + 短命 pending 令牌承载"半登录"态；强制租户下登录时强制入会；2FA 失败接入既有登录锁定；安全事件审计；admin 重置用户 2FA；全栈前端（挑战屏/入会屏/个人设置/租户策略）+ 五语 i18n。

**不做（YAGNI）**：短信 OTP（无网关、SIM 攻击面）、WebAuthn/passkey（独立大子项目）、备份恢复码（已用邮件作恢复，不重复）、"记住此设备 N 天"（留后续增量）、per-角色 2FA 策略（先按租户）。

## §1 现状锚点（落码前复核，行号可能微移）

- **登录** `CP6.WebApi/Controllers/Sys/AuthController.cs`：`Login`（密码 BCrypt.Verify → `_login.EnsureNotLocked`/`RecordFailureAsync` 锁定 → 禁用 E-SEC-003 → `_tenant.CurrentTenantId=user.TenantId` → `BuildAccessToken(user,jti,mustChange)` → `_perm.PrewarmAsync` + 菜单聚合 → `_login.RecordSuccessAsync` + 审计 LoginSuccess → `_refresh.IssueAsync` + `_cookies.WriteAuthCookies` → 返 `{userName,nickName,roleId,menus,mustChangePassword}`，**不返 token**）。私有 `BuildAccessToken(Sys_User,string jti,bool mustChange)`。`ClientIp`/`ClientUa` 私有属性。
- **JWT** `CP6.Core/Utilities/JwtHelper.cs`：`GenerateToken(userId,userName,secret,issuer,audience,expireMinutes,Guid? tenantId=null,string? jti=null,bool mustChangePassword=false)`，HmacSha256，claims=NameIdentifier/Name/tenant_id/jti/must_change_password。
- **Cookie** `CP6.Core/Services/Sys/AuthCookieWriter.cs`：常量 `AccessCookie="cp6_at"`/`RefreshCookie="cp6_rt"`(Path=`/api/auth`)/`CsrfCookie="cp6_csrf"`/`RefreshPath="/api/auth"`；`WriteAuthCookies(resp,accessJwt,rawRefresh,csrf)`/`ClearAuthCookies(resp)`/`static NewCsrfToken()`。
- **锁定** `ILoginSecurityService`：`EnsureNotLocked(user)`(锁→InvalidOperationException("E-SEC-002"))/`RecordFailureAsync(user)`(计数++达阈值置 LockedUntil)/`RecordSuccessAsync(user,ip)`。
- **审计** `ISecurityAuditService.LogAsync(SecurityEventType,Guid? userId,string? userName,string? requestTenantCode,string? ip,string? ua,string? reason=null)` 写 `Sys_SecurityLog`(BaseTenantEntity)，失败不阻断。`SecurityEventType` 枚举现 1~8（LoginSuccess..PermissionDenied）。
- **缓存** `IDistributedCache`（Redis 有连接串则用，否则 AddDistributedMemoryCache）——jti 黑名单 `CacheTokenBlacklistService` 已用同款。
- **配置** `CP6.Core/Services/Sys/SecurityOptions.cs`：根 `SecurityOptions{Password,Lockout,Token,Cookie,Csrf}`，`builder.Services.Configure<SecurityOptions>(GetSection("Security"))`，服务注入 `IOptions<SecurityOptions>`。
- **错误码经 BizException**：Core 服务 `throw new InvalidOperationException("E-SEC-0xx")`，控制器 catch 转 `new BizException(code[,httpStatus])`（∈ `CP6.WebApi.Localization`），`BizExceptionMiddleware` 本地化。
- **当前用户** `(await _perm.GetAsync()).UserId`。**租户** `ITenantContext.CurrentTenantId`（可写）。
- **租户** `CP6.Entity/DomainModels/Sys/Sys_Tenant.cs`（`TenantCode`/`Enable` 等）。
- **i18n seed** 仿 `I18nSecScreenSeed`（`.Items` 接 `Program.cs` i18n `.Concat` 链），五语 ZhCN/ZhTW/En/Ja/Ko。
- **授权** `[RequirePermission(menuKey,action)]`（∈`CP6.Core.Auth`）→ `IPermissionService.HasActionAsync`，无 admin 旁路；权限点需 seed `Sys_MenuAction`+`Sys_RoleAction` 授 RoleId=1。
- **前端** `cp6.web/src`：`api/http.ts`(withCredentials+CSRF 头+401 自动 refresh)、登录态信号 `localStorage 'cp6_authed'`（非 token，httpOnly token JS 读不到）、`views/LoginView.vue`(`authApi.login`)、`router/index.ts`（守卫读 cp6_authed + standalone 静态路由）、`api/sys/auth.ts`。

## §2 数据模型

### §2.1 `Sys_User` 加 3 字段（`CP6.Entity/DomainModels/Sys/Sys_User.cs`）
```csharp
/// <summary>是否已启用 2FA（TOTP 绑定完成）</summary>
public bool TwoFactorEnabled { get; set; }
/// <summary>TOTP 密钥（base32）。绑定时生成；列长 [MaxLength(128)]。
///   注：MVP 明文存列；列加密（DataProtection）列为 hardening 选项，spec §9。</summary>
[MaxLength(128)] public string? TwoFactorSecret { get; set; }
/// <summary>2FA 绑定时刻</summary>
public DateTime? TwoFactorEnrolledAt { get; set; }
```

### §2.2 `Sys_Tenant` 加 1 字段（按租户策略）
```csharp
/// <summary>租户 2FA 策略：0=关闭 1=可选(用户自愿) 2=强制(全员)。默认 0。</summary>
public int TwoFactorMode { get; set; }
```
> 决策：放 `Sys_Tenant` 字段（不建独立策略表）——单一标量策略，YAGNI；后续要多策略再抽表。

### §2.3 邮件 OTP — `IDistributedCache`（不建表）
- key `sec:2fa:otp:{userId}`，value = **OTP 的 SHA-256 哈希**（不存明文）+ 尝试计数（JSON 或两 key），TTL = `Security:TwoFactor:EmailOtpMinutes`（默认 5）。
- 单次有效：验证成功即删 key。重发限流 key `sec:2fa:otp:cooldown:{userId}`（默认 60s TTL）。
- 决策：短命瞬态数据用缓存（仿 jti 黑名单），不污染库。

### §2.4 EF 迁移
`dotnet ef migrations add TwoFactor --project CP6.Core --startup-project CP6.WebApi`（`Sys_User` 3 列 + `Sys_Tenant` 1 列；无新表）。

## §3 组件 / 服务（`CP6.Core/Services/Sys/`）

### §3.1 `SecurityOptions` 加 `TwoFactorOptions`
```csharp
public class TwoFactorOptions {
    public string Issuer { get; set; } = "CP6";        // otpauth:// issuer（认证器显示名）
    public int CodeWindow { get; set; } = 1;            // TOTP 容时窗口（±N 个 30s 步长）
    public int EmailOtpMinutes { get; set; } = 5;       // 邮件 OTP 有效分钟
    public int EmailOtpLength { get; set; } = 6;        // 邮件 OTP 位数
    public int EmailResendCooldownSeconds { get; set; } = 60;
    public int PendingTokenMinutes { get; set; } = 5;   // pending 令牌寿命
}
```
（接入 `SecurityOptions` 根：`public TwoFactorOptions TwoFactor { get; set; } = new();`）

### §3.2 `ITotpService` / `TotpService`（引包 `Otp.NET`）
```csharp
public interface ITotpService {
    string GenerateSecret();                                   // base32, 20 字节随机
    string BuildOtpAuthUri(string secret, string userName);    // otpauth://totp/{Issuer}:{user}?secret=..&issuer=..
    bool Verify(string secret, string code);                   // RFC6238, 30s 步长, ±CodeWindow
}
```
- `Verify` 用 `Otp.NET.Totp(Base32Encoding.ToBytes(secret)).VerifyTotp(code, out _, new VerificationWindow(CodeWindow,CodeWindow))`。
- `BuildOtpAuthUri`：`otpauth://totp/{Uri.EscapeDataString(Issuer)}:{Uri.EscapeDataString(userName)}?secret={secret}&issuer={Uri.EscapeDataString(Issuer)}&period=30&digits=6`。前端用它渲染 QR（前端 qrcode 库，后端只给 URI）。

### §3.3 `IEmailSender` / `SmtpEmailSender` + `LogEmailSender`
```csharp
public interface IEmailSender { Task SendAsync(string to, string subject, string body); }
```
- `SmtpEmailSender`：读 `Email:Smtp`（Host/Port/User/Pass/From/EnableSsl），`System.Net.Mail.SmtpClient` 发送。
- `LogEmailSender`：无 SMTP 配置时的兜底——`ILogger` 输出 `[EMAIL→{to}] {subject}: {body}`（含 OTP），保 dev/gstack QA 无外部依赖可跑。
- **DI 选择**：`Program.cs` 工厂注册——`Email:Smtp:Host` 非空则 `SmtpEmailSender`，否则 `LogEmailSender`。

### §3.4 `ITwoFactorService` / `TwoFactorService`
```csharp
public interface ITwoFactorService {
    int ResolveTenantMode(Guid tenantId);                      // 读 Sys_Tenant.TwoFactorMode（IgnoreQueryFilters，登录期无上下文）
    bool IsChallengeRequired(Sys_User user, int tenantMode);   // user.TwoFactorEnabled || tenantMode==2
    bool MustEnroll(Sys_User user, int tenantMode);            // tenantMode==2 && !user.TwoFactorEnabled
    string BeginEnrollment(Sys_User user);                     // 生成密钥写 user.TwoFactorSecret(未启用)，返 otpauth URI
    Task<bool> ConfirmEnrollmentAsync(Sys_User user, string code);  // 验码 → 置 TwoFactorEnabled+EnrolledAt，审计 Enrolled
    bool VerifyTotp(Sys_User user, string code);
    Task SendEmailOtpAsync(Sys_User user);                     // 限流 → 生成 OTP 存缓存哈希 → IEmailSender 发，审计 EmailOtpSent
    Task<bool> VerifyEmailOtpAsync(Sys_User user, string code);// 比对缓存哈希，成功删 key
    Task ResetAsync(Sys_User user);                            // admin 重置：清 Enabled/Secret，审计 Reset
}
```
- Core 层抛 `InvalidOperationException("E-SEC-01x")`（限流/过期/无效），控制器转 BizException。

### §3.5 pending 令牌（半登录态）
- 复用 `JwtHelper`：新增静态 `GeneratePendingToken(userId,tenantId,purpose,secret,issuer,audience,minutes)`，claims = `NameIdentifier`/`tenant_id`/`token_use`（值 `2fa_verify` 或 `2fa_enroll`），短寿命（PendingTokenMinutes）。**无 jti/不进黑名单**（短命一次性）。
- 写入 httpOnly cookie **`cp6_2fa`**（新增常量，Path=`/api/auth`，httpOnly，Secure/SameSite 同三 Cookie）。`AuthCookieWriter` 加 `WritePendingCookie(resp,token)` / `ClearPendingCookie(resp)`，`ClearAuthCookies` 一并清 cp6_2fa。
- /auth/2fa/* 端点 `[AllowAnonymous]` + 手动读 cp6_2fa + 校验（签名/issuer/audience/未过期/token_use 匹配）→ 取 userId/tenantId。**pending 令牌不是 cp6_at**，普通 [Authorize] 接口不接受 → 半登录态进不了受保护资源。

## §4 流程

### §4.1 登录（AuthController.Login 改造）
密码校验/锁定/禁用/租户停用判定**不变**。`_tenant.CurrentTenantId=user.TenantId` 后、签发三 Cookie 前插入 2FA 分支：
```
mode = _2fa.ResolveTenantMode(user.TenantId)
if _2fa.IsChallengeRequired(user, mode):
    if _2fa.MustEnroll(user, mode):
        purpose = "2fa_enroll"; audit TwoFactorChallenged(reason="enroll")
    else:
        purpose = "2fa_verify"; audit TwoFactorChallenged
    写 cp6_2fa pending 令牌; 返回 { twoFactorRequired:true, mustEnroll:<bool> }   # 不发三 Cookie/不记 LoginSuccess
    return
# 否则照旧：RecordSuccess + 审计 LoginSuccess + IssueAsync + WriteAuthCookies + 返档案
```
> 锁定/审计已在密码阶段完成；2FA 挑战不重复记 LoginSuccess（成功在 2FA 通过后记）。

### §4.2 入会（强制租户 or 可选用户自助）
- `POST /auth/2fa/setup` `[AllowAnonymous]`（登录期读 cp6_2fa；或已登录态读 cp6_at——两种入口）：`BeginEnrollment` 返 `{ otpauthUri, secret }`（secret 供手动输入备选）。**不置 Enabled**。
- `POST /auth/2fa/enroll` body `{code}`：`ConfirmEnrollmentAsync` 验码 → 置 Enabled。**登录期入口**：成功后等同登录完成 → `RecordSuccessAsync`+审计 LoginSuccess+`IssueAsync`+`WriteAuthCookies`+清 cp6_2fa，返 `{userName,nickName,roleId,menus,mustChangePassword}`。**已登录态自助入口**：仅置 Enabled 返 `{code:0}`。

### §4.3 挑战验证（登录期）
- `POST /auth/2fa/verify` body `{code, method}`（`method:"totp"|"email"`，前端明确指定）`[AllowAnonymous]`（读 cp6_2fa，purpose=2fa_verify）：先 `EnsureNotLocked`；按 `method` 调 `VerifyTotp`（method=totp）或 `VerifyEmailOtpAsync`（method=email）。失败 → `RecordFailureAsync`+审计 TwoFactorFailed+`E-SEC-011`。成功 → 同 §4.2 登录完成路径（发三 Cookie）+审计 TwoFactorVerified+LoginSuccess。
- `POST /auth/2fa/email-otp` `[AllowAnonymous]`（读 cp6_2fa）：`SendEmailOtpAsync`（限流 → 发到 user.Email）。返 `{code:0}`（不泄露邮箱）。

### §4.4 admin 重置 + 租户策略
- **admin 重置**：`UserController` 加 `POST reset-2fa` body `{userId}`，`[RequirePermission("user","edit")]`（重置 2FA = 用户编辑权，与授权加固一致）→ `_2fa.ResetAsync` 清 Enabled/Secret + 审计 TwoFactorReset。
- **租户策略**：`GET/PUT /api/sys/two-factor-policy` body `{mode}`（新建 `TwoFactorPolicyController`，作用于**当前请求租户** `ITenantContext.CurrentTenantId`，租户管理员设本租户策略），`[RequirePermission("user","edit")]`（MVP：复用用户管理编辑权=租户管理员级；无独立"租户设置"菜单，列 §9 后续可拆专属权限点）→ 写 `Sys_Tenant.TwoFactorMode`。

### §4.5 半登录态守卫
- pending 令牌（cp6_2fa）非 cp6_at → 普通 [Authorize] 接口返 401（不接受）。无需新中间件。
- 前端：登录返 `twoFactorRequired` → **不置 cp6_authed**，跳 2FA 挑战/入会屏；2FA 完成（发三 Cookie）后才置 cp6_authed。

## §5 错误码（E-SEC-01x，五语 seed）

| 码 | 中文（i18n key=自然语言 or 码，仿既有 E-SEC-0xx 用码作 key） |
|---|---|
| E-SEC-011 | 验证码错误 |
| E-SEC-013 | 验证码已过期或会话失效，请重新登录 |
| E-SEC-014 | 请先完成双因素认证设置 |
| E-SEC-016 | 验证码发送过于频繁，请稍后再试 |
| E-SEC-017 | 双因素认证设置失败，请重试 |

> 复用既有 E-SEC-002（账户已锁定）于 2FA 锁定。`SecurityEventType` 加 9~14：`TwoFactorChallenged=9/TwoFactorVerified=10/TwoFactorFailed=11/TwoFactorEnrolled=12/TwoFactorReset=13/TwoFactorEmailOtpSent=14`，i18n `sec.event.9~14` 五语标签。

## §9 hardening 选项（spec 记录，MVP 不做）
- `TwoFactorSecret` 列加密（ASP.NET DataProtection / 列级加密）。
- "记住此设备"信任 cookie（N 天免 2FA）。
- per-角色策略、WebAuthn/passkey、短信、备份恢复码。

## §10 自审
范围聚焦单一子项目（2FA），与 #1 认证加固解耦叠加；数据模型最小（3+1 字段，无新表，OTP 走缓存）；流程两步式 pending 令牌天然隔离半登录；防爆破复用既有锁定；邮件 dev 兜底保 QA 可跑；授权/审计/i18n/多租户全对齐既有约定。无遗漏跨子系统依赖。
