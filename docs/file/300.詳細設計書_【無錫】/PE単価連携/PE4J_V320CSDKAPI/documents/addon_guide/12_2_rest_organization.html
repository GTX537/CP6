14. REST 組織情報API¶

14.1. 社員情報取得(GET)¶

引数で指定した社員の情報を1件取得します。

14.1.1. HTTPメソッド¶

GET

14.1.2. URI¶

http(s)://(POWER EGGサーバ) /pe4j/api/rest/v1/organization/employee.json

14.1.3. リクエストパラメータ¶

パラメータ名

指定する値

必須

説明

baseDate

日付

必須

組織の発令日を決定するための基準日です。この日付時点の組織図が対象となります。

corpCode

文字列

必須

基準日時点で社員が所属する会社の外部会社コードを指定します。

empCode1

文字列

省略可

基準日時点でのcorpCodeの会社での外部社員コード１を指定します。

empCode2

文字列

省略可

基準日時点でのcorpCodeの会社での外部社員コード２を指定します。

注釈

empCode1、empCode2のどちらか、または両方を指定する必要があります

14.1.4. レスポンス(JSON)¶

パラメータ名

データ型

必須

説明

userid

文字列

必須

ログインユーザID

empName

文字列

必須

社員名

nameFurigana

文字列

社員名ふりがな

mailAddress

文字列

メールアドレス

文字列

携帯電話番号

携帯メールアドレス（非公開に設定されてる場合はnull）

日付

退職日

expireDate

日付

ID有効期限

belongToDepts

JSON

必須

所属情報の配列（パラメタで指定された会社以外の所属は含まない）

所属情報（belongToDepts）のJSON型

パラメータ名

データ型

必須

説明

announceDate

日付

必須

基準日時点での発令日

deptCode1

文字列

外部部門コード１

deptCode2

文字列

外部部門コード２

deptName

文字列

必須

部門名

empCode1

文字列

外部社員コード１

empCode2

文字列

外部社員コード２

titleCode

文字列

外部役職コード

titleName

deliberationOrder

数値

承認順位

isMainBelong

14.1.5. リクエストの例¶

  • "friend00"という外部会社コードの会社で外部社員コード１が"114403"の社員の情報を取得する

  • HTTPのクエリ文字列の例

    baseDate=2018-06-16&corpCode=friend00&empCode1=114403

  • リクエストヘッダを含んだ例

    GET /pe4j/api/rest/v1/organization/employee.json?(HTTPのクエリ文字列) HTTP/1.1
Host: pe280demo.poweregg.net
X-API-Key: 7706d1ce-01a0-463b-a162-d389cec21eb1

    ※Content-Typeヘッダは不要です。

14.2. 部門情報取得(GET)¶

引数で指定した部門の情報を1件取得します。

14.2.1. HTTPメソッド¶

GET

14.2.2. URI¶

http(s)://(POWER EGGサーバ) /pe4j/api/rest/v1/organization/department.json

14.2.3. リクエストパラメータ¶

パラメータ名

指定する値

必須

説明

baseDate

日付

必須

組織の発令日を決定するための基準日です。この日付時点の組織図が対象となります。

corpCode

文字列

必須

基準日時点での部門が存在する会社の外部会社コードを指定します。

deptCode1

文字列

省略可

基準日時点でのcorpCodeの会社での外部部門コード１

deptCode2

文字列

省略可

基準日時点でのcorpCodeの会社での外部部門コード２

lowerDept

真偽値

true：配下部門を取得する false：自部門のみ取得する（省略値）

注釈

deptCode1、deptCode2のどちらか、または両方を指定する必要があります

14.2.4. レスポンス(JSON)¶

パラメータ名

データ型

必須

説明

announceDate

日付

必須

基準日時点での発令日

dept

JSON

必須

自部門の部門情報

lowerDepts

JSON

部門情報（dept、lowerDepts）のJSON型

データ型

必須

数値

deptCode1

外部部門コード１

deptCode2

文字列

外部部門コード２

deptName

文字列

必須

部門名称

deptShortName

文字列

必須

部門略称

deptKana

文字列

部門フリガナ

address

文字列

住所

tel

文字列

電話番号

fax

FAX番号

location

文字列

地区名

deptLevel

数値

必須

組織階層レベル

deptClass

文字列

必須

“1”:通常部門 “2”:申請部門

decide

真偽値

必須

true:自部門での決裁可 false:自部門での決裁不可（上位委譲）

  • "friend00"という外部会社コードの会社で外部部門コード１が"300"の部門の情報を配下部門を含んで取得する

X-API-Key: 7706d1ce-01a0-463b-a162-d389cec21eb1

14.7. 組織図連携¶

発令予定の組織図（部門階層、社員所属、審議者）情報を登録します。
組織図情報については、以下の流れで順に処理を呼び出す必要があります。

Step1：予定組織図の作成
→会社、発令日をパラメタとして、現行組織図をコピーして予定組織図を仮データを作成します。

Step2：部門情報登録更新
→部門情報をを予定組織図の仮データに更新します。
更新を行う場合は更新対象の部門のみではなく、すべての部門情報をリクエストボディにセットする必要があります

Step3：社員所属情報登録更新
→社員の所属情報を予定組織図の仮データに更新します。
更新を行う場合は異動対象社員のすべての所属情報（兼務を含む）をリクエストボディにセットする必要があります

Step4：審議者情報登録更新
→部門の審議者情報を予定組織図の仮データに更新します。
更新を行う場合は更新対象部門のすべての審議者情報をリクエストボディにセットする必要があります

Step9：予定組織図の作成完了
→予定組織図の仮データを予定組織図情報として更新します。

Step2～Step4にてエラーが発生した場合には「StepZ：予定組織図の破棄」を呼び出し、予定組織図の仮データを破棄してください。
