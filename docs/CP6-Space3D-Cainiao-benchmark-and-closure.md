# CP6 3D Space：菜鸟案例研究、代码现状与闭环实施路线

## 一、结论先行

CP6 的 3D Space **不是从零开始**。代码里已经形成“空间层级—地图编辑—库位编码—发布 WMS—Three.js 展示—库存与拣货任务叠加”的可用骨架。但以菜鸟数字空间的产品逻辑衡量，CP6 当前更接近“空间主数据 + 3D 运营查看器”，还不是完整的仓库数字孪生闭环。

完整产品应有五层：

1. **低成本建模工厂**：CAD 语义解析、Excel 业务映射、地图编辑器校正、模型资产库、版本发布。
2. **空间事实主数据**：园区、建筑、楼层、库区、巷道、货架、库位、设备、设施及其属性关系。
3. **人货场运行态**：把 WMS、PDA、WCS、IoT 的库存、任务、人员、设备和告警叠加到空间模型。
4. **运营决策**：指标诊断、路径优化、库位优化、上架推荐、人员调度和方案仿真。
5. **执行反馈**：建议经确认后生成 WMS/WCS/PDA 任务，执行事件回流，再验证优化效果。

CP6 当前第 2 层较完整，第 3 层已实现“货”的一部分，第 4 层有路径 what-if 骨架；第 1、5 层和“人、设备实时态”是主要断点。

## 二、菜鸟三段视频实际展示了什么

### 1. 库内绘制演示（约 176 秒）

| 时间段 | 看到的产品能力 | 对 CP6 的含义 |
|---|---|---|
| 0–30 秒 | 从组件库绘制楼板、墙、柱、功能区、货架、托盘等 | 编辑器必须覆盖仓库设施，不应只支持库区、货架和标记 |
| 30–65 秒 | 调整货架尺寸、层数、每层高度和每层格口数量 | CP6 当前统一 `CellH` 和统一列数不足，需要逐层规格 |
| 65–85 秒 | 按巷道、货架方向和增量批量生成库位编码 | CP6 已有较好的编码规则、预检和批量生成功能 |
| 85–115 秒 | 显示编码、空间属性和业务属性；按库位码定位 | CP6 已支持定位，但通用属性模式和设施属性仍不足 |
| 115–140 秒 | 自动统计面积、货架、库位、托盘、设施、巷道、柱等，并同步 WMS | CP6 有发布 WMS，但缺空间统计看板和完整设施台账 |
| 140–160 秒 | 库位利用率、ABC 周转、库位和货品业务属性 | CP6 有利用率和库存定位，缺货主、SKU 属性、ABC 空间叠加 |
| 160–176 秒 | 人员状态、任务轨迹、到达库位、停留时间和距离 | CP6 尚无人员位置事件、PDA 轨迹和人员作业模型 |

### 2. CAD 解析建模（约 68 秒）

视频显示的不是“上传 CAD 后直接得到漂亮 3D”这么简单，而是一条有人工校正的建模流水线：

- 空间与版本管理；
- 上传 CAD，选择通用解析或按当前图层解析；
- 把 CAD 图层映射为楼板、功能区、货架等业务语义；
- 再导入 Excel 业务数据并查看解析日志；
- 选择版本、可视化预览、初始化地图并发布。

因此，低成本建模的核心不是追求一次性识别任意 CAD，而是“**输入规范 + 自动解析 + 置信度 + 异常清单 + 人工校正 + 版本发布**”。

### 3. 地图编辑器建模（约 160 秒）

视频展示了另一条不依赖 CAD 的路径：

- 拖入货架并设置宽、长、层数、层高、每层格口；
- 多选、对齐、分布、阵列复制；
- 批量编码后直接显示库位码；
- 从组件库拖入托盘等设施；
- 绘制和调整墙体，组成完整二维仓库；
- 一键预览 3D，并查看空间属性和业务属性。

这意味着 CAD 建模和编辑器建模不是两个独立产品，而应共用同一个空间元素模型、属性体系、校验规则和版本发布流程。

## 三、公开交互式仓库演示的业务结构

公开演示进一步证明 3D 只是承载界面，主业务包括：

- **仓库总览**：面积、体积、人员、货量、日入出库量、订单量、拣选时长、及时率、准确率、货损率。
- **指标诊断**：识别人员停留、移动过慢、ABC 分区不合理和路径绕行，并量化预计改善。
- **拣选优化**：导入拣货单、分析任务、查询任务/SKU/库位并进行路径优化。
- **库位维度**：利用率分级、ABC 周转分布、库位和货品明细。
- **人员状态**：工作/空闲筛选、轨迹查询、速度图例、人员定位。
- **SKU 查询**：属性分类、货主、ABC 等条件与全局定位。

所以“通用仓库 3D 可视化”的正确产品定义是：**同一空间坐标系上的业务查询、状态叠加、原因诊断和行动入口**。

## 四、CP6 当前实现状态（按代码核验）

| 能力 | 当前状态 | 代码事实 | 判断 |
|---|---|---|---|
| 空间层级 | 已实现 | `Space_Site/Floor/Zone/Rack/Location` | 仓库内部主骨架可用；园区道路、闸口、停车和室外设施不足 |
| 地图编辑器 | 部分实现 | `SceneStage`、`TemplatePanel`、`genZoneArray`、`genRack` | 支持库区、巷道、货架、阵列、吸附、碰撞、选择和旋转；设施库不足 |
| 货架逐层规格 | 未实现 | `Space_Rack` 使用统一 `CellH`、`Cols` | 无法表达每层不同高度和格口数量 |
| CAD/Excel 建模 | 未实现 | 场景导入导出为 CP6 JSON | 没有 DXF/DWG 解析、图层语义映射、Excel 空间业务绑定和解析日志 |
| 图纸底图 | 数据字段存在，功能未闭环 | `Space_Floor.UnderlayImage` | 编辑舞台有底图层概念，但没有看到实际底图渲染和标定操作 |
| 库位编码与发布 | 已实现 | CodeRule、发布前检查、`LocationPublishController` | 是 CP6 当前最完整的闭环之一，可把空间库位锚定到 WMS |
| 3D 查看 | 已实现 | `FloorViewer.vue` + Three.js | 支持楼层、跨层和全站的可视化骨架 |
| 库存与物料定位 | 已实现主体 | `WmsStockQuery` | 有数量、占用、分配、容量、物料/批次/容器定位；货主、ABC、SKU 属性仍需补充 |
| 拣货路径 | 已实现分析骨架 | `WmsPickTaskQuery`、`PickPathPlanner` | 读取真实任务，支持实际路线与 NN+2opt what-if、跨层和动画；尚未把优化结果回写执行 |
| 工作量热图 | 已实现 | `WmsWorkloadQuery` | 可按库位和时段叠加业务热度 |
| 人员状态与轨迹 | 未实现 | 无人员位置/轨迹实体与查询服务 | 缺 PDA 扫码位置事件、闲忙状态和任务轨迹 |
| 设备实时态 | 仅有框架 | `DeviceLayer` 已有；`WmsDeviceQuery` 返回空数据 | 不能视为真实 WCS/AGV/IoT 接入 |
| 指标诊断与运营推荐 | 未实现 | 无 Space 诊断、推荐和执行反馈模型 | 有图和 what-if，但没有形成可治理的业务建议 |
| 规划仿真 | 未实现 | 无方案、仿真运行和 CAD 回写模型 | 无法比较布局版本或用历史实单验证产能 |

## 五、ERP、WMS 与 3D Space 的职责边界

- **ERP**：需求、价值和业务单据事实——客户订单、产品物料、采购、生产、成本和财务。
- **WMS/MES**：库存和作业执行事实——入库、上架、移库、拣货、复核、出库和生产任务。
- **3D Space**：物理拓扑、空间上下文和空间决策事实——对象在哪里、能否容纳、路径如何、为什么拥堵、怎样调整。
- **PDA/WCS/IoT**：实时状态与事件事实——人和设备此刻在哪里、正在做什么、是否异常。

3D Space 不应复制 WMS 单据，也不应让 ERP 保存实时坐标。它应通过稳定的业务键，把空间元素映射到仓库、库位、SKU、人员、设备和任务。

## 六、建议新增的核心数据模型

### 建模与版本

- `Space_ModelSource`：CAD/Excel/手工来源、文件哈希、解析器版本、坐标变换。
- `Space_ModelVersion`：空间版本、分支、状态、发布时间和回滚关系。
- `Space_ParseJob`、`Space_ParseIssue`：解析进度、置信度、错误和人工校正结果。
- `Space_LevelProfile`：货架每层高度、格口数和深度配置。

### 通用空间元素与资产

- `Space_Element`：元素类型、父级、几何、3D 模型引用、位置、旋转和业务编码。
- `Space_ElementType`、`Space_ModelAsset`：墙、柱、门、月台、输送线、托盘、叉车、闸口等组件库。
- `Space_AttributeSchema`、`Space_ElementAttribute`：不同元素的自定义空间/业务属性。
- `Space_DeviceBinding`：空间设备与 WCS/IoT 设备身份的绑定。

### 运行态、决策与反馈

- `Space_PersonPositionEvent`、`Space_PersonTaskTrace`：人员位置、速度、停留和任务轨迹。
- `Space_DeviceStateEvent`、`Space_Event`、`Space_Alarm`：设备状态、业务事件和告警。
- `Space_MetricSnapshot`、`Space_Diagnosis`：指标快照、异常原因和证据。
- `Space_Recommendation`、`Space_ExecutionFeedback`：建议、审批、执行目标、结果和效果指标。
- `Space_LayoutScenario`、`Space_SimulationRun`：布局方案、历史实单仿真和比较结果。

## 七、关键接口与事件

### 建模接口

- CAD/Excel 上传、解析、进度、预览、图层映射、问题校正和版本发布。
- 组件/模型资产查询、自定义属性模式、逐层货架配置。
- 底图显示、两点标定、坐标原点和旋转校准。

### 运行与决策接口

- 人员位置/状态/轨迹、设备状态/告警、SKU/货主/ABC、空间 KPI 快照。
- 诊断、模拟、推荐、审批应用、撤销和效果对比。

### 建议事件主题

- `space.model.published`
- `wms.stock.changed`
- `wms.pick-task.changed`
- `pda.position.scanned`
- `wcs.device.state.changed`
- `space.recommendation.applied`
- `space.execution.feedback.received`
- `space.alarm.raised`

所有实时事件都应可重放、可去重并带租户、仓库、业务时间和来源标识，不能只依赖前端轮询。

## 八、分阶段实施路线

### P0：先把现状说准确（1–2 个迭代）

- 在产品界面区分“真实数据、模拟数据、暂未接入”，设备层不得再造成已实时接入的错觉。
- 为 Space 建立统一能力状态、数据来源和更新时间提示。
- 把底图显示、比例/原点/旋转标定补成可用功能。

**验收**：用户可判断每个图层的数据来源；上传仓库图后能正确校准并作为绘制底图。

### P1：低成本建模工厂（3–6 个迭代）

- 第一阶段先支持规范化 DXF 图层，不直接承诺任意 DWG 的智能识别。
- 建立 CAD 图层映射模板、Excel 业务绑定、置信度与异常校正队列。
- 统一 CAD 和地图编辑器的 `Space_Element` 模型。
- 增加墙、柱、门、月台、托盘和设备组件库，支持逐层货架规格。
- 增加版本、预览、发布、回滚和差异比较。

**验收**：一个标准仓库可通过“CAD+Excel”或“地图编辑器”两条路径生成同构场景；人工只处理异常项；发布后库位与 WMS 一致。

### P2：人、货、场运行态（3–6 个迭代）

- 接入 PDA 人员位置/任务轨迹；补充闲忙、速度、停留和路径查询。
- 增加货主、SKU 属性、ABC 与库位利用率的统一筛选和空间叠加。
- 接入 WCS/AGV/IoT 设备状态、事件和告警。
- 建立仓库总览 KPI 和按日/班次/区域的指标快照。

**验收**：从 3D 场景可追到具体库存、任务、人员和设备，并能回到来源单据或事件。

### P3：运营决策与执行反馈（4–8 个迭代）

- 把现有路径 what-if 升级为可保存、可审批、可应用的建议。
- 实现库位优化、上架推荐、人员调度和拥堵诊断的第一批规则。
- 建议转换为 WMS/WCS/PDA 执行任务，接收完成/失败/撤销事件。
- 用执行前后指标自动评价建议效果。

**验收**：任何“优化了多少”的结论都能追溯到输入、算法版本、审批人、执行任务和实际效果。

### P4：规划仿真

- 布局方案分支和比较；用历史实单重放验证距离、吞吐和人员需求。
- 将已批准方案发布到生产空间，必要时导出 CAD/标准交换格式。

## 九、最重要的产品原则

1. **先统一空间事实，再追求视觉效果。** CAD 与地图编辑器必须产出同一种元素和属性模型。
2. **不把轮询出来的静态数据称为实时孪生。** 实时态要有事件时间、来源、延迟和质量标识。
3. **不把 what-if 动画称为优化闭环。** 只有建议被执行并收到效果反馈，才算闭环。
4. **CAD 自动化必须允许人工校正。** 低成本来自批量解析和异常处理，而不是假设所有图纸都标准。
5. **3D 是业务入口，不是业务真相本身。** ERP/WMS/WCS/PDA 各自保留权威事实，Space 负责空间映射和空间决策。
