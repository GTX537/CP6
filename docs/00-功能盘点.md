# CP6 功能盘点 + 迈向完整 ERP / 可售 SaaS 的完善路线

> **生成于 2026-06-13。** 本文做三件事：①盘点**现有功能**（已实现并运行）②梳理**已规划新增功能**（需求/文档/实施计划已就绪、待编码）③深挖：要成为**完整 ERP / 可售 SaaS**，**还缺什么、怎么补**。
>
> 定位前提（见 `docs/00-product-blueprint.md` 与项目记忆）：**深耕纸箱行业、做完整可售产品**。故下面的"缺口"按"纸箱厂可售 ERP/SaaS"口径评估，通用 ERP 里与本行业弱相关的模块（如全套 HR 薪资、全套 CRM 营销）标为低优先或不做。
>
> 现有功能基于真实代码盘点：`CP6.WebApi/Controllers`（66 个）+ `cp6.web/src/views`（110+ 页面）+ 6 个后台服务。

## 一、现有功能（已实现并运行）

CP6 当前是一套强大的 **「进销存 + MES」**：販売→生産→在庫正向链 + ERP→MES→WMS 闭环全通。

### 1. 販売管理 MSBB（ERP·15 控制器）
取引先 `BusinessPartner`（9 属性多 Tab：得意先/発注先/買掛先…）· 製品 `Product`（5 步向导）· 見積 `Quotation` + 見積計算 `EstimateCalc`(3 步) · 受注 `Order`（3 步向导 + 取消级联 + 价格修正 + 订单追溯）· 未出荷 `Backorder`/`UnshippedOrder` · 信用单 `CreditNote` · 為替 `FxRate`（多币种）· 印版木型 `PlateMold` · シート単価 `SheetUnitPrice` · FSC 检查表 · OTD（准时交付）报表 · 主数据

### 2. 生産管理 MES（9 控制器）
製造指図 `WorkOrder`(3 步向导) · 生産実績 `ProductionResult` · 品質検査 `QualityInspection` · 不良記録 `DefectRecord` · 設備 `Machine` + 停机监控 · OEE 分析（后台自动算）· 計画ボード `PlanningBoard` · 達成率 `PlanAchievement` · MES 看板 / Control Tower

### 3. 在庫物流 WMS（~35 控制器，体量最厚）
倉庫/库位 · 在庫 `Stock` · 入庫 `Inbound`(予定/実績) · 出庫 `Outbound` + 多倉庫引当 `OutboundRouting` · 拣货/梱包出荷 · 棚卸 `StockTake` · 配送 `Carrier` · 补充 `Replenish` · 仓位优化 `Slotting` · 跨库 `CrossDock` · キット `Kitting` · 返品 `RMA` · 検品 `QcInspection` · **纸器业特化**：原紙卷 `PaperRoll`、インキ `InkLot`、パレット、残材 `Remnant`、印版在庫、サンプル、VMI · 期限/ロット追跡/滞留/欠品 `MaterialShortage` · WCS/IoT 监控/移动作业 · 报表中心

### 4. 系统底座（现有薄层·pms·8 控制器）
登录鉴权 `Auth`(JWT) · 用户/角色/菜单（**单角色 + 页面级菜单授权，仅前端隐藏，无后端强校验**）· 字典 `Dict` · 多语言 `Lang`(5 语) · 操作日志 `OperLog`(Kafka 异步 + 定时清理) · 权限页(只读展示) · Dashboard

### 5. 集成与闭环（Phase 6-10）
ERP→MES→WMS 闭环（Bridge Hook Phase1-4）· IntegrationEvent 持久化 + 重试 Worker + 死信告警 · 集成健康看板 · 后台服务：Kafka 日志 / 设备监控 / 通知 / OEE 计算 / 日志清理

## 三、迈向「完整 ERP」还缺什么（已规划之外的 gap）

把上面 14 份计划都实现后，对照"完整制造业 ERP"，**仍有这些缺口**。按对纸箱厂的价值排序：

### A. 高价值 · 强烈建议补（直接影响"能不能管全闭环"）

| # | 缺口 | 为什么需要 | 现有可借力 | 工作量 |
|---|---|---|---|---|
| **A1** | **MRP / 物料需求计划** | 现在采购 PR 靠"缺料反流/工单缺料"被动触发，没有**前瞻性净需求计算**（按受注/预测 × BOM 展开 − 现有库存 − 在途 → 建议采购/生产）。这是制造业 ERP 的"大脑"，纸箱厂排产备料的核心 | MES `WorkOrder`/BOM、WMS 库存/在途、采购 PR、`MaterialShortage` | 大（新模块） |
| **A2** | **多级 BOM + 工艺路线 Routing** | 製品现有"工程信息"，但需确认是否支持**多级 BOM**（纸箱：原纸→瓦楞板→印刷→模切→成品）和标准工艺路线（工序×工时×机台×标准费率）。MRP 和成本会计（标准工时/费率）都依赖它 | `Product` 工程信息、`CostCenter`↔`Machine`、財務标准成本 | 中（可能是现有扩展） |
| **A3** | **固定资产管理（资产卡片 + 折旧计提）** | 财务科目表已留 `1601 固定资产/1602 累计折旧`，但只有科目没有**资产台账 + 自动折旧凭证**。机器设备多的纸箱厂必备 | 財務 GL/自动凭证引擎、MES `Machine` | 中 |
| **A4** | **资金/银行对账** | 财务有 `BankAccount` + 收付款，但缺**银行流水导入 + 自动对账 + 资金计划**。月结对账的最后一块 | 財務 AP/AR/BankAccount | 中 |
| **A5** | **预算管理 / 管理会计** | 有成本中心维度（`CostCenterId`），但缺**预算编制 + 预算 vs 实际控制 + 分析**。老板看经营的核心 | 財務 GL + CostCenter + 报表 | 中 |

### B. 中价值 · 看客户需求补

| # | 缺口 | 说明 |
|---|---|---|
| **B1** | **现金流量表 + 合并报表** | 财务 08 章把现金流量表延后到 v2；多法人合并报表明确暂不做（单企业纸箱厂）。多客户后按需补 |
| **B2** | **质量管理 QMS 进阶** | 已有 QC 检品 + 不良记录，缺 **SPC 统计过程控制 / 不合格品处理(CAPA) / 来料-过程-出货全链质量追溯闭环 / 质量证书** |
| **B3** | **设备维护 EAM/TPM** | 已有设备 + 停机 + OEE，缺**保养计划 / 点检 / 备件 / 维修工单**（从"监控设备"到"管理设备生命周期"） |
| **B4** | **销售进阶（轻 CRM + 合同）** | MSBB 以受注为中心，缺**销售机会/报价跟进/合同管理/客户信用台账**（信用额度在采购计划里提过，可延伸） |
| **B5** | **需求预测** | MRP（A1）的上游。纸箱多为订单驱动，预测优先级中等，但做 VMI/备库客户需要 |
| **B6** | **自定义报表 / BI 分析** | 各模块有 Dashboard + ReportCenter，但缺**跨模块自定义报表/钻取/经营分析看板**（PUB 代码生成 + 导入导出是基础，可在其上做报表设计器） |

### C. 低价值 / 本行业可不做

- **全套 HR / 薪资 / 考勤**（PUB 组织模型 `Sys_Dept` 够审批/数据权限用；全 HR 与纸箱主业弱相关，除非客户要）
- **全套营销 CRM / 电商**（深耕 B2B 纸箱，营销自动化非核心）
- **生产高级排程 APS**（PlanningBoard 够用；APS 是 MRP 之后的进阶，量大客户再说）

## 四、迈向「可售 SaaS」还缺什么（产品化 gap）

"完整 ERP"是**功能**完整；"可售 SaaS"还要**产品化 + 运营化**。多租户（已规划）是地基，但只是起点：

### A. 商业化必备（卖出去 + 收到钱）

| # | 缺口 | 说明 | 现有可借力 |
|---|---|---|---|
| **S1** | **租户自助开通 + 订阅计费** | OA 章10 提了"模板市场/按租户计费"概念，但缺**真正的计费引擎**：套餐/用量计量(用户数/单据数/存储)/账单/在线支付/试用转付费 | 多租户 `TenantId` 计量基础 |
| **S2** | **租户初始化/引导(Onboarding)** | 新租户开通 → 一键导入默认科目表/模板/字典/演示数据 → 配置向导。开通体验决定转化 | PUB 导入导出/codegen、财务多国别模板、OA 模板复制 |
| **S3** | **租户级配置/品牌定制** | 自定义字段、自定义表单/流程（OA 设计器有）、Logo/主题白标、自定义编码规则。让一套代码适配不同客户 | PUB codegen + OA 设计器 + Space 编码引擎 |

### B. 安全合规必备（企业客户的门槛）

| # | 缺口 | 说明 |
|---|---|---|
| **S4** | **SSO / OAuth / 2FA** | 现 JWT 登录，企业客户要单点登录(SAML/OIDC)、双因素认证、密码策略 |
| **S5** | **数据隔离与合规审计** | 多租户行级隔离(已规划) + 财务审计轨迹(已规划) 是基础；还需**租户数据导出/删除(GDPR)、跨租户访问审计、数据加密(传输+静态)** |
| **S6** | **细粒度审计/操作回放** | OperLog 有；SaaS 要能向客户证明"谁在何时改了什么"，财务 10 章的不可篡改+对账是范本，需推广到全模块 |

### C. 运营/可靠性必备（多客户跑起来不出事）

| # | 缺口 | 说明 |
|---|---|---|
| **S7** | **可观测性/监控告警** | 有 IntegrationEvent 健康 + 死信告警；SaaS 要**全栈监控(APM/日志/指标/链路)、租户级 SLA、容量预警**。已有 `/metrics`(Prometheus)、SignalR 是起点 |
| **S8** | **多租户性能/伸缩** | 共享表行级隔离下，热点租户隔离、查询性能(全表加 TenantId 索引)、分库分表预案 |
| **S9** | **备份/容灾/数据迁移** | 租户级备份恢复、版本升级不停机、租户数据搬迁 |
| **S10** | **开放能力：API / Webhook / EDI** | SaaS 要让客户系统对接：**开放 API + API Key/限流、Webhook 事件订阅、与客户/供应商的 EDI**（纸箱厂常与大客户做 EDI 下单/对账） |

### D. 体验/支撑

- **客户门户 / 供应商门户**（客户自助下单查单、供应商自助报价收 PO——RFQ 已有内部侧，外部门户可延伸）
- **移动端**（WMS 已有移动作业；审批/看板移动化）
- **帮助中心 / 应用内引导 / 在线文档**（产品化的软实力）

## 五、完善路线建议（在 14 份计划之后）

**原则**：先把已规划的 14 份计划落地（核心 ERP 闭环 + SaaS 底座），再按下面分期补完整性与产品化。**不要在核心闭环未通时提前做 SaaS 计费/门户**。

### 第一波 · 完成核心 ERP 闭环（执行已有 14 计划）
依赖主链：**PUB B0 组织 → PUB B1 权限 → OA 审批 → 财务 + 采购**（并行）→ **多租户（OA 章10 系统级收口）**。Space 3D 与 MSBB 逆向可并行。
> 完成标志：销售→生产→库存→采购→财务全闭环，后端三权强校验，单租户可演示完整 ERP。

### 第二波 · 补"完整 ERP"高价值缺口（第三章 A 类）
顺序建议：**A2 多级BOM+工艺路线**（很多后续依赖它）→ **A1 MRP**（依赖 BOM）→ **A3 固定资产** + **A4 银行对账**（财务延伸）→ **A5 预算/管理会计**。
> 完成标志：从"记录业务"升级到"计划+控制业务"（MRP 排产备料、预算管控、资产折旧）。

### 第三波 · 产品化为"可售 SaaS"（第四章）
顺序建议：**S4/S5/S6 安全合规**（企业客户门槛，先过）→ **S2 Onboarding + S3 租户定制**（开通体验）→ **S1 订阅计费**（变现）→ **S7-S9 运营可靠性** → **S10 开放 API/EDI + 门户**。
> 完成标志：客户能自助开通、安全合规、按用量付费、稳定多租户运营。

### 第四波 · 行业纵深 / 差异化（按客户拉动）
B 类（QMS 进阶 / EAM / 轻 CRM 合同 / BI）+ Space 3D 高级可视化 + 需求预测——这些是"卖点"而非"门槛"，按客户需求拉动做。

---

## 六、一句话总结

> CP6 现在是**完整的"进销存 + MES"**；14 份计划落地后成为**完整核心 ERP + SaaS 底座**；要成为**完整 ERP**，还差 **MRP / BOM 路线 / 固定资产 / 银行对账 / 预算**（第三章 A）；要成为**可售 SaaS**，还差 **计费 / 安全合规 / Onboarding / 运营可观测 / 开放 API**（第四章）。建议按"核心闭环 → ERP 完整性 → SaaS 产品化 → 行业纵深"四波推进。
