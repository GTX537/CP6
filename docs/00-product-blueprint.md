> **定位**：把 CP6 从"内部 ERP/MES/WMS 系统"升级为**可商用、可多客户复制**的产品。本走纲是全局蓝图：模块全景、状态盘点、跨模块依赖、推荐建设顺序。各模块自己的总纲/丛书见各 `docs/<module>/`。

> *2026-06-12 更新：C 类未敲定项（Space 3D / PUB / OA）已全部 brainstorming 敲定。*


## 三、关键跨模块依赖（决定建设顺序）

```
① 组织模型 Sys_Dept（PUB 章00）
   ├─ PUB 数据权限 DataScope（Path 子树过滤）
   └─ OA 审批路由（LeaderId/ManagerId → 直属上级/部门长）
   = 两者共同前置，归 PUB 先落，做一次两处用            ← 最高优先

② PUB 权限引擎（四粒度强校验）
   = 所有业务模块的后端强校验底座

③ OA 审批引擎（IApprovalService 实现）
   = 采购/财务审批桩的接通点（同步回调）

④ Space 3D ←(库位编码 join key)→ WMS
   = 混合分权，Space 管几何/WMS 管库存；低耦合可并行

⑤ Bridge Hook = ERP/MES/WMS 联动（已 Phase1-4）
```

## 四、推荐建设顺序（全局里程碑）

| 阶段 | 内容 | 依据 |
|---|---|---|
| **B0 底座前置** | PUB 章00 组织模型（Sys_Dept 树 + LeaderId + Sys_User 三字段） | PUB+OA 共同前置，一切审批路由与数据权限的根 |
| **B1 权限底座** | PUB 权限引擎 M0-M3（多角色→功能→数据→字段）+ 公共模组 | 业务模块强校验底座 |
| **B2 审批中台** | OA 阶段1-2（可用OA → 接采购/财务审批桩） | 兑现 IApprovalService，采购/财务审批落地 |
| **B3 业务编码** | 财务、采购 编码（丛书已齐，接 OA 审批 + PUB 权限） | 需求/文档就绪，可并行 |
| **B4 空间底座** | Space 3D P1（建模+编码引擎）→ P2 叠加 → P3 高级可视化 | 独立模块，可与 B3 并行 |
| **B5 销售逆向** | 販売 MSBB 详细规格逆向（共通→主数据→见积→受注→帳票） | 既存系统文档化，按需推进 |

> **并行性**：B3（财务/采购编码，用 IApprovalService 桩可先行）、B4（Space 3D）、B5（MSBB 逆向）相互独立，可并行；B0→B1→B2 是强依赖主链。
