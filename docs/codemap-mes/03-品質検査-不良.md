## 0. 架构定位

两个相关功能，核心看点是**接缝④**：品質検査判 NG 时双联动——①自动建 DefectRecord 不良记录；②Phase7 把关联库存标 `FAILED` → WMS 出库引当排除 → 实现"NG 阻止出货"。采番 `QC`(检查)/`DF`(不良)。

## 七、⭐ 接缝④专讲：QC NG → 建 DefectRecord ＋ 标库存 FAILED → Phase7 阻止出货

全链在 **`QualityInspectionService.CreateAsync`**（仅 Create 路径），分两段：

**(A) 事务内：NG 自动起票 DefectRecord**（`QualityInspectionService.cs:201-220`，与 QI 头/子表同一 Commit）：
```csharp
// 不合格 → 自動で T_DefectRecord を起票（仕様書 §6.1）
if (qi.OverallResult == 2)
{
    var defNo = await _seq.NextAsync("DF");
    _db.DefectRecords.Add(new DefectRecord
    {
        DefectNo = defNo,
        WorkOrderNo = qi.WorkOrderNo,
        ProcessCd = qi.ProcessCd,
        InspectionNo = no,          // ← 回填形成 QI↔不良关联
        OccurDate = qi.InspectionDate,
        ReporterCd = qi.InspectorCd,
        CategoryCd = "D07",         // 検査由来：その他（後で人手で調整）← 硬编码
        DefectQty = qi.InspectionQty ?? 0,
        DefectDescription = $"品質検査 {no} 不合格自動起票",
        Status = 0,
        Creator = userName, CreateDate = now,
    });
}
```

**(B) 提交后：NG 标关联库存 FAILED**（`:234-237` 调用点 + `:324-357` 辅助方法）：
```csharp
if (qi.OverallResult == 2 && !string.IsNullOrWhiteSpace(qi.WorkOrderNo))
    await TryMarkLinkedStockFailedAsync(qi.WorkOrderNo, no, userName);
// TryMarkLinkedStockFailedAsync：_stockQc==null 则仅 LogWarning 跳过（可选注入）；
// 否则 await _stockQc.MarkLinkedStockByWorkOrderAsync(workOrderNo, StockQcStatus.Failed, $"QC NG: inspection {no}", userName);
// catch(Exception) 仅 LogWarning，QI 已 commit 不回滚（best-effort）
```
> `_stockQc` 是可选注入 `IStockQcService? _stockQc`（`:28`），生产由 DI 同 Scoped 容器真注册（`Program.cs:279` QI + `:292` StockQc），运行期非 null。

**被调实现** `StockQcService.MarkLinkedStockByWorkOrderAsync`（`StockQcService.cs:40-79`）——关联键路径 `WorkOrder → InboundReceipt(WorkOrderNo) → InboundReceiptDetail(ProductCd+LotNo) → Stock`：
```csharp
var pairs = await (
    from receipt in _db.InboundReceipts
    join detail in _db.InboundReceiptDetails on receipt.ReceiptNo equals detail.ReceiptNo
    where receipt.WorkOrderNo == workOrderNo && !receipt.IsDeleted && !detail.IsDeleted
    select new { detail.ProductCd, detail.LotNo }).Distinct().ToListAsync();
if (pairs.Count == 0) return 0;
var stocks = await _db.Stocks.Where(s => !s.IsDeleted).ToListAsync();
foreach (var stock in stocks) {
    if (!pairs.Any(p => p.ProductCd == stock.ProductCd && p.LotNo == stock.LotNo)) continue;
    stock.QcStatus = newStatus;     // = "FAILED"
    stock.Modifier = userName; stock.ModifyDate = DateTime.Now; affected++;
}
await _db.SaveChangesAsync(); return affected;
```
`ValidateStatus`（`:81-87`）仅允许 PENDING/PASSED/FAILED/HOLD，否则抛 `WM-MSG-QC-001`。

**(C) Phase7 最终把关**——WMS 出库引当 `OutboundService.FindCandidateStockAsync`（`OutboundService.cs:325-339`）：
```csharp
return _db.Stocks.Where(s => s.ProductCd == productCd && s.WarehouseCd == warehouseCd
    && !s.IsDeleted && !s.RecallFlag && s.AvailableQty >= needed
    && s.OwnerType == StockOwnerType.Self
    && s.QcStatus != StockQcStatus.Failed
    && s.QcStatus != StockQcStatus.Hold) ...
```
被标 `FAILED` 的库存被 `s.QcStatus != FAILED`（`:334`）排除→无法被引当→**实现「NG 阻止出货」**。`StockQcStatus.IsAllocatable` 仅 PENDING/PASSED 可引当；`Stock.QcStatus` 默认 PENDING。

**测试佐证**（`CP6.Tests/QualityInspection_AutoQcLinkTests.cs`）：NG 后关联 Stock 变 FAILED、无关 Stock 仍 PENDING；合格时 `IStockQcService` 调用 0 次；无关联库存时 QI 仍成功保存。

**字段级数据流（NG 一条线）**：`onSave(overallResult=2+dispositionAction)` → `POST /mes/inspections` → `CreateAsync`：①落 `T_QualityInspection(OverallResult=2)`+`T_QualityInspectionItem`；②同事务落 `T_DefectRecord(DefectNo=DF…,InspectionNo=QC…,CategoryCd="D07",Status=0)`；③commit；④`MarkLinkedStockByWorkOrderAsync`：`T_WorkOrder→T_InboundReceipt→T_InboundReceiptDetail(ProductCd+LotNo)→T_Stock` 命中行 `QcStatus="FAILED"`；⑤后续 WMS 出库 `AllocateAsync→FindCandidateStockAsync` 用 `QcStatus != FAILED` 滤掉→不可出货。

## 关键发现
1. **自动联动只在 Create 路径**：Update 改判 NG 不补建不良、不标 FAILED。
2. **两段事务边界不同**：DefectRecord 与 QI 同事务原子提交；库存 FAILED 在 commit 之后 best-effort，失败仅告警不回滚。
3. **自动不良分类硬编码 `CategoryCd="D07"`**（检查由来·其他），需人工后调。
4. **`IStockQcService` 可选注入**（单测可 null）；生产真注册。
5. **Phase7 阻止出货的真实落点是 WMS 出库引当**（`OutboundService.FindCandidateStockAsync`），QI 只负责标 FAILED。
6. 错误码：`ME-MSG-020/021/022/023/030/031/040/041/043`、`WM-MSG-QC-001`。
