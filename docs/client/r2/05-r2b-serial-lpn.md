# 05 R2B 序列号与 LPN

## 1. 不可逆模型

R2B 只在 R2A 已退出的单个试点仓执行。每个产品成功序列化后设置永久锁定，
不得回退到非序列追踪。批次按产品顺序执行；某产品失败时立即停止后续转换和
新业务，保留之前已成功产品，通过新操作/迁移前滚修复。

`SerialLpnEnabled=false` 时序列、LPN 和相关标签写入返回
`WM-R2B-DISABLED`。Serial/LPN 开启时不得关闭 MOVE；关闭时必须先关闭
Serial/LPN，再关闭 MOVE。

## 2. 维护窗口与只读预检

现场冻结后确认仓库没有 Pending、InProgress、Paused 或 Exception 活动任务。
对每个产品按仓库、库位、批次读取物理库存并完成序列扫描：

- 产品所有非零库存只能位于试点仓；跨仓产品移出本批；
- 数量必须为非负整数；
- 每个库存桶扫描序列数等于物理库存；
- 产品合计、库存桶合计和输入序列数三者完全一致；
- 产品代码唯一，证据快照与 R2A 退出证据已归档。

把只读快照交给 `scripts/test-r2b-preflight.ps1`。代码侧
`SerialInventoryService.EnableTrackingAsync` 会再次拒绝跨仓库存、
活动任务、未启用开关、数量/桶差异和重复序列，避免仅依赖操作清单。

## 3. 审批与转换

1. 只读预检通过并归档；
2. 通过 `WMS_FEATURE_FLAG_CHANGE` 提交 Serial/LPN 开关申请，附 R2A 退出、
   预检和变更单 URI，由非申请人批准；
3. 审批回调再次核对仓库功能 RowVersion；过期申请标记 `Stale`；
4. 按批准清单逐产品调用序列追踪转换，每个产品使用新的 operationId；
5. 成功后立即核对序列台账、产品锁定时间和每个库存桶；
6. 失败后封锁后续产品与新业务，记录失败 operationId/错误码，执行前滚修复。

不得用新 operationId 掩盖响应丢失；未知结果必须用原 operationId 查询或重试。

## 4. 场景验收

- 同一序列号在不同产品下互不影响；
- LPN 打包、移动、拆分、合并、解包和整树移动原子完成；
- 序列/LPN 与库存仓库、库位、批次合计始终一致；
- Web 在响应丢失时复用原 operationId；
- 重放不生成第二份库存事务或序列/LPN 台账；
- 任一无法解释差异立即 NO-GO，停止后续转换。

## 5. 退出

本批所有产品均具有预检、审批、转换、逐桶对账和场景测试证据；无活动故障、
无未解释汇总差异、无降级操作，才允许批准 R2B 退出。R2B 稳定后才能进入
Kubernetes 多仓推广。
