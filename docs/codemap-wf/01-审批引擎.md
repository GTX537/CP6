## 0. 架构定位

OA 不引用任何业务模块（编译期单向），业务实现 `IApprovalCallback` 注册 DI，终态由 `ApprovalDispatcher` 运行时多态直调。DI 全景 `Program.cs:102-124`（`IApproverResolver`/`IFlowEngine`/`IWfNotifier→SignalRWfNotifier`/`ITaskCenterService`/`IApprovalService`/`ApprovalDispatcher` + 4 个 `IApprovalCallback`(Fin.Journal/Fin.Budget/Pur.Po/Pur.Pr) + `IWfTimeoutService` + `WfTimeoutScanWorker`）。`FlowEngine` 注入 `ApprovalDispatcher`；`ApprovalDispatcher` 注入 `IEnumerable<IApprovalCallback>`（DI 自动收集 4 回调）。

## 三、⭐ 流程引擎状态机推进（会签/或签/条件/幂等）— POST /api/wf/task/{id}/act

**前端**：待办中心 `TodoCenter.vue:128-138` `act(approve)`→`flowApi.act(taskId, {approve, comment})`。
**后端**：`FlowController.Act`（`:63-73`，办理人取登录用户）。`FlowEngine.ActAsync`（`FlowEngine.cs:57-103`）：

**幂等闸门**（`:61-64`）：
```csharp
if (task.Status != FlowTaskStatus.Pending) return;   // 已办无效
var inst = ...; if (inst is null || inst.Status != FlowInstanceStatus.Running) return;   // 实例已结束/挂起
```
**办理落痕 + 前加签激活**（`:66-74`）：置 Approved/Rejected + history；`approve && task.AddSignSource=="before"` → `ReactivateSuspendedAsync`。
**会签计票**（`:77-82`）：取本节点未作废任务计 approved/rejected/total → 纯静态 `EvaluateNodeCounts(approved, rejected, total, Countersign)`：
```csharp
case "any":   // 或签：任一同意即过；全驳才否
    if (approved > 0) return (true, true);
    if (rejected >= total) return (true, false);
    return (false, false);
case "veto":  // 一票否决
case "all":   // 会签：全同意才过；任一驳回即否（veto 与 all 共用此分支，语义相同！）
default:
    if (rejected > 0) return (true, false);
    if (approved >= total) return (true, true);
    return (false, false);
```
**未决等其他会签人**（`:84-88`）`if (!decided) { SaveChanges; return; }`。
**已决流转/驳回**（`:90-102`）：
```csharp
CancelPendingTasks(nodeTasks);   // 作废本节点其余在途
if (passed) { var node = FindNode(...); if (node != null) await NextNodeAsync(inst, schema, node); }
else inst.Status = FlowInstanceStatus.Rejected;
await DispatchIfFinishedAsync(inst, actorId, comment);   // ★终态→反向回调业务(最终SaveChanges前)
await _db.SaveChangesAsync();
```
**条件分支 `NextNodeAsync`**（`:203-213`）：沿出边按声明序取首个 `ExpressionEvaluator.Evaluate(edge.Condition, VarsJson)` 为真者进入；无后继→`Status=Approved`。
**进节点 `EnterNodeAsync`**（`:136-183`）：end→Approved；start→直穿；approval→`_approver.ResolveAsync`，**解析失败 `Suspend` 挂起待指派**；重入先作废上轮任务防计票串台；按每审批人建 `Wf_FlowTask`（含委派替换 + 推待办）。

## 四、⭐ 业务接入 + 终态分发回调（接缝核心）

**业务起审** `POST /api/wf/approval/submit`：`ApprovalController.Submit`（`:31-43`，发起人取登录用户，formSnapshot 透传 JsonElement）→ `ApprovalService.SubmitAsync`（`ApprovalService.cs:22-37`，**不碰业务表**）：
```csharp
if (bizType 空) throw "bizType 必填"; if (bizId 空) throw "bizId 必填";
if (await _db.Wf_FlowInstances.AnyAsync(同bizType+bizId+Running)) throw "该单据已有进行中的审批";  // 防重
var binding = ...Wf_ApprovalBindings(BizType && Enable) ?? throw $"未配置 {bizType} 的审批流程绑定";
var vars = formSnapshot is null ? "{}" : JsonSerializer.Serialize(formSnapshot);
return await _flow.SubmitAsync(binding.FlowKey, starterId, vars, bizType, bizId);
```
**终态分发** `FlowEngine.DispatchIfFinishedAsync`（`:109-115`，必须在最终 SaveChanges 前）→ `ApprovalDispatcher.OnInstanceFinishedAsync`（`ApprovalDispatcher.cs:23-42`）：
```csharp
if (string.IsNullOrEmpty(inst.BizType)) return;   // OA 原生表单无回调
var cb = _callbacks.FirstOrDefault(c => c.BizType == inst.BizType) ?? throw $"未注册 BizType={inst.BizType} 的审批回调";
if (approved) await cb.OnApprovedAsync(ctx); else await cb.OnRejectedAsync(ctx);
```

**四个回调**：
| BizType | 实现 | 通过 | 驳回 |
|---|---|---|---|
| `FinJournalPost` | `Fin/JournalApprovalCallback.cs` | `PostAsync` 过账(幂等：已过账跳过；非待复核抛；失败抛→回滚) | RejectAsync |
| `A5_Budget` | `Fin/BudgetApprovalCallback.cs` | `ActivateFromApprovalAsync`(清旧Active→Archived+本版IsActive) | Status=Rejected(不SaveChanges) |
| `PUR_PO` | `Pur/PurApprovalCallback.cs`(`PoApprovalCallback`) | `ConfirmFromApprovalAsync`→Confirmed | `RejectFromApprovalAsync`→Draft |
| `PUR_PR` | `Pur/PurApprovalCallback.cs`(`PrApprovalCallback`) | `ApproveFromApprovalAsync`→Approved | →Draft |
> 财务凭证回调（`JournalApprovalCallback.cs:23-37`）：`PostAsync` 失败抛异常触发整体回滚；审批人=制单人时 `PostAsync` 返 `E-FIN-111`（财务码，非 OA），回调抛异常——OA 不"假通过"。采购/预算回调用 `IServiceProvider` 延迟解析打破 DI 构造期循环。采购侧 `ApprovalServiceAdapter.SubmitAsync`：无启用绑定→`AutoApproved=true` 直通(向后兼容)，有绑定才起真实 OA。

## 五、⭐ 高级流程：退回/加签/委派/超时（⚠️ 无前端 UI，仅后端 REST）

**退回** `POST /api/wf/advanced/sendback` → `FlowEngine.SendBackAsync`（`AdvancedFlow.cs:77-103`）：幂等闸门；目标不存在/退回到 end 抛异常；作废本实例所有在途待办(含挂起)+清计票；`AddHistory("sendback")`；`EnterNodeAsync(目标)`。三落点（上一步/指定/发起人）仅 targetNodeId 不同。
**加签** `POST /api/wf/advanced/addsign`（source=before/after）→ `AddSignAsync`（`:16-52`）：source 非法/非待办/流程已结束 抛；层数上限 `MaxAddSignPerNode=10`；`before` 把原任务挂起(待加签人审完 `ReactivateSuspendedAsync` 激活)；新任务 `Countersign` 继承(计入会签)。
**委派** `POST /api/wf/advanced/delegate`（委托人=登录用户）→ `SetDelegateAsync`（`:54-75`）：不能委派给自己/失效早于生效 抛；建 `Wf_FlowDelegate`。**生效点在建待办时替换** `ResolveActualAssigneeAsync`（`FlowEngine.cs:191-200`，取生效中委派返回(代理人,被代理人) 记"delegate"痕迹）。⚠️ v1 仅建待办时替换，存量在途待办不转。
**超时扫描** `WfTimeoutScanWorker`（每1min，按租户 `TenantScopeRunner.ForEachTenantAsync`）→ `WfTimeoutService.ScanOnceAsync`（`:42-101`）：取 `Pending && DueAt<=now && !TimeoutHandled` 前100条，按 `TimeoutAction`：remind(软,重推+顺延,不置Handled)/approve|reject(硬,系统身份 `Guid.Empty` 调 ActAsync+置Handled)/escalate(硬,换 `EscalateTo`+双痕+推待办)。**双幂等**：TimeoutHandled 标记 + ActAsync 自身幂等。

## 关键发现
1. **无结构化错误码**（grep）：全是 `InvalidOperationException(中文)`→400。关联到的 `E-FIN-111` 是被回调财务模块的码。`OA-D*` 是设计决策编号非错误码。
2. **高级流程无前端 UI**：退回/加签/委派仅后端 REST，前端只有同意/驳回/撤回。
3. **`veto` 与 `all` 会签语义相同**（`EvaluateNodeCounts` veto fall-through 到 all）。
4. **原子性接缝**：`DispatchIfFinishedAsync` 严在最终 SaveChanges 前，回调共享 scoped DbContext，抛异常则一并回滚。
5. **委派 v1**：仅建待办时替换 assignee，存量在途不转派。
