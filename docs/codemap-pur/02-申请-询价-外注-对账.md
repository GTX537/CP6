## 一、采购申请 PR

### PR·手工建单 — POST /api/pur/pr
**前端**：`PrView.vue`「新建申请」→`prApi.create`(`pur.ts:93-95`)。
**后端**：Controller `Create`(`PurchaseRequestController.cs:32-37`)→ `PurchaseRequestService.CreateAsync`(`:58-102`)：行空`E-PUR-050`→建头(`PrNo=NextAsync("PR")`,`Status=Draft`,`Source=Manual`)→逐行物料空`E-PUR-051`/数量≤0`E-PUR-055`。实体 `PurchaseRequest`(`Pur_PurchaseRequest`)，`PrStatus`(Draft0/Submitted1/Approved2/Rejected3/Converted4/Closed9)、`PrSource`(manual/shortage/workorder)。

### ⭐ PR·需求驱动生成（⚠️ 无 HTTP 端点、无生产触发点）
> `PrGenerationService` 落码完整但 **grep 全仓无 Controller 端点、无生产调用方**(仅 DI `Program.cs:170`+单测)。前端 `PrView.vue` 也无「生成」入口。已知遗留(工单BOM缺料驱动PR待MES数据)。
- **① 缺料反流** `GenerateFromShortageAsync`(`:25-62`)：取 WMS `MaterialShortage`→缺口 `shortQty=RequiredQty-AvailableQty`(≤0 返 null)→**幂等锚**(以 PR 侧 `Source=shortage && SourceRefNo=缺料Id` 防重,因 MaterialShortage 无 Handled 字段)→`EstimateAsync` 估价+建议供应商→建头单行。
- **② 工单 BOM 缺料** `GenerateFromWorkOrderAsync`(`:65-118`)：扫 `WorkOrderMaterials` 中 `SupplyStatus==3`(不足)行→幂等集(同工单已开料 ItemId)→逐料缺口 `(PlanQty)-ActualQty`→估价→加行(空则返 null)。
- **估价+建议供应商** `EstimateAsync`(`:136-160`)：①查采购价表(满足 MinQty+有效期,OrderBy MinQty desc,ValidFrom desc)→(Price,SupplierId)；②回退查该物料历史最新 PO 行→(UnitPrice,SupplierId)；均无→(null,null)。
- 本服务**不抛 E-PUR**，异常全 `return null`。

### ⭐ PR→PO·按建议供应商分组转单 — POST /api/pur/pr/{prNo}/convert
**前端**：`PrView.vue`「转采购订单」(`row.status===2`)→`doConvert`(`:206-213`)→`prApi.convert`,提示「已转 {n} 张采购订单」。
**后端**：`ConvertToPoAsync`(`PurchaseRequestService.cs:150-204`)：取 PR(无`E-PUR-056`)/非 Approved`E-PUR-053`→可转行筛选(`Status==0 && 有SuggestSupplierId && 未转出`)→无可转`E-PUR-054`→★**按建议供应商 GroupBy 拆单**：
```csharp
foreach (var group in convertible.GroupBy(l => l.SuggestSupplierId!)) {
    var poDto = new PoCreateDto { SupplierId=group.Key, Type=1, OrderDate=pr.RequestDate, Remarks=$"PR {pr.PrNo}",
        Lines=group.Select(l => new PoLineCreateDto { ItemId=l.ItemId, Qty=l.Qty, UnitPrice=l.EstPrice, RequiredDate=l.RequiredDate }).ToList() };
    var po = await _po.CreateAsync(poDto, userName);   // 复用 PO 服务(EstPrice 作 UnitPrice;null 则 PO 侧阶梯价解析)
    foreach (var l in group) l.ConvertedPoNo = po.PoNo;
    createdPoNos.Add(po.PoNo);
}
```
即**一供应商一张 PO**。状态推进：无任何有效未转行→`Converted`,否则保持 `Approved`(部分转,余行待 RFQ)。送审走 `IApprovalService(BizType="PUR_PR", Amount=0)`,回调 `PrApprovalCallback`。
**错误码**：`E-PUR-056/053/054`。

## 二、询价 RFQ

### RFQ·从 PR 发起 — POST /api/pur/rfq/from-pr/{prNo}
**后端**：`CreateFromPrAsync`(`RfqService.cs:68-116`)：取 PR(无`E-PUR-067`)→可询价行(`Status==0 && 无SuggestSupplierId && 未转出`,空`E-PUR-060`)→建 RFQ 头(`RfqNo=NextAsync("RFQ")`,`SourcePrNo`)→逐行拷贝+**行级追溯** `SourcePrNo+SourcePrLineNo`。实体 `Rfq`(一头三身 Lines/Suppliers/Quotes)、`RfqStatus`(Draft0/Inviting1/Quoting2/Selected3/Converted4/Closed8/Cancelled9)。

### RFQ·邀供应商 + 收报价 — POST .../suppliers + .../quote
- 邀请 `AddSuppliersAsync`(`:119-162`)：已邀幂等；逐供应商 不存在`E-PUR-062`/`!SupplierFlg``E-PUR-063`；加 `RfqSupplier(Invited)`；Draft→Inviting。
- 收报价 `RecordQuoteAsync`(`:165-229`)：未被邀`E-PUR-064`/无报价行`E-PUR-066`/报价行非询价行`E-PUR-065`；按 LineNo upsert `RfqQuote`；该供应商→Quoted；推 Quoting。

### RFQ·比价/选定/回写价表/转PO
- **比价** `RankQuotesAsync`(`:232-265`)：按 LineNo 分组,过期(`ValidUntil<asOf`)Rank=0,非过期 `OrderBy(QuotedPrice).ThenBy(LeadDays).ThenBy(SupplierId)` 赋 Rank=1,2,3(仅建议不自动选)。
- **选定** `SelectAsync`(`:268-311`)：报价不存在`E-PUR-069`/过期`E-PUR-068`；一行一选(改选清旧)；全行有选→Selected。
- **回写价表** `WriteBackPricesAsync`(`:314-348`)：选中报价逐条 `_price.UpsertAsync` 进 `SupplierPrice`,**`Source="rfq"`**,`ValidFrom=today`。
- **转 PO** `ConvertToPoAsync`(`:351-404`)：无选中`E-PUR-070`/选中过期`E-PUR-068`；按选中供应商 GroupBy 拆 PO,`UnitPrice=q.QuotedPrice`(成交价,不走价表),`SourceRfqNo` 追溯;全行转→Converted。
**错误码**：`E-PUR-060~070`。

## 三、外注加工 Subcontract（PO Type=2）

> 外注 PO 复用 `PurchaseOrder`(Type=2,行 UnitPrice=加工费);独有:发支給材(委托WMS)+收成品成本(委托财务)。

### 外注·登记 + 发支給材 — POST .../{lineNo}/consign + .../{lineNo}/issue
**后端**：登记 `AddConsignAsync`(`SubcontractService.cs:25-69`)：PO不存在`E-PUR-071`/`Type!=2``E-PUR-072`/成品行不存在`E-PUR-073`/应发≤0`E-PUR-074`；按 `(PoNo,LineNo,ConsignItemId)` upsert。**发料** `IssueConsignAsync`(`:97-141`)：无支給材`E-PUR-075`/分批量≤0`E-PUR-076`；逐支給材分批/剩余应发→★**委托 WMS 出库**：
```csharp
var wms = await _wmsIssue.IssueAsync(new WmsIssueRequest { ItemId=c.ConsignItemId, Qty=qty, Purpose="subcontract", RefNo=$"{poNo}-{lineNo}" }, userName);
c.IssuedQty += wms.IssuedQty;   // 按实出累加(防吞料锚)
c.WmsIssueNo = wms.IssueNo;
```
**★接缝 `WmsIssueServiceAdapter`**(`:28-58`)：委托 `IStockMovementService.ApplyAsync(OUT, RelatedType="SUBCONTRACT")`,库存不足→`E-PUR-080`。实体 `PoConsignMaterial`(`ConsignQty`应发/`IssuedQty`★实发防吞料锚/`WmsIssueNo`)。
**错误码**：`E-PUR-071/072/073/074/075/076/080`。

### ⭐ 外注·收成品成本核算 — POST .../{lineNo}/finished-cost
**后端**：`CalcFinishedCostAsync`(`:144-182`)：`finishedQty≤0``E-PUR-077`→**成本公式**：
```csharp
var processingFee = poLine.UnitPrice * finishedQty;                   // ①加工费(PO行单价×成品数)
var consignCost = consigns.Sum(c => c.ConsignQty * c.ConsignUnitCost); // ②支給材成本(并入非另付)
var finishedCost = processingFee + consignCost;
```
→**委托财务** `_finCost.PostSubcontractCostAsync`(失败`E-PUR-078`)。**★接缝 `FinCostServiceAdapter`**(`:28-52`)：经 `IAutoVoucherEngine` 按 `Subcontract.CostPosted` 规则生成 **借库存商品FG/贷原材料INVENTORY=FinishedCost**,幂等键 `SC-{PoNo}-{LineNo}`。加工费应付由三单匹配独立记,本适配器不碰应付(零重复)。

### ⭐ 外注·防吞料对账 — POST .../{lineNo}/reconcile
**后端**：`ReconcileConsignAsync`(`:185-235`)：`poLine.Qty≤0``E-PUR-079`→**成品反推应耗**：
```csharp
var unitUsage = c.ConsignQty / poLine.Qty;   // 单耗=计划应发÷计划成品数
var expected = unitUsage * finishedQty;       // 应耗=单耗×实收成品数
var variance = c.IssuedQty - expected;        // 正=多发(含合理损耗)
var anomaly = variance > expected * tol;      // 多领超损耗→私吞/多领未用
```

## 四、采购对账 PurReconcile·堵三漏 — GET /api/pur/reconcile/{poNo}

**前端**：`PurReconcileView.vue`「对账」→`reconcileApi.reconcile`,`hasIssue` 红/绿 alert。
**后端**：`ReconcilePoAsync`(`PurReconcileService.cs:22-92`)：PO不存在`E-PUR-027`→`ResolveToleranceAsync`→逐行三方核对(基于三累计锚):
```csharp
var overInvoice = l.InvoicedQty > l.AcceptedQty * (1 + tol.QtyTolPct);   // ①虚开/重复开票
var overReceipt = l.ReceivedQty > l.Qty * (1 + tol.QtyTolPct);           // ②超量/重复收货
```
★**第三漏:外协吞料**(`:67-81`,仅 Type==2)：逐行**以合格成品数 AcceptedQty 反推应耗**,复用 `ReconcileConsignAsync` 对实发 `IssuedQty`,`HasAnomaly`→hasIssue。

**三漏总览**：
| 漏 | 判据 | 锚 |
|---|---|---|
| ① 虚开/重复开票 | `Invoiced > Accepted×(1+容差)` | PO行三累计锚 |
| ② 超量/重复收货 | `Received > Qty×(1+容差)` | PO行三累计锚 |
| ③ 外协吞料 | `Issued - 应耗 > 应耗×容差` | `PoConsignMaterial.IssuedQty` |
> 对账是**只读诊断层**(不写库不改状态),硬闸门在收货超量挡/三单匹配/外注 IssuedQty。
