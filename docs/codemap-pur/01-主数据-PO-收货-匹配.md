## 一、供应商价表·阶梯带价解析 — GET /api/pur/supplier-price/resolve

**前端**：`SupplierPriceView.vue` 带价试算卡(`:49-55`)→ `pur.ts:18-22` `resolve(supplierId, itemId, qty, onDate?)`，结果 `result===null ? '无适用采购价' : '解析单价:'+result`。
**后端**：Controller `Resolve`(`SupplierPriceController.cs:28-31`)→ `SupplierPriceService.ResolvePriceAsync`(`:15-31`)★阶梯规则：
```csharp
var price = await _db.SupplierPrices
    .Where(p => !p.IsDeleted && p.SupplierId==supplierId && p.ItemId==itemId
        && p.MinQty <= qty && p.ValidFrom <= onDate && (p.ValidTo==null || p.ValidTo>=onDate))
    .OrderByDescending(p => p.MinQty).ThenByDescending(p => p.ValidFrom)   // 取 MinQty 最大档,同档取 ValidFrom 最新
    .Select(p => (decimal?)p.Price).FirstOrDefaultAsync();
```
实体 `SupplierPrice`(`Pur_SupplierPrice`,业务键 `(SupplierId,ItemId,MinQty,ValidFrom)`,`Source=manual/rfq`)。**此解析被 PO 建单复用**。
**错误码**(写库时)：`E-PUR-011`供应商必填/`012`物料必填/`013`单价负/`014`阶梯量负/`015`价档不存在。

## 二、PO 建单·带出供应商价 + 派生状态机 — POST /api/pur/po

**前端**：`PurchaseOrderView.vue` 建单,单价列 placeholder「留空=带价」(`:73`),`submit()`(`:168-182`)前端预校验→ `poApi.create`(`pur.ts:39-41`)。
**后端**：Controller `Create`(`PurchaseOrderController.cs:33-39`,`[RequirePermission("pur-po","add")]`)→ `PurchaseOrderService.CreateAsync`(`:55-145`)步骤：

3. 币种快照 `supplier.CurrencyCd ?? BaseCurrency`；**冻结汇率**(本位币1m/外货 `IFxRateService.ResolveRateAsync`,未登记`E-PUR-023`)。
4. 建头(`PoNo=NextAsync("PO")`、`PostingBasis`=供应商 `PurchasePostingDiv` 缺省"2"检收、`Status=Draft`)。
5. 逐行(`:95-135`)物料空`E-PUR-025`/数量≤0`E-PUR-026`；★**带价**(手填优先,否则调价表,无价挡单)：
```csharp
var unitPrice = ld.UnitPrice is > 0 ? ld.UnitPrice.Value
    : await _price.ResolvePriceAsync(supplier.BpCd, ld.ItemId, ld.Qty, orderDate) ?? throw new InvalidOperationException("E-PUR-022");
```

   算 net/taxAmt(`AwayFromZero`),**三累计锚 Received/Accepted/InvoicedQty 初始0**。
6. 头金额汇总 `GrossAmount=Net+Tax`,一次 SaveChanges。

**★派生状态机** `DeriveStatus`(`:230-245`,纯函数从三累计锚投影)：
```csharp
if (allInvoiced && allMatched) return PoStatus.Closed;
if (anyInvoiced) return PoStatus.PartiallyInvoiced;
```

`RefreshStatusAsync`(`:207-224`)由 GR/匹配回调；草稿/送审/取消不参与。状态枚举 `PoStatus`(Draft0/PendingApproval1/Confirmed2/PartiallyReceived3/Received4/PartiallyInvoiced5/Closed6/Cancelled9)。
**送审** `SubmitForApprovalAsync`(`:148-169`)详见 §五；取消 `CancelAsync`(仅 Draft/PendingApproval/Confirmed,否则`E-PUR-029`)。
**错误码**：`E-PUR-020/021/022/023/024/025/026/027/028/029`。

## 三、GR 双基准收货·委托 WMS 真实入库 + 回写三累计锚 — POST /api/pur/gr

**前端**：`GoodsReceiptView.vue` 先「载入订单行」(`loadPoLines :149-167` 拉 PO 行,预填剩余未收量)→`submit()`只取 `thisQty>0` 行→ `grApi.confirm`。
**后端**：Controller `Confirm`(`GoodsReceiptController.cs:33-39`,`[RequirePermission("pur-gr","add")]`)→ `GoodsReceiptService.ConfirmReceiveAsync`(`:51-131`)：
1. 校验：行空`E-PUR-030`/PO不存在`E-PUR-027`/★PO状态守卫(仅 Confirmed/PartiallyReceived/Received/PartiallyInvoiced 可收货,否则`E-PUR-032`)。
2. **双基准** `var accrual = po.PostingBasis == "1"`(着荷基准)；GR 头状态 `accrual ? Completed : Inspecting`。
3. 逐行★**超收挡**(`poLine.ReceivedQty + ld.ReceivedQty > poLine.Qty`→`E-PUR-031`)；按基准定验收锚 `AcceptedQty = accrual ? ld.ReceivedQty : 0`、`QcStatus = accrual ? "NONE" : "PENDING"`。
4. ★**委托 WMS 物理入库**(`:108-114`)：
```csharp
var wms = await _wmsReceive.ReceiveAsync(new WmsReceiveRequest { PoNo=po.PoNo, SupplierId=po.SupplierId, WarehouseCd=dto.WarehouseCd, Lines=wmsLines }, userName);
gr.WmsInboundNo = wms.WmsInboundNo;
foreach (var gl in gr.Lines) gl.WmsReceiptDetailRef = wms.LineRefs.FirstOrDefault(r=>r.PoLineNo==gl.PoLineNo)?.WmsReceiptDetailRef;
```
5. ★**回写 PO 三累计锚**(`:117-123`)：`poLine.ReceivedQty += gl.ReceivedQty; if(accrual) poLine.AcceptedQty += gl.ReceivedQty;`
6. `_po.RefreshStatusAsync(po.PoNo)` 触发派生。

**★接缝 `WmsReceiveServiceAdapter`**(`:24-66`)三段贯穿 WM030→WM040(详见 [codemap-wms 入庫篇](../codemap-wms/02-入庫.md))：①`CreateOrderAsync`(PoNo钩子,InboundType=1)→②`ConfirmOrderAsync`→③`ConfirmReceiptAsync`(SourceType=Purchase,落 RECV 暂存位,经 `IStockMovementService` IN 真增库存)→返回 `WmsInboundNo=InboundNo`(检收按InboundNo查QcInspection)。
**检收应用** `ApplyQcResultAsync`(`:134-191`,仅检收基准)：`gr.Status != Inspecting`→`E-PUR-036`；查 `IWmsQcQuery.QueryByReceiptAsync(WmsInboundNo)`(`WmsQcQueryAdapter` 按 InboundNo 查 `QcInspection.Status==2`,无记录→默认全合格 PASS)；累加 `poLine.AcceptedQty`。
**错误码**：`E-PUR-030/027/032/026/034/031/035/036`。

## 四、三单匹配·容差判定 → 自动建应付/挂起 — POST /api/pur/match

**前端**：`ThreeWayMatchView.vue` 「载入可开票行」(`loadPoLines :162-180` 算 `remain = max(0, acceptedQty - invoicedQty)`)→`submit()`→ `matchApi.match`,按返回 `apCreated` 分流提示；挂起单「放行/拒绝」。
**后端**：Controller `Match`(`ThreeWayMatchController.cs:33-40`,`[RequirePermission("pur-match","add")]`)→ `ThreeWayMatchService.MatchInvoiceAsync`(`:48-150`)：
1. 行空`E-PUR-040`/PO不存在`E-PUR-027`/★**幂等防重复开票**(同 `(PoNo,SupplierInvoiceNo)` 已 Passed/Released→`E-PUR-043`)。
2. `ResolveToleranceAsync(po.SupplierId)`：具体供应商>全局缺省>硬缺省{0,0,0}严格。
3. ★**逐行容差判定**(`:78-114`)：
```csharp
var remainAccepted = poLine.AcceptedQty - poLine.InvoicedQty;   // 可开票量
var priceVar = poLine.UnitPrice==0 ? 0 : Math.Abs(ld.UnitPrice - poLine.UnitPrice) / poLine.UnitPrice;
var amountVar = ld.Qty * Math.Abs(ld.UnitPrice - poLine.UnitPrice);
var qtyOk = ld.Qty <= remainAccepted;                            // 硬约束:不得超可开票量
var priceOk = priceVar <= tol.PriceTolPct || amountVar <= tol.AmountTolAbs;  // 率容差 或 小额绝对放行
var within = qtyOk && priceOk;
```
4. ★**分流**(`:118-142`)：
```csharp
if (allWithin) {
    var ap = await BuildApAsync(po, match, invoiceDate, userName);   // 容差内→建AP
    if (ap.Ok) { match.Status = Passed; match.ApInvoiceNo = ap.InvoiceNo; await AccumulateInvoicedAsync(poLines, match); result.ApCreated = true; }
    else match.Status = Suspended;   // 财务失败→挂起不动锚
} else match.Status = Suspended;     // 超容差→挂起
```
5. 累加 `AccumulateInvoicedAsync`(`poLine.InvoicedQty += ml.Qty; MatchStatus = InvoicedQty>=Qty ? 2 : 1`→喂 PO 派生 Closed)；仅 `ApCreated` 才 RefreshStatus。

**★接缝 `FinApServiceAdapter`**(`:26-58`)：`BuildApAsync` 组 `PurApInvoiceDto`(PO 冻结币种汇率,到期 `+30天`)→ 借方按 GL 角色 `INVENTORY` 解析(无→`E-PUR-044`)→委托财务 `IFinAp.CreateInvoiceFromPurchaseAsync`(财务侧幂等:同供应商+发票号返既有)建**并过账**应付。
**人工放行** `ReleaseAsync`(仅 Suspended,`E-PUR-045`,重走 BuildApAsync)/**拒绝** `RejectAsync`(Suspended→Rejected,不建AP)。
**错误码**：`E-PUR-040/027/043/034/026/041/045/046/044`。

## 关键发现
1. **三累计锚是全链共同锚**，PO 状态全由 `DeriveStatus` 投影；可开票量=Accepted-Invoiced 是匹配硬约束。
2. **三接缝全接真实**(DI `:163-168`)：GR→WMS真实入库、匹配→财务建并过账(借INVENTORY)、送审→OA。
3. ⚠️ `Program.cs:178-182` 注释过时(称 Stub)，与 `:163-168` 真实注册矛盾——以注册为准。
4. **幂等三处**：匹配防重(`E-PUR-043`)、财务 AP 端幂等、OA 回调幂等。
