# 独立工程需求来源与定义草稿

W194，WP05-13 的内部来源/定义前置，供后续需求集批准与 ITER 准确输入采用。依据 PLM-REQ-01 的 REQ001–003、PROC001–003、PG04 A001–A008。完整商业来源、关系/判据评审与批准仍未交付。

## 身份与来源

`EngineeringRequirementService` 使用独立 `plm-engineering-requirement` 权限资源，`Source`、`Definition` 两个字段权限。来源包和需求分别具有 UUID、不可变版本与摘要。无需先创建工程修订，避免需求依赖设计结果。部门范围通过实际创建上下文、原子绑定及当前组织核对；个人范围按真实创建人，租户仍显式隔离。菜单不自动给角色授权。IAM 部门映射查询只返回 UUID，避免绕过内容权限泄露来源名称。

来源支持 `INTERNAL_PROPOSAL` 和 `UNRESOLVED`：前者是由登录用户提交的真实内部提案；后者保留尚未澄清的来源描述，不声称客户确认。原文条款、位置、取得依据和来源标记与工程解释分开保存。修订产生新版本，原要求所引用的旧版保留；当前源变更显示 `SOURCE_VERSION_CHANGED`。当前对象/字段权限继续控制历史读取、关系依赖、列表与原操作恢复。任一必须披露的依赖不可见时整次读取拒绝，避免通过转录或关系绕过权限。

## 需求、关系与判据

需求准确引用来源包版本、摘要及实际条款 ID。保存可以保留适用对象、必要性、判据、澄清事项等未定内容，状态恒为 `DRAFT_ONLY`。无隐式满足率或批准状态。

关系支持父需求、派生来源、约束来源、冲突对象和依赖对象，均指向准确需求版本，保留覆盖理由、必要性与未覆盖内容。禁止直接自引用及沿证明关系返回本逻辑需求的任一历史版本；冲突关系不是证明边，不参与传递自证判定。分解不修改父项的原条款。当前目标改版显示差异，历史目标不自动替换。

定量判据的上下界使用十进制字符串，整数与小数各最多 1024 位，保存原精度，不转 .NET decimal 或浏览器 Number。端点可未定；上下界倒置、已明确的空区间及指数等不合法表示拒绝。单位、单位依据和精度是待专业评审的拟定值，空值不默认补充；尚未解析为已批准 UOM 或 VER 方法版本。定性判据保存判定依据。方法需求只是“需要验证什么”，不代替 VER 方法或结果。澄清问题只是待办，没有代客户回函、自动发信或默认同意。

## 事务、接口和恢复

- `GET /api/engineering-requirements/owner-v1/{scope|creation-context}`：可信身份和创建范围。
- `GET /api/engineering-requirements/owner-v1?kind=SOURCE|REQUIREMENT&search=...&page=...`：当前范围分页目录；单对象支持 `?version=` 精确历史读取。
- `POST .../commands`：严格输入合同、CREATE/REVISE、准确 ExpectedVersion/ETag；独立 OperationId 与输入原文匹配。
- `GET .../operations/{id}` 和 `POST .../operations/{id}/close`：查询原结果或结束未提交键，迟到命令不能复活关闭键。

PostgreSQL 前向迁移 `20261029150000_EngineeringRequirementV1` 创建来源/需求头和不可变原文版本。版本、部门绑定、原操作和必要审计在 Main Owner 当前事务提交；递增、摘要、准确头与原文、不可变触发器、延迟原操作外键及来源证明共同保护写入。受影响写入的行数与读回原文必须一致。使用现有全局权限屏障及专用表锁；版本竞争以 CAS 拒绝，当前实现未宣称高并发吞吐验证。

新版本合同上限：HTTP/原文 2 MiB，条款、判据、关系及澄清问题各最多 256，关系观察最多 4096 个准确版本、128 层；超限明确拒绝，不截断。后续大规模使用需独立容量评价，不能从本地检查推断生产容量。

页面 `/plm/engineering-requirement` 提供来源条款、准确版本选择、需求解释、关系、判据、历史读取和原键恢复；localStorage 只存租户/用户范围内的公共操作引用，不保存来源正文或整条命令。身份切换、当前权限拒绝和过时响应清除私有页面数据。浏览器锁协调同种原操作，丢失响应时不重发业务命令。
