1. 仅当前对话串行，一次一张卡。开头写卡号、原 scope/acceptance 和映射原 AC 的剩余出口；结束为“卡 DONE”或“拆卡”。BUG 独立进入 Issue。
2. M 原卡≤4h、L 原卡≤8h 有效时间；150% 为强制拆卡点。余卡上限＝原卡上限−原卡已用有效时间，卡池保持 2,052h；已超出部分计缓冲，余卡上限最低为 0。余卡到 150% 需第二次拆分时先报总负责，不自动追加预算或实施。原卡仅对已验证部分 DONE；余项用 b/c 卡紧接下一位。保存原卡定义和原 AC，拆分并集不减范围；原下游须等所有拆分余项完成，不改变严格前置语义。
3. 其他卡定义的业务只登记回对应卡；不在当前卡顺手实施。前置全部 DONE 后才开工，不把局部证据当作依赖降级。
4. 下一卡在当前阶段的可开工卡中选下游链最长者；同长按下列用户序列排序。阶段 0 按用户指定核销序列逐卡对照既有证据。依赖有冲突先指出，不改图绕过。
5. 一卡一分支、一 PR、一份报告。台账仅在 DONE/拆卡 PR 更新；开工由固定席位登记。目标全部所属卡完整完成时，在同一 PR 核对全部原 AC、必需修订场景和远端采用，满足才关闭目标。否则列至多5条缺口，每条归一张现有未DONE卡；无归属即报总负责，不新卡、不改范围。工具拒绝覆盖卡全完整DONE却无合法缺口归属的开放目标。
6. 受影响回归必跑，租户/权限/库存财务精度/并发/迁移保留专项验证；相同输入证据复用且注明实际来源。仅记录调整不重新运行无关产品测试，不启动 Actions，不部署生产。
