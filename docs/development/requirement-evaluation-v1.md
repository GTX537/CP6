# 准确需求版本的专业评价与批准来源 v1

W195-01，WP05-13 的专业定义评审前置。原依据为 WP05 的 WP05-13/14，以及 REQ 阅读主册 REQ-REQ-003/ACT003-02、REQ-REQ-004/FLD004-02。延续[需求来源与草稿合同](engineering-requirement-v1.md)，不替代完整需求集 FLOW 审批、VER 结论或工程冻结。

## 输入与准确版本

原 `EngineeringRequirement` 来源/定义版本、身份和精确十进制合同不变。定量判据可选增加 `evaluation`：`schema=requirement-evaluation/1`、准确 native UOM `unit` 引用、必传布尔 `lowerUnbounded`/`upperUnbounded`。未提供该对象的旧草稿继续合法；序列化空对象引用时省略该字段，不重写旧原文。新字段由服务端校验，未知额外字段仍拒绝。

保存草稿允许未知。送审要求明确适用对象、必要性、非空评价判据、原始来源依据、已知条件/方法需求、定性依据或完整定量定义，且没有待澄清问题。定量判据至少一个数值界；已知界须明确端点包含方式，缺省界须显式声明无界，不能把空值当作无界。准确 UOM 及其基准须当前启用、版次/摘要匹配、维度匹配；拟用单位标签须与准确单位代码一致。不依据 UOM 数量小数位截断需求阈值，也不自动转换原数值、精度或方法。

只有来源已明确的 `INTERNAL_PROPOSAL` 可在本轮进入资格，`UNRESOLVED` 不被当作客户确认。送审固定需求原文、递归准确来源/关系原文和所选 UOM/基准原文；输入摘要依据不可变原文，不包括动态 `isCurrent`/缺项观察。关系目标改版、原来源改版、单位停用或改版均显示不可用。关系原文入包不代表关系已被采纳、冲突已解决或父需求已覆盖。

既有单版本 2 MiB、图 4096 准确版本/128 深度、判据/关系等每类 256 上限保留。新评价包累计原文字节限 16 MiB，序列化记录限 64 MiB；超限明确拒绝，不截断。该限制只约束新送审合同，不缩小旧草稿可保存范围。

## 专业规则、签署与状态

沿用独立 `plm-engineering-requirement` 权限对象，新增 `review-policy`、`review-submit`、`review-decide`、`withdraw` 能力，迁移不自动授权。`query` 与 Source/Definition 读取权限、个人/部门/子树/自定义/租户对象权限持续有效；规则角色必须是当前租户实际启用角色，不生成默认审批人。

规则保存准确依据、角色/职责、每角色独立人数、有效期、启用状态及真实登记用户。HTTP必须显式提供起止日期，不以默认日期补全省略输入。SUBMIT 固定当前准确需求、当次规则、作者/送审者和输入原文。审批者必须有当前动作/对象/字段权限，属于规则专业角色，且不同于本版作者和送审者；一人每包只能签一次。满足各角色人数后生成不可变批准；历史有效签署作为当次签署事实保留，后续角色变化不重写旧签署。

- 无控制记录相当于 DRAFT；初次 POLICY 创建控制记录。
- SUBMIT → IN_REVIEW；本需求在任何环境仍有评审中控制时，定义 REVISE 拒绝。外部来源可以合法改版，但既有包因此失去批准资格。
- APPROVE 达到人数 → APPROVED；RETURN → RETURNED，下一次 SUBMIT 建新包，旧票不迁入新包。
- 评审中的 POLICY 变更使旧包 RETURNED；停用/过期规则不能再送审或批准。原规则登记者撤权阻止新批准。拥有当前签署权限及该专业角色的独立评审者仍可 RETURN 以释放不可继续的包。
- WITHDRAW 撤掉当前批准并结束当前评审。新草稿、新送审或新规则不自动撤销此前批准；旧批准原文保留，只有明确撤回或新批准替换当前引用。规则有效期约束新送审/签署，不追溯删除已作出的批准。

所有批准的 `purpose=DEFINITION_ONLY`：仅证明该准确需求的评价定义已审定，不表示业务满足，不自动解决冲突、覆盖余项或传递父需求满足率。

## PostgreSQL、原操作与历史

`cp6_requirement_evaluation_v1` 保存 environment/tenant/requirement 控制头、不可变控制版本与政策/包/签署/批准。复用实际 Main 原会话权限根、可信部署 EnvironmentId 和原生 scope fence；`RequirementEvaluation:EvidenceMode` 必须显式 REAL/DEMO，缺省失败关闭，已有头禁止跨模式读取。没有修改既有环境或数据迁移部署。

锁顺序为原授权根/Scope → 需求原文 → 评价 → UOM，全部在同一个实际连接与事务内。控制版本 CAS 与 ETag、防重复签署、记录读回、头更新读回、不可变触发器、延迟关联原操作/准确包/批准票数共同约束写入；原操作结果还关联准确控制摘要、版本、环境、证据模式。丢记录、头更新或 journal 写入不能宣称成功。关闭未知键须读回 CLOSED 记录，迟到命令不能再提交。

`Main.Plm.RequirementEvaluation.operations.v1` / `commands.v1` 保存原键、输入摘要、结果、审计；恢复只归原用户，重发相同键不同输入拒绝。恢复和历史读取重新核对当前对象/字段及原包依赖权限。

API 根 `api/requirement-evaluations/owner-v1`：scope、roles、`{id}?version=`、`{id}/controls/{revision}`、commands、source、operations/{id}、operations/{id}/close。历史控制返回当时政策/包/批准，签署仅包含该控制版本之前已提交的票；`controlIsCurrent=false` 明确只读。需求版本与当前/历史控制各自有准确引用，不能据旧批准推断后继需求已批准。批准来源观察始终依据当前控制。

内部 `HoldExact` 由同一原生调用方传入准确需求和预期 control，在其实际 UoW 内检查输入/权限并持有锁，提交前重新核对来源和控制；没有嵌套事务、独立提交或 HTTP 最终使用令牌。HTTP `source` 为 `READ_ONLY_OBSERVATION`，其可用性不是后续采用许可。

## 页面与交付边界

工程需求页面新增准确 UOM/明确无界选择和专业评价面板。专业评价只读取已保存版本；规则角色、依据和日期需显式选择，固定包显示原条款/条件/精确判据，历史控制显示当时批准。浏览器恢复键按环境/租户/用户/REAL-DEMO 隔离，只保存公开操作引用；使用非排队浏览器锁与身份世代检查，身份变化清空私有正文，未知结果先查询/关闭原键。
