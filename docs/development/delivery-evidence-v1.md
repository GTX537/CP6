# 客户签收证据登记 v1

退货申请页可从已保存的原发运行或申请明细打开签收证据，登记单据编号、含时区时间、数量区间、附件及备注，下载原附件，查看分页历史并说明原因撤回。登记与撤回使用独立动作权限；迁移登记动作但不自动授予角色。

## 数据与业务边界

`Main.Wms.RmaDeliveryEvidence.v1` 保存不可变的原件；撤回另存不可变记录，原件不会被覆盖。原发运引用及行 ID 必须匹配实际保存的发运快照和当前可访问仓库。数量位置采用十进制字符串，最多 13 位整数、8 位小数，以左闭右开区间表示。单份证据区间不得重叠且必须位于原发运区间内；不同单据可以描述同一批货，所以列表不累计为已签收或可退数量。

附件使用现有 FileContent Owner 的精确版本引用及当前父对象读取权限。新登记要求附件当前可用；已有证据在附件被暂停后仍保留历史，下载继续由 FileContent Owner 判定。附件选择器读取现有已上传文件，本任务未增加通用 WMS 上传父对象。页面沿用既有文件下载入口，不再重复验证 Owner 已保证的内容哈希。

证据与原命令、操作人事实、审计在同一 PostgreSQL 事务中保存，复用现有 RMA 锁和权限边界。租户、仓库/站点、本人范围、备注字段和附件权限按当前状态决定。已保存内部记录直接反序列化使用，不重新构造资格证明。相同证据 ID 及相同语义输入只生成一份原件；不同输入冲突。撤回后的新登记重放不会重新激活原件。

本扩展收集业务证据，尚未实现正式 DEL 累计签收证明、可退额度、独立批准或正式 IN。原发运的 `DeliveryProofRef` 不因登记被填入，库存及财务不会变化。后续实现必须根据选定来源及政策作出实际决定；可使用明确构造的模拟签收、发票、贷项和历史申领场景。

## HTTP 与恢复

以下均为 POST，路径前缀 `/api/wms/rma/v1/delivery-evidence`：

| 路径 | 用途 |
| --- | --- |
| `/record` | 保存原件，独立 `evidence-record` 权限 |
| `/withdrawals` | 说明原因撤回，独立 `evidence-withdraw` 权限 |
| `/search` | 精确发运行、仓库范围内分页读取；当前状态分页，不承诺快照游标 |
| `/files/search` | 读取当前有权访问的文件选项 |
| `/commands/query` | 查询原登记或撤回结果 |

沿用 RMA 相关 ID、`Cache-Control: no-store` 和写命令 `Idempotency-Key`。外部 JSON 拒绝未知字段。记录与撤回共享命令命名空间，并将动作纳入原请求绑定。旧写命令重放可在撤销写权限后按当前读权限返回原结果；当前撤回状态在列表单独读取。`NOT_OBSERVED` 不证明没有提交；未知提交指向本扩展的原命令查询地址。

浏览器使用私有 IndexedDB，按租户与操作人隔离证据待确认请求，并用 Web Locks 串行处理。先保存完整原请求再发送；不向 localStorage、URL 或广播事件写业务内容。先查询原结果，再由用户明确重派同一原请求；不自动换键重试。身份/范围变化拒绝旧响应展示并保留未确认请求。
