# CP6 分支与工作区统一规则

2026-10-20，WGOV-20261020，用户授权。此页是四仓共同执行规范；[registry.json](registry.json)是固定目录/容量配置，[REGISTRY.md](REGISTRY.md)提供实际命令。旧轮次报告中的3+1额度仅为历史。

## 配额和任务

- 经 origin 核实的 GTX537/CP6、CP6.CRM、CP6.Platform、CP6.AI-Handoff 各保留一个主目录；四仓**合计最多2开发+1集成工作树**，文档、总控和Handoff同样计入。固定席位有用途和COORD负责人，实时任务负责人由开工记录指定。
- 先查看状态，优先复用，满额排队。新对话、重试、修复、评审或任务拆分均不构成新增 worktree、clone、源码副本的理由。只读审查用 `git show/diff`。跨仓替换使用 `bind`：旧席位安全释放并正常移除后才为对应仓库创建新席位，不能在错误仓库工作。
- 超额必须先向用户说明必要性、预计占用、期限和回收条件并取得明确授权；本脚本默认不提供绕过开关。正常额度内分配/复用/收尾直接执行，无须重复询问。例外临时席位由总控登记授权并管理，结束后正常 `git worktree remove`，不得长期转为额外固定席位。
- 每任务/仓库优先一个功能分支 `codex/<任务编号小写>`，修复和验证继续原分支。创建前查已登记任务、本地/远端分支及PR；不得为小修复/进度记录增设分支，更不得在main混入业务工作。确需临时分支先登记所属原任务、保存位置和同轮收尾条件。
- 集成席位start仅切到远端已保存的source SHA，保持detached，不额外建立功能分支；登记检查任务及其对原任务的依赖，finish的verified只表示登记的验证已完成，不代表业务合并/验收。实现修正回原功能分支。
- 登记包含任务编号、仓库、Owner、功能分支、工作区/席位、目标分支、起始提交、状态、PR、依赖和结束条件。任务开始时PR尚无则为null，创建PR后调用record-pr核对来源并登记编号/链接，finish再次核实。产品进度仍只认roadmap.json；占用状态不是业务验收。

## 强制入口及并发

- 每个写入任务开工必须执行 `manage.ps1 status` 和 `start`；中断接续执行 `resume`。四仓共用 CP6 主仓 Git common dir 下 `cp6-workspaces/state.json`，同目录操作系统锁保护检查和占用，原子替换保存。不要复制、重置或手工清空该文件；操作结束应保留小型登记快照/报告，不复制源码。
- start核实origin、物理Git登记、配额、席位仓库、占用、未提交/未跟踪/忽略文件、进程引用、上项HEAD远端保存、重复分支/PR、最新远端目标及可选精确基线，再原子登记唯一写入者。主仓有用户资料不影响席位工作，禁止清理它们腾位置。
- 每席位同时仅一个写入任务，包含集成修改。过期时间不会自动释放，失败会保留starting/closing/replacement记录；先核实Git、实际进程和原Owner交接，再处理。resume只允许原Owner；换Owner须总控有可追溯交接后在锁内更正，不得抢占。中断bind需要总控核对实际remove/add阶段后修复记录，不重复强行删除。
- 开工时核对完整业务意图，脚本只能识别规范任务ID和分支命名，不能识别被改名隐藏的重复业务。进程扫描检查命令行/可执行路径引用，不能证明所有编辑器或外部写入者都已停止，交付人仍须确认实际写入者。

## 完成与暂缓

- 必要实现、相关验证及集中审查完成；按流程合并或明确暂缓/取消/替代；提交及交付资料可靠保存；相关进程停止；PR、分支和工作区处置完毕；执行 `finish` 并释放席位后才算任务收尾。
- finish必须给出已审查的精确HEAD、验证/审查及交付引用。验证文本是执行人的证据声明，不由登记脚本冒充运行产品测试。脚本核实GitHub PR的源HEAD、目标、合并提交在远端目标中。squash/rebase通过实际PR映射核实；cherry-pick须已关闭原PR并提供主线采用提交，脚本比对整个任务的patch-id。不能证明等价时继续人工内容审查，不以SHA不同当作未采用，也不强删。
- 已合并的本任务分支定向清理：查新增提交、其他工作树占用、已登记依赖、开放PR及上游依赖，并由Owner复核未登记消费者。远端删除使用精确旧SHA的条件删除，远端已改变则拒绝；本地使用期望旧SHA的引用删除。该用户授权仅覆盖已核实收尾的任务分支，不授权重写共享历史、绕过保护、批删历史保存引用或生产部署。
- 固定席位切到已确认目标的detached HEAD后留作复用。暂缓/取消/替代须具体原因、下一步、恢复位置，精确HEAD已推送并回读，开放PR先妥善关闭；保留远端分支仍可释放席位。暂缓恢复继续原任务分支。必要文件未保存或进程仍运行时拒绝切换/释放，不能 `reset --hard`、`clean -fdx` 或 `remove --force`。
- 历史清理不是本入口日常职责。主目录、其他项目、Docker、数据库、用户原件及正式制品不在自动清理范围。`prune`仅清失效登记，先dry-run，不替代工作目录回收。
- **每次开发交付必须同时报告：分支处置结果、工作区状态、席位是否释放。** 暂缓也给具体恢复动作，不能只写“有风险/待确认”。

## 容量和客户端边界

- 历史成果优先Git提交及必要附件，禁止按轮次复制或打包含依赖/构建产物的整仓。保留可复用node_modules缓存；其他忽略文件默认阻止复用，确认其可再生成且无需作验证证据后才定向清理。保留配置、独有脚本、原始失败日志、正式制品和用户资料，禁止把目录迁到C盘/其他容器/归档目录冒充节省。
- `status --capacity`统计配置中的四主目录、CP6工作树容器、客户端CP6残留、既有CP6规划报告/归档，嵌套目录去重、跳过链接并报告扫描错误；逻辑字节与C/D磁盘实际空闲分列。明确阈值见registry：总量、单席位、C/D最低空闲。达到阈值先定位增长路径，不能按数字盲删；它是提醒，不是自动删除。
- 脚本会拒绝超额/未知Git副本、错误仓库、重复占用、重复规范分支、脏目录、未保存成果、不符基线及未证实采用的收尾；**不能拦截原生git、资源管理器复制或客户端在聊天开始前预建目录**。没有Git元数据的源码副本仍须人工核实来源，不能靠origin发现全部副本。
- 使用已登记路径打开 **Local** 项目，关闭新聊天的 **Worktree / New worktree** 开关。客户端自动清理及约6个保留数只影响客户端受管树，不是四仓2+1配额；固定席位作为项目根保留。AGENTS不具有客户端级拦截能力。具体客户端核实与操作见REGISTRY。
- PostgreSQL、精简验证、Actions额度、分支保护和生产门禁继续生效。脚本没有触发Actions或部署入口；推送/PR仍须按原规则核实工作流事件，不能假称只要没手动运行就不会触发。
