# WP14-01 独占环境与测试数据需求

本文件只定义后续运行的准入输入。尚未创建数据库、schema、账户、消息主题、容器或备份；资源预约记录均待真实执行任务填写。数据库唯一目标 PostgreSQL，物理布局采用 S02-00 的已交付版本。

## 资源预约单

协调者在执行任务私有报告中登记下列字段，并检查与其他活动任务的实际资源是否重叠；工作树或表面资源名不同不能证明互斥。

| 字段 | 必需内容与责任 |
|---|---|
| task / run / window | 任务 ID、唯一 run ID、协调对话、执行人、开始/结束时间及释放确认 |
| source / artifact | Main、CRM、Platform 实际参与仓库的完整 SHA、远端 main 包含证据、包版本/合同组合 hash、每个运行产物 SHA-256 |
| database | 脱敏后的本地实例标识、专属数据库名、PostgreSQL/驱动版本；连接串与口令不入库 |
| schemas / tenants | S02-00 决策版本、共享/租户边界、可信 TenantId→schema 目录快照、迁移历史和版本；不得自行宣布一租户一 schema |
| principals | 普通应用、后台、迁移/恢复角色名称或匿名代号、实际权限边界；非 Secret 引用；不能用超级用户测试租户隔离 |

| fault controls | 各进程故障注入点、barrier、触发命令、可观察日志；恢复和停止方法，责任人 |
| backup / restore | 来源/授权/脱敏范围、备份 SHA-256、专属恢复目标、前后对账及恢复成功证据；空库/合成 fixture 不称生产数据恢复 |

## PostgreSQL 与租户场景

1. 保留既有 TenantId、授权和跨租户约束。由可信认证/租户目录确定 schema，不接受客户端对象名；列出共享表、租户表、消息/审计记录所属 Owner。
2. A/B 交替使用同一连接池，包括事务异常、取消、超时及重试后的连接复用。记录事务内上下文设置/清除和后台任务缺上下文的拒绝结果；search_path 不作为阻止显式跨 schema SQL 的证据。
3. 普通运行角色测试显式跨租户读写、共享表权限、伪造租户和字段/行/用途权限；若设计仍共用能读所有 schema 的角色，如实记录应用隔离和数据库权限的实际边界。schema 本身不宣称安全隔离。
4. 同事务场景必须保存真实连接/backend 与原生外层 transaction provenance、参与 DbContext、资源锁集合/顺序、CAS 和 commit/rollback 证据。多个连接同名数据库或同 correlation ID 不证明同一个事务。
5. 逐租户迁移/恢复采用迁移专用角色、准确迁移版本和独占迁移锁；中断恢复、部分租户版本差、单租户恢复均另行执行。只前向迁移；应用回退须证明 schema 兼容。
6. 金额/数量按各原 profile 保持合法值域与原文/规范字节。不以统一有限 decimal/numeric、SUM/CAST、clamp/abs、补零缩小合同；原设计极值只作为待运行输入，不能凭静态解析放行存储。

## 数据准备顺序

1. 各 Owner 从 [targets.csv](targets.csv) 领取目标和原验收，再读取完整定义，列出精确数据/步骤/版本。合成数据允许用于明确标注的本地契约或隔离测试，但不能冒充现场/生产数据验收。
2. 每域用自己的真实写入入口建立父事实，保存返回的原 ID/version/receipt/body。必要的底层测试 seed 只能标记为 seed，不能代替真实来源能力或签收。
3. 下游引用完整 namespace/profile/version、原资源/用途/份额、digest/preimage 及真实 issuer/Store 收据，不根据同名字段推断等价；缺一个专业提供者保持未运行或原 FENCED 状态。
4. 每场景独占数据，或显式沿用同一连续场景的前序状态。连续步骤不拆成每步重新 seed 的假成功；失败重试保留原 run 和原键，另建 attempt，不覆盖原失败记录。
5. 收集前后不变量与各 Owner 见证后再释放资源。清理前核对实际绝对目标和 allowlist；不删除既有开发库、原始备份或他人测试数据。本准备任务没有执行清理。
