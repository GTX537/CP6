## 两种提交顺序及原写集

- Main 单库的实际业务和当前暂停或撤权在同一个 PostgreSQL 权威根上等待。合法业务先提交时原业务和审计保留。暂停/撤权先提交时原动作拒绝，原业务写集、Outbox、回执和权限代次按对应报告读回。财务、Space 和后台证据见上表。 [财务会计期间和实际审计](../W597-01/DELIVERY.md) · [Space 刊发事务及 xmin](../W656-01/DELIVERY.md)
- Main 与 CRM 各用独立 PostgreSQL。Main 先持久固定原请求及影响范围，受影响的新写许可停止。CRM 已经取得本地 Owner 的合法业务先提交时原决定和 Outbox 各一次。CRM 原事务封存先提交时迟到的旧授权由本地原生事务拒绝。Main 复核当前当事人、目标 Store、代次及原 CAS 后提交状态、快照、Outbox、审计与原回执。依据实际数据库锁序和持久状态判断。 [配置实际业务先](../W540-01/DELIVERY.md) · [公开入口封存先](../W542-01/DELIVERY.md) · [两阶段暂停](../W649-01/DELIVERY.md) · [仓库 QuickPIN 双序](../W671-01/DELIVERY.md)
- 真实首次封存连接被拒绝时，已持久的原意图停止受影响新写许可，原合法回读与独立操作继续。实际丢弃两库各自的 PostgreSQL COMMIT 确认后，由原件查询和同键恢复核对原写集。原库、后继库和原生身份门的证据分别保留。真撤权和重授的 C02 版本 6→7 及实际 broker 的 14/15 由 W582 核对。目标两个租户的 Main 权限和 CRM 封存均推进到 8。 [实际 C02 代次](../W582-01/DELIVERY.md) · [暂停首次断连与两库 COMMIT](../W649-01/DELIVERY.md) · [用户和原 CAS](../W660-01/DELIVERY.md) · [已提交回执](../W568-01/DELIVERY.md) · [原凭据协议](../W666-01/DELIVERY.md) · [Main 对 CRM 封存确认](../W552-01/DELIVERY.md)
