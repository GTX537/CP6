## 事务与恢复

PostgreSQL 的 WMS 出库、直接取消和 ERP 已授权级联子取消在原 Owner 事务保存实际接收的 WMS→FIN 意图。保存出库号、原输入、操作者、事件 Id 和相关号。ERP 的意图和实际子取消共用保存点。出库和库存提交后，正常请求按原事件 Id 尝试 FIN。未执行或提交结果未知时，到期 Worker 从同一原行继续。

两个出货 hook 在同租户的 Main 共同栅栏内重读并锁定原事件。核对租户有效期和原出库号后，账簿写入和原事件结果一次提交。已知财务失败先回滚财务保存点，再更新原行的失败和退避。提交前再次检查当前租户及到期时间。首次执行使用实际生产者，历史确认重试沿用 `system`，取消使用原入参中的操作者。原事件保留原始输入和关联标识。

已有草稿继续用原发票和已过账凭证过账。取消以原发票和原凭证定位，同租户已过账反冲通过 `ReverseOfId`、原凭证 `ReversedById` 和单号确认，再处理尚未反冲的腿。已有历史事件以保存的原输入及账簿关联恢复，支持归档出库。两类原生产者的库存处理和 HTTP 合同沿用当前 Owner。

- 缺失成本规则和不可反冲的第二张凭证分别产生 `E-FIN-150` 和 `E-FIN-120`，只更新原事件的失败和退避。原草稿及已过账收入凭证恢复后补齐成本腿。已有已过账收入反冲的原发票仅补齐成本反冲，原凭证和原反冲分录回读一致。两种历史源均验证归档后的原事件恢复。核对原始货量 `12.34567891`、价格 `100.0123`、原币价税 `1389.06` 和成本 `91.23`。
