## 实际验证

Windows、PostgreSQL 18.6、Npgsql 8.0.8、net8.0。使用隔离的普通租户 LOGIN 和模拟库存、部门及业务用户。

- `red-creation.trx` 在 W334 运行合同上复现普通角色读取创建部门时的 `42501`。第一次候选通过顶层事务用例，`red-savepoint.trx` 随后复现保存点插入提交后残留一条私有记录。最终按精确行键清理，覆盖同事务审计重放。
- `creation-exact.trx` 通过 5 项、零跳过。主用例验证错误部门、事务回滚、明确归属、一次审计、同事务和提交后重放拒绝、合法无归属、保存点和旧库存 INSERT。历史库存的 no-op 更新取得当前 `xmin` 后，实际归属函数仍以 `42501` 拒绝。另有三种旧部门范围和独立部门管理回归。
- 在 W330 自有夹具的独立克隆库实测 CLI 拒绝旧布局，应用生成的前向 SQL 后读回精确安装回执、普通 LOGIN 与私有执行者的授权，重复安装拒绝。EF CLI 通过设计期上下文生成脚本，日志保留启动配置未提供连接串的提示。脚本另由 `psql` 在核对过的库实际执行。原始 TRX、脚本和 PostgreSQL 日志位于 `D:/CP6-local-test/CP6-72H-20261109/W335-01`，实例已停止。

集中审查覆盖新库存事务标记、审计一次性、保存点、普通角色授权和共享触发器。比对 W330 的固定谓词，`stock` 分支移入显式分派后沿用原租户、ID 和删除条件，其余 29 个 CASE 谓词和已有流水分支保留。普通 Actions 为手动入口，R2 自动入口匹配版本标签。Actions 触发、取消及生产部署为零。
