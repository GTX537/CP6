## 政策原件和专业批准

- 新增 `FinancePolicyOwnerV1`，Owner 为 `FinancePolicy`。会计政策保留 FIN-GL-01 §11 的司法域、准则、事件、有效区间、原币/本位币/汇率精度、舍入、零值处理、OA.Policy、腿规则及依赖、科目映射引用、Guard、SourceContract 和矩阵引用。Scope、根身份、正整数版本、专业资格、状态、控制版本由 Main Finance 生成；OA 原生三字段 Ref 和其独立 digest 原样保留。
- 双方来源合同使用显式 `FINANCE-SOURCE-CONTRACT-1`，保存来源 Owner、来源 schema、事件、有效区间和所需证据键。成本消费者只采用 `Finance Costing` / `COST-GL-SOURCE-1` / `COST_SETTLEMENT`，会计政策必须绑定同一个精确合同，合同覆盖政策区间和全部事件。未实现的其他来源消费者不因此自动获准。
- 请求只能提交配置和专业依据引用。依据必须来自实际受控文档；会计政策由非制单人专业复核，来源合同由不同的人分别代表 SOURCE 与 GL 批准，不能由一个人签双方。发布者不能是制单人；每个动作有独立菜单动作及精确专业资格。专业资格登记沿既有原件，新增用途同步进入 PostgreSQL 约束；迁移只登记菜单动作，不授予角色权限。
- 每个后继沿同一根递增，前驱只能有一个后继；合法区间可以重叠，消费者始终用完整 Ref 精确选版。会计政策专业输入使用封闭 camelCase JSON，重复属性拒绝、未知属性拒绝、nullable 日期必须显式出现，腿依赖不能成环。Unicode Key 1..128 和原因 1..500 按 Unicode 字符计数，保留原值，不执行 NFC、trim 或大小写改写。
- 原件 Ref 的 purpose 分别为 `ACCOUNTING_POLICY` / `SOURCE_CONTRACT`。内容摘要为 SHA-256：前缀 `FINANCE-POLICY-CONTENT-1\n` 加有序属性/原 Unicode 编码的 `{id,version,content}`；content 包括完整 Scope 和批准正文，仅排除自引用 `ref`。复用纯 canonical 编码实现，不把 Finance 摘要冒充 OA digest。不可变原件的 `controlRevision="1"` 表示初始签发；当前控制状态和 CAS revision 由查询外层独立返回，撤销不改写原件。

## PostgreSQL 同事务采用及恢复

`cp6_fin_policy_v1` 保存版本、当前控制、批准、发布原件和命令结果；租户/账套复合外键沿已有不可变账套身份。版本、批准、原件和命令禁止 UPDATE/DELETE/TRUNCATE，只支持前向迁移。既有账套的环境/法人/账套键不可变约束直接复用，不增加重复证明层。

完整 COST-POLICY-1 的 `glAccountingPolicyRef` 与 `sourceContractRef` 通过已注册的原生参与者读取。该参与者复用调用方的连接、事务、Access 和最终权限门，持有财务及原件控制锁至外层提交；实际采用核对业务日期、精确 Ref、当前发布状态和原批准人的当前资格及同一资格版本。资格到期在 AtCommit 再核对。没有独立连接读取或 HTTP 观察替代事务锁。

原生政策 API 为 `/api/fin/policy/owner-v1`：送审、批准、发布、撤销、原件读取和命令回查，共六个 MVC 路由。所有调用使用当前 `X-Finance-Context`；查询、同键重放及写后读取核对账套和依据文档的当前读权。已提交命令绑定原操作者、路由和 canonical 请求，读取历史无需重新取得原写动作；同键不同请求拒绝。效果和结果同事务；未知提交返回 202 `OUTCOME_UNKNOWN` 与自身命令查询地址，`NOT_OBSERVED` 不承诺永久无效果。
