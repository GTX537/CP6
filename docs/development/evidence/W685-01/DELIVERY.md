## 实际路径

- 工序费率旧列表和按日解析要求当前查询、对象范围和两个费率字段可读。Owner v1 各字段单独返回，隐藏值为空。保存只采用实际输入的可写字段，沿用工作中心身份、闭区间、RowVersion 和原事务。保存响应只给操作结果，页面刷新通过原授权列表。制造工序费率和成本单直接接口没有 CSV 或下载用途。
- 在隔离 PostgreSQL 与真实 HTTP 复现 #1214。历史成本详情会披露明细费率，列表会披露工费和合计，FG 接口会披露根据账存快照计算的单位成本。普通登录角色的三个旧请求均返回 200。样本人工费率为 123.45678901，人工额为 246.91，FG 单位成本为 69.295。
- 三条财务读入口共用当前 Finance 查看动作 `fin-cost:view`、`mes-process-cost-rate:query` 及 LaborRate/OverheadRate Read。动作和字段权同一 PostgreSQL 权限事务核对，结果不缓存。费率限定范围沿用实际工作中心和原费率对象范围，在 SQL 返回前核对快照的工作中心、保存有效日和费率值。来源缺少或超范围时整张成本单不可见，详情和 FG 接口沿用成本单不可用错误。本租户全范围的授权财务读者仍能读到缺少当前费率行的历史凭据。
- 费率、历史快照及金额公式采用原精度与存储。显式登记 `fin-cost:view` 的前向迁移和启动种子均保存真实角色配置，部署后租户管理员需要为相应角色授予财务查看和来源权限。
- 手工归集和 MES 完工经 FIN 桥使用相同的 `CollectAsync`。当前 PostgreSQL 入口仍在归集、采番或账簿变更前返回 `FINANCE_OWNER_REQUIRED`，MES 桥可记录失败事件。工单结转和出货 AR 成本沿已采用路径读取已保存的成本快照。此次核销的是历史披露与实际路径，实时归集采用仍在 Finance Owner 工作范围。

## 验证与收尾

Windows、.NET SDK 8.0.424、PostgreSQL 18.6、私有端口 57372。隔离业务数据为模拟，Web 使用实际签名会话和 Main Program，本地制品与原始执行记录在 `D:/CP6-test-artifacts/W685-01/`。

- `baseline.trx` 一项预期失败，在同一用例中复现三个真实 HTTP 200。最初基线构建缺少测试命名空间的记录保留，修正后才运行红灯用例。
- `verification.trx` 20 项通过，5 项因共享费率菜单和工单号的唯一约束在测试准备中失败。复用标准费率夹具并换用独立工单号后，`fixture-recheck.trx` 复核 8 项通过。25 项定向用例按最终结果通过，其中 10 项实际 PostgreSQL、15 项历史成本组件用例，零跳过。
- 实测财务和来源查询缺权、两个费率字段各自隐藏、同会话撤权、全租户来源范围内旧数据、本人费率范围、其他租户、实际金额及八位精度。迁移已有租户和种子后建租户均登记动作，无自动角色授予。归集写前拒绝与原成本组件行为通过。
