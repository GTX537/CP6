## 实际行为

PostgreSQL 出库生成保存了出库明细到原生订单和订单明细 UUID 的绑定。实际原生财务意图现在按该绑定读取当前售价，每一条发货行使用自己的订单行价格。取得售价仍受出库 UnitPrice、来源 order query、对象范围、当前会话与最终权限检查约束，读取和扣减在同一事务的业务锁内。

- 绑定必须对应当前订单和仍可用的实际明细，物料与数量单位沿原绑定合同。当前绑定行无售价时，沿用该出库行可用的既有价格。绑定失效或无法取得价格时返回 409。
- 历史或手工出库单缺少原生绑定时，可继续采用无歧义的已有售价，多个候选售价不一致则返回 409。无订单关联时沿用既有发货开票合同。
- 先核对开票价格，再扣减库存。来源失败保留原预留、状态、流水和包装，也不会保存财务或 ERP 发货意图。合法开票意图仍与出库同时提交，财务重试复用原意图。

此次实际验收采用现有 WMS/AR 合同的四位单价和八位发货数量。两个价格 3 与 12.3456 分别计得 6.37 与 26.22，发票及凭证合计 32.59。既有历史记录、过账重试和取消按当前合同执行。
