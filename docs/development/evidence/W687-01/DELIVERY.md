# W687-01 MES 完工后的财务归集与结转

COORD 从远端主线 `b3236811ec511065814ec8384b69b38330290fca` 复用固定 DEV-1，分支 `codex/w687-01`。受测代码与用例在 `fffe0066779fcdbecb4f8d1dd393bd4fd7568933`。采用 W686 的实时归集机制及既有成本结转。 [W686](../W686-01/DELIVERY.md) · [#1217](https://github.com/GTX537/CP6/issues/1217)

## 实际行为

- 最终工序完工提交且材料反冲成功后，Finance Owner 使用本租户原完工 UUID、工单、完成量及原会话的当前权限。独立要求 `fin-cost:collect` 与 `fin-cost:settle`，复用工单、产品、费率范围及两个费率字段授权。当前会话和参与的来源权限进入最终提交核对。
- 归集采用实际材料消耗、工时和完工基准日的有效费率。成本单明细、CS/GL 采番、结转凭证、会计期间更新和成功事件一起提交。自动路径保留原零总成本处理，记录归集成本单和跳过状态，凭证数为零。已结转工单沿原财务守卫处理。
- 已知财务失败回滚本次财务写入，保留完工、反冲和以完工 UUID 标识的财务终态事件。财务人员解决权限或配置错误后可走既有手工归集与结转。提交结果不确定时沿既有 Owner 协议处理，现有成功完工结果继续返回。该入口在发起完工的请求内执行，进入财务前的进程中断仍需持久恢复设计。
- 到期的旧 `MES → FIN / OnWorkOrderCompletedAsync` 失败事件由后台就地转终态，保留原 ID、输入和尝试次数。只有工单号和操作者文本的旧调用仍返回 `FINANCE_OWNER_REQUIRED`。后台停用这类事件的自动财务重试。

## 本地模拟业务验证

在 Windows、.NET SDK 8.0.424、PostgreSQL 18.6 上执行。使用隔离端口 57374、真实 Main Program、签名 HTTP、模拟工单、工序、BOM、库存和角色。原始结果保存在 `D:/CP6-test-artifacts/W687-01/`。权限失败、结转回滚及零成本场景关闭独立库存财务桥和定时轮询以单独量度成本结转。成功场景使用默认配置，历史事件用例直接执行实际 Worker。

- `baseline.trx` 在改动前复现两项失败。完工及反冲成功后财务返回 `FINANCE_OWNER_REQUIRED`。旧 Worker 处理一条到期事件后存有两条财务事件。
- `verification.trx` 记录 24 项通过，其中 18 项使用 PostgreSQL、6 项为成本组件回归，零失败、零跳过。
- 实际反冲量 2.06172839，保存材料 11.71、人工 263.16、制造费用 56.96，结转生成三笔已过账凭证。重复完工返回 409，财务事件与凭证数保持原结果。
- 分别撤去归集或结转动作时，完工与反冲正常提交，财务事件记录 `ACTION_FORBIDDEN`。差异科目无法过账时，第三笔凭证返回 `E-FIN-104`，成本单、采番、凭证、期间与审计快照回到原状态。修复科目后从实际 HTTP 手工归集、结转，生成三笔凭证，原失败事件留存。旧事件连续轮询两次仍只有原事件，保持一次尝试。
- 受影响项目构建 161 个警告、零错误。复用 W685 的相同路由与权限元数据，更新可追溯的源码位置。任务级集中审查核对实际入口、原完工绑定、双动作及来源授权、事务回滚和旧事件处理。工作流触发规则沿用已核对的主线配置。
