## 原问题与改动

原网关用 `Pending` 查询，PostgreSQL 实际保存 `PENDING`，因此不能取得待打印作业。打印和完成 HTTP 共用 catch：完成已提交但响应丢失时，它发送新的 fail；打印异常或取消也被错误地当作未出纸。没有持久日志或实例互斥，重启丢失原命令键，无法区分未开始、可能已开始和只待完成回放。

Main 原标签入口只有早期授权，领取/完成各自开启事务，历史回执先于当前设备资格返回。实际原产品复现了七个入口在暂停后继续返回 200、五个写入口改变原行；真实撤销 label-print 后创建仍返回 200；禁用设备后原领取回放仍返回 200。创建回放采用后来修改的模板，不能保存原结果。晚期回执插入故障还实际造成 API 500、作业回滚后操作日志重刷一条孤立回执（Receipt 0→1）。

六个服务方法、对应七个 HTTP 入口现复用 IamAdministrationV1.ExecuteCurrentAsync、同一请求 Context、真实签名会话和最终会话/取消检查。模板采用 `wms-mobile:label-manage`，其他标签入口采用 `label-print`。共同认证根后按固定顺序取得标签模板、作业、回执及设备原生围栏；设备现有 Windows、Active、指定设备及仓库条件先于命令回放，在最终事务内决定。新增、状态转换、回执和失败跟踪清理共父事务，晚期失败不能被日志重刷。数据库不可用保持 503，提交未知保持原未知协议；Controller 保留客户端可读的字符串错误码及 no-store。

新 PostgreSQL 回执使用显式 `cp6-label-receipt-v1` 信封，绑定原外部输入，保存原结果 JSON 字符串。创建冻结模板格式和正文，后续列表及领取采用该快照；同键不同创建/命令输入返回 409。旧裸 DTO 回执原字节不改写，旧作业没有创建快照时保持历史范围，不伪造冻结来源。公开接口、单参数服务构造和原 wire DTO 保留；非 PostgreSQL 分支保留历史实现，未新增 SQL Server 验收或数据库迁移。

网关以真实 API 源、租户、actor、设备分区保存 metadata journal，持久化原 claim/complete OperationId、请求版本和状态。临时文件 WriteThrough/Flush 后同目录原子替换；作用域 OS 文件锁和实例 Semaphore 保证同一目录范围只有一个有效执行者。日志不保存令牌、模板或业务 payload，只保存标识、版本、阶段和内容摘要。不可写、损坏或错文件名记录立即报错，已有未决恢复先处理并阻止后续轮询覆盖状态。

领取响应丢失时用原 claim 键/版本取回原领取结果；调用打印前先持久化 PrintStarted，并再次核对当前上下文。打印异常、取消、崩溃或返回后尚未持久化 CompletionPending 的窗口均保持可见的 PrintOutcomeUnknown，不自动 fail 或重新打印。打印返回后持久化原完成输入，完成响应丢失只回放该原完成键。完成 tombstone 防止后续错误待办再次打印。

实际客户端传输也绑定该恢复分区：Cp6ApiClient 给请求附带本地 scope，DynamicApiEndpointHandler 禁止把恢复请求重定向到新源，BearerTokenHandler 在实际附加 token 和安全 GET 刷新回放时核对真实凭据身份，克隆请求保留 scope。普通请求继续使用既有动态端点行为，原单参数客户端/handler 构造保留。网关旧三参数构造保留明确的缺失身份错误，真实 DI 使用新增身份与文件日志依赖；没有静默 NoOp。
