# W439 · BUG-879-LPN-MOVE-COMPOSITION

2026-11-10 UTC。[Issue #879](https://github.com/GTX537/CP6/issues/879) 对应原 WP02-03 / PGT-017 的 LPN Move 实际写者。COORD 单人复用 DEV-2，分支 `codex/bug-879-lpn-move-composition`，基线 `495fd8e30d5e15cb460c73dee3be24f36adf640b`。本窗处理既有移动 API 的可用性、当前授权和事务组合；WMS-TRACE 后续完整合同仍按原任务实施。

## 实际根因和修复

非空 LPN 树先开始自有事务，再调用 PostgreSQL 库存公开独立 Owner。Owner 按合同拒绝已有事务，实际 HTTP 返回 500，日志含 `AUTHORITY_FENCE_UNAVAILABLE`，十三类原行保持。空树绕过库存调用，在租户暂停先提交后仍实际返回 200 并写入整树位置及回执。

LPN Move 现由已有 `OperationsOwnerV1.Mobile:lpn-manage` 持有共同认证根、业务表栅栏和当前 actor。普通命令包装共用原有业务错误回滚协议，Move 核心复用父事务。新增程序集内部 `MoveWithinOwnerAsync`，只供经过授权和对象检查的父 Owner 使用，复用既有库存元数据及两腿核心与事务继承。公开库存独立入口保持其原事务合同。

非空树仍需已有 `wms-stock:move` 动作、各实际库存键与源目的范围；空树也检查两端库区当前资格。回放在 Owner 内读取原回执，按原结果目的库位核对当前范围，不重算旧结果；同位置请求也要通过当前范围检查。库存流水继承实际 Stock 部门并纳入同一最终授权基线。两腿外部通知只在父 Owner 确认提交后调用，回放不重复通知；结果未知仍按已有 503 协议处理。

## 实际验证

明确模拟租户、角色、库位、库存、两棵 LPN 树和序列号，真实 Main Kestrel HTTP / PostgreSQL 18.6 隔离实例。两个场景使用独立租户：非空树包含根上的普通数量 `1.12345678` 与子箱中的独立序列号；空树同样含子箱。

| 场景 | 原版 | 修复后 |
| --- | --- | --- |
| 非空树正常移动 | HTTP 500，独立 Owner 拒绝 | HTTP 200，整树、库存两腿及序列号共同提交 |
| 空树正常移动 | HTTP 200 | HTTP 200 |
| 非空树暂停先提交 | 原版先在正常移动失败，未到此阶段 | HTTP 401，实际等待共同根，原行保持 |
| 空树暂停先提交 | HTTP 200，等待业务表后仍写入 | HTTP 401，实际等待共同根，原行保持 |

修复后 2 项完整场景通过、0 跳过。普通商品源数从 `10.12345678` 到 `9`、目的 `1.12345678`；序列商品源目的总量仍为 `4`。四腿按各商品净额为零，正腿准确引用负腿号。货主 CUSTOMER/CUST1、单位 BOX、估值 `123.4567`、原收货/失效时间、纸卷号、质量 HOLD 和召回标志保持，隐藏价格字段不会触发无关的价格写授权。子箱、SER1 到 DST，另一棵树与 SER2 留 SRC，原闭包保持；仅新增一条对应序列号位置流水。

为四个源/目的 Stock 使用真实部门映射管理入口，实际确认四条库存流水分别继承其实际库存部门、当前普通 actor，并产生相应继承审计。重复原操作号返回完全相同 JSON，十三类原行保持。过期行版本 409、目的不存在 400、目的封锁 409 保持原协议；缺少任一库区范围为 403，非空树缺少库存 move 动作为 403。旧回放和同位置请求在目的范围缺失时拒绝，有权时恢复原结果。

两个原生控制事务阻塞目标租户行和 LPN 表，真实观测暂停已持共同认证根、移动已在后端等待，再先提交暂停、后释放业务锁。两条绿色路径均返回 401 `REAUTH_REQUIRED`，完整写集逐字节保持，暂停后再次回放也为 401。合法 reactivate 后重新登录，继续完成范围与失败原子性检查。

在隔离实例给本次特定操作号的 `T_TaskCommandReceipt` 插入注入明确故障，故障发生在两种商品库存四腿、继承映射与审计、整树位置、序列号及 LPN 事件保存之后。实际返回 503 `AUTHORITY_FENCE_UNAVAILABLE`，完整原行恢复；触发器和函数由测试 finally 精确删除。十三类写集包括 LPN、闭包、内容、序列号、事件、回执、库存、库存流水、序列号流水、WMS 编号行、移动序号行、继承映射及继承审计。PostgreSQL 序列的合法空号不作为业务行回滚失败。
