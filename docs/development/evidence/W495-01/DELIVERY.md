## 原生保留入口

- 限流桶沿用已持久化的 `EraseAfterTicks` 和早删触发器。现行保留 Worker 在独立事务中对已登记租户按期限和批量上限清理，跳过占用中的桶。即使本轮没有待擦除的 Submission，配额维护也会运行。
- `ReadModelCacheIndex` 保存租户、缓存键哈希、Submission ID、原行版本和原期限。注册读取并锁定真实源行，精确重放保留原索引，冲突与陈旧版本被拒。租户复合外键关联不可变的提交消费原件。物理表保存引用元数据，当前回执与详情读取仍走各自的原件入口。
- 缓存索引参与保留单元发现，并在持有现行权限、租户租约及 hold 检查的原图事务内按自身期限删除。较早版本的索引可以到期，业务原件和当前版本索引仍按自己的期限保留。两类数据的提前直接删除均由 PostgreSQL 拒绝。原合成夹具的 409 拒绝和到期删除映射到原生存储与后台 Owner 结果。

## 实测

| 场景 | PostgreSQL 18 结果 |
|---|---|
| 限流桶 | 无 Submission 候选时每批只删 1 行。真实行锁下跳过已锁的到期桶，释放后再删。当前租户未来行及另一租户到期行保留。普通维护角色提前删除返回 23514。 |
| 缓存原期限 | 合法模拟历史中，NeedsReview 版本写入索引后由人工转 Lead 延长业务保留。真实当前版本通过注册入口加入，同键原绑定重放，异版冲突。早删当前索引返回 23514。先处理同资源其他到期原件后，下一轮只因旧缓存索引到期而发现该单元。删除旧行，当前索引的时间与 xmin、源业务版本、PII 和 seal 一致。 |
| hold、回滚、恢复 | 现行 hold 保留到期索引。释放后原权限源变化仍被拒。两个 PostgreSQL 锁超时分别覆盖制品删除及索引删除后的匿名化效果写入，业务图和索引一起回滚。以同一 Started 单元恢复后图和索引一起清理，再次恢复返回原终态。 |
| 真实宿主 Worker | 显式配置的宿主清除了到期限流桶，并将另一个伪造期限的业务候选记为失败，保留原 PII。后台停止已核对。 |

运行使用隔离端口 55574、.NET 8、PostgreSQL 18、实际 Kestrel HTTP 和现行签名/事务路径，业务及身份输入为模拟。 `retention-green-03.trx` 的 4 项通过，加上 `retention-green-02.trx` 中输入一致的原 24 月未到期及限流约束 2 项，共 6 个不同场景通过，0 跳过。

`retention-red.trx` 保存两处基线缺口。首轮构建缺少测试命名空间导入。第二轮实测发现跨到业务表的 FK 会创建内部触发器并触发已冻结 v4 目录校验。最终改用租户限定的原提交消费表作为 FK 目标，原生 v4 的目录门继续在实际运行中执行。历史原件使用 W491 同一隔离装载方式，缓存旧行在提交阶段由真实旧版本与期限初次写入。实际清理使用当前 PostgreSQL 时钟。日志、TRX 和资源记录位于 `D:/CP6-test-artifacts/W495-01`，四次自有 PostgreSQL 均核验停止。
