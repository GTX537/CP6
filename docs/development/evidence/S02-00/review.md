# S02-00 集中设计审查

日期：2026-10-12；方式：本执行对话一次任务级自审，**不是独立专家接受或用户批准**。范围是[本设计](../../../design-handbook/architecture/02-postgresql-tenancy.md)、[验收矩阵](../../acceptance/postgresql-tenancy.json)和准确来源清单；没有评审/修改业务实现。

| 审查点 | 结论与设计位置 |
|---|---|
| 用户 PostgreSQL 决定及 schema 优先评估 | §1 比较三方案并选择混合布局；不批准全库自动一租户一 schema |
| 共享与 tenant 数据、Main/CRM/Platform Owner | §2–3 以当前源码区分目录、IAM、业务、消息和 PublicRoute；保留未分类对象采用门 |
| 主键/唯一域不缩水 | §3 补齐所有主键/业务键的逐表检查；全局键表默认保持共享；消息全局唯一及 queueDomain 不变 |
| 可信名称、PG 字节长度、碰撞 | §4 GUID 确定名称与目录唯一；不接受用户对象名、不依赖截断；不改金额或身份合同 |
| 角色/共享 RLS/显式跨 schema | §5 专用 LOGIN、无跨租成员链；RLS 使用 session_user 可信映射；GUC 仅诊断；helper 最小权；普通角色实测仍 NOT_RUN |
| A/B 复用、取消、保存点、重试 | §6 专用池并强制错误出借负例；无 context 内切租；原operation 整事务重试、UNKNOWN 回查 |
| EF 模型/迁移支持边界 | §6 不声称 EF 原生支持逐租户 schema 迁移；自管映射、缓存键、历史与模型/池成本明确 |
| 原 Owner + Inbox/Outbox 原子性 | §7 同物理库/连接/事务；旧 Platform 自建事务和 CRM SqlTransaction 缺口留待实现；Main/CRM 跨库不虚称 ACID |
| 当前权限/暂停/恢复 | §7–8 scope 与当前最终门分开；技术重投/原结果读独立授权；不借角色或锁扩大写权 |
| 迁移中断、局部失败及回退 | §8 区分事务/非事务 DDL，共享及租户 lineage、锁、真实历史；只前向修复 |
| 单租户备份/恢复 | §9 包含共享切片及外部资产；不回退当前撤权、凭据/lease/已发送事实；不覆盖 B 或全局目录 |
| 成本和未测范围 | §10 档位是测量计划，未测容量/RPO/RTO不承诺；不以多租户高权账号换取成本 |
| 接受与实现/运行状态 | §11–12 和报告将协调交付、设计版本、真实采用分开；27 场景全 NOT_RUN |

本轮文档发现并修正：仅强调消息全局键还不足以保护其他全局 Id/业务唯一键，已补充“未证明 tenant 内唯一域则继续共享”的明确规则。该补充不改变业务代码和原合同，只关闭迁移设计歧义。局部复核范围为数据分类、对应恢复依赖和 PGT-025/027；无需扩大为全仓构建或业务回归。
