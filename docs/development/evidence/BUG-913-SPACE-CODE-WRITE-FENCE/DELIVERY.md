## 改动

现存编码规则新增、修改、删除、批量生成、单格生成五个写入口由原 `CodeEngineService` 使用同Context的当前 `space-code-rule:add/edit/delete/generate`、实际签名会话和认证父事务。认证共同根先于实际规则表SREX；生成冻结 `Space_CodeRule/Site/Floor/Zone/Aisle/Rack` 的原输入读取并对 `Space_Location` 取SREX。原查重、选规则、组码和两阶段写回在同一父事务，传递实际取消并做最终会话检查。回滚清理跟踪，已知数据库故障503，提交未知明确 `SPACE_CODE_OUTCOME_UNKNOWN`，无自动重试。

同租户同作用域默认互斥：创建默认规则先决定当前同作用域记录，已是默认的规则迁入其他作用域时清除目标原默认，其他作用域保留。没有新输入长度、范围、身份或模式限制，不更改原优先级/编码算法、数据表示、模型、索引、权限目录或已发布位置的既有范围。批量重建利用实际租户内非空码唯一索引，清旧码和赋新码一起提交。

原单参数构造器和非PostgreSQL路径保留，原接口请求、成功响应及业务错误不变。错误映射只附于五个写端点，原列表、无写合成预览和预检的读取实现、权限及响应头保持。原发布消费者继续使用原预检；本窗不采用新版LocationDraft/发布或Stock协议。
