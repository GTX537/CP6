# Disabled candidate gate and adoption boundary

The private implementation is `eng/wp01-01/decision-closure/gate_candidate.py`. It is not imported by `manage_roadmap.py`. `evaluate_candidate(root, contract_ref, submission, mode="actual", archive_root=None)` confines contract/evidence/authority files to the evaluation root, rejects path and symlink escapes, verifies SHA-256 and declared length, and parses JSON without duplicate keys or nonfinite numbers. Original archive sources alone may use an explicitly supplied read-only archive root; no archive copy is created. The caller supplies a pinned contract reference; a hash proves integrity relative to that reference, not who authorized it. Actual authority authenticity and remote ancestry are explicitly UNVERIFIED and always reject actual use.

`production_enabled`, `actual_adoption` and `actual_completion` are unconditionally false in every result, including a complete synthetic fixture. The CLI has no synthetic switch and no output-file/write/enable option. Tests call the isolated synthetic mode; every fixture authority/receipt/runtime record is marked synthetic. A positive result means only `SYNTHETIC_ALGORITHM_ONLY`, never a signed production record or business acceptance.

The supported checks read the decision package, delta, matrix, source files, adoption/authority file, obligation evidence and provider receipts. Each obligation's exact source set comes from its own `source_refs` and `owner_authority`, never from all top-level package sources. The immutable preparation input lock supplies original Git revision/representation when applicable; raw source shapes without byte lengths still require the exact declared SHA-256, without inventing an expected length. JSON pointers, line/excerpt and workbook sheet/cell locators are checked against those exact bytes. New delta obligations declare their own source references. Repeated navigation rows merge both assertions and source identities; evidence must bind that complete per-obligation source set. An unrelated but valid top-level source cannot replace an obligation original. A missing materialized archive source rejects with `SOURCE_FILE_MISSING_NOT_MATERIALIZED`, separately from the permanent legacy30/48 historical gaps.

Expected target obligation IDs and all observation/source-assertion values come from the pinned matrix plus the exact delta. Duplicate submitted IDs, missing/extra obligations, missing subassertions, source drift and a different target are rejected. Only PLM-ITER-01 and PLM-REL-01 are supported; the other 123 retain their original production gate.

The inherited matrix also contains 18 structured JSON source assertions (ITER 8, REL 10). Expected, submitted and evidence assertions use the same type-tagged structural comparison: all object fields participate, object key order is immaterial, array order and content remain significant, and JSON-looking strings cannot impersonate objects. Source data is not rewritten. Both actual target baselines must reach the explicit missing-obligation rejection; an internal type error is a validation failure, even though production remains disabled.

Every declared applicable edge must be present. The provider graph supplies provider/consumer repository/task and exact selected contract profile/version/hash. The receipt must bind those identities and package bytes, actual provider/consumer evidence files and remote/package identity. Missing selection (`null` profile/version/hash) is a real pending fact, never replaced with a made-up version. A nonempty string cannot stand in for a file. Synthetic fixture exclusion is possible only with an exact synthetic authority source and edge/target/condition/basis scope plus explicit graph permission. No current real edge has such permission; TASK_DELIVERY dependencies cannot become optional by scenario assertion. The transitive graph is planning closure, not a claim that one scenario uses every dependency; later authorized scenario-specific binding must preserve declared prerequisites and document narrowed runtime applicability.

Source and file-integrity checks are performed in actual mode where inputs exist, but the gate cannot validate a human signature, delegated authority, host observation or remote ancestry. It therefore cannot accept actual evidence. Missing evidence fails closed; STATIC, REFERENCE_ONLY, synthetic, NOT_RUN and FAIL cannot become real PASS. A local package, source baseline or successful transport ACK does not establish consumer adoption or remote main containment.

The three completion predicates are deliberately separate:

1. **WP01-01 task DONE:** exact prospective-basis adoption from verifiable append-only authority, authorized serial production gate integration and targeted regression, required ledger/source mapping updates, local checks and remote main inclusion. Candidate delivery completes only the design subset, so this task remains PLANNED / NOT_CHECKED.
2. **WP01 package inventory closure:** all 123 unchanged original inventory gates plus exact adoption and full coverage of the two prospective bases. Historical original30/48 gaps remain recorded. Inventory closure is not business completion.
3. **ITER/REL target DONE:** exact adopted basis, all inherited and changed assertions and applicable R1, real configuration/Owner implementation/runtime acceptance, exact provider-consumer dependencies and package/remote proofs for their actual owning repositories. Disabling a route cannot fulfill an obligation.

Physical mapping declares each table's physical columns, global internal PK, exact business UQ scope, FK local/target columns, indexes, checks and CAS predicate. TenantId participates in every local parent FK. ProjectNo and IterationNo remain tenant-wide unique; RoundNo is unique within the iteration. A single current-evaluation pointer on Iteration references an evaluation of that same iteration; its single selected candidate defines ActiveSelection. Re-selection appends history then replaces the pointer with CAS. The original nullable ReviewRoundId is not falsely made the evaluation uniqueness scope. REL retains exact original request keys, one root per execution intent, immutable release revisions, target scope versions and Owner receipt versions. Nonoverlapping reservation shares and exact allocation arithmetic require serialized Owner checks, not a hash-only or rounded numeric unique index.

Original bytes and Owner identities remain preserved. PostgreSQL `numeric` is only a bounded exact projection when it fits; original coefficient/exponent/wire bytes remain authoritative. PostgreSQL `text` cannot store NUL and timestamps cannot preserve every external submicrosecond value, so neither is a universal original representation. Internal UUID CAS is distinct from business revisions and existing compatibility bytea rowversion. Global original PK/UQ domains remain shared under `cp6-pg-tenancy-v1`; any proposed identity registration adaptation still needs its own reviewed adoption. Tenant schema names never confer authorization.

Issue #211 restores the independent original Id for Project, Iteration, IterationInput, CandidateObjectRef (candidate table `CandidateRef`), ReviewRound and ExternalRequestReceipt. Each retains required original Id bytes and a required `original_id_key`; `UNIQUE(original_id_key)` prevents two rows sharing the same registered complete identity independently of business keys. Project/Iteration have explicit bare-Id global PKs: their scope is empty and TenantId/parent cannot split equality or lock keys. The four grouped source entries retain exactly Id+TenantId[/IterationId]; a distinct source tuple may have the same raw Id. Bare-Id global scope for those four remains unproven and is not imposed. Parent components resolve original Iteration Id bytes through the same-tenant FK. Fixed original Owner/schema/domain and all scope components participate in full-tuple comparison; collisions never alias identities. Required Owner checks bind raw Id, registered key, exact source scope and tenant/parent assignment on every writer/import/recovery path. These remain candidate duties, not executed DDL or a runtime registry implementation. The superseded all-global intermediate design and first GREEN are preserved separately.

R1 ITER apply lock order and Platform InboxV1/OutboxV2 profiles are not assumed composable. The successor must audit every writer and prove a compatible ordering on one caller-owned connection/transaction. Unknown commit outcome is resolved by the original key under current read authority. No remote network call runs while holding Owner business locks; no new key is generated to escape uncertainty.

Adoption is a later append-only authority record over this exact manifest/version, with the true actor, timestamp, delegated scope and full basis choices. This package creates no such record. Coordinator serial public edits and production gate regression remain separate work. Approval alone cannot turn missing provider/runtime results into PASS.
