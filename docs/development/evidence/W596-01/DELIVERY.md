# W596-01 Space 版本预留与模板初始化的共同提交栅栏

2026-11-15 UTC。Main 基线 `7cd756c715d5a67ecf5170e1697b2781f79ad6cd`，受测源码 `b75c83d1ded887d8de0c1664accf892db5dde4f7`。使用实际 Main Kestrel、隔离 PostgreSQL 18.6、模拟租户、原发布版本、普通模型编辑者、系统与租户库房模板。 [缺陷 #1104](https://github.com/GTX537/CP6/issues/1104) · [PGT-017 #1012](https://github.com/GTX537/CP6/issues/1012)

- 空白与发布版本克隆各执行两种提交顺序。版本、活动草稿指针和原任务在原 Space Serializable 事务持有 Main 当前权限栅栏。暂停先提交返回 401，原写集完全相同；业务预留先提交保留原版本及任务。暂停可以发生在预留提交与最终 HTTP 回执之间，恢复身份后用同键完成或回读相同版本及任务。新键无法重复占用草稿。发布基准在预留与原操作恢复时核对。
- 系统与租户模板分别使原楼层先提交、暂停先于随后租约提交。旧会话返回 401，原任务、楼层及其回执保留，租约与布局未写入。恢复后由原键和楼层回执识别同一楼层，生成一次布局、位置和最终回执，回读写集相同。内部租约取得、续期与释放、布局和最终回执各在实际 PostgreSQL 事务检查当前会话；原有效内部键继续沿用，过长的合法 UTF-8 模板楼层键使用稳定散列。
- 基线 `baseline2` 在五条实际测试复现先后顺序不共用栅栏。最初保留了测试参数类型和标记属性的两次编译失败记录。最终 **29/29 PostgreSQL HTTP 测试，零跳过**，含本轮 6 项、W593 9 项及 W594 14 项；另有相关 Space 单元 **14/14**，零跳过。原 TRX、等待与写集在 `D:/CP6-test-artifacts/W596-01`。
