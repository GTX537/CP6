# BUG-911 — 字典写入当前授权与提交后缓存失效

W455-01；Issue [#911](https://github.com/GTX537/CP6/issues/911)；基线 `1a96df2468232bf44436cf2a12e2d5497f15912a`。本报告记录实际本地结果；最终远端采用、分支处置及DEV-2释放以对应PR、远端main和 `manage.ps1 finish` 为准。

## 改动

现存types/data新增、修改、删除六个写入口由同Context的 `DictionaryMutationOwnerV1` 采用既有 `dict:add/edit/delete`、实际签名会话和当前认证父事务。认证共同根先于实际 `public."Sys_DictTypes"`、`public."Sys_DictDatas"` 的SHARE ROW EXCLUSIVE表锁；查重、查行、级联删除、保存及最终会话/取消检查处于同一父事务。已知数据库故障503，回滚清理跟踪，提交状态未知明确返回 `DICT_OUTCOME_UNKNOWN`，不盲目重试。

类型编码原唯一业务要求在并发新增中串行决定，已存在编码仍用原本地化400；PostgreSQL编辑类型不能占用其他类型编码。未增加编码字符、大小写、长度、数量或合法ID限制，不改模型、索引、存储表示、菜单授权或包。

实际两表和 `dict:{typeCode}` 缓存原本全局共享、没有TenantId，本窗保留该真实范围，未声称租户专属。types/data/options三段读取、下拉启用过滤/排序/DTO/30分钟缓存、原构造器用法与历史非PostgreSQL路径保持。原返回实体、保存计数、404和输入合同保留；数据修改仍使用原记录的TypeCode，不改其归属。

四处原缓存失效位置（数据新增、修改、删除、类型级联删除）移到父事务确认提交后，继续使用原键和服务。回滚/权限失败不会提前清缓存。缓存服务故障发生在数据库提交后时不声称回滚；本窗不提供可靠缓存outbox、未知提交后的缓存协调或其他 `DictService` 独立IMemoryCache采用。类型改名的既有数据关联语义未在本窗重写。
