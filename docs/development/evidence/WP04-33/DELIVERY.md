## 实现

- 既有产品身份接口从 `T_ProductMaster` 原版本见证读取原 UUID、经营料号、品目与三个枝号、原单位码及原状态。当前和历史响应均携带原 Owner、版本与摘要。按同名检索时，每条候选仍有独立 ERP 身份。工程键和既有订单的 `ProductCd` 保留各自原值。
- `POST /api/products/identity-owner-v1/qualification` 在一个 Main 读取事务内接受精确的原产品引用，以及可选的原单位绑定版本、币种政策引用与双 Owner 映射引用。单位必须绑定所选产品版本和摘要。币种通过已采用的 `CurrencyPolicyOwnerV1` 精确读取，含启用状态。显示的币种政策属于本次显式选择，产品币种绑定仍待证。
- 已确认的工程映射给出映射、ERP、工程与物理站点的独立版本引用及真实双方确认。当前采用仍走原身份与站点门。原版本能回读其确认和用途，当前资格变化会使原引用失去新采用资格。
- 旧创建、复制、修改和 WMS 序列写入沿用 PostgreSQL 已采用的产品原版本捕获。旧删除将原主账和工序、材料、档价、联产四类子表交给同一次保存。陈旧 `RowVersion` 时共同回滚，原版本和现有子表可继续读取。历史正文、SKU 和 UUID 均沿用，使用现有 PG 历史存储。
