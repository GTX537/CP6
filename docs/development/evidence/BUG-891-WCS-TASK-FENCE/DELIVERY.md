## 根因与改动

原 list/detail 两个 GET 只有登录校验，无 WCS 动作权限；六种写操作只依赖 HTTP 早期权限，没有最终当前身份/动作门。实际原实现的八个受阻请求在暂停先提交后仍返回 200，六种写操作改变原行；没有 view 动作的用户仍能取得列表和明细。原生撤销 add 后，已进入请求仍创建任务。

原创建先由 WmsSequenceService 单独 SaveChanges 保存编号，再插入任务。测试在实际任务 INSERT 处注入一次原生故障，API 返回 500，却观察到 Numbers 0→1，Tasks 也由 0→1：失败任务仍在请求跟踪器内，被后续操作日志保存重新写入。其余库存、流水和商业出库单原行保持。不是只推断可能残留，完整 JSONB 快照保留实际结果。

八个服务方法现在复用 IamAdministrationV1.ExecuteCurrentAsync、实际签名会话与同一请求 Context。六个写动作继续采用原 `wms-wcs-task:add/dispatch/start/complete/fail/del`。两个读取入口显式采用 `view`，并在实际 WmsPermissionSeed 的 OwnerActions 目录登记该新读取点；目录不自动授予任何角色，采用环境须通过现有 IAM 显式分配 view。未新增字段、仓库/部门、OEM 或设备资格合同。

共同认证根后以固定顺序取得实际 WCS 任务围栏；创建还核同 Context 的现有编号服务并取得编号表围栏。编号、任务及最终身份/取消决定共父事务；失败复用 IAM 的回滚和跟踪清理，后续日志不能重刷失败业务。数据库不可用返回 WCS_AUTHORITY_UNAVAILABLE 503，提交未知保持 WCS_OUTCOME_UNKNOWN，不自动重试。原 WCS API 没有操作意图键，本窗未把它描述为已经具有新版原键设备恢复。

公开 IWcsService、两参数构造、原 DTO、过滤条件、手工状态转换、业务错误与八位数量保持。非 PostgreSQL 使用原实现。Program 显式注入同一 Context/IAM/实际会话和请求取消；Controller 采用已有 OrderOwnerResult，六个原 InvalidOperationException 捕获排除 Owner 错误，保留正确 401/403/503 和 no-store。没有模型、迁移、平台包、库存效果或外部设备调用改动。
