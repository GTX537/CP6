# ERP 共享消息域对象与写入入口

日期：2026-10-15；任务：WP02-02；本轮源码基线：`f6cc17b936d05b0336d319cbfa5097a77511d658`。本清单用于 ERP 八表隔离实现准备，采用 [S02-00 §3/5/7](../../../../design-handbook/architecture/02-postgresql-tenancy.md) 的 Owner、共享域、RLS 与共同提交边界，不新增审查轮次或验收门。

键、列类型和约束复用 [PostgreSQL EF relational inventory](../tenant-connections/postgresql-ef-relational-inventory-7837009a.json) 的 `ErpIntegrationContext` 项，并核对当前 [模型](../../../../../CP6.Core/Services/ErpIntegration/ErpIntegrationContext.cs) 与 [PostgreSQL baseline](../../../../../CP6.Persistence.PostgreSql/Migrations/ErpIntegration/20261002151345_PostgreSqlErpIntegrationBaselineV1.cs)。原 inventory 是 `7837009a` 的模型准备证据，复用了此前构建；本文没有重新提取模型或查询数据库目录，不将它改称本轮运行证据。

八表均由 **Main ERP 集成 Owner** 持有，固定在同一 Main 物理库的 **`erp_integration`**，均有 **`TenantId uuid NOT NULL`**；Platform 只提供消息库实现。下表列出全部 PK、AK 和唯一索引；八表均无 AK、无模型 FK，表内关联与业务引用仍由 Owner 协议核对，不能推断为恢复时无依赖。`PK_*` 均为对应表的主键名。

| 对象（Owner / 位置） | PK；其他唯一索引 | 已知写入入口 | 同事务写集 / 恢复依赖 |
|---|---|---|---|
| `CommandInbox`（Main ERP / `erp_integration`） | `PK_CommandInbox(MessageId)`；无其他唯一键 | `ErpRequestHandler.ProcessAsync/RecordFailureAsync` 写原 payload、哈希、状态与冲突证据；`ErpCommandRetryWorker` 经 handler 重试；`ErpInboxReplayService` 重置待处理状态 | 命令：与 `Request/Aggregate/Outbox` 及实际业务变更同事务；重放：与 `InboxReplayAudit` 同事务。恢复原 MessageId、原字节、绑定 tenant、状态及重试证据 |
| `Request`（Main ERP / `erp_integration`） | `PK_Request(TenantId,Kind,AggregateId,RequestVersion)`；`IX_Request_TenantId_RequestId(TenantId,RequestId)` UNIQUE | `ErpRequestHandler.SaveOutcome` 新增或更新原请求结果；失败记录也走该路径 | 与 receipt、aggregate、结果 Outbox 同事务；恢复 InputSha256、原 RequestId、终态与 ResultDataJson，不能重算后替代原结果 |
| `Aggregate`（Main ERP / `erp_integration`） | `PK_Aggregate(TenantId,Kind,AggregateId)`；无其他唯一键 | `ErpRequestHandler.LoadAggregateAsync/NextResultVersion` | 与命令写集同事务；恢复请求/aggregate/result 水位，保留原 `c03:aggregate` 锁域，不用通用 Inbox checkpoint 替代 |
| `Cp6_OutboxMessage`（Main ERP / `erp_integration`） | `PK_Cp6_OutboxMessage(Id)`；`IX_Cp6_OutboxMessage_MessageId(MessageId)` UNIQUE | handler → `Cp6OutboxStore.Enqueue`；`ErpEventDispatchWorker` → Platform claim（含 `ExecuteUpdateAsync`）、发布/失败状态；`ErpDeliveryReplayService` 重排原消息 | Enqueue 与命令写集同事务；最终失败与 `Cp6_DeadLetterRecord` 同事务；操作员重放与 dead-letter 标记及 `DeliveryReplayAudit` 同事务。恢复 payload/hash、原键、已发送事实及 lease，发布在提交后 |
| `Cp6_DeadLetterRecord`（Main ERP / `erp_integration`） | `PK_Cp6_DeadLetterRecord(Id)`；无其他唯一键 | Platform `Cp6OutboxStore.MarkFailedAsync` 新增 outbound 证据；`ErpDeliveryReplayService.RequeueResultAsync` 调 `RecordReplay` | 与 Outbox 最终失败或重放同事务；恢复 MessageId/hash/方向/原失败与重放证据。ERP command 死信保存在 `CommandInbox`，不能用本表替代 |
| `OrderBridgeDispatch`（Main ERP / `erp_integration`） | `PK_OrderBridgeDispatch(TenantId,OrderKey)`；无其他唯一键 | handler 新增；`ErpOrderBridgeWorker.DispatchOneAsync` 更新尝试/完成/失败；`ErpDeliveryReplayService.RequeueBridgeAsync` 重排 | 新增与真实订单及命令结果同事务；重放与 `DeliveryReplayAudit` 同事务。恢复原 OrderKey、完成/失败/lease 状态并核对订单及 WMS/MES 原效果 |
| `InboxReplayAudit`（Main ERP / `erp_integration`） | `PK_InboxReplayAudit(TenantId,OperationId)`；无其他唯一键 | 仅 `ErpInboxReplayService.ScheduleOnceAsync` 新增 | **Append-only**；与 `CommandInbox` 重排同事务。恢复原 OperationId、MessageId/hash、输入 token、操作者、原因、前次次数和时间 |
| `DeliveryReplayAudit`（Main ERP / `erp_integration`） | `PK_DeliveryReplayAudit(TenantId,OperationId)`；无其他唯一键 | 仅 `ErpDeliveryReplayService.ScheduleOnceAsync` 新增 | **Append-only**；result 重放与 Outbox/dead-letter 同事务，bridge 重放与 dispatch 同事务。恢复原 OperationId、Kind/TargetId、消息证据、输入 token 与操作员决定 |

`CommandInbox.MessageId`、Outbox `Id/MessageId`、dead-letter `Id` 保持原全表唯一域；RLS 不得通过增加 TenantId、复制到租户 schema 或冲突时换键来缩小它们。两张 replay audit 的 EF SaveChanges guard 已拒绝 tracked UPDATE/DELETE；直接 SQL/bulk 不经过该 guard，新租户角色的数据库权限也须保留 append-only。其余六表需要已登记状态更新权限；本文未发现已接入的 ERP DELETE 入口，不据此授予清理权。

事务与 SQL 的实现依据是 [ErpRequestHandler](../../../../../CP6.Core/Services/ErpIntegration/ErpRequestHandler.cs)、[Inbox replay](../../../../../CP6.Core/Services/ErpIntegration/ErpInboxReplayService.cs)、[Delivery replay](../../../../../CP6.Core/Services/ErpIntegration/ErpDeliveryReplayService.cs) 和 [DatabaseSharedContext](../../../../../CP6.Core/Persistence/DatabaseSharedContext.cs)：命令与两类重放使用 Serializable；子业务 context 共享调用方连接并 `UseTransaction`。PostgreSQL 锁由 `ErpSqlLock` → `DatabaseResourceLocks` 的事务 advisory lock 实现；Outbox/bridge 重放另有固定 `erp_integration` 的 `SELECT … FOR UPDATE`，OrderKey 按现有 `bpchar` 比较。八表保持同一宿主库，各次操作涉及的写集必须共用同一物理连接和 `DbTransaction`。

[OrderBridgeWorker](../../../../../CP6.WebApi/BackgroundServices/ErpOrderBridgeWorker.cs) 在原订单提交后持有 dispatch 锁，WMS/MES hook 使用自己的业务 context；不能把 hook 效果说成原命令事务的一部分。Platform `Cp6OutboxDispatcher` 也为 claim、成功/失败状态分别取 context，网络发送在中间。此处对 Platform 的核对源为正式 `0.10.3` 的 `1277da5e0a20c6d96f0a95d0e9b4f20e0008332a`，路径 `src/CP6.Platform.EntityFramework/Cp6OutboxStore.cs`、`Cp6OutboxDispatcher.cs`，不等于新租户 worker 已采用。

还须保留现有非表依赖：[PostgreSqlModelConfiguration](../../../../../CP6.Core/Persistence/PostgreSqlModelConfiguration.cs) 的文本容量、`bpchar`、`C`/`public.cp6_ci_as_provider_v1` 比较语义；容量 CHECK 调用 `public.cp6_cp936_length_v1(text)`，函数定义见 [PostgreSqlManagedTextV1](../../../../../CP6.Core/Persistence/PostgreSqlManagedTextV1.cs)，前置定义校验见 `PostgreSqlMigrationPrerequisitesV1`。六个可变表由 [token manifest](../../../../../CP6.Persistence.PostgreSql/PostgreSqlErpIntegrationTokenTablesV1.cs) 和 [token installer](../../../../../CP6.Persistence.PostgreSql/PostgreSqlTokenV1.cs) 安装 `cp6_rowversion_v1` BEFORE INSERT/UPDATE trigger，调用 `cp6_storage_erp.set_rowversion_v1()` / `cp6_storage_erp.rowversion_v1` 生成 8-byte `bytea` token；两张 audit 的 `InputRowVersion` 是原输入证据。收紧 public/函数/sequence 权限、恢复或部署共享域时必须包括这些依赖，并保留 ERP 独立迁移 lineage。

保留与恢复仍有明确待登记范围：Core/WebApi 当前未发现 `Cp6MessageRetentionService`/`DeleteExpiredAsync` 调用，未找到八表获批准的期限、legal-hold 判定或清理调度。Platform 同名服务是潜在 bulk DELETE writer，且还访问 ERP 模型明确忽略的 `Cp6InboxMessage`，不能直接接入或把库默认天数当成 ERP 保留政策。`Cp6OutboxStore.RequeueDeadLetteredAsync` 是另一潜在写入口，当前 ERP 操作员路径使用自己的 service 以共同提交审计。采用前需核对部署脚本、运维/导入/修复工具、实际数据库触发器及其他 raw/bulk 调用，登记完整 writer 与删除责任；本文仅覆盖所列源码路径。恢复遵循 [S02-00 §9](../../../../design-handbook/architecture/02-postgresql-tenancy.md)：同快照业务数据与八表 tenant 切片、原字节和原结果、IAM/外部效果水位及上述共享定义依赖；保留 TenantId，核全局键冲突，旧 lease/已发送事实先对账，不自动重放。

当前业务采用边界：[ErpIntegrationConfiguration](../../../../../CP6.WebApi/Configuration/ErpIntegrationConfiguration.cs) 的 legacy factory 仍使用 `DefaultConnection`，三个 `Erp*Worker` 仍消费该 factory。handler 与 [ErpQuotationOrderFactory](../../../../../CP6.Core/Services/ErpIntegration/ErpQuotationOrderFactory.cs) 含显式 `public."T_WebBusinessPartner"`、`public."T_Quotation"`、`public."T_QuotationDetail"` raw SQL；Orders 与 `Sys_Tenants` 等 IAM/业务访问仍依赖旧 `CP6Context` 映射及 TenantContext。八表 RLS/EF adapter 不使这些入口成为新租户业务路由；本轮不把 legacy factory、worker 或业务服务接入新路由。全库对象/writer 清单、IAM 与业务 schema 采用、共同授权最终门、实际迁移/恢复仍属后续范围。
