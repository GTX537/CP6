# BUG-917 — 空间层级七写与货架坐标原子性

W458-01；Issue [#917](https://github.com/GTX537/CP6/issues/917)；基线 `7ff0ae085aba7cee41570bbeffc8dcd083df9a84`。本报告记录实际本地结果；最终远端采用、分支处置及DEV-2释放以对应PR、远端main和 `manage.ps1 finish` 为准。

## 改动

库区新增/修改/删除、巷道新增/修改、货架新增/修改七个写入口采用已接入的同Context当前 `space-floor:edit` 父事务。原签名会话和认证共同根先于实际Floor/Zone/Aisle/Rack/Location引用读锁与写锁；查重、子项判断、最终会话/取消与业务写入同一边界。原503、未知结果及回滚清理沿用现有父事务。没有新授权目录、模型、索引、包或工作流。

PostgreSQL库区创建确认当前租户实际未删除楼层，巷道/货架创建确认实际未删除库区。货架FloorId仍由库区得出，拒绝无源空FloorId；可选巷道为空保持，非空须属于实际货架同库区，编辑按已保存的ZoneId决定。原多边形/尺寸、坐标、字段及层级编辑不重挂保持，不给旧历史补值或迁移。

原货架更新与 `LocationGeometryService` 重算保存都在同Context父事务；原RowVersion冲突409保持，重算沿用原算法/已放置范围，不改LocationCode、Status、Version，不引入发布事件。传递请求取消，保留坐标服务原公共构造和调用方式。错误映射仅七写，原读取、巷道/货架删除、场景差量、发布和其他处理体保持。
