## 实际行为

旧入口从直接查表改为采用当前 `OperationsOwnerV1`。租户、当前角色、动作、对象范围和字段决定均在同一 PostgreSQL 事务中核对。对接已采用的业务伙伴原 UUID 及本人、部门、下级部门、自定义、全租户范围。[W163 身份来源](../W163-01/DELIVERY.md)

| 入口 | 当前权限和行为 |
| --- | --- |
| 查重 | `query`。只返回当前对象范围内有效记录的存在状态。 |
| 详情和列表 | `query` 加 `profile-query`。后者单独授权完整档案，保留旧身份查询的最小授权范围。对象范围先于计数、分页和投影。名称不可读时返回 null，按名称筛选或排序返回 403。 |
| CSV | `query`、`profile-query`、`export` 及独立 Export 字段决定。同一对象范围下导出全部匹配行，保留既有列定义和编码。BpName 隐藏时名称列留空，拒绝名称筛选和排序请求。 |
| 新建、修改、删除 | 分别采用当前 `add`、`edit`、`del`。删除同时要求当前管理员角色。新建要求 BpName 写权，旧创建请求可在本人或全租户范围登记，部门范围因旧请求缺少可信归属返回 403。修改保留原代码、UUID 和既有行版本语义。 |
| 保存后回读 | 写入不依赖档案查询许可。明确缺少档案查询权时返回成功及 `data:null`。具备当前档案查询权时按字段决定投影保存结果。回读来源故障使整个事务失败，业务写入与原身份版本同时回滚。 |

有权修改其他字段的使用者可以省略名称或传 null，保留原名称。名称只读且可披露时，旧整表请求可以回送相同名称。隐藏名称不得显式写入。原本合法的金额、数量表示及交易伙伴关联沿用已接受合同。ERP 集成在自己的事务里使用已经选定并锁定的对象运行原校验。Vue 页面接受隐藏名称的档案和无回读的成功响应，保存、导出按钮采用相应动作。

PostgreSQL 前向迁移 `20261116033000_BusinessPartnerProfileUsesV1` 和启动种子登记 `profile-query`、`export`。两项都是动作目录定义，角色需由授权管理员显式分配。正式业务伙伴写入和原身份采集继续使用原表与同事务触发器。
