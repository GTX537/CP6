# W581-01 旧 OA 批量办理逐条核对当前权限

对应 [缺陷 #1079](https://github.com/GTX537/CP6/issues/1079) 和正式 PGT-017。基线 `a33d9c25fb87a160f33aace835d94b079df7c400`，受测源码 `769af18abdab67dad7d5df99095de1a89224c502`。本地 PostgreSQL 18.6、真实 Main Kestrel、隔离模拟业务和连接器。

批量 API 复用既有 Main IAM 事务根。每条分别读取当前权限、待办归属与可编辑字段，再保存办理、流程状态、业务回调和通知。正常批继续按输入去重并逐条回报。确认丢失或基础设施异常沿既有 503 错误传播。受事务保护的旧代理办理保存同步 Web API 的持久派送任务和既有子流程恢复凭据，由提交后的 Worker 接手。

- 基线实际阻塞通过 PostgreSQL 锁观察。管理者先提交撤权时，两条仍错误批准；第一条批准先提交时，第二条也错误批准。修复后撤权先提交得到两条 `IAM_FORBIDDEN`，无批准、终结或通知。首条先提交时只保留一条原批准历史、流程终结及通知。原会话再次请求被拒绝；IAM 更新产生一份原快照更新、Outbox、审计与回执。
- 共享外部节点实测分别覆盖退回和批量审批。模拟提交拒绝期间 HTTP 返回 503，零外部请求、零持久作业，旧待办保留。成功时先提交服务任务，再由真实作业服务按已提交任务标识送达，独立连接可读原办理结果。再次扫描无新效果。
