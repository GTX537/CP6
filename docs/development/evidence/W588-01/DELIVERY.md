# W588-01 旧 OA 事件 HTTP 与持久重试的事务栅栏

[缺陷 #1091](https://github.com/GTX537/CP6/issues/1091) · [PGT-017 #1012](https://github.com/GTX537/CP6/issues/1012)。Main 基线 `0d4225e8bff26b12cf13f3d936e260b2655d19d9`，实际受测 `5e185830dff0600414fe2034671f8c841e0b3336`。隔离 PostgreSQL 18.6、实际 Main Kestrel 和集成重试 Worker，使用模拟租户和事件。重试测试注册真实 Dispatcher 和 WF Hook，并限定扫描到夹具租户。

- Echo 先获取 Main 共同根，复验当前会话，提交前再确认。源事件账、合法工作流实例、触发流水、任务、历史和水位同事务提交。旧格式的合法部分失败仍保存已发起实例、原失败流水和可重试事件账。原事件 ID 完整保存在负载和触发键，原公共台账的显示列依旧使用 30 UTF-16 单元，未拆分代理对。
- 后台重试用独立租户 scope，在同一根内重查当前租户和原待重试行，流程与计次在同一提交。暂停先取得根时不推进次数、不产生业务效果；允许先提交时保留原效果。后续重试按原事件键只补尚缺的一条，原回执和事件行保持身份。外部调用交由既有提交后任务，死信通知在该次事件状态已提交后调用原通知器。
- 基线 4/4 失败。两个等待不到共同根，另两个观察到流程尚未提交而试发流水已出现。最终 `verified/results.trx` 5/5 通过，覆盖 HTTP 和 Worker 各两种真实等待关系、暂停和恢复、150 UTF-16 单元原键与部分提交恢复。初次组合结果 `final/results.trx` 中 29 项通过、5 项断言失败。四项把权限基线取在另一个会推进根的管理读取之前，长键用例误要求既有部分失败响应填写 matchedCount。只改夹具与断言后复验，沿用该次产品二进制的 25 项 PostgreSQL 和 4 项分派回归通过结果。一次并行尝试因 Windows 测试宿主占用程序集而停止，串行复验通过。所有失败原样保留。
- 局部发布核对 310 个文件 SHA-256，实际 Kestrel 存活 200、匿名 Echo 返回 401。产品发布二进制与两次测试相同。日志、TRX、摘要、实际停止记录位于 `D:/CP6-test-artifacts/W588-01`。Actions 无启动、重跑或取消，未部署。
