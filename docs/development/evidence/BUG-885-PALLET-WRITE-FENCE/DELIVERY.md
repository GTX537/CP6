# BUG-885：托盘元数据最终授权与编号原子性

## 原问题与改动

六种现存写入口只有请求早期的 RequirePermission：创建、更新、完成、移至待发运、标记发运、删除。实际暂停先提交后，六种请求仍返回 200 并改变记录。真实原生角色动作撤销先提交后，已进入的更新仍返回 200。创建还先由 WmsSequenceService.SaveChanges 保存编号，再单独插入托盘；插入故障返回 500，编号仍增加。

现复用 IamAdministrationV1.ExecuteCurrentAsync、真实签名会话与同一请求 Context，按各自 wms-pallet 动作在既有共同认证根内决定。托盘表的原生 SHARE ROW EXCLUSIVE 围栏稳定对象状态，位置与角色库区表的 SHARE 围栏稳定直接 SQL 竞争下的区域、封锁及授权范围。最终再检查现有会话，沿用 IAM 提交未知协议，返回 PALLET_OUTCOME_UNKNOWN 503；数据库失败返回 PALLET_AUTHORITY_UNAVAILABLE 503，不盲目重试。

源范围取已存托盘的仓库和实际库位，目的范围取实际位置主数据；区域不接受客户端声明。新增位置须存在、未删除、未初始化隔离且未封锁。历史元数据仍可由仓库全域授权维护，不把新位置准入套用到未改变的历史位置。实际输入字段按当前聚合的已有字段权限检查，仅对变化值要求可写；只读字段原值回传允许。身份、审计用户名取当前 actor。创建只采用同 Context 的既有编号服务，编号与托盘同父事务；失败清理跟踪对象，后续操作日志不能重刷失败对象。

六个 Controller 写方法采用既有 OrderOwnerResult，保留安全的 401/403/409/503，原业务 400 消息、DTO、三位重量和状态转换保持。两参数构造函数仍可用；实际 Program 显式注入 IAM、会话和 RequestAborted。无模型、迁移、共享 Owner 或公共接口变更。
