# BUG-903 — 功能变更申请当前授权与流程父事务

W451-01；Issue [#903](https://github.com/GTX537/CP6/issues/903)；基线 `3e3a333f16cade8e9974f4cd9262de206b8be28c`。记录已执行本地结果；最终远端采用、分支处置和 DEV-2 释放以对应 PR、main 和 `manage.ps1 finish` 为准。

## 原因与改动

既有功能变更申请 Get/Submit/Cancel 在请求入口检查缓存动作后，未在实际业务边界重新决定当前授权。提交和撤回分别借用真实 ApprovalService/FlowEngine 与 TaskCenterService 的 SaveChanges，但没有拥有整个请求的认证父事务。原生故障后业务跟踪仍在，随日志保存重刷；缺失绑定时未保存的申请也可能成为孤立记录。

三个入口现在采用既有 `wms-mobile:device-manage`、实际签名会话和同一个 CP6Context 的 IAM 父事务；认证共同根先于申请表锁，读取 SHARE、写入 SHARE ROW EXCLUSIVE。写入时锁定当前仓库、功能配置和实际审批绑定/定义/版本引用；实际旧 OA/WF 提交或撤回保存处于该父事务内。结束前校验同一会话并传递请求取消。父事务回滚清理跟踪器；未知提交明确返回 `WMS_FEATURE_OUTCOME_UNKNOWN`，不盲目重试。已知审批配置缺失/无效 `E-WF-031..034` 明确转成 503，数据库故障返回 503。

原三参数构造器、非 PostgreSQL 历史路径、业务校验、成功体和内部 ApplyApproved/ApplyRejected 回调保持。PostgreSQL 请求的申请人取当前可信 actor。OperationId 历史回放、规范化、单仓待办唯一、双人分离、版本、证据及保留天数合同保留；既有非依赖业务错误映射保持。没有新增权限、默认授权、实体、迁移、包、工作流配置或通用流程引擎改造。
