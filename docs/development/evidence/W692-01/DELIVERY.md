## 业务行为

- 进程内 Finance Costing 以 `COST_ATTRIBUTION` 在真实外层事务暂存采用意图。费率发布按批准范围引用一个成本中心版本。工单归集按会计日为采用已管理中心的每个人工、制造费用行保存精确中心及工序，用实际成本行 ID 分批。多个成本行使用同一中心时分别保留。单批最多 64 项，单效果最多 1,000 项和 64 个不同中心。
- PostgreSQL 从实际事务中的意图取同账套、同工序及当期有效的批准原件，回执保存原版本、有效区间及批准记录。数据库提交检查批次完整、事务一致和实际结果关联。费用回执关联到成本单的不可变归集版本，后继归集可追溯原用版。已登记的旧兼容中心沿当前用版规则，既有历史无补签回执。
- 费率发布保留原产品身份。已成功的原凭据在当前账套、发布资格及来源读权校验后返回原结果。原工序改版影响新采用，重放不再以当期有效性否决已完成的发布，也不会重复产生发布或采用回执。
- 当前进程内采用限现行制造费率发布和 A2 归集的工序成本中心。完整 FM15 通用登记、标准化原件及其他用途沿 WP11-04 接续，FIN-COST-01 的完整计算、标准依据与账套级结转继续依原任务。显式手工重归集仍保存新业务版本。[FIN-MASTER-01](../../../design-handbook/modules/FIN-MASTER-01.md) · [FIN-COST-01](../../../design-handbook/modules/FIN-COST-01.md)

## PostgreSQL 本地验证

Windows、.NET SDK 8.0.424、PostgreSQL 18.6，隔离端口 57379。实际前向迁移、签名 HTTP、费率审批和发布、MES 完工、手工归集及实际金额。账套、工单、库存、费率基础和专业角色使用模拟业务数据。多批场景模拟已批准的上游中心与费率，采用和成本效果均由生产入口写入。

- `baseline.trx` 在 W691 已受测程序上复现原发布重放返回 409。最新构建零错误。34 项定向用例通过，其中 28 项使用 PostgreSQL，6 项为成本组件回归，零跳过。`affected.trx` 3 项通过，`final.trx` 31 项通过。
- 中断费率发布的最后业务写入，数据库回滚采用及发布变更。用原预览凭据再提交成功。工序改版后，原凭据仍返回同一成功结果及原采用记录，其他人无法用该凭据读取。
