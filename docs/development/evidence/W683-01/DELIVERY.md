# W683-01 库存与收发货单价权限

COORD 在固定 DEV-1 从远端主线 `722fa775db0acbc4aac3c37d1bd3a4f6a3905230` 领取 `codex/w683-01`，依赖 W682-01。已验证产品与测试提交为 `48beb2049498e7e0b963ef4acc9066cd85074fde`。范围是库存、入库单、收货和出库单价的直接消费者。简体中文为标准。[P0 #1210](https://github.com/GTX537/CP6/issues/1210)

## 核对与修复

- 库存列表、单票历史和流水先限定当前范围及仓区。UnitPrice 不可读时返回 null。独立调整与原操作采用当前目标用途；原操作成功回执返回标识和数量等约定字段。移动保持原对象单价和数量。看板价值、盘点、效期及呆滞库存沿用各自已采用的来源价格决定。PostgreSQL 旧报表独立导出仍返回未采用状态。
- 入库单和收货详情按各自当前 query、对象范围和 UnitPrice 决定投影。入库新建和修改、收货过账采用各自价格 Write。收货参照入库计划只使用经过核对的标识、物料和数量，服务端不复制计划价。显式填写的收货价由收货字段写权控制。可见收货交易和新行沿库存父事务落地。采购适配器和委托的生产成品收货不从计划或采购单复制价格。
- 出库详情按当前授权隐藏单价。创建和修改采用目标价格 Write。从订单展开采用来源订单 query、完整对象和 UnitPrice Read。从制造展开无来源价格。拣货、发货和取消使用当前出库状态及有效对象，保留出库已有单价和历史流水合同。
- 针对 #1210，分配仍选择原 FEFO 候选和检查库位。实际选中库存行后，在 RSV 和缺价出库明细写入前检查来源 `wms-stock:query`、UnitPrice Read 和原生库存 UUID 的当前范围。来源价为空也经过该门。已有出库价不被覆盖。只有实际采用候选库存才消费此价格用途。来源参与原事务最终权限门，失败回滚整个分配。
- 四个直接控制器及页面 API 没有独立单价导出、下载入口。WMS 原数值域为数量 decimal(21,8)、单价 decimal(18,4)。本次验证域内八位数量和最大四位价格精确保留，订单自身八位单价继续按既有独立合同使用。
