## 实际行为

- 新的最终工序完工、工时更新与以原完工 UUID 标识的待处理记录同事务提交。记录本租户工单、完工数量、原操作者标识和签发引用，复用现有集成事件表。原签发引用用于验证数据库中的原会话。JWT、Cookie 和刷新令牌留在原认证边界。
- 反冲沿用按材料提交的补偿单位。库存流水、实际用量和剩余材料清单同事务保存。首次反冲前按当前 BOM 取待反冲的材料，重启只继续清单中的剩余部分。财务进入前在事务内核对反冲进度。
- 前台完工请求和集成 Worker 从同一待处理记录继续。每步核对当前租户、原访问签发的有效期和撤销状态、原 MES 完工身份及当前授权，归集和结转分别检查 `fin-cost:collect`、`fin-cost:settle` 及工单、产品、费率来源。权限失败后当场记录终态，保留已经提交的制造和反冲结果。
- 成本单、采番、WIP/FG/差异凭证和原财务事件终态同事务提交。多个实例在现有 PostgreSQL 事务门内读回同一原事件。遇到提交结果不确定时由后续轮询读取原事件和反冲进度。会话到期或撤销、权限拒绝、已知财务失败可由获授权人员处理原因后用既有手工入口。早期中断且库中缺少本次新增待处理记录的工单走现有人工入口。

## 本地 PostgreSQL 验证

.NET SDK 8.0.424，PostgreSQL 18.6，隔离端口 57375，模拟工单、BOM、库存、财务角色、费率和科目。用实际签名 HTTP 提交完工，取独立数据库连接暂停目标 SQL，确认提交点后强制停止实际 API 进程，再启动带实际集成 Worker 的应用进程。原始结果保存在 `D:/CP6-test-artifacts/W688-01/`。

- 原主线 `baseline.trx` 复现一条完工及材料反冲已提交、后续财务待处理记录缺失。
- `restart.trx` 五项通过。分别在首次反冲前、部分反冲后及全部反冲后结束原进程，恢复读取同一完工。部分反冲的已提交材料保留，两笔材料流水各一笔，材料成本合计 14.25。两个实际重启服务同时竞争原完工，成功只生成一张结转成本单和三笔已过账凭证，原事件一次终态。采用有效费率，人工 263.16、制造费用 56.96。
- 在重启前分别撤回结转动作和撤销原访问签发，两例恢复均保留制造结果及终态事件。成本单、采番、凭证、期间和财务审计的 PostgreSQL 快照保持原值。
- `verification.trx` 初次合跑 23 通过、2 项在旧反冲用例准备阶段遇到全局菜单键冲突。两项旧用例在全新隔离库 `backflush.trx` 通过。26 项定向用例通过，其中 20 项使用 PostgreSQL，6 项为成本组件回归，零跳过。受影响项目构建零错误。
- 任务级集中审查覆盖原会话和当前来源权限、共用事务门、两个进程竞争、反冲进度、后续重读及财务原子性。与 W685 相同的权限登记和 MVC 元数据用于更新源码位置。台账结构、生成页及四份项目状态已同步。
