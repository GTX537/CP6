普通 LOGIN 的同一 PostgreSQL 事务可执行真实库存移动原语，写原库存数量、流水、TXN 业务编号和不可变移动序列。现有盘点冻结判断只读取活动盘点和库位键。原生写者规则继续保护已有库存键。固定 NOLOGIN 入口基于本事务创建的流水和归属行记录部门继承及安全审计。普通角色只能调用固定入口，隐私原表和任意审计写入依然受限。Core 前向迁移按实际对象进入仓库草稿和部门校验，保留旧 Owner 的原谓词和触发器。

## 实际验证

Windows、PostgreSQL 18.6、Npgsql 8.0.8、net8.0，使用 SDK 10.0.302 和隔离的模拟租户、部门、用户与库存。

- `stock-writer-exact.trx` 的实际普通登录用例通过。真实服务应用 `2.12345678` 调整，单事务提交或回滚库存、流水、编号、移动序列、部门映射、审计、原 journal 和 Outbox。其他租户的同键库存保留原数量。活动盘点和受保护库存键按现有规则拒绝，固定入口拒绝为历史流水补写部门映射或重放审计。
- `stock-final.trx` 的四项旧 Owner 场景通过，覆盖三种部门范围以及部门管理的租户、CAS、审计和原回执。该批中新的库存测试夹具因两类测试共享同一要求新建的 PG 根目录而未启动。改用独立新根运行新增用例，结果记录于 `stock-writer-exact.trx`。
- `warehouse-regression.trx` 的两项真实 PostgreSQL 回归通过，覆盖库位的隔离初始化和等待草稿仓库提交的旧库存写者。最终补入部门分流时，这段仓库触发器与回归输入一致。审查逐一核对部门触发器的 30 个非库存原谓词。
- Release 安装工具在自有 PostgreSQL 的独立模拟库实测旧 Core 布局拒绝。生成的 EF 前向迁移成功应用后，实际安装回包与原读安装和数据库身份一致。读回技术序列的 `USAGE`、租户仓库草稿键及隔离审计权限。 `cli-dispatch.log`、各阶段原始 TRX 和 PostgreSQL 日志保存在 `D:/CP6-local-test/CP6-72H-20261109/W330-01`。
- 基线保留了普通登录的权限失败。定向实测依次查明盘点头投影、技术 RowVersion 序列、仓库草稿分流和共享部门校验的必要关系。一次诊断因遗漏显式夹具端口在认证阶段被拒，随后用已确认的自有夹具重新抓取 SQL。原始记录分别在 `freeze-query.log` 和 `freeze-live-query.log`。

集中审查覆盖库存与账务数量精度、同事务原写集、原生保护与历史对象、最小授权、前向迁移及旧入口回归。保留既有构建告警。普通 Actions 为手动入口，R2 自动入口匹配版本标签。本窗使用隔离本地环境，Actions 触发、取消及生产部署为零。
