# CodeGen旧元数据显式接入V1

在[版本元数据V1](codegen-metadata-v1.md)上增加明确接入，原MetadataId始终为旧GenTable.Id，不按同名重建身份。只有用户指定旧ID、读取并核对原件后明确调用接入才写入；前向迁移本身不导入任何旧数据，也不执行既有环境切换。

|调用|合同|
|---|---|
|GET /api/pub/codegen/metadata-v1/{旧ID}/legacy|当前view权限；返回MetadataId、SourceFingerprint、Document；未找到404，已接入409|
|POST /api/pub/codegen/metadata-v1/{旧ID}/legacy/adopt|OperationRef、SourceFingerprint；当前可信租户/原会话，新操作须view+save；不接受替换Document、TenantId或主体|
|POST 同根路径/saves/read|沿用原操作查询，可恢复保存和接入的原回执；须原主体和当前view|

旧Table和Columns均按当前租户过滤。锁住两个旧表的原生写入入口后读取一致原件；指纹包含完整表/列实体，包括原ID、租户和审计字段。列按Sort再Id稳定排序，不丢Sort或重编列ID。Document完整映射原渲染字段和固定模板cp6.codegen.crud.embedded/1.0.0；原表列保持原字节意义上的数据值不变，V1仅保存其版本化渲染文档。旧记录不符合当前固定模板输入合同就明确拒绝，旧原件保持，可在未接入时经原管理入口修正后重读；不静默截断或替换字段。

接入先查询原操作，再校验新操作权限、目标未版本化和当前原件。原件变化412、目标已版本化409、同租户旧名称不唯一409；目标不存在404。同键异义409，保存命令和接入命令使用不同原输入形状，不能互相冒充。同一原操作恢复不受后来模板、原件、版本或save撤销影响，但必须仍是原主体、有当前view和有效会话。

接入在现有Owner独立PG事务/IAM完成门下写V1 documents/versions/commands和adoptions，首次Revision=1。adoptions为tenant+原ID不可变关联与接入原件指纹；不复制另一份旧审计原件。提交前失败全部回滚；提交开始后无法确认结果返回UNKNOWN，按原ID/原OperationRef查询或原样重试，不换键盲重试。

表/列锁与旧入口DML互斥。接入后数据库拒绝旧表更新/删除、旧列插入/更新/删除及移入移出；存在接入原件时拒绝旧表/列TRUNCATE。旧Save沿用已有23514到409映射。原ID和旧名称均不能从普通Save绕过接入；已接入同一ID可以继续按V1 CAS保存。V1随后改名不删除旧原件，旧原名称仍保留，不能另建对象夺用。旧读取/旧预览仍展示冻结的历史原件，当前修改应通过V1读取/即时预览；不宣称旧读取自动重定向。

此实现采用共享Owner表及少量元数据管理操作的事务表锁，可能暂时等待其他旧元数据写入；10秒锁等待上限及明确失败沿用原Owner。不是分布式文件事务，也没有一租户一schema或新增权限证明层。数据库权限和TenantId现有边界保留。

Vue输入旧ID→读取旧原件（明确替换草稿）→将读取的旧原件接入V1。接入只提交读取时的原件指纹，不包含用户随后修改的草稿；成功后保留当前草稿，可重新预览并以Revision=1继续保存。412保留草稿且要求重读旧原件。接入原命令在发送前存当前身份的sessionStorage；未知刷新恢复原ID/命令/原件，查询404或后续拒绝仍保留原记录。W262旧pending格式直接兼容，正常保存不会误走接入接口。身份变化隔离和晚到回复拒绝复用已有实现。

本期实际验证使用模拟业务数据、本地隔离PG18和真实Main会话HTTP；页面采用实际Vue/Chrome与明确API/身份夹具。没有生产部署、批量迁移、文件应用、历史删除或编号业务消费者切换。
