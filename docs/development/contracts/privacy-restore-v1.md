# W315：Main 身份墓碑与受控恢复候选 v1

本窗实现中，未验证或远端采用前不称交付完成。来源为 WP02-15 / SYS-PRIV-01；仅覆盖已真实完成的 Main.Identity.Profile.v1 处置。原历史/审计/文件/CRM业务等未接入Owner继续明确PARTIAL；不决定生产灾备、跨环境身份发行切换或部署资格。

## 独立权威与受控候选

原Main源库保留已完成execution及最小不可变墓碑，不被恢复覆盖。恢复仅面向新建的另一PostgreSQL库，物理数据库身份由实际server address/port/database OID/name绑定；运行配置登记CandidateId、RegistrationVersion、私有连接引用、备份SHA-256和显示名。客户端不能传连接串、路径、数据库身份、审批人或墓碑内容。候选数据库comment使用保留标记`CP6-PRIVACY-RESTORE-CANDIDATE/v1/{CandidateId:D}`，位于单库非create恢复之外；实际恢复工具必须保留owner/ACL与数据库级元数据。

业务数据恢复前停止候选应用/worker；按现有受控新库流程执行真实pg_dump -Fc及pg_restore --exit-on-error --single-transaction，禁用clean/create、no-owner/no-acl和禁用触发器。候选前向迁移到当前代码，安装隐私门后再启动验证宿主。源库、候选库身份不同，且环境绑定必须相同。此处只在测试新库运行，不恢复或迁移已有环境。

已完成处置自动产生墓碑。普通Sys_Users原生/EF/批量写者必须保留去标识化用户名、空个人字段、停用和无TOTP/PIN/外部登录映射；允许原有非识别授权/组织引用按其自身合同变化。删除用户后再用相同稳定ID插入个人资料仍拒绝。旧库已有不符合既存处置的资料时迁移失败，不能把不一致当新基线或静默清理。

同一物理库的保守判定使用实际数据库名及OID，连接地址别名不能绕过源/目标分离或未决责任互斥；不同集群恰好同名同OID时也先拒绝，须独立安排无歧义候选。完整批准仍绑定实际地址/端口等精确身份。已处置稳定ID不得移动到新ID/租户，删除后也不能把该ID重新分配到别的租户。

## 来源版本、批准与效果

policies/holds/tombstones的权威版本在同一IAM门内推进。恢复预览绑定源/候选物理身份、可信配置版本/备份、环境、当前来源版本和完整已接墓碑集合的范围；受控当前政策/hold不满足则保持隔离。计划冻结预览，申请人与独立审批人分开，restore-prepare / restore-approve / restore-execute分权。批准及真正执行重核当前身份、权限、版本和目标库身份；静态预览不代替最终门。

执行先在源库保存不可变责任意图，再持有源IAM门并取得候选IAM门。在候选同一事务内重施已完成的Main身份效果、认证撤销、真实身份投影/消息、墓碑与原候选回执，最后写隐私开放记录。候选事务只在源宿主最终会话核对通过后提交；随后保存源结果。没有新增跨库原子性的承诺，两个提交之间结果未知必须按下面协议处理。

不存在于旧备份的主体保持不存在，仅安装墓碑以阻止将来复活，不能记录为删除了资料。旧备份仍有平台身份的主体不得由隐私恢复暗中撤权；保持候选隔离，先由独立IAM恢复解决。实际存在的普通主体复用W314唯一身份效果，不复制原PII到字段审计或回执。

申请、审批元操作与执行责任均按环境、操作者租户及稳定操作者分区；当前操作者改变租户不把旧租户的原操作转移到新租户。当前read只恢复本分区原结果。

## UNKNOWN与开放门

源责任意图和原结果分开。相同操作/不同输入冲突；已知APPLIED只读返回原结果，不要求旧restore-execute仍有效。候选提交应答未知或候选已提交而源提交未知时，源意图保留，GET查询不能自动再次处置；显式recover只核对准确候选原回执并保存已知事实，当前read即可，不能变成新执行。NOT_FOUND不是无效果；close在源门和候选门内核对真实回执，已提交则恢复原结果，否则保存CLOSED，迟到请求不得产生效果。

受管候选所有业务HTTP在认证/输出之前核对独立源结果、准确源/候选身份和当前来源版本，保持源门到响应完成。缺配置、缺原结果、候选未重施、来源不可用或政策/hold/新处置改变都失败关闭。候选提交而源结果尚未知时不会提前开放。原操作历史与当前开放资格分开，历史成功不保证当前仍可读写。

此门只证明已接隐私Owner的恢复条件。身份发行切换、其他消息/业务一致性、外部文件和正式环境切换仍使用各自原有恢复及R2门禁；本窗不启动候选worker对外投递、不冒充生产恢复或完整灾备。

候选通过隐私门后仍须使用独立源库的隐私处置/恢复API；候选自身的该API返回`PRIVACY_RESTORE_USE_SOURCE_PRIVACY_AUTHORITY`，不能以备份中的旧政策在候选另建权威。登录和其他受当前源证明约束的验证请求按原合同执行。正式改变权威的环境推广仍是独立任务。

可信候选配置已有独立源连接时，数据库标记缺失/损坏必须503，不能落入普通主库通道；此模式只接受PostgreSQL。普通未配置恢复的既有宿主仍使用原数据访问合同。
