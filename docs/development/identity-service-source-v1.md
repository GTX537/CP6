# C02 service principal source v1

This is the explicit PostgreSQL Main publisher and CRM native current-source inspection delivered by W116. It supplies source evidence, not public submission acceptance or H01 authorization.

## Contract and cutover

`service-principal.changed.v1` uses aggregate `service-principal:<UUIDv4>`, source profile `cp6-inquiry-service-v1`, tenant, confidential client ID, stable principal UUID, department UUID, full-range integer role subjects, enabled/deleted state, persisted authentication epoch, registration version and monotonically increasing registration revision. No credentials or human identity are exported. Snapshot version is allocated by the existing locked aggregate writer; snapshot, generation and normal/priority Outbox retain one database transaction.

The current bundle is 1.3.0. The retained 1.1.0 and 1.2.0 manifests and all existing event assets remain byte-for-byte unchanged. CRM verifies these retained subsets and refuses service events for old source registrations; 1.1 sources still refuse permission v3. Existing native source registration is immutable. Enabling a new producer requires a separately reviewed source-registration/storage upgrade or new explicitly installed native source with the new bundle digest and a freshly collected full baseline. This task does not migrate any existing environment or relabel old evidence. Activate consumers before enabling emission.

## Main host configuration

Existing `InquiryServicePrincipals.Enabled`, `Version`, `Registrations` and mapped `CrmOidc.ServiceClients` remain the authority. Additional opt-in fields are `IdentityPublicationEnabled` (default false), `IdentityPublicationRevision` (positive Int64), and each registration's `AuthenticationEpoch` (persistent UUIDv4). Principal and department identities remain explicitly configured UUIDv4; role IDs are actual Main integers. Keep credentials in the existing secret configuration, never this C02 configuration or event.

Changes require stopping ingress and draining **all** affected producer/consumer instances before coordinated restart. Increase both the registration version and revision, and assign a new persistent epoch to changed active registrations (a global version change rotates the active cohort). Credential rotation also requires this update. Never derive the epoch from a client name, a startup counter, or an unpersisted random startup value. Reusing a revision with changed public registration facts is rejected. Older instances cannot overwrite a newer source or resurrect a tombstone; an old once-published issuer also checks current source under the Main authentication root before signing.

The opt-in worker waits for the existing C02 bootstrap to be ready for the exact bundle, then reconciles this host-owned source profile in each configured tenant using its own PostgreSQL transaction and the existing authentication root. It does not install storage. Disabled clients publish enabled=false with no role grants. Removing a registration emits a tombstone through the priority Outbox. To retire all registrations, keep publication enabled with a new revision/version and an empty registration set until removal is published; turning the worker off alone is not a revocation. Keep the tenant in the C02 source mapping through this retirement step. Existing known service snapshots are not regenerated as human users by bootstrap.

Permission issuance with publication enabled requires a successful local publication commit, then checks the exact stored registration, epoch, version, revision and roles inside its current IAM transaction. Failed commits never open readiness. This is a Main point-in-time producer; it does not claim instantaneous Main-to-CRM revocation or cross-database locks. Stop/drain during source cutover; CRM publication freshness and invalidation remain mandatory. The new publisher uses the Main Owner PostgreSQL context; adoption by separate tenant-schema source hosts is outside this delivery.

## CRM current service inspection

`IdentityProjectionGraphV2.ServicePrincipals` preserves original native source references. Enabled service principals depend on actual healthy departments and existing role sources. Duplicate active client bindings and any human/service principal UUID collision close graph publication. Disabled/deleted role sources remain explicit facts and never grant actions. Disabled/tombstoned service facts can be published to carry revocation.

`PostgreSqlIdentityServiceInspectionV1.InstallAsync` is an explicit migration-identity operation for an isolated/new approved database. It installs only `crm_identity_service_inspection_v1.lock_service_v1(uuid,boolean)`, no business tables, and never runs on application startup. Grant the runtime reader USAGE on that schema and EXECUTE on that exact function in addition to existing identity read privileges. No table UPDATE privilege is required. The function uses SECURITY DEFINER with fixed pg_catalog search_path, private schema/function ACLs, exact source/signature/owner checks and the existing seven-lock inventory. It locks the actual fence, ingress state and publication rows FOR SHARE so an intervening writer after a Serializable snapshot produces 40001 rather than stale identity.

`HoldCurrentServiceAsync` receives trusted in-process expected client/principal/epoch and the real online expiry only after online authentication has finished. It holds current native identity state in the caller's Serializable transaction. `RequireCurrentServiceAsync` must run immediately before the Owner's final business gate and commit; it checks the original store, connection, transaction, actual PostgreSQL xid, source, fence, publication and expiry. Any failure aborts the complete business attempt; no in-transaction retry, network call or commit is introduced. Npgsql transaction object reuse cannot reuse this evidence.

Both returned objects have `CanAuthorize=false`. They do not authenticate input strings, validate a service JWT/JTI, manufacture a browser session, or authorize an action. The actual H01/public-submit Owner must still obtain real Main-signed service permissions, bind that capture to the current service source, apply current role/site/form/action/field/resource rules, and perform the full original business graph and final gate in one transaction. This downstream adoption remains uncompleted.
