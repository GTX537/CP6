# 资源能力目录 v1

`Main.Mes.ResourceCapability.v1` 保存机器和工作中心的版本化能力声明。机器入口 `/mes/machine-capabilities`，工作中心入口 `/mes/work-center-capabilities`，API `/api/mes/resource-capabilities/owner-v1/{kind}`。读取使用原 `mes-machine` / `mes-work-center:query`，登记须独立 `capability-edit` 动作；迁移登记动作，不授角色权限。对象范围沿原资源的租户、创建人和可信部门映射，历史与原操作回查也要求当前来源读取权限。

## 原件与声明

资源沿用实际 Machine / WorkCenter UUID，目录键为 Tenant + Kind + UUID，版本从 1 递增，独立于原资源的资料、能力描述、归属和控制版本。目录只保存有权人员的声明，不修改原资源表及其效力。记录含准确资源 Owner/Kind/UUID/version/digest、当时完整原资源原文、所用 UOM 及时间含义原文、作者、登记时间和原因。历史原件不可修改、删除或截断。

机器能力按完整数组替换，每项含唯一键、DECIMAL 或 ENUM、量纲、有效期间和依据说明。DECIMAL 使用固定 8 位小数、最多 13 位整数的十进制字符串，支持负值，不经浮点；必须引用实际单位，其量纲和数值精度必须相容。ENUM 与数值/单位互斥。期间必须带时区、最多微秒，终点不含且晚于起点；原文本保留。空能力数组表示尚未声明具体能力。工作中心不接受机器能力数组或产出单位。

工时表达单位需准确 UOM 及其真实时间含义版本；不能从 `TIME`、`HOUR` 等名称推测单位。原主数据中的分钟、秒、小时数保持其原字段含义，选择表达单位不会改义或自动换算。原默认 480、null、0 和宽精度数值按实际原件保留，不被认作已核实产能。产出单位、工时单位未选时明确报告缺项。

依据说明是操作者声明的来源说明，**不是已验证的外部证据、现场测量或专业批准**。响应资格固定为 `DECLARED_NOT_QUALIFIED`，始终保留 `RESOURCE_QUALIFICATION_REQUIRED`。本目录不替代正式 RES-WRITE-1 的能力变更预检、Assignment/Effect 计划、技术适配、准入 Claim，也不授予生产 Start / WO 许可。

## 当前来源与恢复

写入以 `ExpectedVersion=absent` 或准确目录版本进行 CAS，同时核对当前原资源、单位及其基准单位、时间含义。来源变更、停用、伪造摘要或读取拒绝不能产生新版本。历史仍保留原文，同时报告当前变化；不能将历史成功作为当前资格。所有来源与最终授权在实际 Main PostgreSQL 同一事务内参与，版本、头、原请求、结果和审计共同提交。数据库延迟约束要求原资源、单位原文及原操作结果关联存在，缺件整体回滚。

命令携调用方 OperationId；同键同体返回原结果，同键异体拒绝。同内容保存仍核权限/当前来源与 CAS，保存本次原结果而不增加目录版本。结果查询及关闭为 `operations/{id}` 和 `operations/{id}/close`：未发现返回 UNKNOWN，关闭与迟到提交同锁竞争；关闭先胜则迟到写入拒绝，提交先胜返回实际原结果。页面只持久保存当前租户/用户下的操作、种类与对象 UUID，以 Web Locks 协调页面，不存私有正文、不自动换键重发；身份变更和拒绝读取时清理私有数据。

## 工艺采用

工艺步骤可显式增加 `ResourceCapabilities`，每项必须属于该步骤已经选定的准确资源，并固定目录原版本。保存新路线核当前目录及所有原来源，历史路线保留原引用。目录有后继时，旧路线原文不变且报告 `RESOURCE_CAPABILITY_CHANGED`，不能暗中替换为最新版本。旧路线未含此可选成员的原件保持可读，不额外序列化 null 改写其内容。

工程来源检查保存实际目录原文及当前观察，能力声明仍不能让资源资格通过；内部制造基线冻结、工具现场资格、REL/VER/WO/SCHED 采用均保持各自前置。
