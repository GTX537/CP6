1. 每仓库原生版本化ClockPolicy，独立clock-policy动作、当前权限/范围/仓库字段及CAS；真实环境与部署授权来源绑定，同事务不可变原件/journal，原UUID查询/关闭恢复。
2. 部署明确登记POSTGRESQL_CLOCK_TIMESTAMP_V1来源、REAL/DEMO、环境、有效期和已认可的不确定度；默认不可用，客户端不能设源时刻或自授可信性。源配置是运营者的时钟信任声明，并非代码自动证明NTP同步。政策准确绑定来源内容摘要，变更/失效/停用拒绝旧政策；未配置不回退本机或用户时间。
3. 读取真实PostgreSQL advancing clock，并测量单调耗时；源声明不确定度加观察耗时形成保守时刻区间。持久观察高水位拒绝已观测回拨；区间越界、政策未知、读取过慢返回未知。无来源配置不宣称真实时钟验收。
4. 只评估准确原生候选的有效期，CURRENT取可信区间，PLANNED使用明确带偏移的指定时刻且始终预测。边界不确定返回UNKNOWN，半开区间[from,to)；原始偏移和七位小数保留。当前权限/字段/版本/环境最后再核。
5. 独立仓库时钟政策维护与历史/恢复页面；规则审批页展示时间评估，当前身份/权限变化清除敏感内容，未知原操作不自动新建。
6. PostgreSQL/Program HTTP定向边界、跨租户/撤权/CAS/事务回滚、真实取时与回拨/过期来源；相关Vue/types/build，一次完整diff审查。后台构建测试活动时不编辑后台输入。
