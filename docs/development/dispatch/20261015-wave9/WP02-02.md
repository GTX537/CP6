## 要完成什么

在真实 `IdentityMessagingContext` 的固定共享 schema `crm_identity_priority` 接入租户行隔离和已有事务租约，并让 Identity 与 ERP 适配器能在同一个物理连接/事务中顺序执行、共同提交或回滚。此上下文不需要租户动态模型，不将共享消息表复制到每个租户 schema。

实际四表为 `Cp6_DeadLetterRecord`、`Cp6_InboxAggregateCheckpoint`、`Cp6_InboxMessage`、`Cp6_OutboxMessage`，均保留 TenantId、Id 主键、RowVersion 与原字段/排序规则。Checkpoint 唯一域为 ConsumerName+TenantId+AggregateId；Inbox 的 ConsumerName+MessageId、Outbox 的 MessageId 保持全局唯一，不能改成 tenant 内唯一。保持 `IdentityPriority` 基线及 `cp6_storage_identity` token 表的真实行为。

从已合并 ERP 安装器提取单一受保护目录/最小 helper 公共部分，分别处理首次创建和对已知 v1 布局的精确验证后追加 Identity 层；不能复制第二个租户权威目录，不能用 IF NOT EXISTS 接管未知对象。保留 session_user 的 OID+名称绑定、helper 专用 NOLOGIN Owner 和最小权限、FORCE RLS、旧行 USING/新行 WITH CHECK。目录全局事务锁 `(1129330260,1)`、VOLATILE 先锁后读及目录 I/U/D 排他锁规则两上下文共用；目录 TRUNCATE 继续拒绝。

精确扩展可支持的 model/migration profile 与 queue domain，使同一租约明确兼容两个实际上下文；不得接受任意 profile。复用每条 EF 命令前 scope/catalog/身份校验、安全异常和租约生命周期；在一个 TenantStorageTransaction 下顺序调用适配器，不删除并发保护、不嵌套重入 Execute。不要把 DbContext 或连接外借到回调外。
