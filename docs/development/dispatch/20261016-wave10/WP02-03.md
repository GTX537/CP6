# A / WP02-03：字段权限确定性决策

本轮交付可直接供后续 Owner 采用的纯计算组件。完整任务依赖 WP02-02，仍为 PLANNED/NOT_CHECKED；本窗口 CONFIRMED。依据 [任务卡](../../task-plans/WP02.md#wp02-03) 和 [SYS-IAM-01 第5节](../../../design-handbook/modules/SYS-IAM-01.md)，不重新设计权限语义。

## 实际行为

新增 `FieldPermissionDecisionV1` / 必要的 evaluator。输入显式描述同一决定的 registry 版本与完整字段域、有效角色的真实存行、字段映射及各用途约束；输出每字段 Access、来源、用途可用性和可解释的拒绝/不可判定原因。实现前对照原设计的准确字段/版本语义，不凭逻辑名称新增跨仓公共 wire schema。

先按 resource+field 对实际存行取 MIN，之后才为完整有效 registry 域的缺项物化 Access1，来源 `REGISTERED_DEFAULT`；显式聚合为 `EXPLICIT_AGGREGATE`。角色 A 缺行+B3 必须得到3；A缺+B2得到2；A2+B3得到2；显式A1+B3仍按既有MIN得到1；不能逐角色先补1。未知或不完整 registry、未知字段、非法 Access、同一身份冲突存行、版本错配不能默认放行。不同角色不同合法 Access 正是 MIN 输入，不应误作重复冲突。

读、写、导出、下载分别与显式提供的动作/对象/映射及适用约束求更严交集，字段1不能补对象或动作权；缺失必要限制不自动视为批准。组件只证明给定输入下的计算，不能认证调用方自报的 registry、角色有效性、当前授权版本或 Owner 最终提交权。对输入作不可变快照，不保留可外部篡改的集合引用。

## 范围与验证

`FieldRegistry` 当前只是可覆盖静态集合，`PermissionAggregator` 已按存行 MIN，旧 `FieldPermService` 的 null/0 掩码及恢复只读值属于 legacy。本轮这些文件与 CurrentPermissionContext、SensitiveFieldPolicy、公共接口/模型/真实权限入口都只读，不将新组件悄悄接到旧授权链。不删除或重写旧行为测试。

定向验证上述 MIN/默认顺序、未知/冲突/版本输入、用途交集、输入不可变和重复计算一致即可；无数据库或宿主测试。一次集中审查，已有合同证据直接引用。真实认证、完整字段注册发布、撤权 fence、缓存与业务 Owner 接入明确留待后续。
