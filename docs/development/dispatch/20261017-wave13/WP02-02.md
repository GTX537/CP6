# WP02-02：已登记服务租户的资格目录控制命令

> 第十三轮新对话 B 的唯一窗口；使用 executing-plans，按本仓精简验证节奏执行。

**目标：** 为已有service-token-v1安装中的已登记租户提供明确的资格目录控制操作，消除只能手工SQL提供真实Sys_Tenants行的缺口。

**架构与技术：** 复用PostgreSQL18/.NET8、现有五表profile、单物理事务、受保护映射和control owner验证。仅业务行DML，不增加表/列/helper/ACL，不更改现有profile或seal；客户端凭据只经私有stdin输入。

来源：[任务卡](../../task-plans/WP02.md#wp02-02)、[真实签发交付](../../evidence/WP02-02/service-issuance/DELIVERY.md)、[SYS-TENANT-01](../../../design-handbook/modules/SYS-TENANT-01.md)。核对 tools/CP6.TenantStorage/README.md、Program.cs、ServiceRevocationInstallation、ServiceTokenProfileV1 和真实Sys_Tenant字段/冻结baseline。既有服务签发/自撤销已完成，不重复实现。

- [ ] 定义有版本的私有stdin控制命令：inspect准确单租户；initialize只为已在login_tenant登记且缺失的Sys_Tenants行提供明确合法TenantCode/TenantName及资格输入；set-eligibility按预期旧Enable/ExpireDate做null-safe CAS，只更改启停/到期字段及必要原元数据。
- [ ] 每次操作同事务验证物理目标、独立control owner、installation/profile/seal、准确登记映射；复用/提取安装验证仅限保持所有旧语义。不能信任请求自报fingerprint，不能使用runtime或默认业务连接操作目录。
- [ ] 锁定准确租户行；不存在行的初始化需要明确串行约束，避免先查后插入竞态。保留唯一Code/容量/Id和现有本地timestamp without time zone、null不限期语义。更新与发行helper的FOR SHARE自然串行，不改签发入口。
- [ ] 明确输出当前状态、CAS冲突与提交不确定性；提交后丢输出只能标记UNKNOWN，inspect不证明某请求执行过，CAS不解决ABA。新命令不得沿用旧安装器“同输入重试即可恢复”的幂等承诺；真实原结果槽留到独立版本化任务。
- [ ] 自有PG55436验证初始化/重复与唯一冲突、未登记租户、CAS/空值/期限边界、同一行锁与发行资格读取竞争、wrong identity/profile/seal拒绝、取消/回滚和不确定输出分类。用真实库及相关CLI，不用mock证明权限或原子性；共享安装验证有改动才补旧profile对应恢复一次。

**边界：** 不改PG baseline/seal SQL、实体/迁移、映射、角色/凭据，不删除租户，不创建admin/角色，不替代TenantAdminService或业务审计；不是完整租户创建、在线配置更新、同请求持久恢复或全Main采用。旧CLI的安装/恢复合同保持。完整WP02-02仍IN_PROGRESS/CONFIRMED；原17PGT及真实业务验收不提升。
