## 包外但属于原任务的必需断言

四条 INQ 包内向量只覆盖来源路由，不能代替原任务的字段与 decoder 一致性。至少补充下列真实 C#/TS 合同用例，记录各自来源/字段与预期，不修改共同输入包：

- 全部 38 个定义集合和 C#/TS 对应关系；55 处原引用修复及 257 处最终引用解析；生成重跑无漂移。
- 合法与非法字段、required/缺失/null、枚举、闭集 unknown-property、Unicode codepoint 长度边界，包含补充平面字符；不得用 UTF-16 长度冒充 codepoint。
- 三类 source-exact event 的 envelope 和 data 上合法 boolean extension 接受，非 boolean 扩展拒绝；TS 的 unknown index 形状保留、可编译，不能把已知字段限制成 boolean 或把未知属性任意放行。
- `uniqueItems` 使用结构相等：对象属性顺序不影响相等，数组顺序有意义，数字的合法等值表示一致；不同 JSON 类型不混同。覆盖实际 Schema 中对象数组的重复情形，不能只测字符串去重。
- 根/嵌套/数组/转义等价键的重复拒绝，且在目标类型反序列化前发生；required NullOnly 必须额外确认属性存在，不能仅靠转换器。
- 原输入字节/文本独立保留；结构 Key 仅用于 const/enum/uniqueItems，不用于签名、Owner digest、持久化身份或命令重放规范化。
- JS 安全整数边界附近不同数字仍不相等，38 位数/超大指数不经过 double/Number 舍入后比较；不以浮点坍缩得到错误通过。适用数字字段仍按其原 Schema 校验，不用额外有限精度或默认深度限额悄悄缩小合法域。
- 对 LEAD required owner 字段与独立 optional owner 字段分别验证；生成类型 nullable 修正和实际 decoder 规则同时成立。

组合 C# 资产仍包含 MaxDepth=64、递归重复键扫描及 decimal/Int64 数值处理；组合 TS 资产仍以 JSON.parse/Number 和序列化字符串处理部分结构比较。它们是带来源的采用资产，不是已经完成 CRM 验证的实现。需要的适配必须进入可复现生成/变换记录，并由真实生产入口测试覆盖，不能只换一个 helper 名称后沿用错误边界。
