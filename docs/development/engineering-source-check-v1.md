# 工程来源固定与完整性检查 v1

W193 / WP05-11，直接采用 Main PostgreSQL 原生来源、OperationsOwner 当前授权和 Main 原命令日志。入口在工程修订页面的“工程完整性检查”，服务为 `EngineeringSourceCheckService`，API 为 `/api/engineering-source-checks/owner-v1`。这是一份技术预检原证，不创建 Baseline、评审决定、REL 许可或工单。

## 明确的政策与输入

配置规则增加明确的 `ENGINEERING_OPTIONS_AND_CHECKS_V1` 范围和 `engineering-check-policy/1` 正文。旧 `ENGINEERING_OPTIONS_ONLY` 原字节、摘要、批准和行为保留，不能自动作为工程完整性政策。

有权用户在原配置规则入口明确产品类别、内部制造/采购成品、配置适用性，以及 EBOM/MBOM/ROUTING/DOCUMENT/QUALITY_SPEC 五类组成的适用性、最少位置数和依据。仍通过原规则草稿、送审、批准、替换与撤回过程生效。内部制造不能用不适用跳过 BOM/工艺；文档与独立质量规格必须明确提供。未知或空政策不产生默认批准。新增范围允许没有选项定义的明确政策，旧选项范围的最少定义约束保留。

检查命令固定准确修订、候选、ETag、政策引用、原 operationId 和原因；不接受客户端 PASS、自由源实现或数据库绑定。当前产品类别/准确产品引用必须符合政策。配置规则的来源版本变化和撤回都会使旧检查失效。

## 来源及事务参加

登记的原生参加者是工程产品、批准配置政策、工程 BOM/工艺、原生商业物料、单位及基准单位、物理 Site、资源原件、工具规格与原工具控制头、受控文档/文件及独立质量规格。每个实际引用保留 occurrence/path、Owner/version/digest、native schema、当前水位、完整原文或由原 Owner 返回的内容证据。

所有参加者使用同一个 Main PostgreSQL 连接与事务；现有 Owner 的实际锁和当前授权校验继续生效。检查提交前在独立的观察回调树内重读来源并比较，避免遍历中的回调集合被修改。内部 `HoldExact` 仅接受准确 CheckRun 引用，必须重读原候选、批准政策、所有当前来源及当前权限；HTTP 读结果不是可重复使用的最终许可。

来源不可读/临时不可达时，本次逐项记录 UNKNOWN，已保存原证不回写；已知不一致记录 BLOCK。历史原文的读取仍要求当前来源权限，撤权后不能借原键或历史记录披露。文件内容不可用不会拿同名新文件补齐。

工具/资源专业资格、BOM 用量专业评审及其他尚未交付的实际资格按原提供者返回的缺项保留 UNKNOWN；本轮不把 draft 工具或资源存在提升为正式资格。原生内容可固定和具有冻结业务资格是两个不同事实。仅静态签名、缓存、SQLServer WP0 原型、顺序跨服务 GET 不登记为已参加。

## 持久结果与摘要

`cp6_engineering_check_v1.runs` 保存 CheckRun、完整候选输入、政策正文、逐项结果、原生来源水位、权限水位和检查时间。数据库禁止更新、删除和 truncate，并用延迟约束绑定真实原操作、Actor/租户/修订。保存行数和原文回读必须确认，写入丢失不能形成成功原回执。

本新增技术预检版本的命令体上限为 64 KiB，展开后的单条检查原证上限为 128 MiB；超限明确拒绝并整体回滚，不截断或降精度保存。该边界不修改既有来源的合法输入，也不证明完整工程冻结合同已覆盖所有来源规模；大规模历史查询及容量压测尚未执行。

同 operationId 同输入返回原 CheckRun，不重新执行业务；不同输入冲突。未知提交查询原键；显式结束未提交键与成功提交仲裁，不能用新键替换未知结果。页面只保存租户/用户作用域的操作 ID 和修订 ID，以浏览器锁协调重复页面，不保存正文或自动重发。

技术内容采用明确的 Main schema `main-engineering-technical-manifest/1` 与 `CD-ENG-01-Main/1`，不是 RFC8785，也不声称与归档候选 wire 等价。保留准确产品/配置/源身份、发生位置、工程适用依据和语义顺序；对象键按 Unicode 码点排序，顶层组成按稳定身份键排序，UTF-8 紧凑字节 SHA-256。审计原因、检查时刻、操作者、说明性注释、评审决定和发布状态不进入技术摘要；原始输入另有独立摘要。升级需保留旧字节，不能改算历史结果。
