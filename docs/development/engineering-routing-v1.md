# 工艺草稿与准确来源 v1

`Main.Plm.EngineeringRouting.v1` 为工程修订维护独立工艺身份、不可变版本和稳定步骤位置。入口为 `/plm/engineering-routing`，API 为 `/api/engineering-routing/owner-v1`，权限资源为 `plm-engineering-routing`，分别使用 `query/add/edit`。迁移只登记菜单和动作，不授予角色权限。

## 原件与编辑

创建选择当前工程修订工作版本及其准确工程产品。路线的修订身份、产品身份和创建人 UUID 不可替换；修订使用预期版本与 Etag，保存原因、实际操作者和父版本。步骤以 Occurrence UUID 区分，同一工序代码可以出现于多个位置；语义顺序、前置依赖、替代组、适用依据、资源、工具、参数和文档要求分别保留。删除或调整步骤不会改写旧路线或旧工单。

参数数值使用十进制字符串，整数和小数各支持至 1024 位，不经浮点或 CLR decimal 缩减精度；不自动转换单位。重复步骤身份或顺序、非法数字、伪造来源引用拒绝保存。循环、缺失前驱、参数上下限冲突、未知单位/方法/适用性可以保存在草稿中，但列为缺项。当前输出始终为 `DRAFT / DRAFT_ONLY`，不据这些草稿生成生产资格或正式排程通过结论。

新建和修订在同一 PostgreSQL 事务核对工程修订、产品、实际场所、MACHINE/WORK_CENTER 原生来源、工具技术规格和单位的当前准确版本、来源可用性与读取权限。资源身份不是生产资格，技术规格草稿不是已批准工具，受控制造视图、文档、技术适用和工程冻结仍由后续真实 Owner 提供。版本引用中的摘要必须等于持久原件的摘要，不能只凭编号匹配。

## 实际 ProductProcess 采用

`POST legacy-preview` 接收准确的工程/经营双 Owner 已确认映射，读取被授权经营产品的实际 `T_ProductProcess` 行。原件包含全部原字段，摘要绑定准确映射、经营产品引用和有序数据库行；预览不写工艺。

预览按原显示顺序给出待审查步骤，保留实际行 UUID；数值从原 JSON 读取为精确字符串，缺失人数不补 1，原版模号、设备号和工作组代码不提升为准确资源引用，也不从显示顺序虚构正式依赖。用户明确采用后，可补齐来源和调整步骤；命令仅携带映射引用及预览摘要。服务端在事务内重新读取实际原件，若发生变化则拒绝导入；不接受调用者提交原始行作为来源证据。

保存后保留当时的全部原件与步骤；历史查询仍须当前工程产品、经营产品及场所读取权限。历史的原件不会随旧主数据变化而重写。重新导入会留下新版本和差异，技术适用核准仍未完成。

## 工程组成与权限

工程修订的 `ROUTING` 组成可选择属于同一修订、同一准确产品的当前工艺版本。新采用重新核对所有准确来源；历史组成保留原引用，路线更新后报告来源变化，不替换为最新版本。读取路线的父修订原件不递归展开其组成，避免“修订包含路线、路线归属修订”的循环；加入组成导致父工作版本前进，不会使原路线历史失效。

工艺的部门范围继承不可变父工程修订的可信部门映射，使用工艺自身当前授权范围；不根据操作人当前部门猜测历史归属，不另建一份部门权威。创建人范围使用 UUID，租户范围仍受 TenantId 约束。所有来源参与当前授权及事务结束前重核；拒绝会撤销本次版本、原操作和审计。

## 恢复与验收范围

`POST commands` 使用调用方 OperationId；原请求、结果和审计同事务保存。同键同体返回原结果，同键异体拒绝。结果查询与关闭入口为 `operations/{id}` 和 `operations/{id}/close`，恢复使用当前查询权限。确认未知前不换键重发；已关闭未提交键拒绝迟到写入。

页面使用浏览器互斥锁协调同一租户/用户的原操作，仅持久保存操作及对象 UUID。身份变化、当前来源拒绝和迟到响应不能重新展示旧业务内容。历史读取与版本比较不覆盖当前未保存输入。

W186 的本地 PostgreSQL、实际 HTTP、页面验证及审查来源见[本轮交付](evidence/W186-01/DELIVERY.md)。这些证据不代表真实企业技术资料已齐备、工程已冻结、正式 WO/SCHED 已采用或生产已上线。

W203 增加步骤的显式资源能力目录引用：固定准确资源和独立能力版本，当前目录或来源变化会阻止新采用，历史路线保留原件。声明不解除资源资格缺项。参见[资源能力目录](resource-capabilities-v1.md)及[本轮交付](evidence/W203-01/DELIVERY.md)。
