# 制造映射与逐产出草稿

`Main.Plm.EngineeringManufacturingDraft.v1` 是制造关系编制的独立 Owner。它引用实际工程修订、配置、EBOM、MBOM 和工艺版本，为正式输出关系集准备来源；不是 `ENG-OUTPUT-RELATIONS/1`，不能作为冻结或生产准入凭据。菜单及页面为 `/plm/engineering-manufacturing`。

## 身份、来源与权限

根 UUID、创建人、所属工程修订 UUID 和工程产品 UUID 不可替换。新版本携带前版本与 Etag，版本、原字节、摘要和历史不可变。保存时逐项核对当前来源的 Owner、UUID、版本和摘要；父修订的配置原件必须一致。页面必须显式选择来源，不从编码、名称、列表顺序或旧产品字符串推导引用。

独立权限资源为 `plm-engineering-manufacturing`，动作 `query/add/edit`。本人范围使用原创建人；部门范围继承父工程修订的可信映射；租户范围仍受当前租户约束。所有引用还须通过其所属 Owner 的当前权限。迁移只登记菜单与动作，不向角色授予权限。

新保存要求准确来源仍为当前可用版本。历史读取保留原字节和原引用，并报告来源变化；历史原件不会因当前来源变化而自动改写。源权限撤销后，读取、历史、差异和原操作披露同样受限。

## 映射与产出

映射保留稳定位置 UUID 和多对多端点：工程位置、制造投入和相关工序。`MAP`、`SUPPLEMENT`、`EXCLUDE` 分别表示对应、补充投入和拟排除；理由及数量依据是草稿说明，不代表批准的排除、替代、损耗或换算。缺失端点、未知位置和未映射输入逐项列出。

每个产出有独立位置 UUID，即使属于同一产品也不合并。分别保存产物自身工程产品、生成工序、MBOM 投入位置、前序中间产出和配置。中间物流向检查实际工序依赖，并报告循环、无去向、未知投入或缺失生成工序。无投入生成必须说明依据；说明存在不会变成技术批准。主产物必须准确对应根产品；技术角色不决定质量、库存或销售分类。

数量使用十进制字符串，保留最多 1024 位整数和 1024 位小数，不经浮点或固定小数截断。数量类型、上下限、单位、分母及分母单位独立保存。格式错误拒绝；负值、无效分母、反向范围或单位精度冲突作为草稿缺项。单位存在和数量文本不能证明专业换算、适用范围或实际产量。

草稿始终为 `DRAFT/DRAFT_ONLY`。规格要求、关系依据和处置说明不伪造原生规格引用或专业证据。正式关系集、受控文档/质量来源、评审批准、工程冻结及正式工单/排程仍由后续直接前置任务完成；本入口不写库存、工单、质量或财务效果。

## API 与原操作

根路径 `/api/engineering-manufacturing/owner-v1`：

|请求|作用|
|---|---|
|`GET /scope`|当前租户与真人身份|
|`GET /?revisionId=&search=&page=`|当前有权目录，每页 20 条|
|`GET /{id}?version=`|当前版本或指定历史原件|
|`GET /{id}/diff?before=&after=`|按准确位置显示版本差异|
|`POST /commands`|`CREATE/REVISE`，携带原操作 UUID、完整草稿、原因及修订 CAS|
|`GET /operations/{id}`|按原操作查询 `COMMITTED/UNKNOWN/CLOSED`|
|`POST /operations/{id}/close`|结束尚未提交的原操作，已提交时返回原结果|

输入使用闭合 DTO。业务版本、审计和原操作结果在同一 PostgreSQL Owner 事务保存，嵌套来源与最终权限检查共享事务边界。同键同内容返回原结果，同键异体冲突；未知提交不重发。页面通过浏览器锁协调多个标签，仅持久化操作 UUID 和对象 UUID；身份变化清空私有视图，迟到响应不能恢复旧数据。历史查看和差异比较不覆盖未保存编辑。
