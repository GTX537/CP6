# 工程项目与迭代独立 Owner v1

W197 是 WP05-18 的限定实施窗口。依据 [PLM-ITER-01](../design-handbook/modules/PLM-ITER-01.md)、[WP05 任务卡](task-plans/WP05.md)和原 ITER 阅读主册。完整 WP05-18 及七天 D3 仍未关闭。

## 原件、权限与版本

- Owner `Main.Plm.EngineeringIteration.v1`，合同 `Main.Plm.EngineeringIteration.commands.v1`；API `/api/engineering-iterations/owner-v1`，页面 `/plm/engineering-iteration`。
- 原生 PostgreSQL `cp6_engineering_iteration_v1` 保存项目和迭代头、不可变版本及与原操作的延迟外键/证明约束。租户、对象、父项目及编号不可挪移。新迁移仅前向；不执行既有环境迁移。
- `plm-engineering-iteration` 使用 Metadata、Inputs、Tasks 字段权限以及 query/add/edit/start/hold/resume/task-submit/task-confirm 动作。**当前项目成员与当前对象范围取交集**；范围1要求项目创建者，范围2/3/4使用项目的原生部门绑定，范围5仍要求当前成员。所有迭代继承当前父项目范围；先过滤再分页，历史和恢复也重新授权。场地与每个关联产品、需求、文档及文件另查原 Owner 权限。
- 项目创建使用 creation-context 的当前授权版本及显式部门；创建者必须列入成员，负责人必须是成员。只查当前租户启用用户的身份目录，不接收外部姓名冒充成员。激活需负责人、有效准确场地、项目目标、起止日期和至少一个有判据的里程碑。草稿可暂缺产品，不按同名对象推断产品。
- 编号由当前租户配置的 `PLM_PROJECT` / `PLM_ITERATION` 原生采番规则在同一事务内产生。缺规则会失败，不生成默认规则、取 MAX+1 或截短编号。失败时编号、成员投影、版本、原操作一起回滚。
- 对象 Revision/ETag 用于并发；PlanVersion 用于计划/任务范围和权重变化；InputVersion 仅由显式输入采用变化推进。读取准确旧版本不会替换为最新草稿。

## 准确输入与阶段

创建迭代要求 Active 项目及当前项目负责人。NEW_PRODUCT 必须记录无父基线原因；CHANGE / LEGACY_REVIEW 保留合同路径，但没有实际批准 ECO、父基线或历史来源 Owner 时返回明确的不可用结果，不能用伪造引用放行。

输入只接受准确的 W196 需求集 Owner/Id/Version/Digest。服务在同一业务事务持有已批准集合及成员来源，保存集合原始字节文本、批准 submission/decision/application 身份、环境/模式/租户，以及采用人、时间和项目准确版本。客户端不能提交自称已批准的证明。保存的捕获依据是历史事实，不能作为后续操作的授权凭证。

输入来源、项目原产品/场地每次按当前权限复查；集合有更新草稿不会自动使旧批准版本失效，实际成员批准撤回则显示变化并阻止启动/恢复/提交/确认。来源保护不可用时不报告未变化。项目改换产品或场地需显式重新采用输入，旧交付仍按原项目输入解释。已 Submitted/Done 的任务存在时，输入替换要求另有影响评审，本窗口不生成该评审。

本窗口仅开放 Planned → InDesign。HoldState 独立于阶段；暂停时禁止计划/任务写入，恢复重新查原输入、项目来源、当前权限及迭代负责人。此原生前评审阶段尚无外部 OA/VER 请求入口，因此不会自动恢复外部流程。以后接通外部请求时，必须把其权威未决事实检查接入本 Owner，不能沿用空列表假设。100% 工作进度不推进阶段、不完成里程碑、不产生 VER PASS、冻结或发布资格。

## 任务及原操作

任务有明确负责人、独立确认者、交付判据、日期和正权重；成员必须来自当前项目。权重为规范十进制字符串，沿用现有工程精确数值域（整数/小数各最多1024位），不使用浮点或套用 SQL Server decimal 限制。ConfirmedWeight / PlannedWeight 保留精确值；显示百分比截取到两位小数。Blocked 仍在分母，Cancelled 排除，无计划任务时百分比为空。

任务可从 Todo/InProgress/Blocked 提交。提交者必须是负责人，且提供原 DOC Owner 可读、文件内容当前可用的准确文档。交付物自身可为待专业评审文档，**任务交付不冒充文档批准或验证通过**。没有交付物时需批准豁免；当前未接通豁免 Owner，空数组不会放行。

只有当前指定的另一位确认者可以将 Submitted 变为 Done，确认时重查原输入和交付文件；也可退回 Blocked 并保留历史。原负责人失效不阻止当前确认者退回，避免卡住后续重分配。Submitted/Done/Cancelled 不能直接改写原任务计划；Done 不能通过取消擦除确认事实。确认者、时间和原因记录在不可变版本及原操作中。

所有命令有 OperationId。相同字节重放和原结果查询保留原键，当前读权限仍必要；关闭未知未提交原键后禁止迟到写入。页面恢复键按环境、模式、租户、用户隔离，只存对象和操作标识；多标签页锁、身份变化失效和响应校验共同阻止误用旧结果。
