# 独立质量规格 v1

W192 为 WP09-11 提供独立的 Main 质量规格 Owner，以及工程工作修订的准确质量成员引用。规格可以先于工程冻结建立；工程草稿不能自行批准它。原依据为 WP09-11、QA-POL-01 的独立完整 Requirements/原始依据/current head 与 ENG-REV 准确质量成员要求。

## 身份、来源与完整要求

原始内容的 Owner 为 `Main.Quality.Specification.v1`，控制头为 `Main.Quality.SpecificationControl.v1`。准确引用包含 Owner、原生 ID、十进制字符串版本和 SHA-256；内容保存 Environment/Tenant、创建者、修订作者、REAL/DEMO 模式、前版与原始字节。修订不改变产品和厂区身份，但可采用同身份的新准确版本。

每个规格声明产品、实际厂区、检验阶段、专业用途说明、批准的完整性原文及完整性声明。每条要求包括业务标识、质量特性、方法、判定定义、批准标准原文、可选准确单位、原样小数字符串上下限/目标值、适用性、不适用依据、mandatory、waivable 及豁免依据。数值以整数算法比较，不转浮点或截取金额/数量精度；本原生入口支持最多 1024 位整数及 1024 位小数。原文文本和数值原样保存在修订中。

未知适用性可保存草稿，但不能送审或作为可用工程来源。不适用与允许豁免都需要批准原文；强制要求不被技术不适用自动删除。空要求集仍须有完整性原文、声明及独立专业签署，不能把未知要求变成空列表。每版最多 256 条要求、100 项用途说明；原生内容上限 32 MiB。上述为明确版本的新入口边界，不修改既有 QAP 合同或历史输入。

用途字符串是专业声明，不是 REL 用途许可。这里不生成技术 KNOWN/NA、生产 Use、检验结论或企业专业标准。与 QAP 原合同的逐要求版本、source member/occurrence/purpose 引用及生产任务族的最终解析，仍须由 WP09-01/02 对应消费者明确采用；不能将本原生 JSON 宣称为 `QAP-REQ-QUALITY-REQUIREMENTS-1`。

## 审查、修订和撤回

有当前 `review-policy` 权限且可访问该规格的人员显式登记专业角色、每角色独立人数和有效区间。没有默认专业规则。送审固定整版内容、准确政策、作者及完整要求摘要。每次签署重新检查当前身份、专业角色、字段和对象权限、政策发布者当前权限及有效期，禁止作者自签，同一人员在同一包仅签署一次。过去合法签名保留原资格事实；后续撤权阻止未来操作，不改写历史。

批准要求全部专业人数满足，并原子保存签名、批准、控制头和 Main 原操作结果。标准文档必须已通过 W191 实际专业审批与 Owner 应用；文档批准本身不代替质量规格签名。质量 Owner 直接接收有权限人员对准确包的独立签署，本轮没有额外泛化第三种 FLOW 运输入口。

新草稿保留旧批准的历史及其当前有效引用，直到替代版本获批或显式撤回。新的未批准草稿不能冒充旧版批准。退回后可修订/重提；审查中不能改正文或政策。撤回清除当前批准，旧记录仍可在当前读权限下查询；恢复采用需要新修订和重新审查。

## 同事务工程采用

`SourceAsync` 是只读观察，不能成为后续操作的最终锁定凭据。内部 `HoldExact` 要求真实同一 PostgreSQL 连接/UoW，核对准确规格、控制头、批准与完整要求、产品/厂区/单位/文档当前来源和当前权限。来源表和控制写入使用共同事务门；最终复核包括同一事务内的来源变化。正式撤回与消费竞争时按数据库提交顺序裁决。

工程 `QUALITY_SPEC` 成员可在工作草稿阶段选择准确已批准规格；页面能选择“新草稿之外仍有效的旧批准版”。保存成员时在工程实际事务内调用质量来源参与者；读工程历史时保留准确引用并报告撤回/变化。此处不宣称工程 CheckRun、冻结、工单、排程或生产最终 Use 已完成。

## API、权限与运行配置

- `/api/quality-specification/owner-v1`：scope、分页目录、准确历史读取、roles、只读 source、commands、operations 查询/关闭。
- commands：CREATE、REVISE、POLICY、SUBMIT、APPROVE、RETURN、WITHDRAW。除创建外均要求准确 ETag；每次操作携带原操作键。C02 身份/CSRF、严格请求成员、当前租户/对象/字段权限保持有效。
- 菜单 `quality-specification`，动作 query/add/edit/review-policy/review-submit/review-decide/withdraw；字段 Metadata/Requirements。个人范围按规格创建者，部门范围使用实际工程产品部门绑定，不伪造用户部门或另造产品身份。
- 配置必须提供可信 `ScopeAuthorization:EnvironmentId` 和 `QualitySpecification:EvidenceMode=REAL|DEMO`。缺少模式时拒绝服务，不默认为 REAL。REAL 配置本身不能证明真实企业验收。
- 原结果只向原操作者在当前读权限下披露。提交响应丢失后先查询；UNKNOWN 保留原键，关闭只阻止尚未提交的键。已提交历史结果不被后来的正文、撤权或撤回改写，读授权仍会重新核对。

页面 `/mes/quality-specifications` 提供准确来源选择、完整要求编辑、角色规则、专业签署、撤回、历史和原结果恢复。浏览器协调锁与环境/租户/人员隔离的恢复记录只保存操作 ID、对象 ID 和动作，不保存要求正文；恢复不自动重发。未保存的编辑内容不能作为当前受审包签署。
