# CP6 横切接线规范（P1）

> 生成于 2026-07-07。**任何模块的功能代码合并前，必须过本文第六章 DoD 检查**——这是 2026-07-07 全局审计（缺陷主题 T2/T3/T5：73 个写控制器裸 Authorize、WMS/Space 菜单零种子、审计覆盖不均）的制度性根治。
> 模板出处：**Space 波4 横切接线**（2026-07-07 并 main=0ee5da6）是全项目已走通的完整样板，本文把它固化为规范。模块修复波（M-WMS 等）照本文执行。

## 一、权限（功能级四粒度）

1. **资源键 = `menuKey:action`**：MenuKey 下划线小写（如 `wms_inbound`），action 用 `view/add/edit/del` + 高危独立动作（`publish/post/pay/convert/deactivate` 等绝不与浏览混授）。
2. **控制器贴法两条路**：CodeGen 产出的 `BaseCrudController` 子类自动挂操作点；**手写控制器必须逐写端点显式 `[RequirePermission("menu_key","action")]`**（`CP6.Core/Auth/RequirePermissionAttribute.cs`）。类级 `[Authorize]` 只是登录闸，不算权限。
3. **只读 POST 豁免**：纯查询/预览类 POST（如 Space 的 Preview）可豁免为 view 级——豁免须在 PR 说明里点名（Space 波4 仲裁先例）。
4. **种子**：`Sys_MenuAction`（操作点）+ `Sys_RoleAction`（授角色）**逐租户播种**，幂等（键存在即跳过）。样板：Space 波4 种子（52+52 逐租户）。
5. **fail-closed 反射测试（每模块波必交）**：照 `CP6.Tests/Space/SpacePermissionAttributeTests.cs` 泛化——反射扫描本模块全部控制器的 POST/PUT/DELETE 方法，断言"要么有 [RequirePermission]，要么在显式豁免清单里"。**新增写端点漏贴权限 = 测试红**，这是防回潮的关键。
6. **前端**：按钮贴 `v-permission="'menu_key:action'"`，与后端键逐字一致。

## 二、审计（字段级）

1. 实体实现 `IAuditable` 即自动获得字段级审计（CP6Context SaveChanges 拦截器），零额外代码。
2. **贴点优先级：钱与库存优先**——Fin 凭证/发票/付款、Wms 库存移动/盘点、主数据（BP/Product/价表）。看板/日志/快照类不贴。
3. **高频噪音列免审计裁决**：批量操作会高频翻动的列（先例：Space Location.Version 发布批量翻版）经用户裁决可豁免——豁免写进模块波 PR 说明。样板测试：`CP6.Tests/Space/SpaceAuditTests.cs`。

## 三、菜单与路由

1. **Sys_Menu 种子必含 MenuKey**（WMS 48 条漏 MenuKey 是本规范的直接成因）；MenuId 分段管理（WMS 已有段、Space 900 段先例），新模块先登记段位。
2. **路由 path ↔ MenuKey 对齐**；前端动态路由由菜单驱动（`router/index.ts` addDynamicRoutes）——**没有菜单种子的页面 = 洁净部署不可达的暗物质，禁止**。
3. 孤儿路由零容忍：每模块波交付时 `viewModules 路由集 ⊆ Sys_Menu 种子 RoutePath 集`（standalone 全屏页如 Space editor 须显式登记豁免）。
4. 种子交付形式：SQL 入 `docs/seeds/`（样板 `space-menu-seed.sql`）或 C# 幂等 Seed，二选一但**必须随包合并**，不许"部署时手工补"。

## 四、i18n（五语）

1. 新词条一律五语（zh-CN/zh-TW/en/ja/ko）随 `CP6.WebApi/Seed/I18n*ScreenSeed.cs` 幂等种子入 `Sys_Langs`（样板 `I18nSpaceScreenSeed.cs`）；前端零硬编码 CJK。
2. 错误码即词条：`E-XX-nnn` 码号在 spec 里锁水位（防撞车），词条键=码。
3. 存量硬编码清理随模块波顺带收（WMS 抽样 43 处待 M-WMS）。

## 五、错误处理

1. Service 层不裸抛 `e.Message`，用编码错误（Wf 族 `InvalidOperationException("E-WF-0xx")` / Space 族 `BizException("E-SPACE-xxx")`——各模块沿用自己已有的族，别混）。
2. 并发冲突 → 409 语义；权限失败 → 403 且响应零业务信息。

## 六、新功能 DoD（合并闸）

```
□ 写端点全部有 [RequirePermission] 或显式豁免（fail-closed 反射测试绿）
□ Sys_MenuAction/Sys_RoleAction 逐租户种子已交
□ Sys_Menu 种子含 MenuKey，无孤儿路由
□ 钱/库存类实体已贴 IAuditable（或裁决豁免留痕）
□ 新词条五语入种子，零硬编码 CJK
□ 错误走编码错误族
□ 全量测试绿 + commit 即 push
```
