# 关键身份与状态词典

本页统一解释阅读时容易混淆的概念，不定义新的共享DTO，也不把各Owner原字段强行改成同一个名字。准确字段、必填/null/缺席规则及摘要算法仍由[具名合同](D:/CP6/docs/CP6_开发设计文档_20261010/contracts/)和对应模块引用确定。

## 1. 身份不是一根字符串

| 概念 | 用途 | 开发时要区分 |
|---|---|---|
| Target / SPEC | 设计整理目标与其业务规格范围 | 不等于微服务、数据表、路由或部署单元 |
| Owner | 对某项业务事实有权作最终决定的模块 | 调用方、传输方、展示方和审批方未必是该事实Owner |
| Scope | 合同要求的租户、环境、站点等作用域组合 | 各合同轴集合不同，不能只比较TenantId就称同一Scope |
| Business intent / operation identity | 确定一次要产生的业务效果或原操作 | 不能换HTTP key就变成第二次合法意图 |
| Command / Request key | 入口请求的稳定查重及结果定位身份 | 与业务槽、消息ID、attempt分别管理 |
| Message / Event ID | 原事实的运输与接收去重身份 | 重投原事实通常保原ID；修改业务内容不能伪装同一事件 |
| Receipt / ResultRef | 指定原操作的持久结果 | 原回执可以是历史成功，当前业务状态须另读 |
| Ref | 指向Owner拥有的准确对象/版本 | OA-APP等合同将owner/id/version与Link分开；URL不是Ref的替代品 |
| Attempt | 一次发送、执行尝试或公开表单签发尝试 | 含义依模块，不能通用地当业务去重键 |
| Canonical | 某合同认定同一业务意图或资源的准确规范身份 | 不保证所有模块采用同一canonical JSON算法 |
| Alias | 指向同一原意图或结果的别名 | 不得建立第二条独立提交路径，旧别名也应被关闭证明覆盖 |

来源：商业合同H01/H02/A.R03-CT01、Workflow WFC-1/OA-APP-WIRE-2和Stock封闭合同；这些合同均保留实际原文位置，不把解释中的概念名当原wire字段名。

## 2. 版本轴分别比较

| 版本轴 | 主要作用 | 典型误用 |
|---|---|---|
| 设计版本/规范组合SHA | 固定开发依据及接受范围 | 仅按文件名最大版本或最新下载日期选输入 |
| 业务修订/SubjectRevision | 固定待审批、履约或应用的业务内容 | 用当前最新内容解释旧审批决定 |
| RowVersion / ETag | 竞争修改与CAS前提 | 当成跨Owner业务版本，或用旧值查询原结果时重跑新业务守卫 |
| Stream sequence / Receipt revision | 顺序、缺口检测与连续投影 | 按时间戳或消息到达顺序选择赢家 |
| Engineering Revision / Configuration / Baseline / Release | 工程身份、组合与用途准入 | 仅保存ProductId或“最新版”而丢工单冻结依赖 |
| Policy / Permission revision / Epoch | 当前授权及撤权最终边界 | 用缓存TTL、UI权限或审批时授权代替当前新写资格 |
| Writer epoch / Fence revision | 防止旧路径、旧worker或旧代执行者晚到写入 | 租约到期就释放业务预算，或忽略旧别名 |
| Snapshot / Source cut / asOf | 某次准确完整观测的边界 | 把补历史链的APPLIED_AS_OF解释成新的当前值 |
| Delivery attempt / Lease token | 控制一次运输、领取与完成 | 由运输成功推导Owner已生效 |

工程及现有实现边界继承自[固定代码与设计对照](D:/CP6/docs/CP6_编码前整合_20261009/03-现有代码基线.md)；receipt/cut规则见[事务与恢复](D:/CP6/docs/CP6_开发设计文档_20261010/architecture/02-事务回执与恢复.md)及对应模块。

## 3. 库存、义务与许可

| 概念 | 解释 |
|---|---|
| Stock quantity authority | 库存数量最终写权由Stock数量核持有；其他模块提交业务来源或参加约束 |
| Root / span | 有来源的数量根及其半开份额表达，不能等同物料主数据ID |
| Stock Claim | Stock/RSV域的数量承诺；Allocation/Pick可以是承诺内部状态，不能重复扣可用量；不与DEV Claim合表或共用余额 |
| DEV Claim / REL reservation | DEV占用自己的偏差LimitScope，REL管理自己的用途预约，实际执行Owner记录发生；即使引用同一工单也不互代原账 |
| Use / UseLeg | 一次下游真实使用及其完整腿集合；释放时不能只确认局部腿 |
| SourceAction / SourceOccurrenceLeaf | 来源Owner对准确业务行动/发生叶的身份与约束；运输别名不能各持一份余额 |
| Allowance / Entitlement | 对准确原义务/来源份额的合法使用范围；与实物位置、所有权、质量状态分别判断 |
| FinanceOriginalObligation | 财务匹配、退货等竞争的原义务坐标；不能反写抹掉原收货或原过账事实 |
| Movement | Stock持久记下的准确数量效果；Pick准备、发运开始、消息送达不替代它 |
| ActualFact / Suspense | 对现场真实差异及未决效果的保留；不因系统未知或零净差而丢掉逐腿事实 |
| Correction / Reversal | 有权解释原错误效果的后继；不等于一次新的真实业务退货 |
| Permit | 某具名合同准入的候选条件与最后裁决载体 |

Permit不能被泛化为“拿到就永久可写”。例如DEL最终必须重新锁定完整来源cut并核fence/heads，才与Proof共同提交；已COMMITTED的permit又保留历史终态，不被后续来源更正抹掉。详见Stock、RSV、OUT、DEL及RMA模块。

## 4. 常见状态词只在准确合同内解释

| 状态词 | 阅读提示 |
|---|---|
| RECEIVED / RECORDED | 通常描述收到/保存事实，须同时查看application轴 |
| APPLIED / POSTED | 查对应Owner、作用范围、原操作身份及实际回执；不能跨域推广 |
| UNKNOWN / NOT_OBSERVED | 未知或当前未观测，不天然等于未应用 |
| BLOCKED / REQUIRED_FENCED | 当前能力、政策或必要Owner条件不足；不能另走旁路绕过 |
| STALE / CONFLICT | 查看是否持久终态、是否可产生有版本后继，不能一律自动重试 |
| SEALED_NO_EFFECT / CLOSED_NO_EXECUTION | 必须有实际Owner、完整范围及阻止晚到写的持久证明 |
| APPLIED_AS_OF | 只说明准确历史切面的应用/投影，不替代fresh current读取 |
| NOT_RUN / UNPROVEN | 没有对应执行或实际采用证明，不能由静态设计接受覆盖 |
| ACCEPTED / PASS | 先看对象与Scope；可能仅是静态设计、解析、fixture或历史结果 |

状态列表不是一个全局联合枚举。新增代码应使用本模块精确判别联合与错误映射，避免把“不认识的状态”统一映射成成功或可重试。

## 5. 同名不能直接共用类型或算法

| 容易混用的名字 | 必须保留的区别 |
|---|---|
| Candidate / Baseline / Release | 工程工作候选、受测对象、不可变技术基线、REL用途授权以及软件发布制品不是同一生命周期；技术FROZEN不代表可生产 |
| REL authorization / reservation | PO CP22制造链在root创建前核GRANTED用途授权；reservation来自真实root之后的REL原结果，不能提前伪造或代前置授权 |
| digest / hash | 原文件SHA、工程技术摘要、SPACE源内容/manifest/memberManifest、producer请求和WMS semantic摘要分别有原canonical域；同算法名不证明同语义 |
| H编号 | 用来源版本＋Owner＋准确合同名＋方向定位；MASTER02 H31是采购退货/供应商结算，ENG H41是ITER→ENG冻结，不按孤立编号拼接 |
| Scope / Ref | FIN-CREDIT与GL的法人/账簿字段、环境枚举和Ref成员不同；双边无损映射是独立工作，不改源字段装成共同DTO |
| ABC | SLOT按当前行之前累计划级，ANALYTICS按包含当前行累计划级；这是两版有意算法，不抽成无版本“统一ABC” |
| unit / quantityScale | 数量、计价单位、量纲、转换方向和精度各归合同；PRICE允许0..18而EST UnitValue为0..12是能力边界，不能截断或私改全局上限 |
