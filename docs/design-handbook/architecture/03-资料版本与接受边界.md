# 资料版本与接受边界

## 1. 设计输入由准确组合决定

先用Target定位当前选择器，再合读指定正文、强制组合、独审、接受记录与限定勘误。文件名有`DRAFT`或`CANDIDATE`仍可能是被准确接受的冻结字节；文件名较新或包含`PASS`也不自动取得当前权威。

[required-inputs.json](D:/CP6/docs/CP6_开发设计文档_20261010/indexes/required-inputs.json)逐件保存Component ID、原SHA、实际载体SHA、来源JSON pointer和本地路径。`resolved_local_path`可能是准确分片描述符；`resolved_source_identity_path`在完整原件已还原时直达原件。两个SHA不同必须保留各自身份，不能把描述符哈希填写成ZIP原件哈希。

## 2. 四个层级分别处理

| 层级 | 作用 | 处理方式 |
|---|---|---|
| L1 当前正文与强制组合 | 定义当前设计行为及准确附件 | 必须按组合阅读；包中的历史例子不因被收录自动变成当前规范 |
| L2 指定独审和接受 | 说明通过范围、限制、勘误与适用对象 | 与正文一起固定；静态设计接受不替代业务AC运行 |
| L3 发布与来源证明 | 说明来源、发布身份及选择链 | 不将缺发布回执说成主正文缺失；缺口另行登记 |
| L4 历史及前驱材料 | 解释演进、被替代规则和既有结果 | 保留原身份，避免覆盖当前规范或移花接木历史PASS |

当前基础有125个Target、2,181次必需引用。L1/L2实物齐备为124/125，全部已声明L1–L4实物齐备为121/125。差别来自WMS-DEL指定独审、FIN-AP/AR发布回执和FIN-INV历史评审链。**这是材料可定位情况，不是完整阅读率、编码完成率或验收通过率。** 当前精确原文缺口还包括必需清单之外的历史身份，统一见缺件登记。

## 4. 勘误与后继采用

已接受勘误参与当前解释，原冻结正文保持不改。例如H01旧INQ示例的Website=20已由LEAD CP22接受附注限定为Website=10、Manual=20；这属于已有决定同步，不是本轮重新决定枚举。[准确勘误](D:/CP6/docs/CP6_完整成果归档_20261009/完整成果/docs/originals/e9/e97177633a150540__ERRATA.json:8)。

后继接受只解除其明确覆盖的旧设计问题。QA-NCR后续R12接受不能自动宣称所有RMA/FIN路由在运行中已开放；Required fencing、真实Owner采用、政策与运行证据继续按实际路由检查。历史“无已接受设计”的段落应保留历史身份，并在当前解释中标出准确后继。

## 5. 七个状态轴分别记录

| 状态轴 | 例子 | 证据 |
|---|---|---|
| 资料状态 | exact bytes available / represented / unlocated | SHA、字节数、原件或准确表示与校验记录 |
| 阅读状态 | metadata / structured / selected sections / full | 来源、行段或JSON pointer、实际未读范围 |
| 规范接受状态 | 当前选定、限定接受、历史、候选 | Selector、评审、接受及Scope |
| 专业设计采用状态 | 某consumer对某准确后继合同ADOPT | 原Owner角色、consumer版本、准确body/摘要、采用范围与保留项 |
| 实际采用状态 | provider/pin/registration/grant/all-writers是否有证 | 真实Provider、部署/数据库、可信登记、完整参与写者、实际资格；不能仅填同名接口 |
| 实现状态 | 无实现、候选分支、已合入固定主线 | 代码仓库、源码SHA、实际变更与依赖 |
| 验证状态 | NOT_RUN、历史静态PASS、本次本地通过、生产UNPROVEN | 准确输入、环境、执行记录与适用范围 |

一份文件被完整下载，只推进资料轴；一个字段被提取到索引，只推进结构阅读记录；模块设计文档写完，不会自动推进实际采用、实现或验证轴。`required_materials_consolidated`仅表示该组所选当前规范与必要材料已按记录归并，不声称所有历史源码逐行审计、Office视觉完全核验或运行就绪；未核范围仍见各组reading台账。
