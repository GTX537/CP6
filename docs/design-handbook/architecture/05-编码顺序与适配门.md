# 编码顺序与适配门

本页是根据当前选定设计整理的实施建议，不是新的业务边界决定、开发授权或已通过验收的排期。125模块仍逐批补必要附件；每条任务只在其实际依赖材料、准确合同和采用条件满足后推进。本任务没有编写业务代码或运行业务验证。

## 1. 先形成可审查的开发输入

每个切片固定一份输入清单：Target/具体动作、当前正文与必要附件SHA、准确接受Scope、producer/consumer、原wire/profile、所写事实Owner、实际应用/数据库/Provider、完整参与者与writer、锁资源与唯一顺序、业务意图及运输身份、完整写集与Outbox/回执、原操作查询/终态关闭、当前权限及字段可见性、页面所在应用、验收场景。相应材料见[必需输入](D:/CP6/docs/CP6_开发设计文档_20261010/indexes/required-inputs.json)与各模块§2/§12；物理协议未冻结时先做准确适配说明，不能从逻辑动作名称猜DTO。

这里的“门”是动作启用的证据条件。设计接受、专业设计ADOPT、真实provider/pin登记、实际all-writers参加和运行验收分别记录；没有证明的项保持UNPROVEN。一个路由受阻，不要求停止不依赖它的文档或独立基础工作。

## 4. 原结果恢复和切换必须与正向动作一起交付

完整切片包括正常入口、原键重放、同键异义、commit后丢响应、当前权限撤销、必要源未知、取消与晚到竞争、只补投影/回执及真实后继更正。共同提交失败验证全写集回滚；跨阶段已成功的事实保留原结果。恢复原结果不能重新创建源对象、换键重发全部数量，或以TTL/空查询推断无效果。[Stock原意图封闭](<D:/CP6/docs/CP6_完整成果归档_20261009/完整成果/docs/originals/5a/5aed7ccb52e1878b__WMS-STOCK-01_库存数量账与移动_前后端开发Spec_v1.1.1_REVIEW.md:1441>)；[RSV完整参与者关闭](<D:/CP6/docs/CP6_完整成果归档_20261009/完整成果/docs/originals/43/43eb8a01d98631be__WMS-RSV-01_库存预留与批次分配_前后端开发Spec_v1.1.2_REPAIR_CANDIDATE.md:831>)。

旧实现切换应逐范围确定唯一writer和原身份映射；未切换时不自称NEW_CHAIN，候选实现/历史fixture只作输入资产。普通文档校验、静态设计PASS、真实Provider事务验证、业务AC和发布门禁分别留下记录。当前本地手册不提供生产发布授权，也未执行代码、SQL、迁移或归档脚本。
