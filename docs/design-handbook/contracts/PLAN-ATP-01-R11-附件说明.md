## 2. 数据与事务落点

所有数量wire都携带value/uom/scale。value是字符串，最多22位整数、8位小数；存储numeric(30,8)，不能先以System.Decimal或JavaScript浮点接收。OwnerName是NFC的1..128 Unicode码点，允许内部空格、拒绝首尾U+0020及C0/C1；StableId另用ASCII规则。不要混用这两类标识。

| 阶段 | 必须可恢复的事实 | CAS/错误边界 |
|---|---|---|
| 接收 | 唯一principal/operation/requestKey重放槽，完整请求摘要与重放信封摘要；REQUEST、AUTHORIZATION和两收据 | ACCEPTED/etag1，没有政策绑定/OwnerHandle；同key异body冲突 |
| 绑定 | 先严格REQUEST/POLICY、Replay、Evaluation、PolicyIdentity锁，再恢复原阶段，写政策载体/收据/快照/精确事件绑定、供给载体/收据 | SNAPSHOTS_BOUND/etag2；事件绑定不可变；不以当前新事件重新替换历史绑定 |
| 计算 | 五载体、六收据、受保护/公开投影、typed结果子表全部精确派生 | CALCULATED/etag3；逐表/逐域验证，不用行数替代完整性 |
| 终结/恢复终结 | 消耗当前端点授权ticket、原principal和原双摘要、ExpectedETag、完整冷恢复校验；同提交写终态+Audit+Outbox | terminal/etag4；旧子表不可追加。这里的锁序存在上述待决项 |
| 新鲜度 | 授权的ACTIVE observer、evaluation/publicDigest和服务端分配sequence | 追加观察；不改历史评估。最新按sequence，不按观察时间 |

A06在同一读快照中按完整政策身份选最新sequence且readAt≤asOf，再判唯一CURRENT适用政策。0项和多项是不同typed错误；不读取评估历史来伪造当前策略。A05游标绑定完整查询（摘要不含cursor）、主体、当前授权投影、资源和活跃代次；租约不超过授权到期与当前时点15分钟。重新发代次后旧token不能继续使用。

公开GET的200实体为规范化{latestFreshness,result}实际字节，长度/实体digest/ETag分别一致；304必须零实体、零字节/length0。ETag固定前像绑定result与freshness representation digest，无观察用64个0。未执行跨语言byte parity，C#/TS实现仍须与原向量验证。

DDL使用外部cp6_plan_atp_jcs扩展作为严格解析/算法验证依赖。清单中的扩展名、schema registry和零摘要seed并不证明本机可用或部署完成。schema registry必须绑定准确最终bundle，runtime只有受控过程权限；迁移、权限和扩展均留在实现任务验证。
