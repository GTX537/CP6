# PLAN-EXC-01：Owner 契约与分页开发说明

这是 CP12 当前组合的开发阅读附册，补充模块主册和 API 表。**97 个叶契约、10 个专业提案仍为 proposed；实际采用/注册/授权均为 0，运行未证。** 静态设计接受记录不能生成真实 provider pin，也不能沿用 PLAN-PO 已有的专业采用记录。

本次读到的内容是当前规范的语义、字段关系和条件样例。大包中的完整普通业务世界、633 份原生事实、全部本地账本和全链路样例并未因此全部审读；其范围另见模块阅读台账。这里没有执行归档代码、签名验签或业务验收。

## 1. 契约的三层身份

1. 每个事实保留 `owner / namespace / objectKey / lineKey / scheduleKey / occurrenceKey / versionKey / bodyDigest` 八轴。业务体摘要与原始 UTF-8 制品摘要各司其职；摘要相等不能替代完整原文或发行者资格。
2. 叶契约描述真实 Owner 产生的字段、闭合递归 Schema 和业务义务。所有 `sourceFieldResponsibility` 均由该 Owner 负责，EXC、SUP、MRP 不得制造上游事实。
3. Provider 的真实发行身份、通道、契约版本/摘要、Schema 摘要、权限和当前保证要独立核验。业务体内写有 GRANTED 或 QUALIFIED 不会自行产生权限。

当前总数是原 69 叶 + CP03 新 26 叶 + CP04 新 2 叶。两个 CP04 方法/建议根仍保留旧 `EXC-CP03-NATIVE-...` 标识字串，但根 discriminator 为 4.0-proposed；外层 3.0 包族不是早期采用证明。旧 `producerConsumerMatrix` 的 69 行仅为历史索引，注册目标以当前 97 份完整契约为准。

新意图需要完整 current 事实和当前动作授权；接收原有真实回执时，原发行体、原请求键、原资格和原结果不可改写，接收/读取动作另外核验 fresh 授权。Unknown 数量保持 null；不能补 0。进程重启不重置 epoch；新 epoch 必须有合法替换证据。

## 4. EX02 分页协议：公开句柄与私有查询分开

当前为 `EXC-CP04-CURSOR-01 / 6.0-proposed`，适用 EX02。EX04/EX06 不会自动获得同一新版协议。

公开 Cursor 是三个无填充 base64url 段；header 固定 `alg=Ed25519`、allowlist kid、`typ=plan-exc-cursor+jws`，禁止算法降级或从用户 URL 取公钥。公开 payload 只有六项：schema、issuerOwner、protocolId、endpointId、bindingId、bindingDigest。**不包含**完整 filter、principal、provider、Core SDK、mask、cut、排序 tuple、expiry 或 lease。句柄不是授权凭据。

私有 `PrivateCursorQuery` 保存原完整规范化 filter、完整权限业务 core、scope/principal、排序、pageSize、固定 cut/snapshot、lease 与绝对 expiry；`PrivateCursorBinding` 保存 queryRef、previousBindingRef 和最后 tuple。两者连同原始规范化 UTF-8 与制品必须完整保留，不能只保摘要。

header ≤4096 UTF-8 字节、payload ≤512 字节、签名 64 字节，总保守上界 6236 ASCII 字节，小于外部 Cursor 的 8192。**这是句柄上界，不是新的查询条件上界**：原 CaseFilter 2 MiB 传输、OpaqueKey 1 MiB 范围继续存在；8193 字节的合法过滤键不因 Cursor 上界而被拒绝。

### 4.1 首次读取

1. 独立获取当前完整 `plan-exc.read` 权限，按全部请求字段校验 filter。集合数组排序去重，opaque 文本保持精确，不 trim 或忽略大小写。
2. 固定可见范围的数据 cut、roster 和 rowversion，读取第一页。已耗尽则 nextCursor=null。
3. 还有下一页时，MAIN 资格端口原子完成 `RETAIN_INITIAL`：完整 query/filter、第一 binding、固定数据快照与 lease 为 READY。
4. 资格发行者签发公开句柄；输出前再次确认权限。任何未知、保留失败或服务元数据超界都不得先流出半个 200 响应。

### 4.2 继续读取

1. 新的独立 current read 授权，再校验 compact 长度、header/payload、签名与发行资格。
2. MAIN `LOOKUP` 必须返回 qualified FOUND/MISSING/UNKNOWN。FOUND 包含完整原 query/binding/制品/UTF-8，和本次 fresh lookup trust；原历史 READY 不冒充本次调用资格。
3. 精确核对 principal/E/T/selected scope，再检查绝对过期；核对完整原 filter，然后核对原权限 core/head/sequence/mask。
4. 继续使用原 cut，仅取最后 tuple 之后的窗口。有后续页则新建不可变 B2 指向 B1；query/cut/expiry 不变，重复 B1 得到同一窗口。耗尽才输出 null。

| 情况 | HTTP / code | 行为 |
|---|---|---|
| retention/signing/provider 不可用或 UNKNOWN；冲突/残缺保留体；服务元数据超界 | 503 PROVIDER_REQUIRED_FENCED | NONE；无 rows/totals/nextCursor；无业务写入 |
| 编码/签名/alias/schema 无效或完整 filter 改变 | 422 BODY_SCHEMA_INVALID | NONE；不能在原句柄下换查询 |
| now≥expiry，或有资格的 MISSING/RECLAIMED/NOT_FOUND | 410 CURSOR_EXPIRED | READ_NEW_PREDECESSOR；不可用最新 cut 重构原句柄 |
| 用途撤销或 principal/E/T/scope 不匹配 | 403 PURPOSE_NOT_AUTHORIZED | NONE；不泄露元数据 |
| 仍 GRANTED，但完整 SDK/head/sequence/mask 改变 | 412 CURSOR_PERMISSION_CHANGED | READ_NEW_PREDECESSOR；不能混入不同权限页 |

所有失败 branch 的 operationId=null、cursorAdvanced=false。UNKNOWN 与确定的 MISSING 必须区分。

### 4.3 排序、有效期与字段披露

- DETECTED 的时间同值按规范 UUID 的 16 个网络序字节升序，不能用 SQL uniqueidentifier 的存储排序。
- NEED 使用已有业务日历比较语义，排序依据保留在私有查询中。
- SHORTAGE 仅对同可见、兼容 UOM 分组使用精确 TotalDecimal（30 整数位 +8 小数位）缩放整数降序；再按 UUID 排序。未知/null/负值/负零/指数/前导零不能当 0。
- expiry 取首次时间+900 秒、Core 有效期和保留承诺中的最早值。续页和 fresh lookup 都不延长 TTL。
- endpoint 用途拒绝为整页 403；field 用途拒绝使用闭合的整个 REDACTED 对象，不泄漏隐藏 group 数量、原生主键或删掉字段后仍宣称原制品完整。
- CORE 只签发独立权限 SDK；PLAN-EXC 负责公开句柄；MAIN 负责私有读取保留。三方新资格各自建立，不能借旧 Core/PO 采用记录。
