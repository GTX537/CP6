# PLAN-DEM / ERP-ORD：共享设计的验收与页面定位

这份索引保留功能版关系：R01/R02明确接受；R03跨Owner合同及R04工作簿/展示细化仍REVIEW。14类实例合同全是NOT_CONFIGURED，实例ID、组织/角色/租户/Site、版本、证据、批准、生效范围及实际值均未填，不可作生产默认。

原R04交付共有17页、54动作、54过程、140字段、54需求、50检查、12跨Owner合同、14策略、15原SPEC。验收R01 36、R02 122、R03 70、R04 8全部NOT_RUN；R04八项是展示细化。角色不得由字段显示位置推定可编辑：Planning接收页只读来源数量/日期，改变必须回原Owner纠正。

## 页面与请求边界

| 页面要求 | 内容 |
|---|---|
| OD-R02-PREQ-001 | 在订单工作台与任务定位范围内，Sales须按本页进入条件、可见状态、输入与动作合同完成处理；查询不产生状态变化；金额分币种，数量分Item/UOM；列表操作仍逐对象重新授权。 |
| OD-R02-PREQ-002 | 在来源受理、报价转单与复购范围内，Sales / Quote原Owner须按本页进入条件、可见状态、输入与动作合同完成处理；复购不是重复请求；新商业意图新OrderId，原操作重试查回同一OrderId。 |
| OD-R02-PREQ-003 | 在订单头、有效版本与编辑草稿范围内，Sales须按本页进入条件、可见状态、输入与动作合同完成处理；有效商业版不因打开改稿而失效；拟改范围是否暂停由独立控制决定，不暗中恢复或冻结全部订单。 |
| OD-R02-PREQ-004 | 在商业行、分交期与数量分配范围内，Sales须按本页进入条件、可见状态、输入与动作合同完成处理；稳定ScheduleId不使用行号、日期或SKU代替；改变排序不改变身份；相同物料不同价不得合并。 |
| OD-R02-PREQ-005 | 在ATP评估与企业交期承诺范围内，Sales发起 / Planning评估须按本页进入条件、可见状态、输入与动作合同完成处理；采纳不是查询副作用；无运输依据不把送达日复制为工厂可用日；不把ATP当锁库。 |
| OD-R02-PREQ-006 | 在商业确认与审批应用范围内，Sales / OA / Finance各自事实须按本页进入条件、可见状态、输入与动作合同完成处理；客户接受、OA批准、信用结果和Sales Confirm是不同证据；该按钮只产生有效商业确认及回传依据。 |
| OD-R02-PREQ-007 | 在逐份额释放与双边回执范围内，Sales须按本页进入条件、可见状态、输入与动作合同完成处理；不可拆组合不使用默认批次部分成功；未经支持的联合启用协议不放行此模式。 |
| OD-R02-PREQ-008 | 在价格、日期、数量及技术变更范围内，Sales协调 / 各Owner裁决须按本页进入条件、可见状态、输入与动作合同完成处理；纯价格不新增Demand；已开票/发运历史不被新价格覆盖；价格有效范围按行/份额/日期或未结算范围精确表达。 |
| OD-R02-PREQ-009 | 在剩余量取消与执行后果处置范围内，Sales / Planning / 原执行Owner须按本页进入条件、可见状态、输入与动作合同完成处理；取消上限基于权威发运与覆盖；不能用投影0放行，不能因下游不可撤销而删除商业取消事实。 |
| OD-R02-PREQ-010 | 在欠交、重承诺与受控拆分范围内，Sales / Planning须按本页进入条件、可见状态、输入与动作合同完成处理；转移不是商业取消/新销售；无可靠原子启用或协调协议时不得使新旧同时成为计划输入。 |
| OD-R02-PREQ-011 | 在履约、售后关联与业务结束范围内，Sales消费原Owner事实须按本页进入条件、可见状态、输入与动作合同完成处理；不编辑WMS已发或Finance已开票；不把结束原因写成全部履行；财务未完不自动阻塞无关业务结束。 |
| OD-R02-PREQ-012 | 在需求接收队列与合法来源核验范围内，Planning须按本页进入条件、可见状态、输入与动作合同完成处理；Planning可自动执行确定规则或授权人工复核，但人工不能改来源数量/日期后直接接收。 |
| OD-R02-PREQ-013 | 在需求明细、版本与冻结技术范围内，Planning须按本页进入条件、可见状态、输入与动作合同完成处理；不允许计划员直接改Sales来源的需求量/交期；发现错误发起有证据的源纠正申请。 |
| OD-R02-PREQ-014 | 在需求控制、工程影响与Owner回执范围内，Planning及原执行Owner须按本页进入条件、可见状态、输入与动作合同完成处理；Planning暂停不改变商业承诺；QA或PLM禁用不由Planning管理员解除；解除一个原因不恢复所有执行。 |
| OD-R02-PREQ-015 | 在计划覆盖、补给责任与结果展示范围内，Planning须按本页进入条件、可见状态、输入与动作合同完成处理；本册不新写MRP算法；计划量、WO量、入库量按谱系解释，不能相加当履行。 |
| OD-R02-PREQ-016 | 在业务回查、异常恢复与审计范围内，各业务Owner按动作权限须按本页进入条件、可见状态、输入与动作合同完成处理；没有“强制成功”“改状态为已接收”；异常负责人能分派任务但不能因此越权改业务事实。 |
| OD-R02-PREQ-017 | 在明细导入、受控导出与证据范围内，Sales / DOC证据权限须按本页进入条件、可见状态、输入与动作合同完成处理；导入只维护草稿，不隐式Confirm/Release；导出不能泄露隐藏字段或把历史成功写成当前有效。 |

## R04八项展示细化

| ID | 规则 | 期望 |
|---|---|---|
| OD-R04-UI-001 | 显示本次对象/行/份额、当前与编辑版、目标数量或取消分配、审批/当前条件和原操作键。预检后关键事实变化时不保留可直接执行的旧确认态。 | 旧60方案不直接应用；显示准确差异和重新评估入口，历史客户诉求保留。 |
| OD-R04-UI-002 | 批次摘要展示成功、拒绝、未知的明细分组；未知量不展示为确定未释放。不可拆组采用整体启用视图，不套独立批次部分成功。 | 显示S1当前40和S2待核60；不显示整批已完成100，也不开放同意图新键释放60。 |
| OD-R04-UI-003 | 原字段字典中Sales提交前可选的数量/地点，不在Planning接收页变成可改字段。本页只读原载荷，另通过原ACT-038申请源Owner纠正。 | 不将100直接编辑成60接收；来源合法性与供给不足分别处理。 |
| OD-R04-UI-004 | 三类入口各列适用结果、原Owner、当前控制与恢复资格；没有万能重试/强制成功按钮。共用页不扩大角色权限。 | 仅允许有权补显示投影；不重新执行业务释放，不创建第二份Demand。 |
| OD-R04-UI-005 | 历史Accepted与当前Cancelled/被替代及当前控制分栏，不能只给一个成功布尔值。晚到真实事实进入所属Owner事实处理，不按订单新版丢弃。 | 保留v1真实Demand/版和成功事实，同时显示当前取消与处置；不恢复原有效需求。 |
| OD-R04-UI-006 | 已收请求、已阻新执行、指定在途已核清分别显示；各控制原因保留Owner。只解除一项不让页面显示全部已恢复。 | 保留质量Hold；依赖动作仍被该原因阻塞，不由Planning代解除。 |
| OD-R04-UI-007 | 历史Closure保留，新有权事实更正显示当前差异及所属复核义务；正常退货、纠错和补发决定有独立入口与原Owner。 | 有效发运当前90并显示关闭后差异；不删除旧Closure，不自动下10件生产或复活旧需求键。 |
| OD-R04-UI-008 | 显示策略Owner、作用动作、缺成员和原实例状态；原文NOT_CONFIGURED与索引MISSING_OWNER_VALUE保留来源，界面统一提示缺真实实例仅是显示映射。 | 显示待补字段与责任Owner；不默认无限精度/无限授信、不把null当0或N/A放行。 |
