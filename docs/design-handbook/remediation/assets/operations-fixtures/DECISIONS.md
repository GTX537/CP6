Use Python3.13 with jsonschema4.26.0, isolated from project dependencies. Reproducible command: `uv run --no-project --python 3.13 --with jsonschema==4.26.0 python docs/design-handbook/tools/build_operations_fixture_patches.py`; then run `uv run --no-project --python 3.13 python docs/design-handbook/tools/validate_operations_fixtures.py`. The default materialization directory is `D:/CP6-archives/design-revision-20261011-checks/operations`. Source files are only read. The generator pins their SHA values, rejects changed preimages, records deterministic output SHA/bytes and performs positive/negative local data checks. No source scripts are executed.

Digest domains: compact Unicode UTF-8 JSON, sorted object keys and original array order; no implicit decimal parsing. IQC hashes full EvidenceDocument.body, and separately the complete ordered SlotEntry array. IPQC row hashes cover row only; whole-state hashes cover sorted table/key descriptors including rowDigest. Audit.AfterDigest is the full business state before terminal Command/Audit writes. Command terminal hashes and response-content hashes remain distinct. FIN-INV SC20 preserves its original exclusion of resultDigest and adoptionMode; historical FixtureDigest is retained as historical metadata with a separately named full-scenario digest.

OPS045 is a new DEMO approval fixture, not retroactive expansion of POLICY1@1 and not evidence of a real approver. OPS049 proof authority/fence documents and OPS050 line documents are explicitly new DEMO profiles; original opaque upstream references are not upgraded to real Owner evidence. For REAL use, read exact Owner records and authority, enforce same-Uow uniqueness/CAS, permanent fence and complete coverage, then independently execute runtime acceptance.

Consumer selection is atomic: the manifest selects derived machine JSON and the listed current mirrors. Earlier R2/R3 continuous bundles, old PASS reports, split-markdown presentation fragments and review-window excerpts are historical evidence and cannot remain an executable fixture entry alongside revised machine JSON. Do not replace historical hash domains or turn a stale PASS report into a new run. All business acceptance and runtime adoption remain NOT_RUN / UNPROVEN.
