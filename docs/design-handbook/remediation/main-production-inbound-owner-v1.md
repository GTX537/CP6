# Main 报工／入库 Owner v1（W38）

2026-10-21；仅 PostgreSQL。补充 [W37 Operations Owner](main-operations-owner-v1.md)，范围为 `ProductionResultService`、`BackflushService`、`InboundService`、直接完成桥及三个控制器。原历史非 PostgreSQL 路径保留，不是新增数据库目标。无 EF 模型或迁移变更。

## 独立入口与权限用途

|资源|动作与入口|字段|
|---|---|---|
|mes-production-result|query：报工列表、工单摘要；start/suspend/complete/report；Resume 沿用 suspend；服务 recalculate/backflush|无可配置价格字段|
|wms-inbound-order|query/add/edit/del/confirm/cancel|UnitPrice|
|wms-inbound-receipt|query/post：手工收货及公开成品生成服务|UnitPrice|

原会话主体、可信租户、当前有效角色、启用动作及封存字段源在服务边界检查。新增三个 query 和报工 recalculate/backflush 只登记动作目录，不自动授予任何角色；既有动作授权不推导新动作。控制器保留 Owner 的 401/403/409/503 和 no-store，浏览器写入口继续执行原 CSRF。

入库计划/收货查询在没有单价 Read 时返回 null；创建/修改/收货使用各自 UnitPrice Write。参照入库计划需要独立计划 query 和完整来源对象，确认收货只使用其身份与数量，不复制隐藏计划价格，因此不额外要求没有被使用的来源价格 Read。工单摘要及手工收货提供 WorkOrderNo 时须另外具备制造 query 和来源对象权限。只授父业务动作不能调用这些独立入口。

## 完整对象与原生关系

资源范围 1–5、默认 self。报工 self 覆盖工单、全部工序/材料及报工流水 Creator，含软删除兄弟；计划和收货 self 分别覆盖存储头与所有明细，不能只检查当前页面可见行。tenant 范围仍受租户过滤。制造/报工及关联收货的部门范围只沿真实 WorkOrder→Order 存储关系进入显式部门映射；自定义部门集合使用当前资源。独立计划的 PoNo 尚无获准的采购部门映射，不把它、仓库或浏览器输入猜成部门，部门范围拒绝；self/tenant 合法使用保留。

计划和收货还须满足角色仓库/区域范围，完整明细按实际库位对应区域检查；区域授权不推导对无确定库位的整个仓库授权。管理员原有仓库策略不绕过动作、对象和字段用途。身份、产品、库位、区域、父引用和 BOM/规格/楞型匹配使用 PostgreSQL 原生等价语义；纯计算器接收已在数据库解析的键，不能用 CLR 大小写归一化代替身份认定。

计划编辑保留已有明细 Id/Creator/CreateDate，不接受伪造 ReceivedQty；已实际收货的计划不再按普通编辑替换。收货若提供 RefOrderLineNo，必须命中真实计划行及产品；未提供的计划外行仍允许，且不虚增计划行累计。实际批次可以与预期批次不同。采购适配器把不连续的 PO 行号映射到 WMS 实际顺序行号，回传仍保留原 PO 行号；它仍需要独立 WMS 授权，本轮没有授予采购通用委托，也没有把采购整单改为原子流程。

## 事务和保留的业务语义

冻结嵌套请求后，由共同 Owner 新建 READ COMMITTED 事务；拒绝旧事务、脏上下文、预跟踪业务图及不同上下文的库存/序号适配器。共同权限根、相关业务与来源输入表锁、最终主体/版本/范围/部门映射/期限及会话检查贯穿 COMMIT。短表锁会串行化相关跨租户写入，是当前软引用和旧写入口下的明确成本。

一次收货的库存、流水、序号、收货头/明细及计划累计/状态处于同一事务，后续行失败不留下前行库存。计划取消保留已收到库存，不能把取消计划冒充冲销收货。数量 decimal(21,8) 与 WMS 单价 decimal(18,4) 不变，不宣称扩展了既有单价模型。

报工流水、工单/工序累计、状态及本次派生工时同一事务，最终授权失败全部回滚；人工覆盖工时仍不重算。保留原各工序累计算法及开始/中断/恢复/完成规则。完成和检验后的追加数量报工仍合法，且不再次触发自动入库/反冲；取消工单拒绝新报工。后续数量差异处理仍按原业务合同，不在本轮悄然引入新的成本或库存调整。

手工 WM060 保留独立、可选工单、部分/多次收货；不能套用自动桥的整量规则。自动完工桥仍按既有 W01/W01-FG、工单产品和累计良品数一次生成；同工单已有 PRODUCTION 收货时沿用原防重复约束。手工界面的 W03/W04 默认不被改成自动桥仓库。

反冲保留报工确认后按材料独立补偿、原 BOM 计算和允许负库存的合同；同一材料的所有 BOM 行、库存流水和 ActualQty 在一个事务中提交。普通材料业务失败不抹去其他已成功材料，后续补偿按真实 ISSUE 记录跳过成功材料；权限拒绝或结果未知立即停止，不自动重放。BOM/规格/楞型与库存/耗用在事务内读取。反冲失败仍阻止本次财务归集/结转，不能以旧 ActualQty 宣称成本完成。

COMMIT/ROLLBACK 确认丢失返回 `OPERATIONS_OUTCOME_UNKNOWN`，不自动重试。通知和既有财务桥只在已确认提交后 best-effort；不能把本地事务成功说成可靠跨模块投递或端到端原子性。

## 完成动作的有限委托与页面

只有已确认完成报工产生进程内 capability，绑定同一上下文/租户、原主体、父 complete 动作/权限版本、工单号、持久化完成流水 Id 及累计数量。真实 WmsBridge/Backflush 子事务重新检查父动作、完整对象、完成状态、流水及数量，最后再验证；只执行原有自动成品收货和 BOM 反冲，不能由 HTTP 构造，也不授独立 query/post/backflush 或通用仓库权限。原 W37 订单和制造发行委托不变。

六个相关页面复用 `useOperationsIntent`：等待确认前锁定写入、冻结发送内容、拒绝重复点击，隔离旧身份/目标/过时读响应。保存后的真实单号在读回拒绝时仍可见，期间新草稿不被覆盖；UNKNOWN 在当前意图内阻止再发。它不是跨重载、跨进程持久幂等。
