# Main 独立制造／出库 Owner v1（W37）

2026-10-21；仅 PostgreSQL。范围为 `WorkOrderService`、`OutboundService` 和其两个主控制器。其他 WMS/MES 服务、看板、独立报工/入库/盘点及真实业务验收仍按各自任务推进，不能从本次采用推导完成。

## 入口与用途

|资源|动作|用途|
|---|---|---|
|mes-work-order|query|列表、完整单票|
|mes-work-order|add|取号、创建、从订单展开|
|mes-work-order|edit/del/issue/cancel|独立修改、删除、发行、现有服务取消|
|wms-outbound-order|query|列表、完整单票|
|wms-outbound-order|add/edit/del|创建、从来源生成、修改、删除|
|wms-outbound-order|confirm/allocate/pick/ship/cancel|各自状态及库存操作|

新 query 和 MES cancel 只增加动作目录，不给任何角色自动授权。原管理员仓库全域策略不代表动作、对象或字段旁路。当前原登录主体、可信租户、有效角色和真实启用的动作定义在服务内检查；控制器属性与缓存不是最终授权源。取号优先 POST；兼容的 GET 同样要求浏览器 CSRF，不能用安全方法语义掩盖实际序号写入。读响应 `no-store`，Owner 拒绝保留 401/403/409/503，不被控制器转换成普通 400。

资源目录封存：MES 无价格字段；出库 `UnitPrice`。出库查询隐藏价格返回 null；新增/编辑/配货涉及价格写入须有 Write，发货使用价格须有 Read。从订单生成须另查当前 order query/来源对象及价格 Read；从制造生成须另查 MES query/完整来源对象。Read 不推导 Write。字段源失联、角色或定义异常拒绝，不降级为缓存许可。

## 对象与可信映射

两资源支持 1–5、默认 self。self 检查存储头及所有关联明细 Creator，包括软删除兄弟，原生 PG 比较；tenant 范围仍受当前租户过滤。部门 2/3/4 只从真实关联订单的存储 OrderDepartment，经已有显式部门映射及健康 IAM 部门树确定；自定义部门集合按当前资源读取。出库可以通过真实制造工单关联到订单，显式的双重关联必须一致。单独创建、没有订单的对象不把 BaseCd、仓库、名称或浏览器值猜成部门；其部门范围尚无可信映射，因此拒绝，self/tenant 仍可使用。

出库还与实际角色仓库/区域范围相交，覆盖头、所有明细的实际仓库和库位对应区域；跨仓配货只选择授权库存。未分配库位的草稿不能凭一个区域授权推断整个仓库授权。表内大小写及尾空格等价由 PG 合同决定，不靠 CLR 归一化认定身份。关联来源若已取消，新增、修改、发行、分配、拣货和发货均拒绝；查询保留历史可见性，取消可以继续释放存储占用。

## 事务与状态

冻结嵌套请求后开始新的 READ COMMITTED 事务，拒绝旧事务、脏上下文和预跟踪业务图。先取得共同认证权限根，再锁定相关业务表及仓库范围/路由等输入，完整旧图与持久化后的新图都验证。相关服务、库存、序号及路由/欠料适配器必须使用同一个上下文。短表锁是当前软引用与旧写路径下的明确成本：会串行化这些表的跨租户写入，不宣称已经实现细粒度吞吐优化。

制造计划修改保留已有子行 Id、Creator、CreateDate 与实际状态，按数据库原生键匹配；不能借普通编辑写入已发行/完工状态或覆盖已加工数量。有活动出库依赖时不能改写、删除或直接取消制造工单。

出库库存、流水、序号、明细、头及发货包裹处于同一事务；第二行失败不留下第一行已提交效果。取消/发货前按真实库存行聚合存储预留，数量不足或头/明细状态矛盾拒绝，不能截断后报成功。保留部分配货与欠料记录，取消仅释放实际预留；成功取消幂等，已发货不再次扣库存。原有数量 decimal(21,8)、WMS 单价 decimal(18,4) 合同保留；不把历史 WMS 价格模型说成订单的 8 位单价模型。

最终重读全部涉及资源的当前主体、权限版本、目录版本、范围、部门映射版本及租户期限，并再次检查原登录会话；直至 COMMIT 持有权限根。原生撤权与业务提交有确定顺序。COMMIT/ROLLBACK 结果无法确认返回 `OPERATIONS_OUTCOME_UNKNOWN`，不自动重放。

## 内部委托及提交后效果

原订单 add 和制造 issue 在其确认提交后，才给具体真实 Bridge 传进程内的不可由 HTTP 提交的委托，绑定上下文、租户、原主体、父资源/动作、单号及权限版本。下游事务再次验证父动作与完整对象。只允许既有的订单→制造初始计划/出货草稿、制造发行→材料出库草稿（固定 W01）；不授独立查询、编辑、库存操作或通用仓库权限。公共 from-order/from-work-order 接口仍要求自己的动作与来源读取。W36 order cancel 保持原有同事务、具体已发现子项委托，不调用独立入口冒充额外授权。

库存通知、欠料通知和原 ERP/FIN 桥只在确认提交后执行，保留既有 best-effort 语义。失败不把已提交单据变为可重试写入。跨模块财务/ERP效果未纳入本地库存事务，未实现持久 outbox、跨进程 operation 或完整业务验收；禁止据此宣称端到端原子性。

## 页面与验证边界

制造和出库的列表/输入页隔离旧身份、旧目标和过时请求；确认前即占用写入意图，冻结发送内容，避免重复点击。读回失败保留已确认单号/保存结果和新的草稿；未知结果在当前页面阻止再次提交并提示先查单票/列表。该 UI 约束不是持久幂等服务，跨重载、跨进程恢复需后续 operation 任务。
