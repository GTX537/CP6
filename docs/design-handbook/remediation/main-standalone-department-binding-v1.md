# Main 独立对象可信部门绑定 v1

W42-01 / WP02-03，2026-10-22。此合同补齐已有独立 Owner 的部门范围事实来源；不替代业务对象合同、原操作结果或真实跨仓采用。

## 对象身份与维护权限

- PostgreSQL `cp6_operations_owner_v1.department_mappings` 唯一键为 `(tenant_id, object_kind, object_id)`；`id` 为绑定身份，`revision` 每次写入更换。四种类型闭集：`stock`、`stock-transaction`、`stocktake`、`work-order`。
- `object_id` 必须是当前租户的真实既有对象 GUID；库存业务键、生产单号、当前调用人部门及外部 `OwnerCd` 均不转换为部门授权事实。新绑定或启用时对象须未删除；生产指示须没有订单关联。绑定身份/租户/类型/对象不可变，变更只调整组织部门或启停。
- 维护复用 `pub-dept:query/edit`、当前原会话及 IAM Owner。查找只返回对象 ID 和识别名称，最多50项，不披露数量、单价或业务明细；这是绑定管理员的身份目录权限，不是业务操作授权。界面要求主动查找、选择真实对象、选择组织部门、填写理由，没有当前部门默认。
- `POST /api/iam/departments/standalone-mappings` 必须含 operationId、ExpectedVersion、ExpectedReferencesVersion、理由和明确目标。首次绑定使用 `absent`；冲突要求重新读取并明确确认。完全相同原键返回已保存原结果，改输入拒绝。撤销当前编辑权限后原结果也不可披露。UNKNOWN 使用已有 IAM 查询/封闭流程，不自动重放；原结果、绑定和审计在同一事务。
- 审计保留原/新部门、启停、对象身份、理由和操作 ID。跨租户部门/对象、未知类型和空 ID 拒绝。数据库触发器还验证真实对象及同租户部门，保护普通 SQL 写入；不将 schema 本身当权限隔离。

## 业务消费

- 本人范围仍用原 Creator/全图规则，全租户仍用已授权范围；部门/子树/自定义范围使用本绑定和当前健康组织树。缺失、停用、无效祖先、空自定义范围均无对象可见。仓库/库区、独立动作、字段读写、来源查询、状态及租户约束继续相交。
- 库存查询、调整、移库、库存QC及使用相同库存权限查询的看板在 SQL 分页或聚合之前筛选真实库存 ID。部门范围只允许已有且已绑定的目标库存；创建新库存另需明确创建归属合同。
- 库存流水有自身不可变 ID 绑定。历史流水不因“当前存在同仓库/库位/产品/批号库存”自动继承归属；新流水本批也不自动回填部门。历史查询同时要求当前库存和对应流水各自可见。
- 盘点需盘点单绑定及每条明细对应的精确 `StockId` 与完整业务键均在当前库存范围内，包含软删除兄弟行。标题绑定不能授予其他部门的库存；原库存查询来源权限及批准/金额等门禁保留。部门范围新盘点计划未获创建归属合同，最终复核拒绝并回滚。
- 无订单生产指示按自身绑定；**已有订单关联时仅使用原订单部门绑定**，新对象绑定不会覆盖。生产、品质、不良及MES看板中既有的 WorkOrders 权限查询自然消费这条路径；完整来源图和各入口动作仍检查。入库/收货/出库自身的部门规则未在本批扩大。
- 业务表原有锁、身份根锁、最终权限检查保留。映射触发器先取得同一身份根锁，写入/删除/截断更新租户 `standalone-department-mapping` 版本；OperationsOwner 的组织版本同时包含组织/订单绑定与本版本。并发撤权等待当前已授权事务结束，下一操作拒绝；同事务修改版本导致业务回滚。ABA 不维持旧许可。

## 存储、部署与剩余范围

- 前向迁移 `20261022053000_StandaloneDepartmentMappingV1`，无EF模型/快照改动，无SQL Server新实现，不种植真实映射/角色/授权。只在隔离 PostgreSQL 夹具应用；既有环境迁移仍未授权。
- 这四类是首批实际消费，不宣称所有无订单对象已经覆盖。部门范围创建新对象、入库计划/收货/入库QC、跨业务可信继承及新流水自动归属需各自明确 Owner 合同与共同事务，不在查询中猜测。
- RMA仍需 `WMS-IN-RMA-ADAPTER-1`、databaseBinding/MainUow采用证明和正式商业/财务/库存效果 Owner；五种终端处置 `REQUIRED_FENCED` 不因本合同解除。Main持久业务原操作结果/可靠投递与CRM采用仍属七天计划后续窗口。
- 夹具结果只能证明本实现；不提升完整125目标或247运行验收，不冒充DEV/UAT/生产。

## W136 增量：新设备创建合同 v1（2026-10-25）

以上为W42首批历史范围；后续已有类型扩展按各迁移/Owner的真实范围保留。W136只新增 `machine` 的创建归属，不把既有对象维护权交给业务创建人，也不推断其他对象或历史流水。

- `GET /api/mes/machines/creation-context` 在当前原会话 `mes-machine:add` 下提供同租户健康部门和版本。范围2限本部门、3限健康子树、4限明确自定义集合、5可明确选择健康部门；范围1不提供任意指派。范围2/3/4必须主动选择，范围1/5允许保留无绑定创建。不得默认调用人部门。
- `POST /api/mes/machines/operations` 接受原操作ID、`ExpectedAuthorityVersion`、明确 `DepartmentId`（允许时为NULL）及原Machine输入。机器UUID由Owner新分配，调用者Machine.Id不能用于绑定历史对象。旧CreateAsync合法本人/全租户行为保留；部门范围旧入口继续拒绝无归属创建。
- 创建专用句柄只在当前DbContext、原事务、租户、真人和全新UUID中使用一次。真实设备先保存、仅该新ID插入一条映射、再保存原操作/审计，最终检查后共同提交。创建人不能选择已有对象ID，也不能调用IAM维护事务嵌套写入。
- 受控映射插入前核所有参与者的组织版本；单条参数化INSERT及原生校验/版本触发器完成后，验证非映射组织版本未变，只更新参与者的组织版本期望。全部权限源、注册表、范围、真人、有效期检查保留；最后核确切映射revision及新对象当前可见性。受控转换前后额外映射写、同事务撤权、最终来源失败都回滚。并发撤权继续由身份根锁串行。
- 原操作Owner=`Main.Mes.MachineCreation`，合同=`Main.Mes.MachineCreation.v1`，复用Main不可变账，不新增迁移。重复原键只在当前query下披露同输入原结果；不同输入409，已封闭409。公开结果为原操作/精确机器UUID/设备代码/当时选定部门，原输入与审计不公开。后续恢复核原真人、租户、当前query和原机器UUID的当前范围；同业务代码的新对象不能替代原对象。历史回执不授予当前部门权限。
- `GET /operations/{id}` 未见原操作返回UNKNOWN；`POST /operations/{id}/close` 与新创建使用同一身份/业务锁。未提交则保存CLOSED墓碑，已提交则返回当前仍有权查看的原结果。GET不证明不存在；未知时不自动重发/换键。
- 页面在浏览器互斥锁内确认当前身份，只持久化租户/真人范围内原操作ID，不存设备内容/部门草稿。重载只恢复该引用，查询或明确取消原操作；身份切换和迟到响应不能清除其他身份的待恢复引用。初次创建仍只需add，恢复需query，不以恢复权限扩大创建授权。
