## 如何使用资产

1. 从[统一处置表](00-disposition-register.json)找到用例涉及的全部 `targets`，读每个 `outputs` 与准确原依据。`ADOPTION_PENDING` 是有设计待接入，`INTENTIONAL_DIFFERENCE` 是必须保留的域差异，不能为了统一DTO改掉它们。
2. 从[manifest](assets/manifest.json)核原SHA和新资产SHA；组合补丁以[组合派生清单](assets/composed-derivatives.json)为准。特别是ATP同一DDL同时有单位长度和锁序补丁，不能只取其中一份。
3. 使用[验收目录](08-acceptance-catalog.json)的原编号/问题族定位正反例。金额、数量守恒、锁序、重复提交、取消/迟到、撤权与审批重放是必须针对真实实现验证的场景。
4. 记录实现源码SHA、实际Provider/数据库/权限与版本、执行命令和证据。通过一个静态检查不自动改变其他状态；未来真实失败保留原记录，修复后只重验受影响部分。

## 仍受限制的事项

- R01071及其他历史缺件继续按原缺件账；不再要求用户找回指定独审。
- 实际Owner/native schema注册、共同数据库事务能力、全部相关writer/final guard、密钥/审批证据与生产身份未因本次文档修改而获证。
- 本轮没有应用源码改造、生产数据迁移、环境替换、远程Actions运行或部署。新SQL/类型是设计资产；独立编译不能代替数据库及服务测试。
- 遗留程序迁移先固定当时源码SHA；归档旧工厂差异不是对今日运行代码的BUG认定。实际可复现BUG按GitHub Issues流程处理。

当前手册的模块正文在顶部给出本轮适用修订；下方原归档整理与阅读记录保留历史适用范围。实际交付检查见[本地设计验证报告](../evidence/design-completion-validation.json)。
