# 学习方法与掌握标准

## 1. 这套教材怎样才算“学完”

“看完”只表示眼睛经过了文字。面试需要四种不同能力：

| 层级 | 你能做什么 | 验收方式 |
|---|---|---|
| 识别 | 看到术语知道它大概是什么 | 选择题、术语配对 |
| 解释 | 不看资料讲清原理和边界 | 60 秒闭卷口述 |
| 应用 | 在代码或 SQL 里正确使用 | 最小实验、手写题 |
| 迁移 | 遇到变体能分析取舍 | 连续追问、故障题、系统设计题 |

核心主题至少达到“应用”，项目亮点要达到“迁移”。

## 2. 一章的标准学习动作

### 第一步：预检，5 分钟

先看章末验收题，不要急着读答案。给每题标记：

- `A`：能脱稿答并举例。
- `B`：知道结论，但讲不完整。
- `C`：只认得名词。
- `D`：完全陌生。

这样能避免把时间平均花在已经会的内容上。

### 第二步：建立最小心智模型，15～25 分钟

每个概念先回答三个问题：

1. 它解决什么具体问题？
2. 不用它会发生什么？
3. 它的代价或边界是什么？

例如学习 `AsNoTracking()`：

- 问题：只读查询不需要保存实体修改。
- 不用：EF 仍创建跟踪快照，增加内存和 CPU。
- 边界：后续若修改实体并保存，需要重新附加或不要禁用跟踪。

### 第三步：打开 CP6 真实文件，20～40 分钟

不要只看教材摘录。使用 IDE 完成下面动作：

1. 打开给出的文件路径。
2. 跳转到定义。
3. 查找所有引用。
4. 找至少一个测试。
5. 写下一条“代码事实”和一条“设计判断”。

二者不能混淆：

- 代码事实：`StockController.Search` 对查询使用了 `AsNoTracking()`。
- 设计判断：库存查询属于只读路径，因此禁用跟踪更合适。

### 第四步：最小实验，15～45 分钟

实验不追求大，而追求能观察：

- C#：打印值类型复制与引用类型共享的不同结果。
- 异步：比较串行 `await` 与 `Task.WhenAll` 的耗时。
- SQL：查看加索引前后的执行计划和逻辑读。
- Vue：观察 `ref`、`reactive`、解构后的更新差异。

实验记录必须包含：输入、预期、实际、解释。

### 第五步：闭卷输出，10 分钟

关掉教材，用“结论 → 原理 → 项目 → 边界”回答：

> `IQueryable` 表示可继续组合的查询表达式，提供者会把表达式翻译成 SQL；`IEnumerable` 表示内存中的可枚举序列。CP6 的库存查询先在 `IQueryable<Stock>` 上拼接条件，最后 `CountAsync` 和 `ToListAsync` 才执行。如果过早 `ToList`，过滤和分页会搬到内存。边界是并非所有 .NET 方法都能翻译成 SQL，遇到翻译失败要改写表达式或明确切换到内存。

### 第六步：错题复盘，5 分钟

错题不要只抄正确答案。记录错误类型：

- 概念混淆。
- 忘记边界。
- 不会举项目证据。
- SQL/语法不熟。
- 表达没有结构。
- 把未实现内容说成已实现。

## 3. 面试答案的四层结构

### 15 秒：结论层

先直接回答，不绕背景。

> `async/await` 的核心价值是非阻塞地等待 I/O，提高服务器吞吐；它本身不等于新建线程。

### 60 秒：原理层

解释运行机制，并说明最常见的边界。

### 2 分钟：项目层

用 CP6 的真实代码、故障或设计取舍证明自己做过。

### 深挖：追问层

准备至少三种追问：

1. 为什么不用另一种方案？
2. 这个方案哪里会失败？
3. 如何测试、监控和回滚？

## 4. 费曼检查法

如果答案里出现下面词语，必须继续解释：

- “底层就是……”
- “框架自动……”
- “性能更好……”
- “更加安全……”
- “解耦……”
- “高并发……”

例如不能只说“索引让查询更快”。应说明：

> 索引以额外存储和写入维护成本，换取更少的数据页读取。是否更快要看选择性、谓词可搜索性、覆盖情况和统计信息，最终以执行计划与 `STATISTICS IO` 验证。

## 5. 代码引用规则

面试时引用代码要做到“路径 + 行为 + 原因”，不必背行号：

> 在 `CP6.WebApi/Controllers/Wms/StockController.cs` 的库存查询里，我先拿 `Stocks.AsNoTracking()`，再根据查询参数逐步拼接 `Where`，最后做总数和分页。这样条件在 SQL Server 执行，而不是把库存全表拉回内存。

不要说“我们项目里到处都是这么做的”，除非你查过调用面。

## 6. 动手题的证据标准

| 类型 | 合格证据 | 不合格做法 |
|---|---|---|
| C# | 可运行代码和控制台输出 | 只复制教材代码 |
| SQL | 查询、结果、执行计划或 IO 统计 | 只写 SELECT 不执行 |
| Vue | 测试、浏览器行为或构建通过 | 只写组件片段 |
| 项目叙事 | 录音时长、自评、重录结论 | 默读逐字稿 |
| 故障题 | 时间线、证据、根因、预防措施 | 只背 STAR 四个字母 |

## 7. 每日结束的硬验收

每天结束前必须完成：

- [ ] 5 个 60 秒闭卷回答。
- [ ] 2 个连续追问，每个至少追三层“为什么”。
- [ ] 1 个动手实验。
- [ ] 1 段 CP6 代码证据说明。
- [ ] 更新错题本。
- [ ] 把一个答案压缩成 15 秒，再扩展成 2 分钟。

## 8. 何时停止深挖

面试准备不是无限研究。满足下面三点即可暂时停止：

1. 能讲清问题、机制、边界。
2. 能给一个真实项目例子。
3. 面对不知道的下一层，能准确说明自己的认知边界。

示范：

> EF Core 如何把表达式树翻译成 SQL，我能讲到查询提供者遍历表达式并生成数据库方言；再往下具体 visitor 的内部实现我没有读过源码，我不会把推测当结论。

## 9. 学习前环境检查

在仓库根目录执行：

```powershell
dotnet --info
node --version
npm --version
git status --short
```

不要为了做教材实验直接修改业务代码。优先使用临时项目、查询窗口或独立分支。涉及真实数据库写操作前，先确认连接的是本地开发库。
