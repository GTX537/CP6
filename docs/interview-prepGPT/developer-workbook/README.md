# CP6 开发者工作簿

这部分是 GPT 版的第一条主线。它不复制旧版章节，而是围绕 CP6 的真实开发任务组织知识，回答开发者真正会遇到的六个问题：

1. 需求进来以后，我先看哪一层？
2. 一段代码为什么这样写，而不是换一种更熟悉的写法？
3. 正常路径跑通以后，最可能在哪些边界条件翻车？
4. 出错时应该看浏览器、日志、断点、SQL 还是测试？
5. 怎样证明修复有效，而不是“这次刚好没报错”？
6. 怎样把做过的事讲成有证据、有取舍的面试答案？

## 工作簿不是阅读材料

每章都有三类内容：

- `先预测`：没运行之前先写结果。预测错了才会留下记忆。
- `动手验证`：必须产生一个输出，例如响应、日志、SQL、测试结果或断点截图。
- `故障注入`：故意制造并发、超时、重复消息、空值或权限失败，观察系统是否按预期退化。

只看正文而不完成这三类动作，等于没有使用工作簿。

## 工作簿与原理深挖怎么配合

遇到陌生概念时，去 GPT 版的 `principles/` 原理层查完整推导。例如你在请求链里不理解 `IQueryable`，就读表达式树与 EF Core 查询章节；弄懂后马上回到请求链继续跟代码。不要先把所有概念读完再动手，因为那时前面的内容已经忘了。

推荐节奏：

```text
真实问题 10 分钟
  → 源码追踪 25 分钟
  → 查概念 20 分钟
  → 实验与故障注入 25 分钟
  → 闭卷复盘 10 分钟
```

## 完成标准

一个工作簿只有同时满足下面四点才算完成：

1. 能画出关键数据流或状态变化图。
2. 能在仓库中指出至少三个真实代码证据。
3. 能演示一个正常结果和一个失败结果。
4. 能用两分钟回答“为什么这样设计、代价是什么、下一步怎么改”。
