# 08 · 制造业领域建模与系统边界

制造系统不是把 ERP、MES、WMS 名词堆在一张架构图上。真正的边界来自决策节奏：谁决定做什么、谁执行、谁记录事实、谁结算价值。本章建立从客户订单到采购、生产、质检、库存、发货与财务的数据链。

## 1. 四层系统边界

```text
ERP：订单、采购、主计划、成本、财务
MES：工单执行、工序、报工、设备、质量现场
WMS：仓库、库位、批次、入出库、盘点
设备/边缘：PLC、传感器、扫码、机台信号
```

现实中一套系统可能覆盖多层。面试重点是语义边界，不是产品名称。

## 2. 从客户订单到生产

```text
Sales Order
→ demand / forecast
→ MPS 主生产计划
→ MRP 物料需求
→ purchase requisition / planned order
→ purchase order / production order
→ issue material
→ operation reporting
→ finished goods receipt
→ shipment / invoice / cost
```

每个箭头都有数量、时间、状态和追溯关系。

## 3. 主数据

- Product/Material：物料编码、基本单位、批次/序列规则。
- BOM：一件产出需要哪些投入及损耗。
- Routing：经过哪些工序、标准工时/设备。
- Work Center/Equipment：产能与日历。
- Warehouse/Location：库存物理位置。
- Supplier/Customer：交易伙伴。

主数据错，交易系统再稳定也只会更快地产生错结果。

## 4. BOM

BOM 需要版本、生效日期、替代料、副产品、损耗、单位换算。多层展开要防循环。

Engineering BOM、Manufacturing BOM 可能不同：设计结构与实际生产/包装结构不完全一致。

历史工单应冻结当时 BOM 快照或版本引用，不能主数据一改过去用料跟着变。

## 5. Routing 与工序

定义顺序、工作中心、准备/加工时间、计量点、质检点、是否允许并行/跳过/返工。

标准时间用于计划和成本，不等于实际时间。报工记录事实，差异用于改善。

## 6. MRP

简化：

```text
Gross Requirement
- Available Inventory
- Scheduled Receipts
+ Safety Stock
= Net Requirement
```

再按批量规则、提前期和日历产生计划建议。

难点：需求/供应日期、已分配库存、在途、替代料、良率、最小订购量、冻结期。不是简单库存减法。

## 7. 计划与排程

MRP 回答“需要什么、什么时候”；有限产能排程回答“在哪台设备、什么顺序真正能做”。

约束：设备能力、模具、人员、换型、清洗、物料齐套、交期、优先级。急单插入会改变其他订单承诺，系统应显示代价而不是只允许拖拽。

## 8. 工单

工单承载产品、数量、日期、BOM/工艺版本、批次规则和状态。

状态转换要控制：未下达不能领料，关闭后不能普通报工，取消要处理已领料/在制品。

## 9. 领料与反冲

领料：显式从库存发到工单/线边仓，追溯清晰。

Backflush：报工时按 BOM 自动扣料，操作简单，但实际用料、替代、损耗偏差需补机制。负库存/延迟报工会让账面短期失真。

盘点冻结时反冲如何处理是明确业务决策，不是代码异常吞掉即可。

## 10. 报工

记录合格、不良、工时、设备、班次、批次。报工可驱动进度、WIP、入库、用料和成本。

必须有幂等、防超报、冲销/补录、并发和结账期规则。

## 11. 质量

- IQC 来料。
- IPQC 制程。
- OQC 出货。

质量状态影响可用库存。PENDING 是否可分配要明确；FAILED/HOLD 通常禁止。放行、让步接收、返工、报废都有审批和追溯。

不良代码应分层、稳定，不能只写自由文本，否则无法 Pareto。

## 12. 库存账

至少区分：

- Physical：物理在库。
- Allocated/Reserved：已承诺。
- Available：可再承诺。
- In-transit：在途。
- Quality hold：质检冻结。
- Consignment/VMI：所有权不同。

“账上有但找不到”可能是库位、批次、单位、冻结、延迟过账或线边实物移动未记录。

## 13. 批次与序列

批次管理一组同源物料；序列号追踪单件。需要：生成规则、供应商批次映射、分批/合批、效期、状态、召回。

正反向追溯必须穿过领料、报工、产出、发货，不能只在库存表有 LotNo。

## 14. FIFO 与 FEFO

FIFO 按收货/生产先后；FEFO 按最早到期。系统推荐批次还需考虑质量状态、客户要求、锁定和库位效率。

推荐与强制要区分。允许人工换批时记录原因与权限。

## 15. 盘点

流程：创建范围 → 冻结/快照 → 计数 → 复盘/复点 → 差异审批 → 调整 → 关闭。

盘点期间允许哪些交易决定快照能否解释。循环盘点按 ABC/风险频率进行，不必全仓停摆。

## 16. WIP

在制品位于工序之间，数量、状态、位置可能不在传统仓库。要定义 WIP 何时增加/减少、返工路径、报废和跨工序转移。

只看成品与原料库存会丢失车间中间态。

## 17. OEE

Availability × Performance × Quality。定义损失分类比公式重要。计划停机、换型、待料是否计入分母必须统一。

设备信号与人工报工时间可能冲突，需要可信来源和校正规则。

## 18. 成本

标准成本用于计划/估价；实际成本汇总真实材料、人工、制造费用。差异包括价格、用量、效率、产量。

库存交易与财务分录归属要明确：哪些动作过账，何时结期，失败如何补偿。不能每次库存移动都盲目发财务事件。

## 19. 包装/印刷特色

- 原纸卷号、克重、幅宽与长度。
- 拼版/合板：一次生产多个产品，共同材料与损耗分摊。
- 版、刀模、油墨配方与换型。
- 首件确认、色差、套印不良。
- 边角料、准备损耗、超产/欠产。

数据模型要表达共产品和实际损耗，不能强套一工单一产出。

## 20. 集成边界

系统间传“事实事件”而非共享数据库随意更新：

```text
WorkReportPosted
StockMoved
QualityReleased
ShipmentConfirmed
```

事件有 EventId、TenantId、OccurredAt、schema version、correlation id。消费者幂等，失败可重放。

## 21. 时间与班次

技术时间存 UTC，业务展示按工厂时区；班次日期独立计算。夏令时地区可能出现重复/缺失本地时间，不能只存无时区字符串。

## 22. 状态与冲销

已过账事实不要直接删除/改写。用 reversal 产生反向记录并关联原单，保留审计和财务可解释性。

草稿可以编辑，Posted 的修改必须是受控业务动作。

## 23. 需求访谈

不要只问“你要什么字段”。问：

- 现在怎样做，哪一步最痛？
- 例外怎样处理？
- 出错如何发现和补救？
- 哪个数字用于决策/结算？
- 谁能改，改后谁受影响？
- 一天量、峰值、离线多久？

用户提出的按钮可能只是他们想到的解决方案，真正需求是减少等待或错误。

## 24. 验收

从状态、不变量、并发、权限、离线、集成、审计写 Given/When/Then。正常保存只是一条。

## 25. 必做练习

1. 画订单到收款/成本的数据流。
2. 展开三层 BOM，加入损耗和替代料。
3. 设计盘点状态机与冻结规则。
4. 画一个批次正向和反向追溯。
5. 为报工写幂等、并发、冲销、弱网验收。
6. 为包装拼版设计共产品与损耗分摊问题清单。

## 26. 闭卷问题

1. ERP/MES/WMS 边界按什么划分？
2. MRP 与有限排程区别？
3. BOM 为什么需要版本快照？
4. 反冲的收益和风险？
5. Available 与 Physical 为什么不同？
6. 盘点冻结要决定哪些交易？
7. 批次追溯需要穿过哪些单据？
8. OEE 为什么定义比公式难？
9. Posted 为什么用冲销？
10. 集成事件为什么要幂等和 schema version？
