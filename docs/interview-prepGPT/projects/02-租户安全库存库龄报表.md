# 项目 2 · 写一个租户安全的库存库龄报表

## 目标

实现按仓库、产品、所有权和库龄区间汇总库存的只读报表。使用 Dapper/明确 SQL 练习窗口与聚合，同时确保 TenantId、参数化、分页、超时、执行计划和 DTO 边界正确。

## 1. 先定义一行代表什么

报表一行定义为：

```text
当前租户 + 仓库 + 产品 + 库龄桶 + 所有权类型
```

指标：Physical、Allocated、Available、库存价值（若单价存在）。库龄基准优先 ReceiveDate；缺失时业务如何处理必须决定，不能默认为今天掩盖历史。

## 2. 库龄桶

```text
0-30
31-60
61-90
91-180
181+
Unknown
```

区间边界用半开/闭区间写清。以 `@AsOfDate` 为固定时点，报表重跑可复现，不使用查询过程中变化的 `GETDATE()` 作为隐藏输入。

## 3. API 契约

```http
GET /api/wms/reports/stock-aging?warehouseCd=W1&asOfDate=2026-07-22&page=1&pageSize=50
```

DTO 不接收 TenantId。TenantId 从 `ITenantContext` 取得。

参数约束：asOfDate 不得未来过远；page≥1；pageSize≤200；编码长度符合 schema；排序字段白名单。

## 4. SQL 骨架

```sql
WITH Base AS (
    SELECT
        s.WarehouseCd,
        s.ProductCd,
        s.OwnerType,
        s.PhysicalQty,
        s.AllocatedQty,
        s.AvailableQty,
        s.UnitPrice,
        DATEDIFF(day, s.ReceiveDate, @AsOfDate) AS AgeDays
    FROM dbo.T_Stock AS s
    WHERE s.TenantId = @TenantId
      AND s.IsDeleted = 0
      AND (@WarehouseCd IS NULL OR s.WarehouseCd = @WarehouseCd)
      AND (@ProductCd IS NULL OR s.ProductCd = @ProductCd)
), Bucketed AS (
    SELECT *,
      CASE
        WHEN AgeDays IS NULL THEN 'UNKNOWN'
        WHEN AgeDays <= 30 THEN '000-030'
        WHEN AgeDays <= 60 THEN '031-060'
        WHEN AgeDays <= 90 THEN '061-090'
        WHEN AgeDays <= 180 THEN '091-180'
        ELSE '181+'
      END AS AgeBucket
    FROM Base
)
SELECT WarehouseCd, ProductCd, OwnerType, AgeBucket,
       SUM(PhysicalQty) AS PhysicalQty,
       SUM(AllocatedQty) AS AllocatedQty,
       SUM(AvailableQty) AS AvailableQty,
       SUM(PhysicalQty * COALESCE(UnitPrice, 0)) AS StockValue
FROM Bucketed
GROUP BY WarehouseCd, ProductCd, OwnerType, AgeBucket;
```

这是起点，不是可直接生产复制的最终 SQL。特别检查负 AgeDays、时区、单位/币种和 UnitPrice 为 null 的业务语义。

## 5. 可搜索性

DATEDIFF 用于分类输出，不一定是筛选主条件。若要只查 180 天以上，最好把条件转换为 ReceiveDate 截止日期：

```sql
s.ReceiveDate < DATEADD(day, -180, @AsOfDate)
```

避免在列上 DATEDIFF 后过滤，使索引更有机会使用范围。

## 6. 可选条件的计划问题

`(@WarehouseCd IS NULL OR s.WarehouseCd=@WarehouseCd)` 方便但可能产生通用计划和估算问题。数据量大时选择：

- 生成少量固定 SQL shape。
- `OPTION(RECOMPILE)` 对低频报表。
- 存储过程分支。

先用真实分布测，不因看到 OR 就必改动态 SQL。

## 7. 排序与分页

按 `WarehouseCd, ProductCd, OwnerType, AgeBucket` 稳定排序。聚合结果的 key 组合本身若唯一，可分页；否则补稳定列。

COUNT 统计分组数量，不是底表行数。可以：

- 单独 `COUNT(*) FROM (group query)`。
- `COUNT(*) OVER()` 在聚合结果上带 total。

比较执行计划，避免为了少一次往返导致大排序/重复计算。

## 8. Dapper 实现边界

```csharp
var tenantId = tenantContext.CurrentTenantId;
var command = new CommandDefinition(
    sql,
    new { TenantId = tenantId, query.WarehouseCd, query.ProductCd, query.AsOfDate },
    transaction: transaction,
    commandTimeout: 30,
    cancellationToken: ct);

var rows = await connection.QueryAsync<StockAgingRow>(command);
```

连接由 factory/Context 规范管理。参数类型与列匹配。若与 EF 写入同一事务，显式传当前 DbTransaction。

## 9. 索引推导

候选前缀：TenantId、IsDeleted/过滤、WarehouseCd、ProductCd、ReceiveDate。一个索引很难同时完美服务全仓报表、单仓产品和库龄范围。

收集常用参数分布，比较：

- 全租户全仓夜间报表。
- 单仓交互报表。
- 单产品追踪。

可能需要报表快照/汇总表，而不是给 OLTP Stock 加超宽索引。

## 10. 安全测试

两个租户使用相同仓库/产品编码但不同数量。调用时不允许传 TenantId。断言 A 的 Physical 不含 B。检查日志和缓存 key 也包含租户。

尝试排序字段注入：`sort=ProductCd; DROP...`。实现必须使用白名单映射，不把输入直接拼标识符。

## 11. 正确性测试

- ReceiveDate 边界 30/31/60/61。
- null → UNKNOWN。
- future receive date 的规则。
- decimal 价值精度。
- CUSTOMER/SELF 分开。
- Available 汇总仍等于 Physical-Allocated（若行级不变量成立）。
- 同码跨租户隔离。

## 12. 性能测试

用倾斜数据至少 100k 行。记录：

```text
parameter set
rows scanned/returned
logical reads
CPU/elapsed
actual vs estimated
sort/hash spill
memory grant
```

同时测库存写入受新索引影响。

## 13. 缓存

若缓存报表，key 包含 TenantId、所有 filters、asOfDate、page/sort、权限范围。定义 TTL 和库存变化后的失效。遗漏 TenantId 是严重数据泄漏。
