# 01 · 自我介绍与项目主线

以下是结构化草稿，不是让你逐字冒充。年限、职责、模块、客户、生产使用情况和数字必须按真实履历修改。

## 1. 自我介绍四段式

1. 身份：经验年限、方向、主力技术栈。
2. 能力：两个与岗位最相关的标签。
3. 证据：一个代表项目和个人职责。
4. 匹配：为什么想做这个岗位。

## 2. 30 秒模板

> 您好，我是有 **[X 年]** 经验的全栈开发工程师，主力技术栈是 **.NET、SQL Server 和 Vue**，最近的工作重点是制造业管理系统。我在 CP6 项目中主要负责 **[真实负责范围]**，做过从业务建模、后端 API、数据库到前端页面和部署排障的完整链路。我希望继续深耕生产管理系统，这个岗位在技术栈和制造业务上都与我的经验高度重合。

只保留一个钩子。不要 30 秒报十个组件名。

## 3. 1 分钟模板

> 您好，我是 **[X 年]** 经验的全栈开发工程师，主力是 .NET 8、SQL Server、Vue 3 和 Element Plus。过去 **[真实年限]** 我主要做制造业信息系统。
>
> 我的代表项目 CP6 是一套纸器/包装行业的进销存和制造平台，业务覆盖订单、生产执行、仓储，以及逐步扩展的审批、采购、财务等能力。我在其中负责 **[列 2～3 项真实责任]**。我最能体现价值的两件事，一是 **[真实技术决策，例如库存写入口/多租户]**，二是 **[真实故障或交付]**。
>
> 我想应聘这个岗位，是因为它需要能把生产业务、SQL、后端和前端连起来的人，这正是我过去项目里积累最多的部分。我也希望在真实车间需求和团队交付中继续把这套能力做深。

## 4. 3 分钟项目介绍

按六段：

### 背景，20～30 秒

> CP6 来源于纸箱包装企业核心系统刷新。业务上要把报价、订单、生产、质量、库存和发货的数据连起来，减少多系统重复录入和对账困难。

### 范围，20 秒

区分状态：

- 已实现并能从代码/页面验证的模块。
- 当前正在实现的模块。
- 只有设计文档/路线图的模块。

不要把 README 中“下一程目标”全部说成已生产落地。

### 架构，35 秒

> 后端是 .NET 8 的 Web API，按 WebApi、Core、Entity 分层，EF Core 为主、Dapper 用于精确复杂查询；前端是 Vue 3、TypeScript、Element Plus 和 Pinia；数据库 SQL Server。请求横切有认证、租户、权限、本地化、异常和审计，实时变化通过 SignalR，部分日志/通知使用 Kafka、RabbitMQ。

### 我的职责，30 秒

使用准确动词：

- 我独立完成……
- 我主导……
- 我参与……
- 团队共同完成……

如果 CP6 是个人练习/独立项目，也要如实说“个人端到端项目”，不要虚构团队和生产用户。

### 两个深点，60 秒

只挑两个你能被追五层的：

1. 库存强一致写路径和已知移库限制。
2. 多租户读过滤、写盖章、后台 scope 和绕过面。
3. httpOnly Cookie + CSRF + refresh 并发。
4. 工作流/审批状态机。
5. SQL 性能和生产排障。

### 结果与成长，25 秒

结果用核对过的证据：测试通过、页面链路、缺陷下降、恢复时间、交付范围。成长说方法变化：

> 我最大的成长是从“把页面和接口写出来”，转到“先定义不变量、失败路径和验证证据”。例如库存主交易、通知副作用、多租户隔离和反射守卫，我会分清强一致边界与最终一致边界，而不是用一个事务或一个权限按钮笼统概括。

## 5. 项目讲解的证据层级

| 证据 | 强度 | 示例 |
|---|---|---|
| 实际运行/测试 | 高 | 构建、测试、HTTP 脚本、截图 |
| 当前源码 | 高 | Controller/Service/迁移/页面 |
| 设计文档 | 中 | 表示方案，不等于已实现 |
| README 摘要 | 中低 | 可能滞后 |
| 记忆中的数字 | 低 | 必须核对 |

## 6. 个人贡献怎么说

错误：

> 我做了整个 ERP/MES/WMS/财务/采购/工作流，几千个测试都是我写的。

更可信：

> CP6 当前覆盖多个业务域。我重点负责/深入过的是 ___、___ 和 ___。我可以现场从页面、API、Service、表结构讲完整链路。其他模块我了解整体边界，但如果不是我主要完成的，我会明确说明。

## 7. 项目数字

说数字前记录：

- 统计日期。
- 命令。
- 范围定义。
- 是否包含生成文件/测试用例参数化。

例如“测试数”可指测试方法、发现的 test case、端到端剧本，三者不能混用。

## 8. 被质疑“项目是不是你做的”

不要防御，进入证据：

> 您可以任选一个链路往下问。我能从页面状态、HTTP 契约、Controller、事务和表结构讲到失败路径。比如库存查询和库存变动我都可以现场画出来。对于不是我主要负责的模块，我也会明确边界，不把团队成果全算在自己身上。

## 9. Java 经验不足

> 我的主力语言是 C#，Java 的生产经验 **[如实说明]**。我不会把“概念相似”说成“已经熟练”。能迁移的是依赖注入、Web 管道、ORM、事务和并发这些原理；需要补的是 Java 语法、Spring 约定、构建与排障工具。如果岗位需要，我会用一个小服务加测试和实际部署验证，而不是只看语法对照表。

## 10. 桌面客户端经验不足

> 我的主要交付是 Web，桌面客户端的实际经验 **[如实说明]**。C# 语言和异步/事件模型能迁移，但 UI 线程、Dispatcher、数据绑定、打包升级和设备接入是桌面端特有能力，我不会说成无成本平移。我愿意通过一个真实小功能快速补齐。

## 11. 录音验收

每个版本录三遍：

- 第一遍只看关键词。
- 第二遍删除空话和技术清单。
- 第三遍让朋友在任何钩子处打断追问。

自评：时间、事实、个人贡献、业务价值、技术深度、边界各 5 分。任何一项低于 4 分都重录。
