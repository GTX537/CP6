# 01 · .NET 运行时、类型与内存

## 学习结果

完成后你应能：

- 解释 C# 源码从编译到执行的主要阶段。
- 准确描述值类型和引用类型的“变量里存什么”。
- 判断装箱、字符串分配、可空值类型和数值精度问题。
- 用 CP6 实体属性解释类型选择，而不是只背定义。

## 1. 从源码到机器执行

### 一句话结论

C# 通常先编译成 IL 和元数据，运行时由 CLR 加载、验证并通过 JIT 把实际执行的方法编译成机器码；发布时也可以使用 ReadyToRun 或 Native AOT 改变编译时机。

### 关键角色

| 名称 | 作用 | 容易混淆 |
|---|---|---|
| C# 编译器 | 语法/类型检查，生成程序集 | 不直接等同于生成最终机器码 |
| IL | 与 CPU 指令集相对独立的中间语言 | 不是解释型脚本 |
| CLR | 类型加载、GC、异常、JIT 等运行环境 | `.NET` 不只是 CLR |
| JIT | 把要执行的 IL 编译为本机码 | 通常按方法、按需发生 |
| GC | 管理托管堆对象生命周期 | 不负责所有资源，如文件句柄 |

### 面试追问：托管与非托管

“托管”表示对象生命周期和类型安全主要由 CLR 管理。数据库连接的 C# 包装对象在托管堆上，但它背后的 socket、句柄属于有限的外部资源，仍需要 `Dispose`/`await DisposeAsync` 及时释放。

## 2. 栈和堆不是值/引用类型的定义

### 正确模型

- 值类型变量直接包含它的值。
- 引用类型变量包含对对象的引用。
- 存储位置由上下文和运行时优化决定，不能把“值类型一定在栈、引用类型一定在堆”当定义。

例如一个类的 `int` 字段随对象一起位于托管对象布局中；捕获到闭包的局部变量也可能提升到堆对象。

### 最小实验

```csharp
public sealed class Box
{
    public int Value { get; set; }
}

var a = 10;
var b = a;
b++;

var x = new Box { Value = 10 };
var y = x;
y.Value++;

Console.WriteLine($"a={a}, b={b}");      // a=10, b=11
Console.WriteLine($"x={x.Value}, y={y.Value}"); // x=11, y=11
```

解释重点不是“堆栈”，而是复制行为：`b = a` 复制数值；`y = x` 复制引用，两个变量指向同一对象。

## 3. 参数传递：默认都是按值

C# 默认参数传递都是“把变量当前内容复制给形参”。引用类型按值传递时复制的是引用。

```csharp
static void Mutate(Box box) => box.Value = 99;

static void Reassign(Box box) => box = new Box { Value = 100 };

static void ReassignByRef(ref Box box) => box = new Box { Value = 200 };
```

- `Mutate` 改变共同指向的对象。
- `Reassign` 只让局部形参指向新对象，调用者变量不变。
- `ref` 允许方法改写调用者变量本身。

`in` 表示只读引用参数，`out` 要求方法赋值。不要把它们和引用类型混为一谈。

## 4. struct、class、record 怎么选

| 类型 | 默认语义 | 适合 | 风险 |
|---|---|---|---|
| `class` | 引用语义 | 有身份、可变生命周期的实体/服务 | 共享可变状态 |
| `struct` | 值语义 | 小、不可变、频繁创建的值 | 大结构复制成本；可变 struct 陷阱 |
| `record class` | 引用类型 + 结构化相等 | DTO、命令、事件、值对象候选 | `with` 是浅复制 |
| `record struct` | 值类型 + 结构化相等 | 小型不可变数据 | 仍有复制成本 |

EF Core 实体通常用 class，因为需要身份、跟踪与导航关系。DTO 可以考虑 record，但项目当前大量 DTO 仍是普通 class，这不是错误；选型要看序列化、可变性和团队约定。

## 5. 相等性与哈希

### 三种常见相等

- 引用相等：是否同一个对象。
- 值相等：内容是否相同。
- 业务相等：领域定义的唯一性是否相同。

重写 `Equals` 时通常也要重写 `GetHashCode`，因为哈希集合要求：相等对象必须产生相同哈希码。反过来不要求，不同对象允许哈希冲突。

可变对象作为 `Dictionary` key 很危险：如果参与哈希的字段在加入后改变，集合可能再也找不到它。

## 6. 装箱与拆箱

值类型被当作 `object` 或某些接口使用时可能发生装箱：创建托管对象并复制值。拆箱要求实际装箱类型精确匹配。

```csharp
object boxed = 42;
long wrong = (long)boxed; // InvalidCastException
long ok = (int)boxed;
```

泛型集合 `List<int>` 避免了旧式 `ArrayList` 中大量装箱和运行时强制转换。

## 7. 可空值类型与可空引用类型

`int?` 是 `Nullable<int>`，运行时确实有 `HasValue` 和 `Value` 语义。

`string?` 属于可空引用类型注解，主要是编译器静态流分析；`string` 和 `string?` 在 CLR 类型层面通常仍是同一个 `System.String`。

因此：

- `int?` 改变了值类型表达能力。
- `string?` 改变了编译器契约，不会自动阻止反射、JSON 或旧代码传入 null。

## 8. 数值类型与制造业数据

### `decimal` 与 `double`

`double` 使用二进制浮点，范围大、硬件支持好，适合测量、科学计算、图形。`decimal` 用十进制表示法，适合需要十进制舍入直觉的金额。

```csharp
Console.WriteLine(0.1 + 0.2 == 0.3);       // 通常 False
Console.WriteLine(0.1m + 0.2m == 0.3m);   // True
```

但“金额用 decimal”不等于万事大吉：

- 仍有有限精度和范围。
- 除法仍会舍入。
- 数据库列的 `decimal(p,s)` 可能比 C# decimal 更窄。
- 币种小数位、税额舍入和汇率规则属于业务规则。

CP6 `Stock` 使用 `decimal(21,8)` 保存数量，`decimal(18,4)` 保存单价。面试要解释精度选择，而不是只说“decimal 精确”。

### 时间类型

`DateTime.Now` 使用服务器本地时间，跨时区系统容易歧义。更稳妥的通用策略是：持久化 UTC，边界层按租户时区显示；但必须先核对现有业务约定。不要在面试中假装 CP6 已经全面 UTC 化，当前实体仍大量使用 `DateTime.Now`。

## 9. string 的不可变性

字符串修改会产生新字符串；循环大量拼接时可能创建许多中间对象。`StringBuilder` 适合未知次数的累计拼接，但少量插值通常更清晰。

比较标识符时明确指定比较规则：

```csharp
string.Equals(codeA, codeB, StringComparison.OrdinalIgnoreCase)
```

面向用户的语言学排序与内部代码比较不是一回事。仓库码、产品码通常更适合 Ordinal 规则。

## 10. GC 必会边界

GC 的代际假设：多数对象生存期短。Gen 0 频繁回收，长期存活对象逐步晋升。大对象通常进入 LOH，回收成本更高。

你不需要背内部阈值，但要会诊断方向：

- 分配速率是否过高。
- 大集合是否一次物化。
- 缓存是否无限增长。
- 事件订阅或静态引用是否让对象无法回收。
- 是否把 `IDisposable` 问题误判成 GC 问题。

## 高频陷阱

1. 值类型一定在栈上。
2. 引用类型按引用传递。
3. `decimal` 没有精度和舍入问题。
4. GC 会自动及时关闭数据库连接。
5. `record` 一定不可变。
6. `with` 会深复制整个对象图。
