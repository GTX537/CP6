# 数据级多语言方案（决策文档 · 不落码）

> i18n 完整优化方案「第六步：数据级多语言」。前五步（P1~P5）解决的是**UI 文案**多语言；本步解决的是**主数据**多语言——这是两层不同的东西，最容易被混为一谈。本文给出选项与建议，供决策后再落码。

## 1. 问题定义

UI 文案（按钮/菜单/字段标签）已由 P1~P5 多语言化。但**主数据是数据不是文案**：
- 产品品名（`製品マスタ` 的品名 1/2、CP品名）——目前单值（录入语言，多为日文）。
- 交易先名称（`取引先マスタ` 客户名/供应商名）——单值。
- 各种「区分」枚举值、单位、工程名等——部分在 `Sys_Dict`/`MasterGenericCode`，部分单值。

后果：中文操作员在「受注一覧」看到的客户名、品名仍是日文（数据本身就是日文录入的），UI 框架翻了、数据没翻。

**核心认知：这是 ERP 最容易漏的一层，且大多数 ERP 的现实选择是"不做"**——主数据保持录入语言，因为：① 翻译主数据是持续的运营成本（每新增一个品就要翻 5 语）；② 跨语言搜索/对账/单据一致性要求"同一个品名"全公司一致。

## 2. 三个选项

| 选项 | 做法 | 适用 |
|---|---|---|
| **A 不做（推荐默认）** | 主数据保持单值录入语言。UI 框架多语言，数据按录入显示。 | 内部系统、单一运营语言、当前阶段 |
| **B 关键主数据加「名称多语言」子表** | 对**少数高可见主数据**（品名、客户名、单位）加 `*_I18n` 子表，按 locale 取值、缺失回退主值。 | 真要给不同语言操作员看本地化品名/客户名时 |
| **C 全量主数据多语言** | 所有主数据字段都多语言化。 | 几乎不推荐（运营成本爆炸、对账困难） |

## 3. 选项 B 的设计（若决定做）

只对「值得翻」的少数字段做。候选范围（按价值排序）：
1. 产品品名（`製品マスタ`：CP品名/品名1/品名2）
2. 交易先名称（`取引先マスタ`：客户名/供应商名）
3. 单位、工程名等小字典类（其实更适合并入 `Sys_Dict` 多语言，而非主数据子表）

**表结构（子表方案）**：
```
T_Product_I18n (Id, ProductCd, LangCode, ItemName1, ItemName2, ...)
  UNIQUE(ProductCd, LangCode)
T_BusinessPartner_I18n (Id, BpCd, LangCode, BpName, ...)
  UNIQUE(BpCd, LangCode)
```
解析：取名时 `当前 locale 的子表值 → 主表原值(录入语言) → 空`。和 P3 的 `Sys_Lang` 租户回退是**同一思路**（覆盖→默认回退），可复用心智模型。

**影响面（这是为什么要先决策）**：
- **写**：主数据维护页要加「各语言名称」录入 Tab（每个品/客户多录几语）——运营负担。
- **读**：所有**展示主数据名称**的查询都要 LEFT JOIN 子表 + locale 参数（受注一览/报价/出库/报表/下拉选择…几十处）。或在服务层包一个「按 locale 取名」的解析器统一注入。
- **搜索**：按名称搜索要跨语言（搜中文名也能命中日文录入的品）——子表让搜索更复杂。
- **单据/报表**：打印单据用哪个语言的品名？通常跟「客户的语言」而非「操作员的语言」——又是一层规则。
- **迁移**：现有主数据回填——只能把录入语言塞进 `LangCode=ja` 行，其余语言留空待翻。

**工作量估算**：子表+实体+迁移（小）；维护页多语言 Tab（中）；**几十处读取点改 JOIN/解析器（大，是主成本）**；翻译运营（持续）。

## 4. 建议

- **现阶段：选 A（不做）**。理由：CP6 当前是内部/单运营语言场景；主数据多语言的**读取改造面大、运营成本持续**，性价比低于已完成的 UI 多语言。
- **触发升级到 B 的条件**：出现「不同母语的操作员共用同一套主数据、且看不懂录入语言」的真实诉求（如华策无锡日方+中方共用、且要求各看本地品名）。届时**只做品名+客户名两类**，用「服务层 locale 取名解析器」而非散落 JOIN，控制读取改造面。
- **小字典类（单位/区分/工程名）**：不要走主数据子表，**并入 `Sys_Dict` 多语言**（字典表加 5 语列或挂 `Sys_Lang`），这条独立于 B、价值高成本低，可优先于 B 单独做。

## 5. 决策项（待确认）

1. 现在选 **A（不做，推荐）** 还是 **B（品名+客户名子表）**？
2. 若 B：先做哪类（建议品名优先）？读取改造走「服务层解析器」（推荐）还是「逐查询 JOIN」？
3. 是否单独先做 **`Sys_Dict` 字典多语言**（独立小项，价值高）？
