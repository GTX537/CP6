# Day 4：底层原理、系统设计与工程闭环——学习路线与完整掌握标准

> Day 1 解决 C#/.NET，Day 2 解决 SQL/Vue，Day 3 解决面试表达；Day 4 要解决一个更容易暴露经验深浅的问题：**为什么系统这样设计，出问题时你能否沿整条链路定位并修复。**
>
> 本日不是“再看一遍知识点”。每章都必须完成：理解原理、画出链路、写出最小实现、解释失败模式、完成口述与验收。只有能独立输出，才算学会。

---

## 一、Day 4 学完后你应具备的能力

你应能从一次“库存查询”讲完整条链路：

```text
用户点击查询
  → 浏览器事件循环执行回调
  → Vue 生成请求参数
  → HTTP/TLS/TCP 传输
  → ASP.NET Core 中间件与鉴权
  → Controller / Service / EF Core
  → SQL Server 执行计划、锁与事务
  → JSON 响应
  → 浏览器渲染
  → 日志、指标、追踪记录全过程
```

并能回答四类问题：

1. **原理题**：TCP 为什么可靠？HTTPS 保护了什么？进程、线程、异步各是什么？
2. **设计题**：库存扣减如何防超卖？缓存、消息队列、数据库分别承担什么责任？
3. **质量题**：单元测试、集成测试、端到端测试怎么分工？什么应该 mock？
4. **生产题**：系统变慢、502、数据库连接耗尽、容器反复重启时，先看什么？

## 三、每章统一学习法

### 第一遍：建立地图（20% 时间）

- 先读目录、粗体结论和图，不抄笔记。
- 用一张白纸写出“输入 → 处理 → 输出 → 失败点”。
- 标记不认识的词，但不要立即跳去搜索，先看完上下文。

### 第二遍：追问原理（30% 时间）

对每个概念追问四次：

1. 它解决什么问题？
2. 没有它会发生什么？
3. 它付出了什么代价？
4. 在 CP6 的哪条链路里能看到它？

### 第三遍：动手验证（30% 时间）

- 不复制整段答案；先自己写，再对照。
- 每个实验保留命令、预期结果、实际结果和差异。
- 故意制造一次错误，例如错误端口、超时、重复请求或失败事务。

### 第四遍：脱稿输出（20% 时间）

- 30 秒：先给结论。
- 2 分钟：原理 + 项目例子 + 坑。
- 5 分钟：画图并接受追问。

## 四、“完整掌握”的五级标准

| 等级 | 表现 | 是否过关 |
|---|---|---|
| L1 听过 | 看见术语觉得熟 | 否 |
| L2 能复述 | 能背定义，不能举例 | 否 |
| L3 能应用 | 给定场景能写出方案 | 基础过关 |
| L4 能诊断 | 方案失败时能定位原因并修复 | 面试目标 |
| L5 能权衡 | 能比较替代方案、说明边界与成本 | 5 年经验目标 |

每章结束时，不问“看完了吗”，只问：

- 能否不看资料画图？
- 能否写一个最小可运行例子？
- 能否说出至少三个失败模式？
- 能否用 CP6 场景回答“为什么”？
- 能否指出方案不适用的边界？

## 六、开始前自测

以下问题答不上来是正常的，它们就是 Day 4 的学习入口：

1. `await` 等数据库时，线程、进程和操作系统分别在做什么？
2. 浏览器输入 URL 后，DNS、TCP、TLS、HTTP 按什么顺序发生？
3. HTTP 401 与 403、502 与 504 分别表示什么？
4. “使用 Redis 提升性能”为什么不是一个完整设计？
5. 消息至少投递一次时，消费者怎样避免重复扣库存？
6. 单元测试为什么不应该真的连接 SQL Server？集成测试又为什么应该？
7. 容器显示 Healthy，是否代表用户一定能正常使用？
8. P95 延迟从 200ms 涨到 3s，你按什么顺序排查？

把首次答案保存下来。完成 Day 4 后重新回答，对比两次答案的结构、深度与项目证据。

## 七、14 天详细学习计划

> 每天按 3.5–5 小时设计。若你每天只有 2 小时，把每一天拆成两天，不要删掉实验和复述。

### 第 1 天：进程、线程、内存与 GC

**输入学习（90 分钟）**

1. 读第 1 章第 1–2、12 节；
2. 自己画“进程地址空间：代码段、静态区、托管堆、线程栈”；
3. 用自己的话解释：值类型不一定在栈、闭包为何延长变量寿命、GC 语言为何仍泄漏。

**动手（60 分钟）**

- 找一段 CP6 async 查询，标出 CPU 执行段和 I/O 等待段；
- 找一个捕获变量的 lambda，判断闭包生命周期；
- 用 `dotnet-counters` 或 IDE 诊断工具观察进程线程数、堆大小与分配率（环境允许时）。

**输出（45 分钟）**

- 录 3 分钟：“await 等数据库时有没有线程？”；
- 完成一张栈/堆/闭包图；
- 写 3 个内存问题假设及各自证据。

**过关线**：不背“值类型在栈”这种错误口诀；能区分高分配率与对象泄漏。

### 第 2 天：DNS、TCP 与连接池

**输入学习**：读第 1 章 3、4、13 节，手画 TCP 握手、重传、连接复用。

**动手**：运行 `Resolve-DnsName`、`Test-NetConnection`、`curl -v`；故意使用错误端口，记录每层现象。

**输出**：解释“DNS 成功为何仍打不开网站”“扩 WebApi 为什么可能耗尽 DB 连接”。

**过关线**：能说出 TCP 是字节流、没有消息边界；能解释连接池等待与查询慢的区别。

### 第 3 天：TLS、HTTP、认证与浏览器

**输入学习**：读第 1 章 5–7、11、14–17 节。

**动手**：在浏览器 Network 记录 CP6 请求完整 Header、状态、Timing；追踪 `http.ts` 的 CSRF 和并发 refresh。

**输出**：画 Cookie/httpOnly/CSRF/CORS/JWT 的职责图；口述 401、403、502、504。

**过关线**：能解释客户端超时为何不代表数据库回滚；能解释共享 refresh Promise 防了什么竞态。

### 第 4 天：系统设计基本功

**输入学习**：读第 2 章 1–3、12 节。

**动手**：为“300 工厂库存查询”估算平均/峰值 QPS、响应流量和数据库连接预算。

**输出**：写需求、规模、不变量、主链路、故障模型五段式设计开场。

**过关线**：在提 Redis/Kafka 前先给业务不变量和数量级。

### 第 5 天：事务、并发与幂等

**输入学习**：读第 2 章 6–8、18 节。

**动手**：用两个独立连接验证“先查再扣”的竞态，再验证条件 UPDATE；设计幂等表唯一约束。

**输出**：比较原子更新、乐观锁、悲观锁；解释幂等与并发为什么不是一个问题。

**过关线**：能用时间线说明超卖；能回答 DB 提交成功但响应丢失后如何处理。

### 第 6 天：消息、重试与死信

**输入学习**：精读第 2 章 5、13–16、19 节，并打开真实 `IntegrationEventRetryWorker.cs` 对照。

**动手**：运行/阅读 RetryWorker 五类测试；画状态机；分析双实例可能重复派发的窗口。

**输出**：解释退避、抖动、租约、消费者幂等、死信重放；说明 CP6 Kafka 设置为什么不能照搬到库存事件。

**过关线**：能指出持久化事件已有的保证与尚未证明的边界，不按类名臆测模式。

### 第 7 天：缓存、多租户与完整设计

**输入学习**：读第 2 章 4、7–10、17、20–21 节。

**动手**：构造相同 ItemId 的 A/B 租户缓存负向测试；画一次缓存旧值回填竞态。

**输出**：10 分钟设计“生产报工”，覆盖离线重发、库存/OEE/成本和事件恢复。

**过关线**：缓存 key 包含所有影响结果的隔离维度；每个异步步骤都有失败后状态。

### 第 8 天：单元测试与可测试设计

**输入学习**：读第 3 章 1–4、12–15、20 节。

**动手**：给 RetryWorker 补 dispatcher 抛异常测试；把一个 `DateTime.UtcNow` 规则改为可控时间。

**输出**：为库存过账列正常、边界、非法、并发、重复、跨租户矩阵。

**过关线**：能说明每个 mock 的理由；测试失败时能从名称读出被破坏规则。

### 第 9 天：真库/API/前端/E2E 测试

**输入学习**：读第 3 章 16–19、21–25 节。

**动手**：运行一条 SQL Server rowversion 测试或完整分析其两个 DbContext；解剖 `CpFilterBar.spec.ts` 和 golden path。

**输出**：写五层测试计划，并明确每层“证明了什么、没有证明什么”。

**过关线**：不把 InMemory 绿色当 SQL Server 正确；不把“页面能打开”描述成完整交易 E2E。

### 第 10 天：Docker 与容器网络

**输入学习**：读第 4 章 1–4、11–16 节，逐行对照两份 Dockerfile 与 Compose。

**动手**：画宿主、Web、API、DB、RabbitMQ、Kafka 的主机名和端口；检查所有卷的数据寿命。

**输出**：解释多阶段缓存、localhost 陷阱、Kafka 内外 listener、卷与备份差异。

**过关线**：能从宿主和容器两种网络视角给正确地址。

### 第 11 天：可观测性与告警

**输入学习**：读第 4 章 5–6、17–19 节，对照 `BridgeMetricsCollector`。

**动手**：查看 `/metrics`；为库存过账设计日志、指标、trace；排除高基数 label。

**输出**：给一个 P95 告警写影响、阈值、持续时间、dashboard 和 runbook。

**过关线**：能用同一 traceId 串日志与 span；能解释 scrape 查 DB 的成本。

### 第 12 天：生产排障与恢复

**输入学习**：读第 4 章 7–10、20–26 节。

**动手**：在测试环境制造错误端口/依赖不可用；按假设—证据—结论记录；设计一次数据库恢复。

**输出**：15 分钟 504 排障录音和一份 runbook。

**过关线**：先确认影响和业务结果，再止血；结论必须附证据，不用“可能是网络”结束。

### 第 13 天：综合功能实现

**输入学习**：读第 5 章 9–19 节。

**动手**：完成出库过账的规格、表/索引、API、事务骨架、前端未知结果处理和测试矩阵。

**输出**：代码/伪代码、三张图、错误合同、测试结果。

**过关线**：同一事务保护库存/单据/流水/事件；前端超时不会诱导用户盲目再扣一次。

### 第 14 天：故障注入与面试验收

**输入学习**：读第 5 章 20–24 节，回看所有错题卡。

**动手**：至少注入三类故障：并发、提交后响应丢失、broker 不可用；保存状态证据。

**输出**：30 秒、2 分钟、5 分钟三版口述；完成 100 分评分表；首次自测重新答一遍。

**过关线**：75 分以上且没有“库存可负、重复扣、串租户、永久丢事件”任一硬伤。

## 九、间隔复习安排

每个知识点在四个时间重新输出：

- 学完立即：闭卷写 5 句话；
- 24 小时后：回答章末题，不先看答案；
- 3 天后：把它放进一个故障/设计场景；
- 7 天后：录 2 分钟并接受连续追问。

判断是否需要回炉：

- 只能说定义，回到“问题与机制”；
- 能讲正常路径，讲不出失败，回到时间线/故障实验；
- 能讲方案，讲不出代价，做替代方案对比；
- 能背答案，找不到 CP6 证据，重新读真实代码。

## 十、硬性毕业条件

下面任一项不通过，都不能称为“完整掌握”：

1. 不看资料画出浏览器到 SQL Server 的请求链路；
2. 用真实 CP6 文件解释至少五处设计；
3. 完成至少一个真数据库并发/约束验证；
4. 完成一个 Vue 行为测试和一个关键 E2E 分析；
5. 完成一次可恢复的消息失败分析；
6. 完成一次容器网络或 502/504 故障演练；
7. 完成一次备份恢复方案或实际隔离恢复；
8. 综合设计评分达到 75 分且无安全/一致性硬伤；
9. 20 道终极追问题中至少 16 道可脱稿回答；
10. 所有“我认为”后面都能给代码、测试、日志、指标或实验作为证据。
