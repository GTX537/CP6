## 3.0 为什么"懂业务"比"会写代码"值钱

先建立一个心态。你去面这个岗位，竞争对手大概分两类：

1. **纯技术型**：Spring/.NET 很熟，但从没进过车间，不知道"报工"和"入库"的区别，把 MES 当成"又一个 CRUD 系统"。
2. **业务型转开发**：在工厂待过几年，懂生产，但代码能力弱。

这个 JD 明确写了"3年以上制造相关工作经验优先"——说明招聘方**宁可要懂业务的**。你的策略是：用你 CP6 的开发经历，把自己塑造成**第三类人——懂业务的开发**。你没在车间拧过螺丝，但你把车间的业务流程写进过代码，这本身就是最深的"业务理解"。因为**要把一个流程写成能跑的系统，你必须比业务员更清楚每一个例外分支**。

一句面试金句，先记住：

> "我做 CP6 的时候最大的体会是：**生产管理系统难的从来不是技术，是把车间那套'大家心里都懂、但没人写下来'的规则，变成计算机能执行的确定逻辑。** 比如'这批货急，插到前面去'——业务上一句话，系统里要处理排产重算、产能占用、前序工单顺延、物料重新引当，一连串。我这三年主要在训练的，就是听懂前一句、写对后一连串。"

这句话说完，面试官基本就知道：你不是来写 CRUD 的。

**本章的每一节，都在给你攒这种"前一句 → 后一连串"的翻译能力。**

## 3.1 制造业信息化全景图：谁管什么，数据怎么流

### 3.1.1 先建立一张分层图（务必会画）

面试白板上，你能徒手画出这张图，印象分立刻拉满。这是制造业信息化的经典"金字塔"（对应工业界的 ISA-95 分层模型，但你不用背标准号，会讲就行）：

```
┌─────────────────────────────────────────────────────────────┐
│  经营决策层    BI / 报表 / 老板驾驶舱                          │  看：赚不赚钱、交期准不准
├─────────────────────────────────────────────────────────────┤
│  计划层        ERP  (订单/采购/库存账/财务/成本)               │  管：钱和料，"要做什么"
│                APS  (高级排产，有限产能优化)                   │  管：怎么排最优
├─────────────────────────────────────────────────────────────┤
│  执行层        MES  (工单/派工/报工/质检/追溯/OEE)             │  管：现场，"正在做什么"
│                WMS  (库位/出入库/盘点/批次)                    │  管：料在哪、账实一致
│                PLM  (产品/BOM/工艺/图纸/版本)                  │  管：产品长什么样
├─────────────────────────────────────────────────────────────┤
│  控制层        SCADA / DCS  (监控与数据采集)                   │  管：把设备信号汇上来
├─────────────────────────────────────────────────────────────┤
│  设备层        PLC / 传感器 / 数控机床 / 扫码枪                │  管：真实的机器动作
└─────────────────────────────────────────────────────────────┘

         数据流（双向）：
         上 → 下：计划下达（订单→工单→派工→设备参数）
         下 → 上：实绩反馈（设备信号→报工→完工入库→成本→利润）
```

**记忆口诀**："计划层管钱和料，执行层管人和机，控制层管信号，设备层管动作。"

### 3.1.2 每一层到底管什么（用一句人话概括）

| 系统 | 全称 | 一句人话 | 关键问题 |
|------|------|----------|----------|
| **ERP** | Enterprise Resource Planning 企业资源计划 | "钱和料的总账本" | 接了多少单、要买多少料、赚不赚钱 |
| **MES** | Manufacturing Execution System 制造执行系统 | "车间现场的实时记录仪" | 这张工单做到哪道工序了、做了多少、坏了多少 |
| **WMS** | Warehouse Management System 仓库管理系统 | "料的位置和数量的守门人" | 这批料在哪个库位、还有多少能用、批次是哪批 |
| **PLM** | Product Lifecycle Management 产品生命周期管理 | "产品的设计档案室" | 这个产品的 BOM、工艺、图纸、改了几版 |
| **APS** | Advanced Planning & Scheduling 高级排产 | "考虑产能约束的排产大脑" | 3 台机、20 张单，怎么排交期最准、换型最少 |
| **SCADA** | Supervisory Control And Data Acquisition | "设备信号的采集器" | 机器转速、温度、当前状态实时传上来 |

### 3.1.3 边界在哪（面试高频，务必讲清 ERP vs MES）

这是**最经典的面试题**——"ERP 和 MES 有什么区别？"下面是标准答法，你要能脱口而出：

> **ERP 是"计划的账本"，MES 是"执行的现场"。**
>
> - **时间粒度不同**：ERP 一般管到"天"（这单这周交），MES 管到"分钟/秒"（这道工序 14:32 开始，14:58 报了 500 个好品）。
> - **关心的东西不同**：ERP 关心"要做多少、成本多少、什么时候交"；MES 关心"现在谁在哪台机上做哪道工序、做到第几个、坏了几个、为什么坏"。
> - **数据方向不同**：ERP 把订单**下发**成生产需求，MES 把车间实绩**反馈**回去（完工数、工时、不良），ERP 再拿这些算真实成本、扣库存、结账。
> - **一句总结**：ERP 说"要做什么"，MES 说"正在做什么、做得怎么样"。ERP 是大脑和账房，MES 是车间的眼睛和手。

**在 CP6 里你怎么佐证**：

> "在 CP6 里这条边界是实打实的。ERP 侧有订单（`T_Order`）、报价、成本；MES 侧有工单（`T_WorkOrder`）。工单头上有个 `OrderNo1/OrderNo2/OrderNo3` 字段，就是从 ERP 受注**展开**下来的锚点——一张受注可能拆成多张工单。工单再往下有工程明细（`T_WorkOrderProcess`，一道道工序）和实绩（`T_ProductionResult`，一次次报工）。报完工，完工数量反算回工单头的 `CompletedQty`，再影响成本和入库。ERP 和 MES 各管一段，中间靠'受注号'这根线缝起来。"

### 3.1.4 数据怎么流（一个具体例子，能讲活全景图）

光记分层图不够，你要能讲"一笔数据怎么在各层间流动"。举个例子——**客户下了一个 5000 个礼盒的单**：

```
① ERP 接单：受注 5000 个 → 订单评审通过
        │ 下发
        ▼
② ERP/MRP：按 BOM 算料 → 缺白卡、缺 DIC-2020 油墨
        │          └──► 采购请购→PO→收货→三单匹配（料备齐）
        │ 生成生产需求
        ▼
③ ERP → MES：受注展开成工单 WO（带工艺路线：印刷→模切→糊盒）
        │ 排产（APS/MES）：排到 3 号印刷机，明天 8:00-10:00
        │ 下发
        ▼
④ MES → 车间：工单发行，工人扫码报工
        │         设备信号（SCADA/IoT）：机器转速、停机自动上报
        │ 反馈实绩（完工数、不良、工时）
        ▼
⑤ MES → WMS：完工 4980 入成品库（带批次）
        │ MES → ERP：回传实际料工费
        ▼
⑥ ERP：归集实际成本 → 发货扣库存 → 应收开票 → 月末结账
        │ 汇总
        ▼
⑦ BI/驾驶舱：这单赚多少、交期准不准、OEE 多少
```

**讲这个例子的价值**：它把"上→下下发、下→上反馈"的双向数据流讲活了。面试时你说"我拿一个礼盒订单走一遍数据流给您看"，然后画这个，比干讲分层图强十倍。

### 3.1.5 中小制造企业的现实：一套系统全包

面试官如果是中小厂出身，你要懂这句话：

> "教科书上 ERP/MES/WMS/PLM 是四套系统、四个供应商。但**中小制造企业的现实是——买不起、也养不起四套，往往一套系统全包**。CP6 就是这种形态：一个 .NET 8 后端 + Vue 3 前端，里面 ERP、MES、WMS、采购、财务、OA 全在一个库、一套权限、一套多租户框架下。好处是数据不用做集成、天然打通；代价是模块边界要靠**代码纪律**守住——比如 CP6 里库存只有 `StockMovementService` 一个写入口，禁止任何模块直接 UPDATE 库存表，就是在'一套系统全包'里人为守住 WMS 的边界。"

这段话有两个加分点：① 你懂大厂和小厂的现实差异；② 你在一体化系统里知道怎么**用工程手段守边界**（单一写入口），这是架构意识。

## 3.2 生产业务全流程走一遍（本章主线）

这一节是本章骨架。我们从"客户来询价"一路走到"月底对账开票"，把一张单子在工厂里的一生走完。**每个环节都用统一结构讲**：

- **业务目标**：这一步到底为了啥
- **关键单据**：这一步产生/流转什么单
- **常见痛点**：车间/办公室的人为什么头疼
- **系统怎么支撑**：正经系统该干什么
- **CP6 对应**：你项目里哪个模块/表

先看全流程一张图：

```
 客户
  │  ① 询价/报价
  ▼
[评审] ──② 订单评审(能不能做/交期/信用)
  │
  ▼
[技术准备] ──③ BOM + 工艺路线(做什么、怎么做)
  │
  ▼
[MRP运算] ──④ 物料需求计算(要买什么、要生产什么)
  │           ├──► [采购] 请购→询价→订单→收货→三单匹配→付款
  │           │
  ▼           ▼
[排产] ──⑤ 有限产能排程(哪台机、什么时候、换型)
  │
  ▼
[工单下达] ──⑥ 生产指示发到车间
  │
  ▼
[领料] ──⑦ 按BOM领料出库(WIP形成)
  │
  ▼
[报工] ──⑧ 报合格/不良/工时(逐工序)
  │
  ▼
[质检] ──⑨ IQC/IPQC/OQC
  │
  ▼
[入库] ──⑩ 完工入库(成品)
  │
  ▼
[发货] ──⑪ 拣货→打包→发运
  │
  ▼
[对账开票] ──⑫ 应收/开票/成本归集/结账
```

下面逐环节展开。

### 环节① 接单 / 报价

**业务目标**：把客户"我想要这个"变成一张能算钱、能承诺交期的正式订单。报价阶段要算出"这单我报多少钱不亏"。

**关键单据**：询价单（RFQ）、报价单（Quotation）、销售订单（Sales Order / 受注）。

**常见痛点**：
- 报价靠老师傅拍脑袋，新人不会算，报低了亏、报高了丢单。
- 报价和实际成本对不上——报的时候按标准，做完发现纸涨价了、损耗超了。
- 同一个客户同一个产品，不同批量单价不一样（阶梯价），业务记不住。

**系统怎么支撑**：把报价做成**结构化成本估算**——材料费 + 各工序加工费 + 损耗 + 管理费 + 利润，每一项可追溯。产品有阶梯价表，选了数量自动带出单价。

**CP6 对应**：
- `Quotation` / `QuotationCalc` / `QuotationDetail`：报价头 + 成本估算 + 明细。
- `EstimateCalc` / `EstimateCalcProcess`：见积（估算）计算，按工序算加工费——这在纸器业尤其重要，因为一个盒子要经过印刷、模切（トムソン）、糊盒好几道，每道工序费率不同。
- `ProductLotPrice` / `SheetUnitPrice`：阶梯价 / 每令（纸张单位）单价。
- `Order` / `OrderDetail` / `OrderProcess` / `OrderMaterial`：受注头 + 明细 + 工序 + 用料。

**车间对话体**：
> 业务员：「这个客户要 5000 个礼盒，帮我报个价。」
> 系统（结构化）：纸材费（按克重×令数×纸价）+ 印刷费（4 色×版数×印次费率）+ 模切费 + 糊盒费 + 8% 损耗 + 15% 毛利 = 单价 ¥X，阶梯价里 5000 个落在"3001-10000"档，带出 ¥X.XX。
> 面试点：**报价不是一个数，是一棵可展开的成本树**。你做过 EstimateCalcProcess 就是在做这棵树。

---

### 环节② 订单评审

**业务目标**：正式接单前，确认"这单我们到底能不能接、敢不敢承诺"。

**关键单据**：评审记录 / 订单状态流转。

**常见痛点**：
- 销售为了业绩乱承诺交期，车间根本排不进去，最后延误赔款。
- 客户信用额度超了还继续发货，货发出去收不回钱。
- 技术上做不了（尺寸超机器幅面、特殊工艺没设备）到投产才发现。

**系统怎么支撑**：评审是一道**闸门（gate）**，卡住不合格的单。检查项：信用额度、产能是否排得下、技术可行性、图纸/版模是否齐备。评审常常需要多部门会签——这就是工作流。

**CP6 对应**：
- OA 工作流引擎（WFS）：CP6 有完整的审批流引擎，评审会签走 `IApprovalService` + `Wf_ApprovalBinding` 单源审批绑定。
- `BusinessPartner`：客户主数据，信用额度、结算条件都在这里。

**车间对话体**：
> 销售：「客户催得急，我先答应下周三交了。」
> 生产经理：「你先让系统评审——上周三那批还没做完，这周三机台全满，你答应了谁来做？」
> 面试点：**评审是把"销售的嘴"和"车间的产能"对齐的闸门**。系统的价值是让这个对齐**有数据、有留痕、卡得住**。

---

### 环节③ BOM / 工艺路线

**业务目标**：定义"这个产品用什么料做（BOM）、经过哪些工序怎么做（工艺路线）"。这是**一切生产计划的技术底座**——没有 BOM，MRP 算不出要买什么；没有工艺路线，排不了产、报不了工。

**关键单据**：BOM（物料清单）、工艺路线（Routing / 工程）。

**常见痛点**：
- BOM 不准——图纸改了 BOM 没跟着改，领料领错、算料算错。
- 工艺路线漏工序，排产漏排、成本漏算。
- 多版本管理混乱——客户改了规格，新旧 BOM 分不清哪版在用。

**系统怎么支撑**：BOM 要支持**多层**（成品→半成品→原料）、**展开**（算总用量）、**反查**（这个料用在哪些产品上）。工艺路线要能定义工序顺序、每道工序的标准工时、标准损耗、用哪类设备。都要**版本化**。

**CP6 对应**：
- `ProductMaster` / `ProductMaterial` / `ProductProcess`：产品主数据 + 用料（BOM）+ 工序（工艺路线）。
- 工单展开时，`WorkOrderProcess.ProcessCd/TaskCd` 明确注释"从 `PA050.ProductProcess.ProcessCd` 展开"——也就是**工艺路线是工单工序的模板**。
- `WorkOrderMaterial`：工单用料，从产品 BOM 展开。

**车间对话体**：
> 采购：「这批订单我要买多少牛皮纸？」
> 系统：订单 200 个礼盒 × BOM 里每个用 0.8 ㎡ × (1 + 5% 损耗) = 168 ㎡，扣掉库存现有 50 ㎡，请购 118 ㎡。
> 面试点：**BOM 是"要买多少"和"要领多少"的唯一真相源**。BOM 错一个数字，采购和成本全错。这也是为什么 BOM 必须版本化、必须和图纸联动。

### 环节④ MRP 运算

**业务目标**：MRP（Material Requirement Planning，物料需求计划）回答一个核心问题——"为了满足这些订单，我到底要**买什么**、**买多少**、**什么时候到**，要**自己生产什么**、什么时候开工"。

**关键单据**：MRP 运算结果 → 请购建议、生产建议。

**MRP 的基本公式（要会讲）**：

```
净需求 = 毛需求 − 现有库存 − 在途量 + 安全库存
如果 净需求 > 0：
    是外购件 → 生成请购建议（考虑采购提前期，倒推下单日）
    是自制件 → 生成生产建议（考虑生产提前期，倒推开工日）
```

**常见痛点**：
- 手工算料，算不过来也算不准，漏料导致停线。
- 不考虑在途和提前期，要么料到早了压库存，要么到晚了停产。
- 需求变动没重算，按老需求买了一堆用不上的料。

**系统怎么支撑**：MRP 引擎按 BOM 逐层展开，扣减库存和在途，考虑提前期倒排，输出请购单和生产单。好的 MRP 支持**净改量运算**（只重算变动部分）。

**CP6 对应**：
- 采购请购 `PurchaseRequest`，它的 `Source` 字段特别能佐证 MRP 思路——来源可以是 `manual`（手工）、`shortage`（缺料反流）、`workorder`（工单 BOM 缺料）。也就是说**工单发现 BOM 缺料，自动反流生成请购**，这正是 MRP"需求驱动采购"的落地。
- `MaterialShortage`（WMS）：缺料记录，是缺料反流的源头。

**车间对话体**：
> 生产计划员：「下个月这一堆订单，料够不够？要买啥？」
> MRP：逐单展开 BOM → 汇总毛需求 → 扣库存扣在途 → 牛皮纸缺 3 吨（供应商提前期 7 天，建议 X 日下单）、白卡缺 1 吨、专色油墨 DIC-2020 缺 20kg……一键生成请购建议。
> 面试点：**MRP 是"把一堆订单翻译成一张采购清单和一张开工清单"的引擎**。CP6 的 PurchaseRequest.Source=workorder 就是这条链的证据。

### 环节⑤ 采购（请购 → 询价 → 订单 → 收货 → 三单匹配 → 付款）

**业务目标**：把 MRP 或人工提出的"要买什么"，变成"向谁买、多少钱、货到了、账对了、钱付了"的闭环。

**关键单据链**：
```
请购单(PR) → 询价(RFQ)/报价 → 采购订单(PO) → 收货单(GR) → 三单匹配 → 应付发票(AP) → 付款
```

**常见痛点**：
- 请购和订单不分——谁都能直接下单，采购失控。
- 供应商发票和实际收货对不上：发票开 100 个，实际只收了 95 个，或者单价和 PO 谈的不一样，财务月底一笔笔核对，累死还容易漏。
- 收货没验就入账，付了钱才发现货有问题。

**系统怎么支撑**：**请购（PR）和订单（PO）分离**——PR 是"内部要买"，PO 才是"对外承诺"。核心是**三单匹配（Three-Way Match）**：把 PO（订了多少、什么价）+ 收货验收（实收多少）+ 供应商发票（要收多少钱）三张单对齐，容差内自动建应付、超容差挂起人工裁决。

**CP6 对应（你的强项，讲细）**：
- `PurchaseRequest`（PR，需求入口）→ `PurchaseOrder`（PO，对外承诺）→ `GoodsReceipt`（收货）→ `ThreeWayMatch`（三单匹配）。
- `ThreeWayMatch` 这张表你要讲透：它比对 **PO 行可开票量（`AcceptedQty − InvoicedQty`）** 和 **发票价差**，容差内 `Status=Passed(0)` 自动建 AP，超容差 `Status=Suspended(1)` 挂起等人工放行 `Released(2)` 或拒绝 `Rejected(3)`。
- 明细 `ThreeWayMatchLine` 记 `PriceVarPct`（价格偏差率）、`RemainAccepted`（可开票量）、`WithinTolerance`（是否在容差内）。
- `MatchTolerance`：容差配置。
- `SupplierInvoiceNo` 还是幂等键，透传财务防重复建应付。

**车间对话体**：
> 财务：「这张供应商发票能付吗？」
> 三单匹配：PO 订了 1000 个 @¥5，收货验收了 980 个（20 个不良退了），发票开 980 个 @¥5.02。数量匹配（发票量 ≤ 可开票量 980）✅；价格偏差 (5.02−5)/5 = 0.4%，容差设 2% 内 ✅ → 自动建应付，可付。
> 如果发票 @¥5.5：偏差 10% > 2% → 挂起，等采购主管确认是不是涨价了、要不要放行。
> 面试点：**三单匹配是"用规则代替人肉核对"的经典业务自动化**。你能把 Passed/Suspended/Released/Rejected 四态和容差机制讲清楚，面试官就知道你真做过采购。

### 环节⑥ 生产计划与排产（有限产能 / 号机 / 换型）

**业务目标**：把"要生产什么"排到"具体哪台机、什么时间段做"，并且要**排得下、排得优**。

**关键概念**：
- **有限产能排程**：机器产能是有限的，不能无限往上堆。排产必须考虑每台机每天只有那么多小时。
- **号机（Machine）**：具体到哪一台设备。同类型可能有 3 台印刷机，能力不同。
- **换型（Setup / Changeover）**：从做 A 产品切到做 B 产品，要换版、洗墨、调机，这段时间不产出。**换型时间是排产的大敌**——排得好可以把同色/同版的单排一起，少换型。

**常见痛点**：
- 无限产能排产（只看订单不看机台能力），排出来根本做不完。
- 频繁换型浪费产能——今天红色明天蓝色后天又红色，一天洗三次墨。
- 急单一来全乱套，没法快速看到"插进去会挤掉谁"。

**系统怎么支撑**：排产要基于**工作日历**（哪天上班、上几班）、**机台产能**、**换型矩阵**，做有限产能排程。高级的用 APS 做优化（最小化换型、最大化交期达成）。要能看甘特图、支持拖拽调整、算出冲突。

**CP6 对应**：
- `Machine`（M_Machine，号机主数据）、`WorkCenter`（工作中心）、`MachineDowntime`（停机）。
- `WorkOrderProcess.MachineCd`（这道工序派给哪台号机）、`PlanStartTime/PlanEndTime`（计划时间段）。
- `WorkOrder.Priority`（1=通常 2=急ぎ 3=特急）——**急单优先级就在工单头上**，排产按它插队。
- （CP6 记忆里有"排产两缺口待产品裁决"：Reschedule 无过去日期/号机冲突检知、AutoArrange 不避已占用时段——这说明你踩过排产的真实坑，面试可以聊。）

**车间对话体**：
> 车间主任：「这个急单今天必须插进去！」
> 排产系统：3 号印刷机今天已排满 A、B 两单，插 C 单要把 B 顺延到明天，B 的交期是后天还来得及；但 C 和 A 不同色，中间要换型 40 分钟。确认插单？
> 面试点：**排产的核心矛盾是"有限产能"和"无限需求"**。"插单"这个动作，系统要能算出连锁反应（谁被顺延、要不要换型、交期会不会破）。这就是 3.0 说的"前一句 → 后一连串"。

---

### 环节⑦ 工单下达

**业务目标**：把排好的生产计划，正式**下发到车间**，让现场知道"该干这张单了"。

**关键单据**：生产工单 / 制造指图（Work Order）。

**工单状态机（要会背，CP6 真实定义）**：

```
0=下书き(草稿) → 1=確定済 → 2=発行済(可着手) → 3=着手中 → 4=完了 → 6=検査済
                                          ↘ 5=中断中
                                          ↘ 9=取消 (仅0/1/2可取消)
```

**常见痛点**：
- 工单发下去信息不全，工人不知道用什么料、什么工艺、做多少。
- 纸质工单，进度看不见、容易丢。
- 工单下了但料没备齐，到现场才发现缺料停工。

**系统怎么支撑**：工单要带齐"做什么产品、多少量、什么工艺路线、用什么料、什么交期、什么优先级"。下达前检查物料齐套。状态可追踪。

**CP6 对应**：
- `WorkOrder`（T_WorkOrder，制造指図）：`WorkOrderNo`（WOYYYYMMDD-NNNN 采番）、`ProductionQty`、`CompletedQty`、`DefectQty`、`DeliveryDate`、`Priority`、`LotNo`。
- 状态用 `WorkOrderStatus` 常量类，`IsCancellable()` 明确规定只有草稿/确定/发行三态可取消（着手后不可取消——这是业务约束写进代码）。
- 一张工单展开 N 个 `WorkOrderProcess`（工序）+ N 个 `WorkOrderMaterial`（用料）。

**车间对话体**：
> 工人：「今天做哪张单？」
> 系统（工单）：WO20260715-0003，礼盒 5000 个，特急（Priority=3），工序：印刷→模切→糊盒，用料：白卡 200 张、DIC-2020 油墨 5kg，交期后天。
> 面试点：**工单是"计划"和"执行"的交接单据**。它一头连着 ERP 受注，一头连着车间报工。工单状态机是 MES 的心脏。

---

### 环节⑧ 领料

**业务目标**：按工单 BOM，把料从仓库领到车间，形成在制品（WIP）。

**关键单据**：领料单 / 出库单。

**常见痛点**：
- 超领、少领——领多了浪费、账不准；领少了停工。
- 领料不记批次，出了质量问题追不到用了哪批料。
- 领了料工单取消了，退料流程混乱。

**系统怎么支撑**：按 BOM 生成领料建议，出库时扣库存、记批次、更新 WIP。支持退料、补料。

**CP6 对应**：
- `WorkOrderMaterial`（工单用料）→ WMS 出库 `OutboundOrder`/`OutboundOrderDetail`。
- 库存扣减走 `StockMovementService`（唯一写入口），`StockTransaction` 记流水。
- 领料出库会减 `Stock.PhysicalQty`，批次 `LotNo` 全程带着。

**车间对话体**：
> 仓管：「这张工单领料，牛皮纸给你哪批？」
> 系统（FIFO/FEFO）：按先进先出/先到期先出，给你 LOT20260601 这批（最早入库），扣 168 ㎡，剩余 32 ㎡。
> 面试点：**领料是"库存账"和"生产账"的交接点**。领出去的料从"库存"变成"在制品（WIP）"，成本从仓库转到工单上。批次必须跟着领料走，否则追溯断链。

---

### 环节⑨ 报工（合格 / 不良 / 工时）

**业务目标**：工人做完一道工序，向系统**报告实绩**——做了多少好品、多少不良、花了多少工时、用了哪台机。这是 MES 最核心、最高频的动作。

**关键单据**：生产报工 / 制造实绩（Production Result）。

**报工要采集什么（务必会列）**：
- **数量**：良品数、不良数。
- **不良明细**：不良原因代码（哪种缺陷）。
- **工时**：人工工时、机器工时（算成本用）。
- **时间戳**：开始、中断、恢复、完工。
- **人机料**：作业者、号机、批次。

**常见痛点**：
- 报工靠纸+事后录入，不实时、易造假、数据滞后一天。
- 只报总数不报不良原因，质量问题没法分析改善。
- 工时不准，成本算不对。

**系统怎么支撑**：现场报工（扫码/触摸屏/PDA），实时采集。支持开始/中断/恢复/完工/数量报告多种报工类型。工时可自动派生（按时间戳）也可人工覆盖。

**CP6 对应（讲细）**：
- `ProductionResult`（T_ProductionResult，制造实绩）：`ResultType`（1=开始 2=中断 3=中断解除 4=完了 5=数量报告）——**报工不是一个动作，是一串时序事件**。
- `GoodQty`/`DefectQty`/`ActualLossRate`（实绩损耗率）、`DefectReasonCd`（不良原因，关联 `M_DefectCategory`）、`SuspendReasonCd`（中断原因）。
- `OperatorCd`（作业者）、`MachineCd`（号机）。
- 工时：`LaborHour`/`MachineHour`（本次报工可选覆盖）；工序级 `WorkOrderProcess.ActualLaborHour`/`ActualMachineHour` + `ActualHourSource`（Derived/Manual/Import/StandardFallback/LegacyFallback，**工时来源分级回退**）+ `IsHourOverridden`。
- 报工累加到工序 `WorkOrderProcess.GoodQty/DefectQty`，再汇总到工单头 `WorkOrder.CompletedQty/DefectQty`。

**车间对话体**：
> 工人（扫码枪对着工单条码）：印刷工序，扫开始 → 做 → 扫完工，报 4850 好、150 坏，坏的选"套印不准 D02"。
> 系统：ResultType=完了，GoodQty=4850，DefectQty=150，ActualLossRate=3%，DefectReasonCd=D02，MachineHour 按开始/完工时间戳自动算 1.5h。累加到工序，工序满了推进到下一道。
> 面试点：**报工是 MES 的脉搏**。你能讲清"报工是时序事件（开始/中断/完工）、要采集不良原因和工时、逐级汇总"，就证明你真理解 MES。

---

### 环节⑩ 质检（IQC / IPQC / OQC）

**业务目标**：在关键节点检验质量，不合格的挡住，别让坏货流下去。

**三道质检关（务必分清）**：

| 简称 | 全称 | 中文 | 检什么 | 挡什么 |
|------|------|------|--------|--------|
| **IQC** | Incoming Quality Control | 来料检验 | 供应商送来的料 | 挡住不合格料进厂 |
| **IPQC** | In-Process Quality Control | 制程检验 | 生产过程中的半成品 | 挡住不合格半成品流到下工序 |
| **OQC** | Outgoing Quality Control | 出货检验 | 发货前的成品 | 挡住不合格品发给客户 |

（有的厂还有 **FQC** 最终检验，介于 IPQC 和 OQC 之间。）

**常见痛点**：
- 检了没系统记录，判定靠人、追溯靠翻纸。
- 不合格品没被系统"冻结"，照样被领用/发货。
- 抽检标准、判定规则不统一。

**系统怎么支撑**：按检验模板（检验项、标准、抽样方案）检验，判定合格/不合格。**不合格品要在系统里被冻结（HOLD）**，不能被引当/出库。检验记录可追溯。

**CP6 对应**：
- `QcInspection`/`QcInspectionItem`（WMS 侧检验）、`QualityInspection`/`QualityInspectionItem` + `InspectionTemplate`（MES 侧检验模板）。
- **库存 QC 状态**：`Stock.QcStatus`——`PENDING`/`PASSED` 可引当，`FAILED`/`HOLD` 被挡住（`StockQcStatus.IsAllocatable()`）。这就是"不合格品被系统冻结、不能出库"的落地。
- `Stock.RecallFlag`（召回标记，true 禁止出库）。

**车间对话体**：
> 品质：「这批料 IQC 没过，先别让人领。」
> 系统：把这批库存 QcStatus 置 HOLD，引当逻辑 `IsAllocatable()` 返回 false，任何工单都引当不到它，物理上就挡住了。
> 面试点：**质检的系统价值不是"记个结果"，是"让不合格品在系统里动不了"**。你能指出 QcStatus 参与引当判定，就说明你懂"质检要卡住流程"而不是"事后台账"。

---

### 环节⑪ 入库（完工入库）

**业务目标**：成品做完、检验合格，入成品库，从"在制品"变成"可发货成品"。

**关键单据**：完工入库单 / 入库单。

**常见痛点**：
- 报完工不等于入库——中间检验没过怎么办？
- 完工数和入库数对不上（有的坏在入库前）。
- 入库没记批次/生产日期，成品追溯断。

**系统怎么支撑**：完工 → （质检）→ 入库，增成品库存、结转 WIP 成本到成品成本、记批次和生产日期。

**CP6 对应**：
- WMS 入库 `InboundOrder`/`InboundOrderDetail`/`InboundReceipt`/`InboundReceiptDetail`。
- 入库增 `Stock.PhysicalQty`，带 `LotNo`、`ReceiveDate`、`ExpiryDate`（效期）。
- 工单 `Status=完了(4)` → `検査済(6)` → 触发入库。

**车间对话体**：
> 仓管：「这张工单做完了，成品入库。」
> 系统：完工 5000，检验合格 4980（20 个 OQC 挑出），入库 4980 到成品库位，批次 LOT20260715，生产日期今天。WIP 成本结转到成品。
> 面试点：**入库是 WIP → 成品的转换点，也是成本归集的关键节点**。完工数、合格数、入库数三个数字的关系，能讲清就是懂。

---

### 环节⑫ 发货 / 对账开票

**业务目标**：把成品发给客户，然后跟客户对账、开票、收钱；同时内部把这单的成本归集清楚、月底结账。

**关键单据链**：
```
发货：拣货单 → 打包 → 发运单/送货单 → 签收
财务：应收(AR) → 开票 → 收款；成本归集 → 月末结账
```

**常见痛点**：
- 发货和开票对不上，客户对账扯皮。
- 成本月底才归集，做的时候不知道亏没亏。
- 结账慢，账实不符要花几天调。

**系统怎么支撑**：发货扣成品库存、生成应收；开票和发货挂钩；成本按工单实际归集（料 + 工 + 费）；月末结账把所有成本、收入、库存对齐。

**CP6 对应**：
- WMS 出库/发货：`OutboundOrder`、`CarrierShipment`（承运）、`ShippingPackage`（装箱）。
- 财务 AP/AR/总账（CP6 有完整 FIN 模块）。
- 成本：标准成本 vs 实际成本，`ProcessCostRate`（工序费率）、`WorkOrderProcess.ActualLaborHour/ActualMachineHour` 归集实际工费。

**车间对话体**：
> 财务：「月底了，这单到底赚没赚？」
> 系统：收入（发货 4980 × 单价）− 成本（实际用料 + 实际工时 × 费率 + 分摊制费）= 毛利。做的时候报工报得准，月底一键归集，不用手工核。
> 面试点：**这一环把"生产"和"钱"闭环了**。前面每一步报得准（领料准、报工准、入库准），月底才对得上。这也是为什么 MES 数据质量直接决定财务准确性。

## 3.3 核心业务概念详解（面试官随口就问）

这一节是"术语弹药库"。面试官可能在任何时候插一句"那你说说 BOM 是什么""OEE 怎么算"，你要能不打磕巴地用业务语言答出来。**每个概念：一句人话定义 + 关键点 + CP6 佐证。**

### 3.3.1 BOM（物料清单）——多层 / 展开 / 反查

**一句人话**：BOM（Bill of Materials）就是"做这个产品，需要哪些料、各多少"的配方表。

**三个必懂操作**：
- **多层 BOM**：成品 → 半成品 → 原材料，一层套一层。礼盒 = 盒身（半成品）+ 盒盖（半成品）+ 缎带；盒身 = 白卡纸 + 油墨。
- **BOM 展开（正查）**：给定要做 X 个成品，逐层算到底要多少原材料。做 100 个礼盒要多少白卡？逐层乘下去。
- **BOM 反查（Where-Used）**：给定一个原料，查它用在哪些产品上。牛皮纸涨价了，哪些产品成本受影响？反查一把全出来。

**CP6 佐证**：`ProductMaterial`（产品用料 = BOM）、`ProductProcess`（工艺）、`WorkOrderMaterial`（工单展开的用料）。MRP 就是靠 BOM 展开算净需求。

**面试点**：BOM 准确性是制造系统的地基。"BOM 错一个数，采购、领料、成本、MRP 全错"——这句话要会说。

---

### 3.3.2 工艺路线与工序

**一句人话**：工艺路线（Routing）是"这个产品要经过哪几道工序、什么顺序、每道用什么设备、标准工时多少"。

**关键点**：
- 工序（Operation/Process）有**顺序**（印刷必须在模切前）。
- 每道工序有**标准工时**（算产能、算成本）和**标准损耗率**。
- 工序绑定**设备类型/工作中心**（这道工序在哪类机上做）。

**CP6 佐证**：`ProductProcess`（产品工艺）→ `WorkOrderProcess`（工单工序，带 `SortOrder` 执行顺序、`PrevProcessCd` 前序依赖、`StdLossRate` 标准损耗、`LeadTime` 提前期、`MachineCd` 号机）。

**面试点**：工艺路线是排产和报工的骨架。"没有工艺路线，就没有工序，就报不了工、排不了产、算不了工时成本。"

---

### 3.3.3 工单（生产指示）

**一句人话**：工单是"叫车间做某个产品多少量的一张正式指令"，是计划和执行的交接单。

**关键点**：见环节⑦。核心是**状态机**（草稿→确定→发行→着手→完了→检查）和**取消约束**（着手后不可取消）。

**CP6 佐证**：`WorkOrder` + `WorkOrderStatus` 常量 + `IsCancellable()`。

---

### 3.3.4 批次与追溯（正向 / 反向）

**一句人话**：批次（Lot/Batch）是"一批一起生产/一起进货的料或货的编号"，追溯就是"顺着批次查上下游"。

**两个方向（务必分清）**：
- **正向追溯（顺查）**：给定一批原料，查它做成了哪些成品、发给了哪些客户。"这批有问题的油墨，都印了哪些货、发给了谁"→ 用于**召回**。
- **反向追溯（逆查）**：给定一个成品/客诉，查它用了哪些批次的料、哪台机、哪个班次、哪个工人做的。"客户投诉这箱印歪了，查是哪批版模、哪台机、谁做的"→ 用于**查根因**。

**合规背景**：食品、药品、包装（尤其食品接触包装）行业，**批次可追溯是法规硬要求**。出了食品安全事件，要能在小时级锁定波及范围。纸器/印刷包装做食品盒的，客户（食品厂）会审你的追溯能力。

**CP6 佐证**：
- 库存四要素唯一键含 `LotNo`：`(WarehouseCd, LocationCd, ProductCd, LotNo)`——**批次是库存的一等公民**。
- `StockTransaction` 记每一笔移动的批次流水，串起追溯链。
- 工单 `WorkOrder.LotNo`、报工 `ProductionResult`、原料批次（`PaperRoll.RollNo`/`InkLot.InkLotNo`），层层带批次。
- `Stock.RecallFlag`：召回标记，正向追溯锁定后一键冻结。

**面试点**：**追溯的本质是"每一次料的转移都不丢批次信息"**。追溯断链一定是某一步没记批次（领料没记、报工没记）。你能指出"批次要全程不丢"就是懂追溯。

### 3.3.5 库存的几本账（为什么会账实不符）

这是**面试超高频**。库存不是"一个数字"，是**好几本账**：

| 账 | 含义 | 举例 |
|----|------|------|
| **实物账（物理库存）** | 库位上实际有多少 | 仓库真有 1000 个 |
| **可用账（可用库存）** | 能被新订单用的 = 实物 − 已占用 | 1000 − 已被工单引当 300 = 700 可用 |
| **在途（在途库存）** | 已采购未到货 / 调拨在路上 | PO 下了 500 还没到 |
| **冻结（不可用）** | 质检 HOLD、召回、待处理 | 200 个 IQC 没过被冻 |

**公式**：`可用 = 实物 − 引当中 − 冻结`。

**CP6 佐证（讲这个显专业）**：
- `Stock` 表：`PhysicalQty`（物理）− `AllocatedQty`（引当中）= `AvailableQty`（可用），可用量物化在 DB 但只由 Service 算。
- `QcStatus`（PENDING/PASSED 可用，FAILED/HOLD 冻结）、`RecallFlag`。
- **写入口唯一**：`Stock` 表注释明确"書込口は StockMovementService のみ。直接 UPDATE 禁止"——这是保证账准的关键工程约束。

**为什么会账实不符（要会答）**：
1. 有交易没记账（领了料没做出库单、盘盈盘亏没处理）。
2. 记账时机不同步（物理动了账没动，或反之）。
3. 单位/换算错误、批次串了。
4. 多个写入口并发改库存，没有事务/锁 → 数据竞争。（CP6 用单一写入口 + 事务解决。）

**盘点怎么做（务必会讲）**：见 3.3 尾部的"盘点"小节。

---

### 3.3.6 盘点（Stock Take / 实地盘点）

**一句人话**：盘点就是"实际去数一遍库存，跟系统账对比，差了就调平并查原因"。

**盘点类型**：
- **全盘**：全库一次性数（通常停工、月末/年末）。
- **循环盘点（Cycle Count）**：按周期滚动盘一部分（A 类料常盘、C 类料少盘），不停工。
- **临时盘点**：出问题了临时数某区/某料。

**盘点四步流程（CP6 真实状态机）**：

```
0=计划 → 1=カウント中(点数中) → 2=差异確認中 → 3=承認待ち → 4=完了 / 9=取消
```

**关键点**：盘点差异要**上级审批**才能调账（防止随便调平掩盖问题）。差异金额超阈值必须审批。

**CP6 佐证**：`StockTake`（棚卸头）+ `StockTakeDetail`。字段：`StockTakeType`（1=全盘 2=循环 3=临时）、`ApprovalThresholdAmount`（差异金额审批阈值）、`ApproverCd`（审批人）。**差异超阈值必须上级批**——这是防舞弊的业务规则。

**面试点**：**盘点不是"数一遍"，是"数完还要查为什么差、还要有人为调账负责"**。你能讲出"差异审批阈值"，说明你懂盘点的管理属性不只是技术。

---

### 3.3.7 先进先出 FIFO / 效期管理 FEFO

**一句人话**：
- **FIFO（First In First Out）先进先出**：先入库的先发/先用，避免料在仓库放到过期/劣化。
- **FEFO（First Expired First Out）先到期先出**：按**保质期**排，最早到期的先出——比 FIFO 更适合有效期的料（油墨、胶水、食品）。

**为什么重要**：油墨、胶水会过期结块，纸放久了会受潮变黄。不管顺序，就会有料烂在仓库。

**CP6 佐证**：`Stock.ExpiryDate`（效期，注释明写"FEFO 引当用"）、`Stock.ReceiveDate`（FIFO 用）。引当时按这俩排序取批。`InkLot.ExpiryDate` + 开封状态（未开封 180 天 / 开封后 30 天，开封后效期缩短）。

**面试点**：**引当（allocation）不是随便挑一批，是按 FIFO/FEFO 规则挑**。你能把"油墨开封后效期缩短"讲出来，就是行业纵深。

---

### 3.3.8 安全库存与补货点

**一句人话**：
- **安全库存（Safety Stock）**：为了应对需求波动和交货延迟，故意多备的一点"垫底库存"，防止断货停线。
- **补货点（Reorder Point, ROP）**：库存降到这个线，就该补货了。`ROP = 日均用量 × 采购提前期 + 安全库存`。

**权衡**：安全库存高 → 不容易断货，但占资金、占仓位；低 → 省钱，但风险大。这是个成本与风险的平衡。

**CP6 佐证**：MRP 净需求公式里的 `+ 安全库存` 项；缺料反流（`MaterialShortage` → `PurchaseRequest.Source=shortage`）就是"降到补货点自动请购"的一种落地。

---

### 3.3.9 OEE（设备综合效率）——务必会算

**一句人话**：OEE（Overall Equipment Effectiveness）衡量"一台设备到底有多少产能被真正有效利用了"，是制造业最重要的设备 KPI。

**公式（背下来，CP6 里就是这么算的）**：

```
OEE = 可用率(Availability) × 性能(Performance) × 良率(Quality)

可用率 = 实际运行时间 / 计划运行时间     ← 有没有在跑（停机、换型损失）
性能   = 实际产量 / (理论产能 × 运行时间) ← 跑得快不快（速度损失、小停）
良率   = 良品数 / 总产量                  ← 做得好不好（不良损失）
```

**举例计算（面试可能让你现算）**：
- 计划运行 480 分，停机 80 分 → 可用率 = 400/480 = **83.3%**
- 400 分理论能做 4000 个，实际做了 3400 个 → 性能 = 3400/4000 = **85%**
- 3400 个里 3230 个好 → 良率 = 3230/3400 = **95%**
- **OEE = 83.3% × 85% × 95% ≈ 67.3%**

（业界经验：OEE 85% 是世界级，60-70% 算不错，很多厂在 40-60%。）

**CP6 佐证**：`OeeDaily` 表就是逐日逐机算 OEE。字段完全对应：`Availability = ActualRunMinutes / PlannedRunMinutes`、`Performance = (Good+Defect)/(Capacity × 运行小时)`、`Quality = Good/(Good+Defect)`、`Oee = A×P×Q/10000`。注释还明确它是**派生表**（由停机 `MachineDowntime` + 报工 `ProductionResult` 重算），不做字段审计——这点你可以讲，显示你懂"派生数据不重复审计上游"的设计取舍。

**面试点**：能现场算 OEE，能把三个因子对应到"停机/速度/不良"三类损失，就是懂 OEE 的人。**面试官最爱追问"OEE 低怎么分析"——答：拆三因子，看哪个拖后腿。可用率低查停机/换型，性能低查速度/小停，良率低查不良。**

---

### 3.3.10 良率与不良代码体系

**一句人话**：良率 = 好品占比；不良代码体系是"把不良按原因分类编码，好统计和改善"。

**关键点**：不良不能只记"坏了 150 个"，要记"为什么坏"——套印不准？尺寸超差？脏污？分类编码后才能做**帕累托分析**（找出占比最大的不良类型，重点改善）。

**CP6 佐证**：`DefectCategory`（M_DefectCategory，大分类 `CategoryCd` D01~D07 + 小分类 `DetailCd`，如"D01 尺寸不良 / 巾寸法外れ"）；`DefectRecord`（不良记录）；报工 `ProductionResult.DefectReasonCd` 关联到分类。

**面试点**：**"不良要分类"是质量管理的起点**。没有不良代码体系，就没有改善的抓手。你能讲"两级不良分类 + 报工时选原因 + 后续帕累托"，就是懂质量。

---

### 3.3.11 完工反冲（Backflush）vs 工序报工

**一句人话**：这是"怎么扣料"的两种策略——
- **完工反冲（Backflush）**：不逐次记领料，等完工时按 BOM **一次性倒扣**用料。省事，适合料稳定、损耗可预测的场景。
- **工序报工（逐工序领料/报工）**：每道工序实际领多少、报多少，都实时记。准，但操作多，适合料贵、损耗波动大、要精细追溯的场景。

**权衡（要会讲）**：
- 反冲：录入少、快，但**按标准扣，实际损耗对不上账实**（标准 5% 损耗，实际 8%，那 3% 差异反冲不出来，要靠盘点/差异调整）。
- 逐工序：准、可追溯，但录入负担重、现场配合度要求高。

**CP6 佐证**：CP6 记忆里有"完工反冲（backflush）"的实现和"完工反冲仍是 P0 未完"的记录——说明这是真实项目里权衡过的点。你可以说："CP6 里成品完工反冲和逐工序报工是并存的，贵料（油墨、纸卷残米）走精细的批次消耗，标准辅料走反冲，是按料的价值分级处理的。"

**面试点**：能说清"什么料适合反冲、什么料适合逐工序"，就是懂成本核算的现场取舍。

---

### 3.3.12 标准成本 vs 实际成本

**一句人话**：
- **标准成本**：事先按标准用量 × 标准价算出来的"应该花多少"，用于报价、计划、考核。
- **实际成本**：事后按真实用料、真实工时、真实费用归集的"实际花了多少"。
- 两者的差 = **成本差异（Variance）**，是管理的抓手（用量差异、价格差异、效率差异）。

**关键点**：报价用标准成本（不然算不出价），核算用实际成本，月底比差异找问题。"报的时候标准损耗 5%，实际做出来 9%，这 4% 差异要查是料的问题、机的问题还是人的问题。"

**CP6 佐证**：`ProcessCostRate`（工序标准费率）算标准；`WorkOrderProcess.ActualLaborHour/ActualMachineHour` + `StdLossRate` vs `ActualLossRate` 对比出差异。`EstimateCalc` 用标准成本报价。

**面试点**：**"标准是计划的尺，实际是核算的秤，差异是管理的镜"**——这句话记住。

---

### 3.3.13 交期相关概念：提前期 / 节拍 / 推拉

**这几个词面试官爱串着问，一起搞清：**

- **提前期（Lead Time）**：从下单/开工到交付/完工要多久。分**采购提前期**（下 PO 到料到货，MRP 倒排下单日靠它）和**生产提前期**（开工到完工）。提前期不准，MRP 就排不准。
- **生产节拍（Takt Time）**：客户需求节奏——`节拍 = 可用生产时间 / 客户需求数量`。比如一天上班 480 分，客户要 240 个，节拍 = 2 分/个，意思是"平均每 2 分钟必须产出 1 个才跟得上需求"。是精益生产的节奏基准。
- **推式 vs 拉式生产**：
  - **推式（Push / MRP 驱动）**：按预测和计划提前生产，往下游"推"。好处是产能利用足，坏处是可能做多了积压。
  - **拉式（Pull / 看板驱动）**：下游用了才补，用需求"拉"上游生产（丰田看板 Kanban）。好处是低库存，坏处是要求供应链稳定。
- **MTO vs MTS**：**按单生产（Make To Order）**——接了单才做，库存低但交期长（定制品、纸器多是 MTO）；**按库存生产（Make To Stock）**——按预测先做囤着，交期短但压库存（标准品）。

**CP6 佐证**：`WorkOrderProcess.LeadTime`（工序提前期，天）、采购提前期用于请购倒排。纸器/印刷包装以客户订单驱动，基本是 **MTO** 形态——所以 CP6 的主线是"受注→工单"而不是"预测→备货"。

**面试点**：能讲"提前期驱动 MRP 倒排""节拍是需求节奏""纸器是 MTO 按单生产"，就把计划逻辑串起来了。

---

### 3.3.14 在制品 WIP（Work In Process）

**一句人话**：WIP 是"已经开始做、但还没完工入库的半成品"，卡在车间流水线上的那些货和它们身上的成本。

**关键点**：
- WIP 是资产，占用资金。WIP 越多，压的钱越多，管理越乱。
- WIP 成本 = 已投入的料 + 已投入的工 + 已分摊的费。
- 精益生产追求**降低 WIP**（减少在制、加快流转）。

**CP6 佐证**：领料后料从库存变 WIP（`WorkOrderMaterial` 挂在工单上），报工累加工时到 WIP，完工入库时 WIP 结转成品成本。工单在"着手中(3)"到"完了(4)"之间，它身上的成本就是 WIP。

**面试点**：能讲"领料→WIP→完工结转"这条成本流转链，就是懂成本会计和生产的接口。

## 3.4 纸器/印刷包装行业特色（你的行业纵深）

这一节是你的**独门武器**。大部分候选人只会泛泛的"制造业"，你能讲纸器/印刷包装的行业细节，且有 CP6 真实实体佐证。**这一节能让面试官记住你。**

### 3.4.1 纸卷 / 克重 / 令数——纸的度量衡

**业务背景**：纸不是按"个"算，是按物理量算，且有一套自己的度量衡：

- **克重（连量 / Basis Weight）**：每平方米多少克（g/m²）。K280 = 280g/m² 的牛皮纸。**克重决定纸的厚薄、强度、成本**。
- **令数（令 / Ream）**：纸张的计量单位，业界一令通常是 500 张（标准尺寸）。买纸报价常按令。
- **纸卷（原纸卷）**：卷筒纸按卷管理，一卷就是一个独立库存单位，用"幅宽 × 纹向 × 残米长 × 芯径"识别。
- **残米管理**：卷筒纸用一段少一段，要实时减"残米长"，低于阈值就是残卷（边角料），要么拼小活要么废弃。

**CP6 佐证（PaperRoll 实体，字段全对得上）**：
- `PaperRoll.RollNo`（一卷 = 一独立库存单位，业务主键）。
- `PaperGrade`（纸质 K280/K210/SK）、`WidthMm`（幅宽 905/1100/1310mm）、`BasisWeight`（连量 g/m²）、`GrainDirection`（纹向 T目/Y目）。
- `OriginalLengthM`（入库米长）、`RemainingLengthM`（**残米长，用一次减一次**）、`DisposeThresholdM`（废弃阈值，残米低于此值→废弃候补）。
- `CoreDiameterInch`（芯径 3/5 寸）、`MfgLotNo`（造纸厂批次，追溯用）、`ParentRollNo`（分切母卷，一大卷切成几小卷）。
- 状态：0=在库 1=使用中 2=残米 3=废弃。

**车间对话体**：
> 印刷师傅：「这活要 1100 幅、K280 的纸，仓库有没有？」
> 系统：有 3 卷，其中 ROLL20260601-00012 残米 1200m、纹向 T 目，够这活。用完剩 320m，低于 500m 阈值→自动标残卷。
> 面试点：**纸卷不是"数量=5"这么简单，是"每一卷独立、按米消耗、纹向/幅宽/克重都要匹配工艺"**。你能讲残米管理和纹向，行业味十足。

---

### 3.4.2 版模管理（版 / 模 / 刀模）

**业务背景**：印刷要**版**（印版，每种颜色一块），模切要**刀模/木型**。版模是重资产，管理复杂：

- **版模有寿命**：印刷版、刀模用多了会磨损，有"通し数（累计使用次数）"和"限界通し数（寿命上限）"，到寿命要换。
- **版模要版本管理**：产品改规格，版模改版，新旧版要分清、要记适用起止日期。
- **版模有存放位置**：一个厂几千套版模，找不到就是灾难，要管到"场所/棚/线"。
- **版模有归属和送修**：客户的版模（客供）、送外协加工、送修、返还、报废，全流程要追。

**CP6 佐证（PlateMold 实体——注释直接标"★★★ 最複雑マスタ"）**：
- 业务主键 `(WdPtnNo, WdRev)`——**一版型 N 个 Rev 做版本历史**，改版 Rev+1，前版设"适用终了日 = 新版适用开始日 −1"。
- `TypeClass`（版型分类：0300 橡胶型/0450 胶印型/0600 木型/0650 箔版）、`CompositionQty`（付数=面付）、`ColorQty`（色数）。
- `WdQty`（通し数，批处理累加）、`LimitWdQty`（限界通し数=寿命）——**版模寿命管理**。
- `PlaceCd`/`ShelfLineCd`（场所/棚线，系统管理不可手改）——**版模定位**。
- `SupplierCd`/`ProcessDestination`/`DeliveryDate`/`ReturnScheduleDate`/`ReturnDate`/`ReturnReason`/`DispActualDate`——外协/送修/返还/报废全流程。

**车间对话体**：
> 生产：「这单要用 A 客户礼盒的刀模，在哪？还能用吗？」
> 系统：木型 WD00123 Rev3（现行版），存放场所 B 区 3 号棚 2 线，通し数 8500/限界 10000，还能用；再做 1500 个就到寿命要报废重做。
> 面试点：**版模是印刷包装厂的核心资产管理难题**。你能讲"版本历史、寿命通し数、存放定位、送修返还全流程"，就是深度行业理解。这个实体注释都写"最複雑"，你搞过它就是硬通货。

---

### 3.4.3 油墨配色与批次

**业务背景**：印刷颜色是命根子，专色配色 + 批次管理很讲究：

- **专色 / 配色**：客户要的颜色（品牌色）常是专色，靠几种基础墨按配方调出来，用色号（DIC-XXX、Pantone-XXX）标识。配色要记配方、记历史，保证批次间颜色一致。
- **油墨批次 + 效期**：油墨是液体，有保质期，**未开封和开封后效期不同**（开封后氧化快）。要 FEFO。
- **批次混合**：剩的旧墨和新墨混着用，要记"混合来源"，效期取更早的那个。
- **粘度 / 固形分**：油墨的物理参数，影响印刷效果，要记录。

**CP6 佐证（InkLot 实体）**：
- `InkLotNo`（批次主键）、`ColorCode`（色号 DIC-XXX/Pantone-XXX）、`InkType`（OFFSET/フレキソ/UV）。
- `OpenStatus`（UNOPENED/OPENED）、`ExpiryDate`（效期）——注释明写"未开封 180 天 / 开封后 30 天"效期切换。
- `ParentLotNoA`/`ParentLotNoB`（**混合来源两个母批次**，混合时旧批 2 件 OUT + 新混合批 1 件 IN，效期继承更早的）。
- `ViscosityCp`（粘度 cP）、`SolidContent`（固形分 %）。
- 配色历史 `InkColorMatchHistory`（WMS）——记配方和配色历史。

**车间对话体**：
> 印刷师傅：「这单专色 DIC-2020，仓库墨够吗？别拿快过期的给我。」
> 系统：DIC-2020 有 2 批，LOT-A 开封了还剩 3kg（开封效期 7 月 20 到，快过期先用）、LOT-B 未开封 15kg。按 FEFO 先给 LOT-A。
> 面试点：**油墨批次是"效期 + 配色一致性"的双重挑战**。你能讲"未开封 vs 开封效期、批次混合、专色配方"，行业纵深拉满。

### 3.4.4 合板 / 拼版生产的共产品（一张大纸出多个产品）

**业务背景**：这是印刷包装**最独特的成本难题**。为省纸、省印次，常把**多个不同产品拼在一张大纸上一起印一起切（拼版/合板）**。一次生产**同时产出好几种产品（共产品 / Co-Product）**：

- 一张大纸模切下来，同时出 3 种不同的盒子。
- 成本怎么分摊到这 3 种产品上？按面积？按数量比？——**共产品成本分摊**是难点。
- 一种产品做够了另一种还没够怎么办？（连产比例不匹配）

**CP6 佐证（ProductCoProduct 实体）**：
- 注释直接说是"トムソン工程（模切工序）Popup 的連産品リスト"。
- 业务复合主键：`製品コード + 工程コード + 行番`——一个产品在模切工序下有多个共产品行。
- `QtyRatio`（**数量比率**，各共产品产出比，总计=模切工序的个数）、`CoProductName`、`NextProcessCd`。
- 用途注释：工程 CD = 0600/0601/0602（トムソン=模切）的连产品行。

**车间对话体**：
> 成本会计：「这批拼版印刷，一张大纸出 A 盒和 B 盒，纸钱和印刷费怎么分？」
> 系统：按 QtyRatio 分摊——A 盒占 60%、B 盒占 40%，共同的纸材费和印刷费按比例摊到两个产品的成本上。
> 面试点：**共产品/拼版是印刷包装区别于一般离散制造的特色**。一般制造一张工单出一种产品，拼版是一次产出多种，成本要分摊。你能讲 QtyRatio 分摊，就说明你懂这个行业的成本特殊性。**这是很多做过一般 MES 的人都不懂的点，讲出来很加分。**

---

### 3.4.5 损耗率——印刷包装的成本命门

**业务背景**：印刷包装损耗特别大且特别关键：

- **调机损耗**：印刷开机要调墨、对版、试印，前面几十上百张是废的（调机废）。
- **过程损耗**：印刷、模切、糊盒每道工序都有损耗。
- **损耗率直接吃利润**：报价按 5% 损耗，实际做到 10%，多出来的 5% 纸和墨全是白扔的钱。
- **小批量损耗率更高**：调机损耗是固定的，量越小摊得越狠——所以小单报价损耗率要放高。

**CP6 佐证**：
- `WorkOrderProcess.StdLossRate`（标准损耗率）vs `ProductionResult.ActualLossRate`（实绩损耗率）——**标准 vs 实际损耗对比**就是成本管控核心。
- 报价 `EstimateCalc` 里损耗率是成本项。
- 纸卷 `RemainingLengthM` 残米、`RemnantMaterial`（余料）——损耗和余料回用。

**车间对话体**：
> 老板：「这批活怎么亏了？」
> 成本分析：报价按 5% 损耗，实际印刷损耗 8%（调机多试了 200 张）+ 模切损耗 6%，纸材成本超了 60%，吃掉了利润。
> 面试点：**损耗率是印刷包装的成本命门，小批量尤其致命**。你能讲"调机损耗固定、小单摊得狠、标准 vs 实际损耗对比"，就是真懂这行的成本。

## 3.5 车间的真实痛点语言包（业务翻译能力演示）

**这一节是本章的高潮，是 JD 那句"根据用户需求开发"的直接演练。** 面试官最想验证的能力就是：**用户用大白话抱怨，你能翻译成系统需求，并给出方案。** 下面每个痛点，按"**车间原话 → 翻译成系统需求 → CP6 对应方案**"三段式。

背下这几个案例，面试时任何"你怎么理解用户需求"的问题，都能现场演一遍。

---

### 痛点① 车间主任说："单子插不进去！"（插单 / 急单）

**车间原话**：
> "这个客户是大客户，货急，今天必须给我插到前面做！别跟我说排满了！"

**翻译成系统需求**：
1. 工单要有**优先级**字段，急单能标高优先级。
2. 排产要支持**插单重排**——插一个进去，系统要算出：挤掉哪些单、它们顺延后交期会不会破、要不要额外换型。
3. 要能**可视化看到连锁影响**（甘特图上一插，后面自动顺延，红色标出破交期的）。
4. 插单要**留痕**（谁批准的插单，防止随便插乱套）。

**CP6 对应方案**：
- `WorkOrder.Priority`（1=通常 2=急ぎ 3=特急）——优先级已建模。
- 排产按优先级 + 交期插队，`WorkOrderProcess.PlanStartTime/PlanEndTime` 重算。
- （诚实地说：CP6 记忆里记着"Reschedule 无过去日期/号机冲突检知、AutoArrange 不避已占用时段"是待完善的缺口——面试时可以坦诚讲"我们知道插单重排的产能冲突检知还没做完整，这正是有限产能排产最难的部分"，反而显真实。）

**面试话术**：
> "'插单'这三个字，业务上是一句话，系统上是一连串：优先级 → 重排 → 冲突检知 → 交期影响 → 审批留痕。我做 CP6 排产时最深的体会是，急单插队不难，**难的是算准'插进去会挤掉谁、谁会破交期'**——这是有限产能排产的核心。"

---

### 痛点② 仓库说："账上有货，就是找不到！"（库位管理缺失）

**车间原话**：
> "系统说这个料还有 500，我在仓库翻了半天找不到，这系统不准！"

**翻译成系统需求**：
1. 库存不能只管到"仓库级"，要管到**库位（Location）级**——精确到哪个货架哪一格。
2. 入库要**指定库位、上架有记录**；出库要**按库位拣货**。
3. 要能**库位查询**——输入料号，告诉我它在哪几个库位、各多少。
4. 批次也要绑库位（同一个料不同批次可能在不同库位）。

**CP6 对应方案**：
- `Stock` 表唯一键含 `LocationCd`：`(WarehouseCd, LocationCd, ProductCd, LotNo)`——**库存精确到库位 × 批次**，不是仓库级汇总。
- `Location`/`WmsBin`（库位/储位主数据）、`Pallet`（托盘）。
- `SlottingPlan`（上架策略）、`OutboundRoutingRule`（拣货路径）。
- 纸卷 `PaperRoll.LocationCd`/版模 `PlateMold.PlaceCd+ShelfLineCd`——重资产定位到棚位。

**面试话术**：
> "'账上有货找不到'的根因，99% 是库存只管到仓库级、没管到库位级。CP6 的库存唯一键是仓库+库位+产品+批次四要素，就是为了让每一个数量都'有地址'。找不到货本质是系统里那个数量没有地址。"

---

### 痛点③ 财务说："月底对不上账！"（结账 / 成本归集）

**车间原话**：
> "月底了，库存金额和总账对不上，差了好几万，一笔笔查到崩溃。"

**翻译成系统需求**：
1. 每一笔库存移动都要**有凭证、有金额、可追溯**（不能有"暗账"）。
2. 库存交易和财务过账要**同源、同步**（不能库存动了财务没动）。
3. 成本要能**按工单实际归集**（料+工+费），完工结转清晰。
4. 要有**期末结账流程**，锁定当期、对齐库存账和总账。

**CP6 对应方案**：
- `StockTransaction`（每笔库存移动的流水凭证）+ 单一写入口 `StockMovementService`——**杜绝暗账**，任何库存变动都有流水。
- 财务 FIN 模块 AP/AR/总账，三单匹配 `ThreeWayMatch` 用 `SupplierInvoiceNo` 幂等防重复建应付。
- 成本按工单 `WorkOrderProcess.ActualLaborHour/ActualMachineHour` × `ProcessCostRate` 归集。
- （CP6 记忆里有"月末结账""成本归集"相关模块，还有"审计豁免须字段级实查"的严格纪律。）

**面试话术**：
> "月底对不上账，根因往往是'库存有交易财务没记'或'两边不同源'。CP6 的做法是库存只有一个写入口，每笔移动都落 StockTransaction 流水，财务和库存共享同一批交易事件——同源了，就不会对不上。**对账问题的解法不是'对账工具',是'从源头保证只有一本账'。**"

---

### 痛点④ 品质说："客诉了，查不到源头！"（追溯断链）

**车间原话**：
> "客户投诉这箱盒子印歪了、还掉色，问我们是哪批出的问题、还有多少流出去了——我查不出来！"

**翻译成系统需求**：
1. 成品要能**反向追溯**到：用了哪批纸、哪批墨、哪套版模、哪台机、哪个班、谁做的。
2. 原料/半成品要能**正向追溯**到：这批墨印了哪些成品、发给了哪些客户。
3. 追溯链**不能断**——每一次料的转移（领料、报工、入库）都要记批次。
4. 查出波及范围后，要能**一键冻结/召回**未发的库存。

**CP6 对应方案**：
- 批次贯穿全链：原料 `PaperRoll.RollNo`/`PaperRoll.MfgLotNo`、`InkLot.InkLotNo`；工单 `WorkOrder.LotNo`；报工 `ProductionResult`（记 OperatorCd/MachineCd）；成品库存 `Stock.LotNo`。
- `StockTransaction` 流水串起每一次转移的批次，正反向追溯都靠它。
- `Stock.RecallFlag`（召回标记，true 禁出库）+ `QcStatus=HOLD`——查到波及范围一键冻结。
- 版模追溯 `PlateMold.WdPtnNo+WdRev`（哪套版哪个 Rev）。

**面试话术**：
> "追溯断链一定是某一步没记批次。CP6 把批次做成库存唯一键的一部分，让批次'无处可丢'——领料带批次、报工带号机作业者、入库带批次，每一环都记在 StockTransaction 里。查客诉时，从成品批次逆着流水往上查到原料批次、再顺着查所有波及成品，一条链。**追溯的功夫不在'查'，在'平时每一步都不丢批次'。**"

---

### 痛点⑤ 老板说："我不知道现在车间在干嘛！"（现场不透明）

**车间原话**：
> "我走一圈车间看不出个所以然，到底哪些单在做、做到哪了、哪台机在闲、今天能不能交货，我心里没数。"

**翻译成系统需求**：
1. 要有**实时的现场看板**——每张工单在哪道工序、进度百分比、哪台机在跑/在闲/停机。
2. 要能看**当日/当班的产出、不良、达成率**。
3. 交期风险要**提前预警**（这单照现在进度会破交期）。

**CP6 对应方案**：
- 工单状态机（着手中/中断/完了）+ `WorkOrderProcess` 工序进度 + 实时报工 `ProductionResult` → 汇总成看板。
- `OeeDaily` 设备效率、`MachineDowntime` 停机 → 设备状态。
- （CP6 二三四期规划里有"驾驶舱/dashboard"，正是老板要的现场透明化。）

**面试话术**：
> "老板要的'透明'，本质是把车间每个工人手上的报工、每台机的状态，实时汇总成一屏。前提是报工要实时、要准——所以现场报工（扫码/触屏）是根，看板是果。没有实时报工，看板就是假的。"

---

### 痛点⑥ 计划员说："换型换到手软，一天洗三遍墨！"（换型损耗）

**车间原话**：
> "排产的人不懂，一会儿排红盒、一会儿排蓝盒、下午又排红盒，我一天洗三遍墨、换三次版，机器一半时间在调机，产量上不去！"

**翻译成系统需求**：
1. 排产要考虑**换型成本**——把同色/同版/同规格/同纸的工单**聚在一起排**，减少换型次数。
2. 要有**换型时间矩阵**（从产品 A 切到 B 要多久），排产算总换型时间。
3. 换型损失要计入 **OEE 可用率**，让管理者看到"多少产能被换型吃掉了"。

**CP6 对应方案**：
- 排产按 `WorkOrderProcess.MachineCd` + 产品属性聚类排程；油墨色号 `InkLot.ColorCode`、版模 `PlateMold.WdPtnNo` 是聚类维度。
- 换型停机计入 `MachineDowntime` → 拉低 `OeeDaily.Availability`。

**面试话术**：
> "换型是排产的隐形杀手。系统的价值是把'同色同版'的活自动聚一起排，把一天三次换型压到一次。这也是为什么排产不能只按交期排，要按'交期 + 换型最小化'多目标优化——这正是 APS 高级排产的价值。"

---

### 痛点⑦ 采购说："料买多了压死，买少了停线！"（库存与齐套）

**车间原话**：
> "上次牛皮纸买多了压了一仓库半年用不完，这次白卡又买少了工单停线等料，我到底该按什么买？"

**翻译成系统需求**：
1. 采购不能拍脑袋，要**需求驱动**——按 MRP 净需求 + 安全库存 + 补货点算该买多少。
2. 工单下达前要**齐套检查**（Kitting Check）——料不齐不下达，避免开工才发现缺料停线。
3. 缺料要能**自动预警并反流请购**，别等停线了才发现。

**CP6 对应方案**：
- MRP 净需求驱动 `PurchaseRequest`；`MaterialShortage`（缺料）→ `PurchaseRequest.Source=shortage/workorder` 自动反流请购。
- 安全库存/补货点参与 MRP 净需求公式。

**面试话术**：
> "'买多压死、买少停线'是库存管理的永恒矛盾，解法是让采购由需求驱动、由数据算，而不是靠人估。CP6 的缺料反流——工单一发现 BOM 缺料就自动生成请购——就是把'停线才发现'提前到'计划就发现'。"

## 3.6 需求分析方法论：从"用户说要什么"到"系统该做什么"

JD 说"根据用户需求全新开发"——这一节教你一套**可复述的需求分析方法论**，面试问"你怎么做需求"你能有章法地答，而不是"就跟用户聊聊"。

### 3.6.1 核心认知：用户说的是"解决方案"，不是"需求"

**最重要的一条**：用户说"我要一个报工扫码功能"——**这是他想象的解决方案，不是他的真实需求**。你的工作是**往回问，问出他真正要解决的问题**，因为他想的方案未必最优，甚至南辕北辙。

> 用户："给我加个扫码报工。"
> 差的开发：好的，我做个扫码。（照着做，可能做错）
> 好的开发："您现在报工是怎么做的？为什么想改成扫码？是嫌手输慢，还是手输老出错，还是想实时看进度？"——**问出背后的痛，才能给对方案。**

### 3.6.2 5W1H 追问法（需求访谈的骨架）

对任何一个需求，用 5W1H 系统地问一遍，保证不漏：

| 维度 | 问什么 | 例（报工扫码） |
|------|--------|----------------|
| **Why** | 为什么要这个？解决什么痛？ | 手输慢？出错？要实时进度？防漏报？ |
| **Who** | 谁用？谁受影响？ | 一线工人（可能不会用智能机）、班长、财务 |
| **What** | 具体要什么？扫什么？记什么？ | 扫工单条码，记良品/不良/工时/号机 |
| **When** | 什么时候用？频率？实时性要求？ | 每道工序完成时，一天几百次，要实时 |
| **Where** | 在哪用？环境如何？ | 车间现场，油污、粉尘、可能没 WiFi |
| **How** | 怎么用？现在怎么做的？ | 现在纸质记录事后录入；工人戴手套操作 |

**这张表你要能默画出来**。面试时说"我做需求会用 5W1H 过一遍，尤其 Why 和 Where 最容易被忽略"，立刻显专业。

### 3.6.3 四种需求挖掘手段

1. **现场观察（去现场！）**：坐在车间看工人真实怎么干。**用户说的和实际做的常常不一样**。你会发现他嘴上说"扫码就行"，但戴着油手套根本按不准触屏——这只有到现场才看得到。
2. **单据流梳理**：跟着一张单子走完全程，看它从哪来、到哪去、每一步谁经手、填什么。**单据流就是业务流的化石**，梳理单据流能还原真实流程。
3. **例外流程挖掘（最关键！）**：正常流程谁都会说，**真正的需求藏在例外里**。要主动追问：
   - "退货怎么办？"
   - "盘点盘亏了怎么处理？"
   - "料领错了怎么退？"
   - "工单做一半客户取消了？"
   - "扫码枪坏了/没网了怎么报工？"
   - "报错了怎么冲销？"
   - **这些例外流程，才是系统 80% 复杂度的来源。** 面试时强调这一点，证明你有经验。
4. **原型确认**：画个低保真原型/流程图给用户看，"你要的是不是这样？"——**在写代码前用便宜的东西对齐理解**，比做完了返工省 100 倍。

### 3.6.4 需求文档的最小结构

面试问"你的需求文档怎么写"，给这个最小骨架（不用花哨，够用即可）：

```
1. 背景与目标   —— 为什么做，解决什么痛，成功标准是什么
2. 干系人       —— 谁用、谁批、谁受影响
3. 业务流程     —— 现状流程 + 目标流程（画图）
4. 功能需求     —— 具体要什么（用户故事：作为X，我要Y，以便Z）
5. 例外/边界    —— 退货、取消、盘亏、异常……（重点！）
6. 非功能需求   —— 性能、并发、离线、权限、审计
7. 数据与集成   —— 涉及哪些数据、和哪些系统对接
8. 验收标准     —— 怎么算做完了
```

**重点强调第 5 项**：好的需求文档一半篇幅在写例外。

### 3.6.5 完整案例演练：车间要"报工用扫码"

**这是本节的压轴，面试时可以完整讲一遍，展示你的需求分析全流程。**

**第一步：不要急着做，先问 Why（往回追）**

> 我："您现在报工怎么做的？为什么想改扫码？"
> 车间主任："现在工人下班前在纸上填当天做了多少，第二天办公室录入系统。想改扫码。"
> 我："改扫码是想解决什么？"
> 车间主任："一是纸质录入慢、还老录错；二是数据滞后一天，我当天看不到进度；三是有工人多报少报，想防一下。"
>
> **← 到这里，真实需求浮现了：不是'扫码'，是'实时 + 防错 + 防造假'。扫码只是手段之一。**

**第二步：5W1H 补全**

> - Who：一线工人，年纪偏大，不都会用智能手机 → **界面必须极简，大按钮，少输入**。
> - Where：车间现场，油污粉尘，工人戴手套 → **触屏可能按不准，PDA 扫码枪 + 物理按键更靠谱**；车间角落 WiFi 弱 → **要考虑离线缓存补传**。
> - When：每道工序完成时报，一天几百次 → **单次操作要在 10 秒内完成**。
> - What：扫工单条码带出工单信息，报良品/不良数、选不良原因、自动记工时/号机/作业者。

**第三步：现场观察验证**

> 去车间蹲半天，发现：工人戴手套确实按不准触屏；有台机在角落 WiFi 时断时续；工人对"选不良原因"很抵触（嫌麻烦）。→ **方案要调整**。

**第四步：例外流程挖掘**

> - 扫错工单怎么撤？→ 要有冲销/撤回。
> - 一道工序两个人接力做怎么报？→ 要支持中断/接续（CP6 的 ResultType 开始/中断/恢复正好对应）。
> - 没网时怎么办？→ 本地缓存，恢复后补传（幂等防重）。
> - 报完发现数错了？→ 允许当班修正，跨班要审批。

**第五步：方案权衡（给选项，讲代价）**

| 方案 | 优点 | 缺点 | 适用 |
|------|------|------|------|
| 平板触屏 | 便宜、界面丰富 | 手套按不准、怕摔怕油 | 干净工位 |
| 工业 PDA + 扫码枪 | 耐用、扫码快、有物理键 | 贵 | 油污车间（推荐） |
| 固定工位一体机 | 稳定、大屏 | 不能移动 | 固定报工点 |

> 权衡建议：油污车间用工业 PDA，防错（扫码代替手输工单号）+ 实时（联网即传）+ 离线缓存兼顾，不良原因做成"高频原因大按钮 + 其他"降低抵触。

**第六步：对应到 CP6 落地**

> - 报工写 `ProductionResult`：`ResultType`（开始/中断/恢复/完工/数量报告——正好支持接力和分段）、`GoodQty`/`DefectQty`/`DefectReasonCd`/`OperatorCd`/`MachineCd`。
> - 工时 `LaborHour`/`MachineHour` 按时间戳自动派生（`ActualHourSource=Derived`），减少手输。
> - 离线补传用幂等键（`ResultNo` 唯一）防重复报工。

**面试收尾金句**：
> "这个案例我想说明的是：**用户说'扫码'，我交付的是'实时+防错+防造假的报工体系'。如果我照字面做个扫码，可能忽略了没网的场景、忽略了工人戴手套按不准，上线就被骂。需求分析的价值，就是把'用户想的方案'还原成'用户的问题'，再给出真正合适的方案。**"

## 3.7 需求变更管理（JD 原文条目）

JD 里通常有一条"需求变更管理"或类似表述。变更管理是把双刃剑——**做不好，项目被变更拖死；做好了，是你专业度的体现。**

### 3.7.1 为什么变更危险（先讲清风险）

面试官问"怎么看待需求变更"，先说清风险，证明你敬畏它：

1. **影响面难评估**：改一个"小需求"可能牵动一串。比如"报工加个字段"听着小，但可能影响报工界面、数据库、成本计算、看板统计、历史数据兼容。
2. **工期被吃掉**：变更不评估直接做，工期黑洞，其他功能被挤。
3. **回归风险**：改动可能破坏已经测好的功能，不做回归就上线，埋雷。
4. **责任不清**：口头改需求、没留痕，出了问题谁负责说不清。
5. **范围蔓延（Scope Creep）**：一点点加，最后完全超出预算和工期。

### 3.7.2 规范的变更流程（话术要顺）

> "我处理变更的流程是四步：**评估影响 → 书面确认 → 纳入版本 → 回归测试。**"

1. **评估影响**：收到变更，先评估——改哪些模块、多少工作量、影响哪些已完成功能、有没有风险。给出"这个改动要 X 人天，会影响 A、B 功能，需要重测 C"。
2. **书面确认**：**任何变更必须书面确认**（邮件/工单/需求变更单），写清改什么、为什么、谁批准、影响和代价。**口头需求一律不做**——这是保护双方。
3. **纳入版本**：变更排进版本计划，不插队打乱当前迭代（除非紧急且走审批）。让变更**有序**而不是随时打断。
4. **回归测试**：变更实现后，不只测新功能，要**回归测试受影响的老功能**，防止改坏。

### 3.7.3 拒绝的艺术：不说"不"，说"代价和排期"

**这是高段位**。面试官爱问"用户不停加需求你怎么办"：

> "我不会直接说'这个做不了'——那样显得不配合。我会说**代价和排期**：'这个可以做，需要额外 3 天，会让原定这周的 X 功能顺延到下周，您看是插进来还是排到下个版本？' 把选择权和代价一起交还给用户。**用户要的往往不是'立刻'，是'知道什么时候能有、代价多大'。** 大部分不合理需求，在看到真实代价后会自己降优先级。"

再补一句显成熟：
> "另外我会区分'变更'和'本来就漏了的需求'。如果是我需求没问清导致的遗漏，那是我的责任，我不会算成变更甩锅给用户；如果是用户新增的想法，那走变更流程。分清这个，合作才长久。"

### 3.7.4 CP6 实践佐证（你真做过闭环）

**这是你的杀手锏**——CP6 的开发流程本身就是一套变更闭环，可以直接讲：

> "CP6 的每个改动我都走一套闭环：**spec（写清要改什么、边界在哪）→ plan（拆成任务、评估影响）→ 实现 → 审查（review）→ 线上实证（上线后真实验证）**。比如有个改动涉及审批归属校验，我们发现放开权限会导致越权代批，就先冻结在 admin-only，等校验落地了再放开——这就是'评估影响 → 不急着改 → 有序纳入'的实践。每个改动都有 spec 留痕、有 review 把关、有线上实证兜底，就是把变更管理落到工程纪律里。"

（这段用了你 MEMORY 里真实的"spec→plan→实现→审查→线上实证"和"审批归属校验暂缓放权"的例子，非常可信。）

**面试点**：变更管理的本质是**"让改动有评估、有留痕、有回归、有序"**。你能把它和 CP6 的 spec-plan-review-实证闭环对上，就证明你不是纸上谈兵。

## 3.8 面试问答集（30 问）

下面是 30 个高频问题，每题给**业务语言的参考答案**。答案都短小精悍、可背诵，回答时用你自己的话 + CP6 例子扩展。

---

**Q1：MES 和 ERP 有什么区别？**
> ERP 是"计划的账本"，管钱和料、要做什么、成本多少、什么时候交，粒度到天；MES 是"执行的现场"，管正在做什么、做到哪道工序、做了多少坏了多少，粒度到分钟。ERP 下发需求，MES 反馈实绩，MES 的数据回流 ERP 算真实成本。CP6 里 ERP 的受注（T_Order）展开成 MES 的工单（T_WorkOrder），靠受注号缝起来。

**Q2：WMS 和 ERP 里的库存有什么不一样？**
> ERP 库存是"账"——总量、金额、够不够、成本多少，管财务口径；WMS 库存是"物"——精确到库位、批次、托盘，管"东西具体在哪、怎么拣"。ERP 关心 500 个值多少钱，WMS 关心这 500 个在哪几个库位、哪些批次。CP6 的库存唯一键是仓库+库位+产品+批次四要素，就是 WMS 的物理粒度。

**Q3：怎么设计一个追溯系统？**
> 核心一句话：**让批次在每一次料的转移中都不丢失**。原料进货记批次，领料带批次，报工记号机/作业者/批次，完工入库记批次，每一次移动都落一条带批次的流水。正向追溯（原料→成品→客户，用于召回）和反向追溯（成品→原料/机/人，用于查根因）都靠这条流水链。追溯断链一定是某一步没记批次。CP6 把批次做进库存唯一键 + StockTransaction 流水，就是为了让批次无处可丢。

**Q4：库存为什么会不准？怎么保证准确？**
> 三个根因：①有交易没记账（暗账）；②记账不同步（物理动了账没动）；③多个写入口并发改库存数据竞争。保证准确的办法：库存**只留一个写入口**、每笔移动都落流水凭证、用事务保证原子性、定期盘点校正。CP6 的库存只能通过 StockMovementService 改，禁止直接 UPDATE，每笔走 StockTransaction，就是这个思路。

**Q5：库存有哪几本账？**
> 至少四本：实物账（库位上实际有多少）、可用账（能被新单占用的=实物−引当−冻结）、在途（采购/调拨在路上的）、冻结（质检不合格、召回、待处理）。公式：可用=实物−引当中−冻结。CP6 的 Stock 表 PhysicalQty−AllocatedQty=AvailableQty，加上 QcStatus 冻结和 RecallFlag 召回，就是这几本账。

**Q6：OEE 是什么？怎么算？OEE 低怎么分析？**
> OEE=可用率×性能×良率。可用率=实际运行/计划运行（停机换型损失），性能=实际产量/理论产量（速度损失），良率=良品/总产量（不良损失）。三个都是百分比，乘起来。比如 83%×85%×95%≈67%。OEE 低就拆三因子看哪个拖后腿：可用率低查停机换型，性能低查速度小停，良率低查不良。CP6 的 OeeDaily 表就是逐日逐机这么算的。

**Q7：什么是 BOM？多层 BOM 和 BOM 反查是什么？**
> BOM 是产品的"配方表"——做这个产品要哪些料、各多少。多层 BOM 是成品→半成品→原料一层套一层。BOM 正查（展开）是算做 X 个成品要多少原料，反查（where-used）是查某个原料用在哪些产品上（用于料涨价评估影响）。BOM 是 MRP、领料、成本的地基，错一个数全错。

**Q8：MRP 是干什么的？基本逻辑？**
> MRP 回答"为满足订单，要买什么、买多少、什么时候到，要生产什么、什么时候开工"。逻辑：按 BOM 逐层展开算毛需求，减现有库存、减在途、加安全库存=净需求，净需求>0 的外购件生成请购（按提前期倒排下单日）、自制件生成生产单。CP6 的 PurchaseRequest.Source 有 workorder（工单 BOM 缺料自动请购），就是 MRP 需求驱动采购的落地。

**Q9：三单匹配是什么？为什么重要？**
> 三单匹配是把采购订单（PO，订了多少什么价）+ 收货验收（实收多少）+ 供应商发票（要收多少钱）三张单对齐，容差内自动建应付、超容差挂起人工裁决。重要是因为它用规则代替财务人肉核对，防止多付、错付。CP6 的 ThreeWayMatch 比对可开票量（收货−已开票）和价格偏差率，四种状态：通过/挂起/放行/拒绝。

**Q10：什么是排产？有限产能排产难在哪？**
> 排产是把"要生产什么"排到"具体哪台机、什么时间段做"。难在"有限产能"——机器能力有限，要考虑每台机每天工时、换型时间、交期优先级。最难的是插单：插一个急单进去要算出挤掉谁、谁会破交期、要不要多换型，一连串连锁反应。无限产能排产（只看订单不看机台）排出来根本做不完。

**Q11：什么是换型？为什么排产要考虑它？**
> 换型是从做 A 产品切到做 B 产品，要换版、洗墨、调机，这段时间不产出。换型是排产大敌——频繁换型浪费产能（今天红明天蓝后天又红，一天洗三次墨）。好的排产把同色/同版/同规格的单排一起，减少换型。这是排产优化的核心目标之一。

**Q12：IQC、IPQC、OQC 分别是什么？**
> 三道质检关：IQC 来料检验（挡不合格料进厂）、IPQC 制程检验（挡不合格半成品流到下工序）、OQC 出货检验（挡不合格品发给客户）。质检的系统价值不是记结果，是让不合格品在系统里被冻结、动不了。CP6 的库存 QcStatus=FAILED/HOLD 就不能被引当出库。

**Q13：完工反冲和逐工序报工怎么选？**
> 完工反冲是完工时按 BOM 一次性倒扣料，省事但按标准扣、实际损耗对不上账；逐工序报工是每道工序实际领报都记，准且可追溯但录入负担重。选法看料的价值：贵料、损耗波动大、要精细追溯的走逐工序（比如油墨、纸卷），标准辅料走反冲。CP6 里两者并存，按料价值分级。

**Q14：标准成本和实际成本的区别？差异怎么用？**
> 标准成本是事先按标准用量×标准价算的"应该花多少"，用于报价和计划；实际成本是事后按真实料工费归集的"实际花了多少"。两者的差是成本差异，是管理抓手——报价按 5% 损耗实际 9%，这 4% 差异要查是料、机还是人的问题。标准是尺，实际是秤，差异是镜。

**Q15：什么是 WIP？为什么要管它？**
> WIP 是在制品——已开工未完工入库的半成品和它身上的成本。要管是因为它是占用资金的资产，WIP 越多压的钱越多、管理越乱。WIP 成本=已投料+已投工+已分摊费。精益生产追求降低 WIP、加快流转。CP6 里工单从着手到完了之间身上的成本就是 WIP。

**Q16：先进先出 FIFO 和 FEFO 有什么区别？**
> FIFO 先进先出，按入库时间排，先入的先出；FEFO 先到期先出，按保质期排，最早到期的先出。有效期的料（油墨、胶水、食品）用 FEFO 更合适，避免过期。CP6 的 Stock 有 ReceiveDate（FIFO）和 ExpiryDate（FEFO），引当时按规则排序取批。油墨开封后效期缩短，尤其要 FEFO。

**Q17：安全库存和补货点怎么理解？**
> 安全库存是应对需求波动和交货延迟多备的垫底量，防断货停线；补货点是库存降到该线就补货，ROP=日均用量×采购提前期+安全库存。安全库存高不易断货但占资金，低省钱但风险大，是成本和风险的平衡。CP6 缺料反流（降到线自动请购）是它的一种落地。

**Q18：盘点怎么做？盘出差异怎么处理？**
> 盘点是实际数一遍跟系统账对比。类型有全盘（停工全数）、循环盘点（滚动盘一部分不停工）、临时盘点。流程：计划→点数→差异确认→审批→完成。关键是差异要上级审批才能调账，差异金额超阈值必须批，防止随便调平掩盖问题。CP6 的 StockTake 有 ApprovalThresholdAmount 和 ApproverCd 就是这个。盘点不只是数，是数完还要查为什么差、有人为调账负责。

**Q19：不良为什么要分类编码？**
> 因为只记"坏了 150 个"没法改善，要记"为什么坏"——套印不准、尺寸超差、脏污……分类编码后才能做帕累托分析，找出占比最大的不良类型重点改善。没有不良代码体系就没有改善抓手。CP6 的 DefectCategory 有大小两级分类，报工时 DefectReasonCd 选原因。

**Q20：车间工人不愿意用系统怎么办？**
> 这是最现实的问题。首先理解他们抵触的原因：多数是"增加了负担、没给他们好处、界面太难用"。对策：①界面极简，一线工人用的界面要大按钮、少输入、防错（扫码代替手输）；②让他们感到好处（报工快了、不用手写台账、不用背黑锅）；③现场观察真实操作场景（戴手套按不准触屏这种，只有到现场才知道）；④培训 + 试点先行，找愿意配合的班组打样。**系统上不去，十有八九是没站在一线工人角度设计，而不是工人的错。**

**Q21：如果让你从零做一个报工功能，你怎么开始？**
> 我不会先写代码，先问 Why：现在怎么报工的、为什么要改、要解决慢/错/滞后/造假哪个痛。然后 5W1H 补全：谁用（工人年纪大不会智能机→界面极简）、在哪用（油污车间戴手套→PDA 比触屏靠谱、可能没网→离线缓存）、什么频率（一天几百次→单次 10 秒内）。再去现场观察验证。然后挖例外：扫错怎么撤、接力做怎么报、没网怎么办、报错怎么冲销。最后给方案权衡（平板/PDA/一体机各自代价）。CP6 里落地成 ProductionResult，ResultType 支持开始/中断/恢复/完工，工时按时间戳自动派生，离线用 ResultNo 幂等防重报。**核心是：用户说'扫码'，我交付的是'实时+防错+防造假的报工体系'。**

**Q22：需求变更太频繁怎么办？**
> 我走四步：评估影响→书面确认→纳入版本→回归测试。任何变更必须书面留痕，口头需求不做。面对不合理变更我不说"做不了"，说代价和排期："这个可以做，要 3 天，会让 X 顺延，您看插进来还是排下版？"把选择权和代价一起还给用户。还要分清"变更"和"我需求没问清导致的遗漏"——后者是我的责任不甩锅。CP6 里每个改动走 spec→plan→实现→审查→线上实证的闭环，就是把变更管理落到工程纪律。

**Q23：你怎么理解"懂业务"对一个开发的意义？**
> 懂业务的意义是能把"用户一句大白话"翻译成"系统一连串确定逻辑"。比如车间说"这单急，插进去"，业务是一句话，系统是优先级+重排+冲突检知+交期影响+审批留痕一连串。不懂业务就会把 MES 当成又一个 CRUD，做出来现场没法用。我做 CP6 最大的收获就是：生产系统难的不是技术，是把车间那套"大家心里都懂但没写下来"的规则变成计算机能执行的确定逻辑，尤其是那些例外分支。

**Q24：一张销售订单，从接单到出货，在系统里经过哪些环节？**
> 接单报价→订单评审（信用/产能/技术可行）→BOM 和工艺路线→MRP 算料→采购（请购→PO→收货→三单匹配→付款）→排产（有限产能/号机/换型）→工单下达→领料→报工（合格/不良/工时）→质检（IQC/IPQC/OQC）→完工入库→发货→对账开票。每一环有对应单据，前一环的输出是后一环的输入。CP6 里从 T_Order 展开 T_WorkOrder，工序 WorkOrderProcess，报工 ProductionResult，一路到入库出库和财务对账，是完整闭环。

**Q25：印刷包装行业和一般离散制造，系统上有什么特别的地方？**
> 几个特色：①纸按物理量管（克重 g/m²、令数、纸卷按米消耗有残米管理），不是按个；②版模是核心重资产，要版本管理、寿命通し数、存放定位、送修返还全流程；③油墨是液体，专色配色要记配方、批次有效期（开封后缩短）、批次可混合；④拼版/合板一次产出多个共产品，成本要按比例分摊；⑤损耗率特别关键尤其小批量（调机损耗固定、量越小摊得越狠）。CP6 里 PaperRoll（残米/纹向/克重）、PlateMold（版本/寿命/定位）、InkLot（效期/配色/混合）、ProductCoProduct（共产品比率分摊）这几个实体就是这些特色的落地，这是一般 MES 不覆盖的深度。

**Q26：一张工单从下达到完工，状态怎么流转？着手后能取消吗？**
> CP6 工单状态机：草稿(0)→确定(1)→发行(2，车间可着手)→着手中(3)→完了(4)→检查済(6)，中途可中断(5)、取消(9)。关键约束：**只有草稿/确定/发行三态可取消，着手后不可取消**（IsCancellable() 就这么规定的）——因为一旦开工领了料、报了工，就产生了成本和 WIP，不能简单一删了之，得走冲销/退料。状态机把业务规则（什么时候能干什么）固化进了代码。

**Q27：怎么理解生产系统里的"派生数据"？为什么有的表不做审计？**
> 派生数据是由其他数据算出来的、没有独立真值的数据。比如 OEE 日报（OeeDaily）完全由停机记录和报工记录重算得出，本身不是"录入"的。这类数据的取舍是：不重复给它做字段级审计——因为它的每次变化只是上游数据的镜像，审计它等于复制上游噪声，日频重算即可。CP6 里 OeeDaily 就明确注释豁免审计、由测试坐实零审计行。这体现的是"审计要审真值源头，不审派生结果"的设计判断。

**Q28：多租户/多工厂的制造系统，数据隔离怎么做？**
> 每条业务数据带租户/工厂标识，查询自动按当前租户过滤，写入自动盖租户号，跨租户读写要严格挡住。CP6 的 BaseBizEntity 统一处理 TenantId 自动盖章、全局查询过滤、软删、乐观锁——业务代码不用每次手写租户条件，框架层保证隔离。这样一套系统能服务多个工厂/公司而数据互不串。制造集团常见多工厂场景，这是刚需。

**Q29：你没在车间干过，凭什么说你懂生产？**
> 我没在车间拧过螺丝，但我把车间的业务流程写进过能跑的系统。要把"插单""三单匹配""批次追溯"这些写成计算机能执行的确定逻辑，我必须比业务员更清楚每一个例外分支——退货怎么办、盘亏怎么调、扫码枪坏了怎么报工。写代码逼着我把"大家心里都懂但没写下来的规则"全部问清、想透、落地。做 CP6 这三年，我是从"实现业务"这个角度深度理解生产的，这种理解不比在产线上浅。而且我能同时听懂车间的话、写出对的系统——这正是这个岗位要的"懂生产的开发"。

**Q30：给你一个全新的生产管理系统需求，你第一周会做什么？**
> 我不会第一周就开始写代码或设计表结构。第一周我会：①**泡车间**——去现场看真实作业，跟着一张单子走完全程（接单到出货），观察工人实际怎么干（而不是听他们说怎么干）；②**梳理单据流**——收集现有所有单据（订单、工单、领料单、报工单、检验单），单据流就是业务流的化石；③**访谈关键角色** 用 5W1H——业务、计划、车间主任、仓管、品质、财务各问一遍，尤其挖例外流程（退货、盘亏、插单、取消）；④**画现状流程图 + 目标流程图**给他们确认。等我把"现在怎么转的、痛在哪、要变成什么样"搞清楚，再动手设计。**第一周的产出是理解和共识，不是代码。** 需求没对齐就写代码，是返工的开始。

## 本章小结：面试前最后再过一遍

**三条主线，务必记牢：**

1. **全景图**：计划层（ERP/APS）管钱和料，执行层（MES/WMS/PLM）管人机现场，控制层（SCADA）管信号，设备层管动作。ERP vs MES 是"计划账本 vs 执行现场"。中小厂一套系统全包（CP6 就是），靠代码纪律守边界。

2. **全流程**：接单→评审→BOM/工艺→MRP→采购(三单匹配)→排产(有限产能/换型/插单)→工单→领料→报工(合格/不良/工时)→质检(IQC/IPQC/OQC)→入库→发货→对账。每一环记住"业务目标+关键单据+痛点+系统支撑+CP6 对应"。

3. **翻译能力**：车间一句大白话，你能拆成一连串系统逻辑。"插单""账上有货找不到""月底对不上""客诉查不到源头"——每个都能翻译成需求 + CP6 方案。需求分析用 5W1H + 现场观察 + 例外挖掘 + 原型确认，用户说的是解决方案不是需求，要往回问 Why。

**行业纵深（你的独门武器）**：纸卷克重令数残米、版模版本寿命定位、油墨效期配色混合、拼版共产品分摊、损耗率命门——这些一般候选人不懂，你有 CP6 实体佐证，讲出来面试官记住你。

**最后一句心法**：
> 面试时别背术语，讲你干过的事。每个概念后面都挂一个"CP6 里我是怎么做的"，把抽象知识变成"我的经历"。**你不是来证明你会写代码的（那是默认项），你是来证明你是'懂生产的开发'的。** 这一章给你的每一句话，都是为了让面试官在心里默默点头："这人，进过车间。"

祝你面试成功。
