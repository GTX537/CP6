## §0 文档说明与如何使用

### 0.1 谁用、怎么用

| 角色 | 怎么用本册 |
|---|---|
| 测试工程师 | 按 §4 选套件 → 按 §2 备数据 → 逐条执行 §5/§6 → 在 §11 缺陷台账登记「实际结果/是否通过/缺陷号」 |
| UAT / 验收 | 跑 §5 全部 E2E + §8 验收映射的关联用例，对照 §8 AC 出验收结论 |
| 培训老师 | §5 E2E 即"演示脚本"；§9 错误码表用于讲"操作错了会看到什么" |
| 开发 | §10 追溯矩阵定位"改某功能点影响哪些用例"；§12 待确认项推动业务澄清 |

### 0.2 用例两层结构（重要）

- **本册 = 登记册（执行层）**：每条用例给出 `编号 / 名称 / 优先级 / 预期结果（含错误码原文）/ 下游·数据检查`。足够让"熟悉系统 + 备好数据"的测试者执行并判定通过与否。
- **单页 SOP §13 = 详细步骤（权威层）**：含逐字 9 列（前置 / 测试数据 / 操作步骤 / 异常处理 等）。本册 §6 每页小节头部给出对应 SOP 路径，需要手把手步骤时去查。
- **编号一致**：本册沿用各 SOP §13 的原始编号（如 `TC-M04-ORDER-024`），不另起编号，便于双向对照。跨页 E2E 用例为本册新增，前缀 `TC-M04-E2E-`。

### 0.3 通过判定原则

1. **预期结果含错误码的**：必须出现**该编号的提示/拦截**，且**不落库 / 不触发下游**（边界用例）。
2. **闭环用例**：以"下游·数据检查"列为准（MES 工单 / WMS 出荷指示 / 注文追溯事件状态），不能只看前端提示成功。
3. **只读页用例**：以"无任何写按钮 + 数据正确呈现"为准（注文追溯 / OTD / 信用单 等）。
4. **`待业务确认` / `待实现` / `代码未发现`**：执行时**照实记录现状**，不判 Fail，登记到 §12 推动澄清。

## §5 模块级·跨页端到端用例（TC-M04-E2E-01~15）

> 这些是**单页 SOP 无法独立覆盖的跨页业务链**，是 UAT/验收与培训演示的主体。每条含：覆盖页 / 优先级 / 前置 / 数据 / 步骤 / 预期 / 下游检查 / 映射 AC·总册。数据统一用 §2。

### TC-M04-E2E-01 正向主链：询价→算价→报价→建档→受注→追溯
- **覆盖**：§6.1→6.3→6.5→6.7→6.10　**优先级**：P0　**映射**：AC-01 / 总册 TC-M04-001
- **前置**：§2 步 1~4 主数据齐；销售账号。
- **步骤**：1) 見積計算書录规格+工程→Step3 算价→保存（记 EMC）；2) 御見積書束ね该 EMC→確定登録（两段）→発行（记 QTN）；3) 製品マスタ引入 QTN→5 步→保存（记 PRD）；4) 受注入力引入 PRD→数量 5000→保存（记 WO）；5) 注文追溯输 WO 查询。
- **预期**：EMC/QTN/PRD/WO 四号均生成且**采番唯一**；受注一覧可查 WO；注文追溯有 MES/WMS **SUCCESS** 事件、失败/死信=0。
- **下游检查**：MES 製造指図一覧有该 WO 工单；WMS 出庫指示一覧有製品出荷指示；ShipStatus=0。

### TC-M04-E2E-02 受注保存闭环冒烟
- **覆盖**：§6.7→6.10 + MES/WMS　**优先级**：P0　**映射**：AC-08 / 总册 TC-M04-005　**关联**：ORDER-024/025/026
- **前置**：C0001、PRD2026070001 已建；`Bridge:Enabled=true`。
- **步骤**：受注入力填头+引製品+数量 5000→保存→记 WO→分别查 受注一覧 / 注文追溯 / MES 製造指図一覧 / WMS 出庫指示一覧。
- **预期**：保存成功+WO 号；OrderStatus=CONFIRMED；注文追溯 MES/WMS **SUCCESS**、无 FAILED/DEAD；MES 工单存在；WMS 出荷指示存在。
- **下游检查**：受注数量 = 工单/出荷指示数量（一致性，ORDER-032）。

### TC-M04-E2E-03 取消未着手→反向级联解锁
- **覆盖**：§6.8→MES/WMS/§6.10　**优先级**：P0　**映射**：AC-10 / 总册 TC-M04-006　**关联**：ORDERLIST-017~021
- **前置**：未出荷、工单≤発行、出库≤引当 的受注。
- **步骤**：受注一覧选单→取消→填理由→**探查**（DB 不变）→实施。
- **预期**：探查返回"可取消"且 DB 不变；实施后 Outcome=Cancelled、OrderStatus=CANCELLED。
- **下游检查**：MES 工单取消；WMS 出库指示取消 + 库存**引当解锁**；注文追溯有 `OnOrderCancelledAsync` 反向事件（TRACE-025）。

### TC-M04-E2E-04 取消已出荷被拒绝
- **覆盖**：§6.8　**优先级**：P0　**映射**：AC-10 / 总册 TC-M04-007　**关联**：ORDERLIST-024
- **前置**：ShipStatus≥5 的受注。
- **步骤**：受注一覧选单→取消→填理由→探查。
- **预期**：Outcome=Rejected，提示 **PA-MSG-CANCEL-002/003**，DB 未变。
- **下游检查**：工单/库存无任何变化。

### TC-M04-E2E-05 取消半路（生产中）→ NeedsDecision →强制部分取消
