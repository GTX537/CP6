## 二、模块依赖关系

```
                         ┌─────────────────── 横切收口 ───────────────────┐
                         │  多租户（#6 OA阶段4 Phase C，系统级 TenantId）   │ ← 全模块 tenant 实体落地后一次集中
                         └────────────────────────┬────────────────────────┘
  ┌─── 主链（强依赖）──────────────────────────────┘
  PUB B0 组织#1 ─→ PUB B1 权限#2 ─→ PUB 公共模组#3
       │                  │（强校验底座，业务模块消费）
       └─→ OA 阶段1#4 ─→ OA 阶段2-3#5 ─→（接采购/财务审批）
                              │
  财务 GL#7 ─→ 财务 AP/AR#8 ─→ 财务 成本/报表#9
                    ▲（采购 IFinAp 接 #8）   ▲（AR 成本结转 ← MRP/成本）
  采购 MVP#10 ─→ 采购 扩展#11                │
       ▲（PR 接审批#4·建票财务#8）           │
  计划中台 MRP#12 ──(建议采购PR→#10·建议工单→MES)──┘
  Space 后端#13 ─→ Space 编辑器#14 / Space viewer#15  （独立支线，可全程并行）
```

**关键依赖事实**：
- **PUB B0（组织 Sys_Dept）= 整条主链的根**：PUB 数据权限 + OA 审批路由都依赖它。**第一个落。**
- **TenantId 全系统延后到 #6 OA 阶段4 Phase C** 一次集中做（各模块计划本阶段都不引入 TenantId）。
- **跨模块全走桩起步、低耦合**：采购的 IFinAp/IWms/IApproval、MRP 的转单 IPlanToPr、Space 的 IWms 都是契约+桩，下游模块编码后接真实——**任何模块可独立起步，不被未编码模块绑死**。
- 财务/采购/MRP/Space 四支**相互独立、可并行**；强依赖只在各自模块内部（GL→AP、B0→B1）。

## 三、推荐执行波次（可落地顺序）

> 原则：先落各支线的"根"（可独立起步），再叠依赖层。波内可并行。每个计划先**修订定稿**再编码（建议 subagent-driven 逐 Task）。

### Wave 0 · 各支线的根（可立即起，无跨模块前置）
| 计划 | 为什么先 |
|---|---|
| **#1 PUB B0 组织模型** | 主链总根，最小（S），OA/数据权限/审批都等它 |
| **#7 财务 GL 内核** | 财务根，借贷恒等地基 |
| **#12 计划中台 Phase A（用量内核抽取）** | 独立、低风险（見積回归兜底）、MP-D2 已确认无前置缺口 |
| **#13 Space 后端地基** | 独立支线根 |

### Wave 1 · 第一依赖层（并行）
| 计划 | 依赖 |
|---|---|
| **#2 PUB B1 权限引擎** | #1 |
