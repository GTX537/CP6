## 准备工作（第 0 步）

打开命令行，确认这些工具都有：

```bash
dotnet --version       # 8.0 或更高
node --version         # 20 或更高
docker --version       # 25 或更高（看第 12 章会用）
git --version          # 任意版本
```

如果某个没装，先装上再回来。装完打开项目跑一遍：

```bash
# 后端
cd D:\CP6
dotnet restore
dotnet build

# 前端
cd D:\CP6\cp6.web
npm install
```

不用现在启动，跑通 build 就行。后面每一章可能会要你启某个服务。

## 几个"前置心智"，先打个底

如果你在哪一章读到这些词卡住，回来这里看一眼。

### 1. 编译 vs 运行

- **编译**：把你写的 C# / TypeScript 代码翻译成机器能跑的形式（dll / js bundle）。错误在这一步发现 = 还没上线呢。
- **运行**：实际跑起来。错误在这一步发现 = 用户已经看到了。

资深开发的本能：能让错误在编译期暴露，绝不留到运行时。CP6 用大量泛型、`[Authorize]`、强类型 DTO 就是为这个。

### 2. 同步 vs 异步（async/await）

- **同步**：A 干完 B 才能干。打电话给客服，对方查询时你只能在线等。
- **异步**：A 启动后让出位置，B 可以同时干。打电话给客服，对方查询时你可以挂电话先干别的，结果好了再回拨。

`async / await` 是异步的语法糖。CP6 里几乎所有数据库操作都是 `async`，意思是"我去查数据库的时候，这个线程别傻等，去服务别的请求"。

### 3. 客户端 vs 服务端

- 浏览器里跑的代码 = 客户端（前端）
- 你的电脑或云上跑的代码 = 服务端（后端）

中间靠 HTTP 通信。你按一个按钮 → 浏览器发 HTTP 请求 → 后端收到 → 查数据库 → 返回 JSON → 浏览器渲染。CP6 的所有功能都是这个套路。

### 4. 数据库这个特殊角色

数据库不是"代码里的一个对象"，它是**进程外的一个独立程序**，通过网络协议（哪怕同一台机器也走 TCP）跟你的后端说话。所以：

- 慢：每次查询要打包请求 + 网络传输 + 等结果
- 难"撤销"：写了就在硬盘上，回滚要靠事务机制
- 真相唯一：缓存可能错，DB 永远是真相

CP6 的很多设计（缓存策略、Bridge Hook 重试、库存铁律）都是围绕"数据库是慢但真实的"这个事实展开。

### 5. 接口（interface）和实现（class）

- `IRepository<T>` 是接口，描述"应该有什么方法"
- `RepositoryBase<T>` 是实现，告诉电脑"具体怎么做这些方法"

为什么分开：你可以换实现（测试时用假的、生产时用真的）而不动用方。CP6 大量用这个模式，第 02、06 章会反复看到。
