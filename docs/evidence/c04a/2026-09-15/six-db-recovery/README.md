## 新现场与恢复边界

- 本机在 `2026-09-15T10:43:38.5Z` 重启。交接时六个旧预览进程现均不存在，旧 PID 清单不得重用。
- Docker Linux 引擎管道不可用；没有启动 Docker Desktop、旧预览、transport 或替换服务。第六库没有声称通过，Docker 启动可能按已有策略恢复其他容器，需明确此次环境启动范围。
- 部署 Agent 仍运行且自动启动，不能用旧进程消失证明独占窗口或管理员写入已隔离。
- 五个备份依次产生，不是六库共同时间点的停写切换快照。正式操作窗口仍须评估现场变化并绑定最终备份，不能覆盖或删除本次证据。
- 这里只证明真实数据库备份可恢复且可读、结构一致；未做 CRM11 migration map 的全量规范化数据对账、应用解密和正式切换计时。
- 原数据库身份、ONLINE/可写状态及原文件字节已复核；未初始化、冻结、启用实际来源或目标。副本持久保留，不当作应清理的测试残留。
- 初始化提交退休触发器后禁止只换回 0.1 DLL；任何目标 Written 后禁止覆盖原库或恢复旧源。本次备份不放宽该边界。
