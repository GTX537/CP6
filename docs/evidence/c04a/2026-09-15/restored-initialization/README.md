## 隔离与证据范围

四个显式 SQL 连接全部改为本次三个恢复库；Identity 配置中的空连接由现有实现从 Auth 连接赋值。运行时清除继承环境，仅传入必要 Windows 路径和 Development。初始化未启动 HTTP 或后台 Worker。API 启动则采用独立 loopback 端口，并把 issuer 指向由本次进程保留、没有 TLS 响应的本地端口，避免向原身份服务发送凭证；因此它证明 API 能在真实恢复结构和 Closed 门禁上启动，不证明身份对账、登录、完整宿主/Core/Web/transport 恢复。

初始化前后的身份内容比较只在内存读取，以主键排序的 SQL JSON 计算整表摘要，不输出 PII 原值。它是保留既有数据的检查，不是 CRM11 migration map/canonicalizer 全量迁移对账；迁移历史新增记录按其正常语义单独允许。内容比较发生在隔离 API 启动前，启动阶段不据此声称对账数据继续不变。

私有执行脚本最初在连接别名转换/空 Identity 连接识别阶段拒绝输入，初始化尚未启动；复用已恢复的三库后修正。首次内容检查也明确区分追加迁移行和修改既有数据。诊断在归档内保留，未将这些脚本准备问题记为产品 SQL 回归，也没有重复初始化。

## 尚未关闭的采用前置

第六个 Docker `CP6DB` 备份/实际恢复仍等待 Docker 引擎就绪。真实 C02 的完整独立宿主恢复、私有密钥解密与身份登录、独占窗口/部署入口控制以及变化字节批准继续开放。

这次实测确认初始日历仍为空。规则继续沿用 America/New_York、周一至周五 09:00–17:00、节假日单独维护；不能虚构一个已存储版本。`SaveConfigurationAsync` 需要业务写入，Closed 会拒绝；Enabled 后保存即可进入 Written。后续必须明确受控初始化或其他经审阅的顺序，不能直接绕过门禁，也不能等第一条 Lead 才认定越过恢复边界。

本轮不会把三个隔离副本的成功视为实际环境已采用。真实初始化、三源冻结、完整集合启用仍待明确实际批准；CRM11 正式验收、采用门禁及 C04B 只读观察周期保持开放。
