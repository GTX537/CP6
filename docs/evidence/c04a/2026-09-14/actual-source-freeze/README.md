# 实际来源冻结组件交付证据

实现与边界见 [ACTUAL-FREEZE](../../../../../tools/CP6.Crm.SourceFence/ACTUAL-FREEZE.md)，执行阶段、代码输入、失败及复用范围见 [验证索引](local-validation.json) 和 [原始日志与 TRX](local-execution.zip)。本任务只交付冻结/回执组件，实际重新开放仍须目标门禁和路由恢复协调；没有执行实际库冻结。

新增 17 个不同验证和 3 个直接受共享事务抽取影响的代表回归分批通过。初始缺少新 API、nullable 编译诊断和 SQL 测试夹具事件类型失败均保留。修正夹具后只补对应项；批准摘要基线和 JSON 格式验证修改后只验证直接相关项。审查发现的回执嵌套格式问题经新增测试复现，规范序列化校验修复并定向通过。期间一次夹具删除超时，已明确核对并清理唯一残留测试库，以本机共享内存连接补完该项；不把失败重写为通过。

[集中审查及定向关闭](review.json)、[独立发布文件清单](published-files.json)、[最终清理观察](cleanup.json)分别记录。发布 DLL 另跑一次最小 CLI 夹具检查；既有预览未替换。旧成功结果不改称最终字节重跑。

测试均使用唯一命名、自建并销毁的真实 SQL 数据库。审核摘要为合成夹具值，不是实际批准；实际原生和 Docker 来源仅做读取。[来源摘要](source-inventory-summary.json)记录两份独立 CP6DB 的相同 broker GUID、Docker 的 sa 会话和不同 Compose 来源。身份、主体、会话、镜像和启动路径原件保留本机，公共记录只保留去敏分类与原件摘要。

源码从最新确认的远端 main 建立独立任务分支；分叉的本地 main 与根工作区其他内容保留。独立 Release 发布不替换现有预览，不构建镜像，不触发 Actions。后续跨源写入身份隔离、目标与路由恢复协调、CRM02 0.2 实际采用签收、CRM11 与只读观察期仍开放；整体目标 **60%（3/5）**。
